# Workflow разработки

## Источники задач

Задача может прийти из:
- голосовой заметки;
- prompt, подготовленного через GPT;
- прямого prompt в Codex;
- issue/ticket;
- письменного продуктового требования.

## Режимы работы

### Full SpecKit

Использовать для крупных, рискованных или неоднозначных задач.

Артефакты:
- `spec.md`
- `plan.md`
- `tasks.md`

Поток:
`specify → clarify → plan → tasks → implement`

### SpecKit-lite

Использовать для средних задач.

Формат:
- цель;
- что входит;
- что не входит;
- acceptance criteria;
- риски;
- вероятно затрагиваемые файлы;
- проверки.

### Короткий prompt

Использовать для маленьких локальных изменений.

Формат:
- изменить ровно X;
- не менять Y;
- запустить релевантные проверки;
- показать изменённые файлы.

## Обновление документации

Обновлять документацию только тогда, когда задача существенно меняет:
- архитектуру;
- структуру проекта;
- продуктовое поведение;
- workflow;
- важные решения;
- публичные интерфейсы или контракты.

Не логировать каждую мелкую правку.
