# Видение продукта

## Проблема

Проекты и состояние связанного оборудования периодически выгружаются сторонним сборщиком в виде снимков данных. Между загрузками могут меняться параметры контроллеров, панелей управления и других устройств: имена, IP-адреса, MAC-адреса, версии, состав оборудования и эксплуатационное состояние.

Необходимо сопоставлять снимки одного логического проекта во времени и показывать значимые изменения, не принимая перестановку JSON, временные показатели, неполный сбор или ошибки чтения за реальные изменения конфигурации.

## Целевые пользователи

- AV-инженеры;
- специалисты технической поддержки, контролирующие состояние и изменения инфраструктуры.

Пользователь анализирует изменения, проверяет их ожидаемость и фиксирует результат проверки.

## Рамки MVP

- запускать локальный демонстрационный MVP прямым открытием `index.html` без backend и установки зависимостей;
- хранить versioned state в `localStorage` и переносить его через полный JSON backup;
- принимать снимки данных, сформированные сторонним сборщиком;
- поддерживать в MVP версионированный формат Extron и распознаваемый legacy-вариант предоставленного примера;
- сохранять исходный файл и метаданные загрузки без изменения;
- проверять структуру и полноту снимка;
- нормализовать данные проекта, контроллера и связанных устройств;
- связывать снимки с одним логическим проектом по согласованным идентификаторам;
- сопоставлять одни и те же устройства между снимками с указанием уверенности;
- сравнивать текущий снимок с предыдущим и две выбранные даты;
- выявлять добавление, удаление и вероятную замену оборудования;
- выявлять изменения имени, IP, MAC, hostname, модели, part number, firmware, версии проекта, сетевых параметров и GUI;
- разделять изменения конфигурации, эксплуатационные события и проблемы качества данных;
- показывать старое и новое значения, время, объект, важность и источник данных;
- не считать отсутствующее из-за ошибки поле удалением без подтверждения полноты снимка.
- предоставлять карточку проекта, журнал изменений и фильтры;
- позволять подтверждать ожидаемые изменения и оставлять результат проверки;
- сравнивать снимок с предыдущим, двумя выбранными датами и утверждённым baseline.
- демонстрировать workflow ролей администратора и AV-инженера на уровне интерфейса без заявления о настоящей авторизации;
- применять срок хранения три года по умолчанию при открытии приложения или ручном запуске retention, не гарантируя сохранность browser storage;
- использовать только синтетические, обезличенные или явно разрешённые для локального анализа данные.

## Что не входит в продукт

- непосредственный сбор данных с оборудования — снимки предоставляет сторонний сборщик;
- автоматическое изменение конфигурации или управление оборудованием;
- backend, серверная база данных, настоящая многопользовательская авторизация и централизованное хранение в browser-only MVP;
- обязательные уведомления и экспорт отчётов в первой версии.
- форматы других производителей и пользовательский конструктор mapping в первой версии.
- production-обработка чувствительных инфраструктурных данных до принятия отдельной защищённой архитектуры.

## Критерии успеха

- система корректно связывает снимки одного проекта;
- изменение значимого поля отображается как одно понятное событие со старым и новым значением;
- изменение IP или имени не превращает устройство в новое при наличии стабильного идентификатора;
- неполный снимок не порождает ложное массовое удаление оборудования;
- пользователь может восстановить хронологию изменений проекта по датам;
- для неоднозначного сопоставления система показывает уровень уверенности и требует подтверждения.
- приложение открывается двойным кликом по `index.html`, не требует сети и сохраняет demo state после reload в том же browser profile.
