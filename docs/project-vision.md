# Видение продукта

## Назначение

MVP_SPHERE_SR — локальный инструмент автоматизированной инвентаризации, опроса и аналитики терминалов ВКС, контроллеров и панелей управления. Он объединяет данные SR, результаты сетевых проверок и историю состояния устройств на одном главном дашборде с фильтрами.

## Пользователь

Единственная роль — «Администратор МЦТП». Многопользовательский доступ, внешняя авторизация и другие роли не входят в текущий продукт.

## Основные возможности

- импорт XLSX SR и поддержание актуальной/исторической карточки устройства;
- классификация ВКС, контроллеров и панелей;
- главный экран с доказуемыми latest-state и period-метриками, глобальными фильтрами и drill-down;
- отдельная аналитика минимально подтверждённых перезагрузок по истории uptime с фильтрами, временными и территориальными графиками;
- безопасный локальный импорт учётных данных для polling scripts;
- формирование явного плана опроса и per-IP результатов;
- bounded ping и последующее подключение документированных vendor adapters;
- локальная аналитика без передачи файлов и результатов во внешние сервисы;
- зашифрованное хранилище без прикладной квоты.
- полностью русская пользовательская часть с единым словарём подписей и статусов;
- локальный «Справочник» с десятью тематическими разделами, поиском и контекстной помощью.
- воспроизводимый запуск скачанной GitHub-копии на поддерживаемом Windows-ПК без системной установки и повышения прав;
- прямое открытие `index.html` без установки для непостоянного анализа в текущей вкладке;
- единый каталог модулей и терминов, из которого автоматически строятся навигация и связанные материалы Справочника.

## Не входит

- модули «Проекты аудита», «События», «Сопоставления», «Снимки»;
- облачное или централизованное хранилище, telemetry, CDN;
- управление или изменение конфигурации оборудования;
- догадки о vendor API по названию модели;
- защита от полностью скомпрометированной ОС или текущей Windows-сессии.

## Критерии успеха

- `index.html` является единственным пользовательским режимом, открывается напрямую без browser storage, сервера и секретов;
- рабочие файлы и vault на диске не содержат plaintext;
- роль и навигация соответствуют целевому продукту;
- объём состояния ограничивается диском, а не 4 МиБ;
- секреты не появляются в UI, state, аналитике, polling output и логах;
- неизвестный vendor protocol останавливается fail-closed;
- Dashboard не выдаёт отсутствие источника за нулевое значение и не считает одно устройство дважды в current-state KPI;
- после получения подтверждённых протоколов адаптеры можно добавлять независимо от UI и хранилища.
- новый ПК получает чистый сеанс после открытия `index.html`; GitHub переносит код, но не рабочие данные;
- повреждённая или неподтверждённая среда запуска не исполняется.
- исходные значения SR/JSON остаются неизменными при русской презентации данных;
- пользователь не видит необработанные внутренние коды статусов; неоднозначные SR и GCPlus помечены как требующие уточнения, а неподтверждённые признаки перезагрузки не увеличивают аналитический счётчик.

## Открытые входные данные

Для реализации реального опроса по каждому семейству устройств нужны: официальный протокол/endpoint, версия API, схема аутентификации, TLS/SSH требования, read-only команды, примеры безопасных ответов, timeout/rate limits и ожидаемые поля результата.
