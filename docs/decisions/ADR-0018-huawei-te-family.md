# ADR-0018: Один guarded web-CGI алгоритм Huawei TE30, TE40, TE50 и TE60

**Статус**: Принято и подтверждено контролируемыми опросами TE30/TE40/TE50/TE60

**Дата**: 2026-09-05

## Контекст

Huawei TE40 уже использует подтверждённый локально web-CGI flow. Пользователь предложил проверить его совместимость с TE30, TE50 и TE60 и не создавать дублирующие алгоритмы.

Официальный Huawei HTTP API reference V600R019C00 совместно охватывает TE30, TE40, TE50, TE60 и TX50 и описывает общий `/action.cgi` authentication family. Это подтверждает архитектурную гипотезу, но не гарантирует конкретные установленные версии firmware.

После внедрения пользователь выполнил опросы реальных TE30, TE50 и TE60 тем же алгоритмом, ранее подтверждённым на TE40. Все три опроса завершились корректно и сформировали результаты по аналогии с TE40. Тем самым гипотеза подтверждена для всех четырёх проверенных моделей и установленных на них версий firmware.

## Решение

1. Использовать один transport для точных моделей TE30, TE40, TE50 и TE60.
2. До передачи credentials проверять login bundle и совпадение planned model с `WEB_GetLoginInfo.szTermType`.
3. После входа повторно проверять planned model по version resource и требовать serial или валидный MAC.
4. Оставить TE20 и остальные Huawei `protocol_required` без network attempt.
5. Не менять exact-IP allowlist, TLS-policy, resource allowlist, response bounds, redaction, job/ACK и output JSON structure.
6. Считать общий алгоритм подтверждённым для TE30, TE40, TE50 и TE60 по результатам контролируемых реальных опросов; новые модели не включать без отдельной проверки.

## Последствия

- TE40 сохраняет прежнее поведение с более строгой pre-auth identity проверкой.
- TE30, TE50 и TE60 используют подтверждённый общий контракт без отдельных adapter copies.
- Несовместимая прошивка завершится диагностируемо и не будет ошибочно признана ожидаемой моделью.
- TX50 не включается автоматически, несмотря на общий официальный справочник.
