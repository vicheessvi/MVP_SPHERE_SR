# ADR-0070 — только явные порты и совместимый stream-log upgrade

Дата: 2026-11-25. Статус: принято по прямому требованию администратора.

## Порты

Администратор отозвал прежний комплексный режим HTTP/Telnet: таблица служит
только списком целей, значения по умолчанию не меняются. Старая общая галочка и
счётчики создавали впечатление запланированного закрытия даже при Answer-only.
Автоматическая фактическая запись в его рабочем запуске без журналов не подтверждена;
тестовый upload не создаёт job/network, но опасная legacy опция полностью удалена.

disable_insecure_management_services запрещён при plan validation/probe/новом
launch/resume всех schema, включая сохранённые bulk планы. Исторические отчёты
и приватные guarded adapter fixtures остаются читаемыми, не дают новый launch.
Сохраняются только отдельные подтверждённые TE20 HTTP/Telnet open/closed/Не менять
и single-target guards. Не выдумываются port contracts других моделей и не
выполняется автоматическое восстановление прежних портовых состояний.
После XLSX/SR импорта selectors/collectors сброшены; значения колонок не tasks.

## Логи

Скриншот показывает полный обход папки и единственный blocker incomplete_log,
остальные замечания не блокируют. В feature 062/064 XML EOF стали требованием
для File-парсера, хотя исходный формат разбирается как stream строк LogModule,
не корректное XML-дерево. Это отбрасывало распознанные записи исторического
неизменённого файла. Сырая пользовательская папка здесь недоступна; точный EOF
конкретного файла не объявляется проверенным.

Теперь scanner.ok означает полный успешный byte-read и известный header/event
grammar, а sourceCompleteness=complete|fragment отдельно описывает envelope.
У полностью прочитанного фрагмента используются только прежние валидные записи;
скан не становится доказательством полноты или отсутствия выключений. Source/rule
refs и sourceFragment сохраняются, видны в drilldown. Никакие теги/байты не
дописываются. Short/failed IO и неизвестный header остаются ошибкой/unknown.

Source quality сливается так, что полный дубликат сильнее fragment. Offhours
with only-fragment observations и без положительных выключений не получает none.
Положительные команды учитываются по прежним правилам; авария питания ими не
доказывается. Завершённый safe результат публикуется атомарно с warnings, не
скрытой потерей прежней базы. Настоящий read failure старого доказательства всё
ещё блокирует замену и требует проверки, не превращается в успех.

Event grammar/версии не изменены: старые успешные current-rule complete scans
остаются достоверными и восстанавливаются из checkpoint без повторного тела.
Новый enum валидируется в checkpoint payload; raw/EOF text не копируется в БД.
Legacy scan payload без enum читается совместимо. Повторный неизменённый import
не требует новой полной перепроверки из-за fragment quality.

## Проверки

Retired ID через API schema 3/4/5, прямой probe, legacy recovery; независимые TE20
actions; upload/Answer-only default selectors и task IDs; отсутствие job до старта.
Complete/fragment marker parity, short read fail, checkpoint enum/reuse, complete
duplicate и SQL negative coverage. Real Python/SQLite/browser воспроизводит old
EOF failure, использует два old-shape ready scans, читает только исходный фрагмент,
публикует warning/положительное событие и подтверждает SHA-256 неизменного файла.
Реальных записей устройств/портового rollback в разработке не выполнялось.
