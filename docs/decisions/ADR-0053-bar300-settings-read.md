# ADR-0053: последовательное чтение настроек Huawei Bar 300

Дата: 2026-11-13. Статус: HTTP подтверждён контролируемым чтением и сверкой администратора; остальные поля в работе.

Exact Bar 300 использует прежние pre-auth модельный код 18 и post-auth проверку модели/устойчивой идентичности. Только после них текущий web-bundle допускает узкий read-only `WEB_GetCfgParamAPI` по `enable_http`. Контрольный цикл: код `0` и меню «HTTP выключено» → администратор вручную включил HTTP, повторный read-only опрос вернул `1`/«Включено» → администратор вручную выключил HTTP, обновил страницу, третий опрос вернул `0`/«Выключено». Текущая форма также показывает `2=выключить`; 0 остаётся подтверждённым legacy-кодом. Отсутствующий marker и незнакомый код дают неизвестное, а не ложный факт. Инструмент команд записи не отправлял.

Источником нового поля служит `WEB_GetCfgParamAPI:enable_http`; импорт требует exact Bar 300 и этот источник. Box 300/600 не наследуют поле; старые JSON не меняются. Никакой команды записи, внешней передачи или сохранения credentials нет. Telnet, SSH, автоответ, NTP, Wi-Fi, питание и другие настройки будут проверяться по очереди с администратором.

Следующим параметром подтверждён Telnet: администратор сам выполнил цикл «Выключено → Включено → Выключено», а три exact read-only опроса дали `enabletelnet=0 → 1 → 0` и соответствующие значения. Исходная защита восстановлена и повторно проверена. Bundle также задаёт `2=Выключить`; общая security-группа содержит пароли, но инструмент запрашивает только один `enabletelnet`. Box 300/600 не наследуют этот факт. Инструмент не отправлял команд записи.

Для SSH подтверждён ручной цикл «Включено → Выключено → Включено», read-only опросы после exact model/identity вернули `enable_ssh=1 → 0 → 1`. Исходное включённое состояние восстановлено и проверено. Web-форма также показывает `2=Выключить`; общий security-запрос содержал бы пароли, поэтому инструмент читает только `enable_ssh`. Box 300/600 не наследуют поле, инструмент команд записи не отправлял.

Автоответ проверен отдельно. После уточнения администратора исходный режим был «Авто», а не «Вручную»; ошибочное предварительное сопоставление не попало в код. Затем администратор вручную переключил «Авто → Вручную → Авто», три узких read-only чтения дали `autoreply=0 → 1 → 0`. Только exact Bar 300 получает `deviceSettings.fields.autoAnswer` с `0=enabled/Авто`, `1=disabled/Вручную`; Box 300/600 не наследуют поле. Обычный опрос не меняет режим входящих вызовов.

NTP читается только тремя ID `synSerTime`, `ntpGetMode`, `timeServer` после exact model/identity и текущих bundle-маркеров. Администратор подтвердил «Включена»/«Вручную» и наличие сервера; затем сам выполнил два цикла: режим «Вручную → Авто → Вручную», read-only `ntpGetMode=1 → 0 → 1`, и синхронизация «Включена → Выключена → Включена», read-only `synSerTime=1 → 0 → 1`. Исходный ручной сервер сохранён и сверён администратором; его строка остаётся в локальном JSON, но не выводится в диагностике или документации. Другие модели не наследуют этот read-контракт. Значение настройки не доказывает успешный обмен с NTP-сервером.

Wi‑Fi: администратор показал в меню Bar 300 два отдельных положения «Запрещать» — клиент и точка доступа. После exact model/identity guarded чтение `WEB_GetWifiStatModeAPI` с CSRF дало `ucWifiMode=0`, что соответствует обоим выключенным. Затем администратор вручную разрешил только клиент; повторное чтение дало `ucWifiMode=2`, клиент включён, точка доступа выключена. После ручного возврата клиента в «Запрещать» третье чтение подтвердило `ucWifiMode=0` и оба выключенных переключателя. Отдельный цикл точки доступа дал `0→1→0` при выключенном клиенте; восстановление снова подтверждено чтением. Текущий bundle задаёт режимы 0/1/2/3 как выключено/точка доступа/клиент/оба; значение 3 пока подтверждено лишь схемой bundle. В обычный JSON добавляется только `modeCode`, `clientEnabled`, `accessPointEnabled`. Широкий `WEB_GetWifiCfgAPI`, который может вернуть SSID, не вызывается; `wifi_fun_enable=1` относится к возможности Wi‑Fi и не подменяет состояние переключателей. Неизвестный код или отсутствие маркеров даёт неизвестное. Box 300/600 не наследуют чтение. Инструмент не изменял Wi‑Fi.

SNMP v2: администратор подтвердил отсутствие этой версии в меню exact Bar 300; по умолчанию отображается SNMP v3. В JSON и локальном отчёте для Bar 300 фиксируется `not_exposed/version_not_supported` только для SNMP v2. Это не доказательство отключения SNMP целиком, состояния v3 или закрытого сетевого порта. Box 300/600 не наследуют данную уточнённую причину; сетевой запрос SNMP не выполнялся.

Автообновление exact Bar 300: по правилу администратора пункт «Тип сервера: Вручную» означает отключённую возможность обновления прошивки, любой другой доступный вариант — включённую. На снимке текущая локализация «Руководство» = «Вручную». Bundle формы использует `cloudType`, ручной код `Q=7` и ограниченный набор иных кодов `{2,5,6,8,10,11}`. После model/identity один узкий read-only `WEB_GetCfgParamAPI` только с `cloudType` вернул 7; новое поле `autoUpdate=disabled` подтверждено живым опросом. Иные коды проверены синтетически, настройки устройства не менялись. Версионированное правило `bar300-cloud-type-audit-v1` с `meaning=firmware_update_capability` не утверждает, что обновление уже произошло. Не запрашивать соседние регистрационные поля и не переносить это CGI-правило на Box 300/600 либо REST-правило Bar 310 сюда.

Питание: первый снимок с раскрытым меню был неоднозначен (верхняя строка 1 минута, выделенный вариант 10 минут); после точного чтения `sleepTime=10` администратор подтвердил фактические 10 минут. Текущий bundle связывает 10 с 10 минутами; повторный обычный опрос exact Bar 300 дал `powerManagement.sleepTimeCode=10`, `sleepMode=interval`. Добавлено только узкое чтение `sleepTime`, соседняя базовая группа с учётными записями не запрашивается. Wake-on-LAN, пробуждение по лицу, очистка во время сна и автоматический перезапуск требуют отдельных проверок; скриншот не превращается в JSON-факт. Другие модели не наследуют поле.

Wake-on-LAN проверен отдельно: видимому «Запрещать» соответствует `enable_wol=0` после model/identity; обычный опрос exact Bar 300 добавляет `powerManagement.networkWakeEnabled=false` из второго узкого `WEB_GetCfgParamAPI`. Код 1 соответствует «Давать возможность» только по текущей web-форме, реальный цикл ещё не проводился. Ошибка второго чтения не отменяет подтверждённый сон и не превращается в `false`. Box 300/600 не наследуют поле.

Остальные видимые переключатели питания проверены по одному: `faceWakeUp=0`, `sleepCloseAPP=0`, `autoReboot=0` после точных model/identity gates. Контрольный JSON добавил `faceWakeEnabled=false`, `clearMemoryInSleepEnabled=false`, `automaticRestartEnabled=false` к сну 10 минут и выключенному WOL. Каждый отдельный сбой чтения оставляет только соответствующее поле неизвестным. Включённые коды 1 пока подтверждены только формой; при `autoReboot=1` период в днях не выводится до чтения `autoRebootVal`. Скрытый `suppotReboot` не приравнивать к автоперезапуску.
