# ADR-0032: guarded HTTPS polling Polycom RealPresence Group 300/310/500/700

Дата: 2026-10-25. Статус: Group 310 проверен контролируемым локальным read-only опросом; Group 300/500/700 ожидают отдельных эксплуатационных проверок.

Администратор запросил новый алгоритм опроса четырёх моделей Group Series и предоставил доступ к одному подключённому Group 310. [Официальный Integrator Reference Guide 6.2.2](https://kaas.hpcloud.hp.com/pdf-public/pdf_9121586_en-US-1.pdf) описывает общий для серии командный API через SSH/22 и Telnet/24. Telnet не выбран из-за передачи секретов без защиты; SSH не входит в production Python standard library и не должен становиться скрытой внешней зависимостью. Контролируемое чтение текущего web-интерфейса Group 310 подтвердило пригодный локальный HTTPS/443 путь.

На Group 310 выявлены и проверены: статическая login-схема, `POST /rest/session` для входа и выхода, `GET /rest/system`, `/rest/system/status`, `/rest/system/time`, `/rest/system/uptime`, а также узкое read-only чтение единственного MAC-параметра через `POST /rest/config` с ключом `names`. Новым адаптером в памяти подтверждены модель, устойчивый идентификатор, MAC, прошивка и 13 записей состояния без ошибок ресурсов или выхода. Реальные IP, credentials, session cookie и значения ответов не сохранены в репозитории или документации.

Публичная страница входа и текущий bundle должны соответствовать Polycom-контракту до отправки пароля. Точное имя модели доступно только после входа: неавторизованный `/rest/system` возвращает 403. Поэтому остаётся ограничение: при явно выбранном IP и самоподписанном сертификате нельзя криптографически подтвердить точную модель до credentials. Проверка сертификата включена по умолчанию; отключение возможно только по существующему явному разрешению пользователя в текущем запуске. После входа модель обязана в точности совпасть с выбранной, а серийный номер либо MAC — подтвердить устойчивую идентичность. Неизвестный web bundle, модель, схема ответа или отсутствие идентификатора дают безопасный отказ. HTTPS не понижается до HTTP; настройки устройства не записываются.

Один общий core обслуживает четыре отдельных transport и точные модели. Group 310 имеет статус `confirmed_local_validation`; Group 300/500/700 получают `provisional_user_validation` до отдельных реальных проверок. HDX и варианты Group с суффиксами остаются `protocol_required`. Существующие job, ручной импорт, сеансовый пул credentials и выходной JSON не меняют границ безопасности. Решение реализуется в feature `031-polycom-group-polling`.
