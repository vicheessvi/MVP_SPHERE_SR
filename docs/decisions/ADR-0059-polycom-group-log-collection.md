# ADR-0059: сбор оригинальных системных логов Polycom Group

**Статус:** подтверждено администратором для exact Group 300/310/500/700 на проверенных устройствах, 2026-11-15.

## Контекст

Инструмент уже имел независимые опции JSON и логов, отдельную выбранную папку, timestamp-папку и browser ACK, но цепочка сохранения принимала только XML Huawei. [Руководство Poly для RealPresence Group Series](https://kaas.hpcloud.hp.com/pdf-public/pdf_9126112_en-US-1.pdf) описывает `Diagnostics → System → Download Logs → Download system log` и указывает GMT для записей. Текущий web-bundle подключённого exact Group 310 после model/identity показал точный `GET /a_getsyslog.cgi`. Контрольный ответ: HTTP 200, Content-Disposition `.tgz`, отсутствующий Content-Type, ограниченная положительная длина и gzip magic. Полный tar.gz прочитан и проверен только в памяти; содержимое и имена членов не выводились и не сохранялись. Доступ к недоверенному сертификату разрешён администратором лишь для этого исследования.

## Решение

Сохранить общий guarded HTTPS/443 Polycom adapter с четырьмя exact wrappers. Только после существующих pre-auth bundle, post-auth model и serial/MAC gates и двух маркеров текущего download handler допускается один сеансовый GET точного экспортного URL. Ответ принимается лишь при `.tgz` в Content-Disposition, bounded Content-Length, gzip magic и совместимом либо отсутствующем MIME; HTML/неизвестная схема отклоняются. Поток ограничен 64 МиБ и передаётся существующему `on_log` как `<IP>.tgz`, без server spool, содержимого в JSON/status или автоматической распаковки. Group 310 первоначально прошёл полный read-only прогон действующего адаптера с in-memory discard sink. Затем администратор отдельно подтвердил успешное сохранение логов на всех четырёх точных моделях; новые `logCollection` получают `confirmed_user_validation`. Это не меняет подтверждённый статус их обычных JSON-настроек и не повышает исторические provisional-файлы.

В job, loopback server и browser save добавлен явный allowlist `.tgz`/`polycom_syslog_tgz_v1`/`application/gzip`, при сохранении прежнего `.xml` пути Huawei. Ручной импорт определяет gzip `.tgz`, точный IP и модель Polycom по актуальной SR, показывает только метаданные. Архив не передаётся существующим Huawei event parsers. Режимы только логов, только JSON и оба остаются независимыми. Ошибка одного архива не останавливает остальные устройства.

## Последствия

Системные журналы сохраняются в собственном оригинальном формате в явно выбранной папке. Устройство не изменяется, HTTP/Telnet fallback не добавляется; старый Group 300 с HTTPS-несовместимой прошивкой остаётся недоступен для защищённого сбора. Руководство Poly отмечает удаление старых записей при заполнении журнала, поэтому архив не доказывает полную историю. Событийная аналитика перезагрузок/питания по Polycom требует отдельного исследования внутреннего формата и не входит в это решение.
