# ADR-0045: узкое чтение настроек exact Huawei Bar 310

Дата: 2026-11-10. Статус: реализовано для подтверждённых полей; ручная сверка значений с меню администратора и оставшихся пунктов питания ожидается.

На подключённом exact Bar 310 после pre-auth проверки модели и post-auth проверки идентичности прочитаны только перечисленные в feature 043 config-ID через существующий `POST /v1/om/config` в read-form. Текущий bundle подтвердил имена полей и варианты значений, ответы подтвердили прямую схему ключей. Исходный bundle, сырые ответы, внутренний адрес, Site name, NTP-сервер, пароль и токен не сохранялись в проекте. Обычный опрос прошёл повторно после реализации, новые поля получили статус `read` без команд изменения.

Новые запросы ограничены `huawei-bar310-rest-v1`; Box 310/610 сохраняют прежний контракт. Перед каждым модельным чтением требуются bundle-маркеры; невалидная или неполная схема оставляет только конкретное поле `unavailable` либо `protocol_required`, не скрывая другие успешные значения. Wi‑Fi пароль/SSID не запрашиваются, дополнительные поля ответа отбрасываются. Для Bar 310 SSH использует 1/2, а не кодировку TE; NTP и автоответ декодируются по текущим вариантам web-формы. HTTP и явная write-задача сохраняют прежние границы.

Коррекция семантики автоответа после контролируемой проверки администратором: на том же Bar 310 последовательность «Авто → Вручную → Авто» после сохранения и обновления страницы дала машинные коды `1 → 0 → 1`. Статические китайские опции bundle показывали обратную подпись и поэтому не являются достаточным доказательством для русскоязычного UI данного устройства. Для exact Bar 310 в JSON применяется `1=автоматически`, `0=вручную`; другие модели это правило не наследуют. Агент не отправлял команд записи.

Дополнительная сверка текущего устройства: NTP включён и задан вручную; строка сервера посимвольно совпала с экраном при сравнении только в памяти. Клиент Wi‑Fi, приоритет сети и точка доступа выключены и совпали с тремя отдельными read-only флагами. Чувствительное имя сервера в исходники, тесты, журнал и ответы не включалось.

Администратор отдельно подтвердил, что SSH включён; это совпало с `enable_ssh=1` в текущем read-only срезе. Снимок питания подтверждает сон 10 минут, выключенную очистку в спящем режиме и выключенную автоперезагрузку. Поля питания, не показанные на этом экране, не считаются вручную сверенными.

Администратор подтвердил, что HTTP в web-меню отключён, что совпало с `enable_http=0` в текущем срезе. Это подтверждение конфигурационного значения, а не отдельная проверка TCP listener порта 80.

Имя сайта со скриншота администратора посимвольно сравнено с отдельным read-only ответом после exact model/identity gates; совпадение подтверждено. В выводе был только булев результат сравнения. Значение не помещено в Git, fixtures, документацию или аналитический статус.

Уточнение статуса автообновления: администратор подтвердил, что страница «Сервер → Основные службы → Тип сервера» доказывает возможность обновления прошивки на Bar 310. Раскрытый список содержит «Вручную», «SMC2.0», «SMC»; отдельного «Авто» нет. Подтверждённая семантика: «Вручную» = возможность отключена, любой другой доступный пункт = включена. Статический bundle связывает раздел с выбором сервера; при видимом «Вручную» два read-only ресурса вернули `serverType=-1`, что web-страница отображает первым доступным вариантом. `cloudType` относится к облачной платформе, а `autoUpgFlag` — к подтверждению перед обновлением; оба не используются. Для exact Bar 310 введён versioned `server_type_audit_rule` с `meaning=firmware_update_capability`, проверкой ресурсов, допустимых кодов и model/identity gates. Текущий ручной режим подтверждён контрольным read-only опросом как `disabled`; ветки SMC/SMC2.0 проверены синтетически, без изменения устройства. Значение доказывает возможность обновления по подтверждённому правилу, но не факт уже выполненного обновления. Box-контракты не менялись.

Подтверждённая группа питания содержит управление Shut Down/Restart, время сна, периодический автоматический перезапуск, очистку в спящем режиме и энергосбережение. Администратор предоставил снимок страницы питания текущего Bar 310: отображаются сон 10 минут, очистка в спящем режиме выключена и автоперезагрузка выключена; это совпадает с машинными значениями. Отдельных расписаний включения/выключения и очистки после перезагрузки на этом экране нет, и в подтверждённой группе они не найдены. Они явно отмечены как неподтверждённые для иных вариантов; `autoReboot` не выдаётся за них.
