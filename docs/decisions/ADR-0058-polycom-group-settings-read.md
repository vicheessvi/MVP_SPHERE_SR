# ADR-0058: новые read-only настройки Polycom RealPresence Group

**Статус:** подтверждено администратором для exact Group 300/310/500/700 на проверенных устройствах, 2026-11-15.

## Контекст

Общий HTTPS-опрос четырёх точных моделей уже имел model/identity gates, но девять групп `deviceSettings` оставались неизвестными. На подключённом Group 310 после отдельного разрешения текущего недоверенного сертификата и точной проверки модели/идентичности исследованы текущие web-bundle и объявленный им файл меню. Для каждой новой настройки найдено только конкретное имя read-only конфигурации; широкое чтение и соседние поля с паролями/SNMP community не выполнялись. Администратор сверил значения по меню по одному параметру. Сырые ответы, адреса NTP и учётные данные в проект не записывались.

## Решение

Сохранить прежний HTTPS/443 transport и четыре exact wrappers. После post-auth exact model и serial/MAC общий core выполняет только однопараметрические, ограниченные по размеру чтения `/rest/config` при наличии обеих текущих bundle-связей: поля формы и полного имени настройки. Каждый ответ требует ровно одну переменную с тем же именем; `isSecure` и неизвестные коды отклоняются. Отказ одного параметра не отменяет прочие. Никаких write, HTTP/Telnet fallback и запросов соседних секретов.

- Telnet: точный переключатель доступа.
- HTTP: одновременно Web Access, HTTPS-only и настроенный web-порт; это настройка меню, не измерение TCP listener.
- SNMPv2: служба и флаг версии 2 сохраняются отдельно; работающий v2 возможен только при обоих включённых. Выключенная служба даёт «отключено», но не «версия отсутствует».
- Автообновление: только переключатель Automatic Software Updates, не факт ранее установленной прошивки.
- Автоответ: отдельные одноточечный и многоточечный режимы, без общего бинарного вывода.
- NTP: подтверждённый ручной режим, основной и второй адрес; второй использует доказанное web-правило экземпляра `1`. Адреса остаются только в выбранном JSON/XLSX, не в диагностике.
- Wi-Fi: `not_exposed` для точной серии, не утверждение о физическом радиоинтерфейсе.
- SSH: по уточнению администратора основной источник — `Enable SSH Service`; если текущий интерфейс его не показывает, резервный источник — `Enable Legacy API Over SSH` с явной пометкой основания. Резервный источник не является прямым измерением общей службы или порта 22.
- Питание: подтверждено действие `Hung-up Button Long Press → Power Off`; настройка сна не выводится.

Администратор отдельно подтвердил новые поля exact Group 300, 500 и 700 после проверки Group 310. Успешные результаты всех четырёх точных моделей теперь имеют `confirmed_user_validation`, но только при совпадении их текущего bundle, модели и идентичности. Это не доказывает совместимость каждой версии прошивки: старый Group 300 с HTTP-only web-интерфейсом по-прежнему не получает fallback с учётными данными. Импорт принимает факты только при exact adapter/model/contract/source и сохраняет сложные значения в безопасной таблице/XLSX; исторические JSON с `provisional_user_validation` не переписываются и не повышаются автоматически.

## Последствия

Девять групп получают явный статус без ложного `disabled` при неизвестном ответе. Проверка Group 300/500/700 сообщена администратором; агент не получал сырые JSON этих устройств. Будущий firmware/schema drift по-прежнему блокирует отдельные поля. Изменение настроек будет отдельной задачей.

## Поправка SSH: приоритет основного пункта

[Руководство Poly](https://kaas.hpcloud.hp.com/pdf-public/pdf_9126112_en-US-1.pdf) отдельно описывает `Enable SSH Service` и объясняет, что отключение Legacy API само по себе не убирает доступ по SSH для системной связи. На проверенном Group 310 в текущем меню и web-bundle есть только Legacy API. Его новое резервное аудиторское чтение подтверждено контролируемым read-only опросом и получает `basis=legacy_api_fallback` и версию правила `polycom-ssh-source-priority-v1`.

На другой прошивке основной пункт допускается только при однозначной связке *видимый пункт меню → boolean-поле в текущем bundle → безопасное полное имя конфигурации*. Имя не угадывается и не публикуется заранее. Если основной пункт виден, но его связка или ответ неверны, поле остаётся неизвестным; резервный источник не подставляется. Прямой путь помечается `provisional_user_validation`, пока администратор не проверит его на реальном устройстве с таким пунктом. Исторические JSON с прежним объектом Legacy API сохраняются без переписывания.
