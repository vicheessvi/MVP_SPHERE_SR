# ADR-0062: Срез «Учёт» для событий ВКС

**Статус:** принято 2026-11-18

## Контекст

Администратору нужен отдельный обзор терминалов ВКС со статусом оборудования «Учёт» в актуальной SR: какие из них перезагружались и какие имеют записи выключения питания. В журналах Huawei есть как подтверждённые штатные команды, так и длительные паузы без записей. Администратор отдельно подтвердил, что оба вида питания нужны, но строго раздельно. Для Polycom TGZ событийного контракта пока нет.

## Решение

- Знаменатель — только устройства категории ВКС из текущей SR с нормализованным значением поля «Общий статус оборудования»/«Общий статус» = «Учёт». Статус локации его не заменяет.
- Числители — уникальные устройства с `confirmed_reboot`, `power_off` и `suspected_power_loss` из уже проверенных модельных индексов Huawei TE/310/300. События и устройства показываются разными числами; предположение не суммируется с подтверждённым выключением. SR/model/IP/stale/provisional gates сохраняются.
- Общие фильтры обновляют диаграммы, рейтинги, карту, списки и XLSX. Круг питания использует непересекающиеся сектора: наличие подтверждённого выключения имеет приоритет, если устройство имеет оба вида, а предполагаемые случаи дополнительно показаны отдельным числом и рейтингом. Серый сектор означает «событие не выявлено либо разбор недоступен», не «исправно».
- Карта 7×24 показывает число уникальных терминалов в ячейке и отдельное число событий; время локально для терминала. Вид карты переключается между тремя видами без изменения исходных логов.
- Два XLSX создаются только локально через vendored SheetJS. В файле питания отдельные числовые столбцы штатных выключений и предполагаемых пауз, временные границы и текстовое основание достоверности. Все текстовые ячейки принудительно имеют тип string, без формул.
- Расчёт использует индексированные данные и кеш по SR/фильтрам; 100 строк на экране не ограничивают суммы или выгрузку. Исходные XML и исторические JSON не переписываются.

## Последствия и ограничения

Срез помогает приоритизировать проверку, но по логам нельзя утверждать, что устройство выключено сейчас или питание аварийно пропадало. У Polycom TGZ пока только метаданные; его устройство остаётся в знаменателе, но ноль событий нельзя трактовать как доказательство отсутствия проблем. Следующий полезный слой — показатель покрытия журналами по каждому устройству, чтобы отдельно показывать «нет событий» и «нет анализируемых данных».
