# ADR-0026: Закрытие HTTP и обработка Telnet на Huawei Bar 310

**Статус:** принято

**Дата:** 2026-09-20

## Контекст

Пользователь потребовал применить существующую opt-in задачу закрытия HTTP/80 и Telnet/23 к точному Huawei CloudLink Bar 310. Контролируемое исследование реального устройства подтвердило `/v1` login/session, exact Bar 310, stable identity и внутренний SystemSettingsService. UI bundle использует `POST /v1/om/config` для чтения и `PUT /v1/om/config` для сохранения. Обработчик предупреждает при переходе HTTP из безопасного `0` в небезопасное `1`; устройство принимает idempotent `0` и отклоняет `2`.

HTTP-параметр читается корректно. Контрольное чтение `enabletelnet` на проверенной firmware вернуло код отсутствующего параметра. По уточнению администратора управление Telnet в web-интерфейсе Bar 310 отсутствует; текущий контракт больше не читает и не записывает этот параметр. Историческое наблюдение о недоступности TCP/23 относится только к проверенному устройству.

## Решение

- Разрешить capability `disable_insecure_management_services` только exact Bar 310 aliases, не Box.
- Сохранить plan schema v3, отдельный список целей, явный opt-in, pre/post exact-model и stable identity gates.
- Перед записью прочитать только HTTP и проверить его management markers текущего bundle.
- Разрешить единственный Bar payload: `enable_http=0` через один `PUT /v1/om/config`.
- Подтверждать успех post-read `enable_http=0`; TCP listener не определяет статус.
- Отображать для Telnet модельное состояние `not_exposed` — управление через текущий web-интерфейс отсутствует; не делать запросов к настройке Telnet и не объявлять TCP/23 закрытым.
- Любой HTTP marker/schema/model/identity drift блокирует запись.
- Credentials, cookie, access token и raw body остаются в памяти и не входят в результат.

## Последствия

Bar 310 получает проверяемое закрытие HTTP и честный отчёт об отсутствии web-управления Telnet. Контракт не обещает изменить настройку, которую firmware не позволяет прочитать. Это решение ограничивалось Bar; более поздняя feature 028 добавляет отдельные provisional HTTP-only действия для точных Box 310/610 после подтверждения целевого значения администратором. TE-модельные значения и transports не меняются.
