# ADR-0028 — Случайный интервал между устройствами

## Цель и область

План автоматического опроса принимает две границы интервала в целых секундах: «От» и «До». После подтверждения записи результата предыдущего устройства и перед следующим поддерживаемым устройством Python-runtime выбирает значение из включительного диапазона, исключая значение предыдущего интервала. Особый диапазон 0–0 отключает паузы полностью. Перед первым устройством и после последнего дополнительной паузы нет. Порядок устройств, ACK записи, фильтры, адаптеры и безопасность учётных данных не меняются.

## Решение

- В плане schema v3 используются `intervalMinSeconds` и `intervalMaxSeconds`; обе границы обязательны вместе, целые, неотрицательные, `min <= max`.
- Первый интервал выбирается из всего диапазона. Каждый следующий выбирается равномерно из остальных значений без повторного перебора; обе границы достижимы, но два соседних выбранных значения всегда различаются, включая `0`.
- Для трёх и более поддерживаемых устройств диапазон должен содержать не менее двух значений, кроме 0–0: этот режим не выбирает значения интервала и сразу переходит к следующему устройству после ACK сохранения JSON. Одно ненулевое значение отвергается интерфейсом, loopback API и исполнителем до первого сетевого обращения.
- Ранее созданные планы с `intervalSeconds: 0` работают без пауз при любом числе устройств; фиксированное ненулевое значение принимается только при не более чем двух поддерживаемых устройствах. Новые планы не сохраняют фиксированное поле.
- Ноль внутри более широкого диапазона остаётся обычным выбранным значением: после него следующий выбор обязан отличаться. Интервал не помещается в JSON результата и не содержит секретов.
- При открытии плана обе границы по умолчанию равны `0`; пользователь может задать любое допустимое целое значение для каждой границы.
- В режиме 0–0 интерфейс показывает предупреждение о работе без пауз и держит кнопку запуска недоступной до отдельного подтверждения. Подтверждение действует только на текущую попытку, сбрасывается при изменении границ и после вызова запуска; в план и постоянное хранилище не записывается.

## Проверка и риск

Границы проверяются при построении плана, на loopback API и в исполнителе. Регрессия охватывает включительность границ, отсутствие соседних повторов включая ноль внутри диапазона, массовый режим 0–0 без ожидания, невозможный одноэлементный ненулевой диапазон и совместимые старые планы. Реальный сетевой опрос не требуется для проверки механизма интервала; длительность фактического ожидания может отличаться от выбранного числа секунд на время планирования ОС.
