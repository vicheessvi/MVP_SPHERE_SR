# ADR-0017: Адресный выбор и домен в плане опроса

**Статус**: Принято

**Дата**: 2026-09-05

## Контекст

Массовый План автоматического опроса выбирает устройства каскадом Тип оборудования → Производитель → Модель. Администратору требуется быстро опрашивать одно известное устройство и ограничивать массовый план значением столбца SR «Домен». При этом нельзя разрешить произвольный сетевой адрес, fuzzy/historical matching или новый путь передачи credentials.

## Решение

1. Добавить явные режимы `filters` и `single_ip` в один существующий экран плана.
2. В `single_ip` нормализовать IPv4 и разрешать цель только при одном точном совпадении среди актуальных устройств SR. Ноль, несколько совпадений или некорректный адрес дают пустой набор.
3. Показывать карточку цели из локального memory state без ping или web-запроса.
4. Добавить «Домен» первым уровнем массового каскада, сохранив multi-select, «Все», «Не указано» и очистку недоступных дочерних значений.
5. Не менять plan v2, Python server/job/adapters и ACK workflow. `deviceIds`/`devices[]` остаются единственным источником exact-IP allowlist; raw IP-поле формы не сохраняется.

## Последствия

- Один план может выбирать ровно одно устройство или массовое пересечение четырёх фильтров.
- Дубликаты IP становятся явной блокирующей проблемой, а не причиной опроса случайной строки.
- Домен участвует только как производный атрибут актуальной SR.
- Extron, Huawei TE40, credentials, TLS, schedule, interval и output semantics не меняются.

## Проверка

- Pure selector tests для пяти статусов IP и domain cascade.
- UI/card/source assertions и 25k performance regression.
- Полная frontend/Python/reference/security matrix.
