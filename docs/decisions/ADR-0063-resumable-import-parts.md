# ADR-0063: Порционная база и восстановление импорта логов

**Дата:** 2026-11-18 · **Статус:** реализовано, ожидается эксплуатационная проверка полного архива.

## Контекст

Порог 128 МиБ на всю безопасную проекцию был инженерным ограничением feature 058, а не требованием администратора. При растущей истории он блокировал сохранение. Администратор сообщил общий размер логов 102,64 ГиБ и потребовал продолжение импорта без повторного чтения обработанных файлов.

## Решение

База получает небольшие упорядоченные порции метаданных и записей. SHA-256 позволяет ссылаться на ранее записанные порции без повторной передачи тела. Суммарного прикладного лимита нет; 16 МиБ — верхняя защитная граница одной порции, а не БД. Текущий клиент формирует порции около 1 МиБ/1024 строк. Незавершённая передача не меняет текущую ревизию. Восстановление читает порции с проверкой хэша и порядка. Legacy BLOB, прежняя ревизия и исходники не удаляются до успешной публикации; предыдущая ревизия сохраняется. Совместимый старый HTTP-маршрут остаётся с прежним защитным размером запроса; новый клиент его не использует.

Готовый результат разбора каждого Huawei XML записывается в отдельную таблицу checkpoint до подтверждения обработки файла в UI. Это только структурированные маркеры, интервалы и контрольные суммы — не исходный XML. Область учитывает SR и версию/режим; ключ учитывает путь, размер, mtime, SHA-256 префикса, формат, модель и device ID. Новый/изменённый файл получает другой ключ, остальные результаты пригодны даже при добавлении новых файлов. После повторного выбора папки сканеры не читают тело уже подтверждённых файлов, но префиксы проверяются. После успешного сохранения общей аналитики удаляются только включённые в неё checkpoints.

Чтение увеличено с 64 КиБ до 1 МиБ, повторный разбор одинаковой временной метки убран, на обычном browser runtime допустимы два Worker при наличии ресурсов. Порядок включения в индекс остаётся исходным и детерминированным. Тепловые карты кешируются по готовой выборке. UI раздельно показывает прочитанные байты, обработанный объём, среднюю скорость с начала чтения, восстановленные файлы, этап объединения и этап записи.

## Последствия

Ограничения диска, RAM, SQLite и одной слишком большой записи остаются физическими/техническими условиями, но не общим потолком истории. Браузер всё ещё держит рабочие индексы аналитики в памяти; это не server-side SQL аналитика произвольного масштаба. После перезапуска папку выбирает пользователь: File API не возвращает доступ автоматически. Предыдущая уже запущенная версия вкладки не получает checkpoints задним числом; её нельзя закрывать для обновления до безопасного сохранения. Для 102,64 ГиБ точная скорость зависит от носителя и состава логов.
