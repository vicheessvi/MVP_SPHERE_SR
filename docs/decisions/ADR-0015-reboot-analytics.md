# ADR-0015: Расчёт перезагрузок Extron по Date и Uptime

**Статус:** принято
**Дата:** 2026-09-02

## Контекст

Пользователю нужен отдельный модуль после Главного экрана, который по JSON-опросам и актуальной SR считает перезагрузки. Подтверждённый пример Extron содержит локальные часы устройства в `webBlocks.Device Status.Date` и uptime в `webBlocks.Device Status.Uptime`. Из одного файла можно вычислить последний запуск как разность этих значений.

## Решение

Вводится версия правила `extron-reboot-v2`:

1. Участвуют только parsed results, точно связанные с устройством актуальной SR.
2. `Device Status.Date` разбирается только в подтверждённом Extron-формате; uptime — из числового поля или строгого `[Nd ]Hh Mm Ss`.
3. Для каждого пригодного файла вычисляется `bootAt = Date − Uptime`; один файл достаточен для одного события последнего запуска.
4. Расчётные времена запуска одного устройства в пределах пяти секунд объединяются. Новое время создаёт следующую перезагрузку.
5. Один и тот же запуск в нескольких файлах не дублирует событие.
6. События являются непостоянной производной аналитикой. KPI, графики, лидеры и таблица используют один filtered event set.
7. Локация и адрес берутся из актуальной SR и явно маркируются; историческая локация без версионированной SR не заявляется.

Если `Time Zone` недоступен, Date считается локальным wall-clock временем устройства и показывается без преобразования в часовой пояс компьютера. `uptimeObservedAt`, `capturedAt` и `File.lastModified` допускаются только как видимо маркированные fallback при отсутствии Date.

## Последствия

- Один пользовательский файл теперь сразу даёт расчётное время последнего запуска.
- Несколько реальных запусков между опросами, не ставших последним запуском ни в одном файле, восстановить нельзя.
- Поздняя загрузка безопасно перестраивает кластеры boot timestamps.
- Внешняя chart-библиотека, постоянное хранилище и сетевые полномочия не нужны.
- Для более точного времени будущий adapter может фиксировать timestamp непосредственно при чтении uptime, не меняя правило аналитики.
