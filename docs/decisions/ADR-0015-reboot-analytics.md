# ADR-0015: Доказуемая аналитика перезагрузок

**Статус:** принято
**Дата:** 2026-09-02

## Контекст

Пользователю нужен отдельный модуль после Главного экрана, который по истории JSON-опросов и актуальной SR считает перезагрузки и выявляет закономерности по времени, устройствам, локациям и адресам. Значение uptime описывает только время после последнего запуска; оно не позволяет восстановить точное число нескольких запусков между двумя опросами. Legacy JSON содержит строку `webBlocks.Device Status.Uptime`, а новые автоматические результаты могут дополнительно содержать число `Uptime Seconds` и top-level `capturedAt`.

## Решение

Вводится версия правила `reboot-min-v1`:

1. Участвуют только parsed results, точно связанные с устройством актуальной SR.
2. Uptime читается только из подтверждённого числового поля или строгого legacy-формата `[Nd ]Hh Mm Ss`; конфликт исключается.
3. Результаты группируются по device, сортируются по observation timestamp, одинаковые противоречивые timestamps исключаются.
4. Для соседней пары вычисляется интервал последнего запуска второго наблюдения. Перезагрузка подтверждается только когда весь интервал позже первого наблюдения.
5. Пара создаёт максимум одно событие с `minimumCount=1`. Итог называется «минимум подтверждённых перезагрузок».
6. События являются непостоянной производной аналитикой. KPI, графики, лидеры и таблица используют один filtered event set.
7. Локация и адрес берутся из актуальной SR и явно маркируются; историческая локация без версионированной SR не заявляется.

Legacy `File.lastModified` допускается как ограниченный источник observation time и видимо маркируется. Для новых автоматических файлов Extron adapter фиксирует `uptimeObservedAt` сразу после чтения уже подтверждённого uptime resource; это основной источник, а top-level `capturedAt` начала опроса остаётся совместимым fallback. Device Date/Time и произвольные поля не используются.

## Последствия

- Исключаются ложные события из одного падения счётчика, неоднозначного IP или конфликтных данных.
- Несколько реальных запусков внутри интервала недосчитываются до доказуемого минимума одного.
- Поздняя загрузка безопасно перестраивает соседние пары.
- Внешняя chart-библиотека, постоянное хранилище и сетевые полномочия не нужны.
- Для более точного времени будущий adapter может фиксировать timestamp непосредственно при чтении uptime, не меняя правило аналитики.
