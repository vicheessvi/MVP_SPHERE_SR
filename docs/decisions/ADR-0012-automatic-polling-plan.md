# ADR-0012: План автоматического опроса и сеансовый credential pool

**Статус**: принято

**Дата**: 2026-09-01

## Контекст

Пользователь потребовал строить план каскадом из актуальной SR, принимать общий XLSX `Логин | Пароль`, не использовать старые credentials и сохранять каждый JSON до начала интервала. Единственный UI-режим остаётся прямым `file://index.html`, который не может запускать Node/PowerShell или получать абсолютный путь каталога записи.

## Решение

1. UI вычисляет каскад `Тип оборудования → Производитель → Модель → selectedDevices` чистой детерминированной проекцией.
2. «Все» является отдельным взаимоисключающим маркером; дочерние selections очищаются при изменении родителя.
3. XLSX credentials проверяется в памяти текущей вкладки только для safe summary. Пары не входят в state/DOM/plan и исчезают при reload.
4. Тот же XLSX обязательно передаётся локальному CLI для конкретного запуска. Plan содержит только SHA-256 отпечаток, и CLI отклоняет несовпадающий файл до сети. CLI читает только `.xlsx`, создаёт общий уникальный пул в памяти и не обращается к историческому vault.
5. Plan v2 содержит все выбранные устройства и polling support; unsupported учитываются, но не вызывают даже ping.
6. Runner обрабатывает устройства последовательно. Callback атомарной записи каждого JSON завершается до ожидания интервала. Ошибка основной записи пытается создать локальную recovery-копию и останавливает batch; отмена прерывает ожидание.
7. PowerShell launcher требует явные Plan, Credentials и Output. В Output создаётся существующая timestamp-папка.

## Последствия

- `index.html` остаётся единственным UI runtime, но сам сетевой процесс по-прежнему запускается локальным скриптом.
- Секреты существуют в памяти двух изолированных текущих операций: безопасной проверки UI и polling process; перенос через JSON запрещён.
- Старый DPAPI CredentialVault остаётся историческим совместимым кодом, но новый automatic workflow его не использует.
- Неподтверждённые vendor protocols остаются `protocol_required`.

## Отклонённые варианты

- localhost control server: создаёт второй runtime и расширяет attack surface.
- credentials в plan JSON: создаёт копию секретов в Downloads.
- browser polling: блокируется CORS/self-signed TLS и смешивает UI с сетевыми полномочиями.
- ожидание до записи или пакетная запись в конце: создают риск потери результатов.
