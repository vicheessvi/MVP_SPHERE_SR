# ADR-0027 — Раскрываемая аналитика истории опросов

**Дата**: 2026-10-14

## Контекст

Обзор перезагрузок всегда показывал длинную таблицу событий и группировал устройства/локации для диаграмм по отображаемым именам. Три соседних аналитических модуля были заглушками. Пользователь запросил компактный обзор с детальными таблицами, сравнение версий и раздельную диагностику ошибок.

## Решение

- Сохранить существующее правило `extron-reboot-v2` и общий набор фильтров. Детальные строки строить только из уже отфильтрованных событий.
- Устройства и локации группировать по устойчивым ID. Для рейтинга локаций и адресов по перезагруженным устройствам считать уникальные ID устройств; даты, часы и обычные рейтинги считают события.
- Открывать по одной детализации нажатием на карточку, не показывать таблицу событий по умолчанию.
- Версии читать только из точных `Project Info.Version` и `Firmware.Version` успешных однозначно сопоставленных результатов. Сравнивать хронологически внутри каждого устройства.
- Ошибки брать из уже подтверждённого `pollStatus`; `authorization_error` и `network_unreachable` показывать раздельно. Иные статусы не интерпретировать.
- Все таблицы остаются производными и сеансовыми; исходные SR и JSON не меняются.

## Последствия

История с одинаковыми именами разных устройств больше не объединяется в детальных рейтингах. Число перезагрузок означает обнаруженные уникальные времена запуска, а не гарантированно полный журнал между опросами. Время устройства без часового пояса остаётся локальным временем устройства.
