# ADR-0065 — ВКС «Учёт»: выключения в нерабочее время

Дата: 2026-11-23. Статус: принято по запросу администратора.

## Решение

Новый срез в существующем модуле использует только актуальную SR, категорию ВКС,
статус оборудования «Учёт» и прежние валидированные событийные индексы. Начальное
окно — два календарных месяца, можно выбрать даты. Федеральный календарь РФ,
пятидневка с переносами подтверждены администратором. В рабочие дни учитывается
[18:00,24:00) + [00:00,07:00), выходные/праздники — целиком. Региональные исключения
и сокращённые рабочие дни не выводятся из предположений.

Читаемый offline календарь 2024–2027: [перечень Банка России](https://www.cbr.ru/other/holidays/),
проверен 2026-11-23. Рабочий перенос 20.02.2027 также воспроизведён в
[приказе федерального учреждения со ссылкой на постановление №1187](https://www.vspu.ru/sites/default/files/media/docs/2026-11/12028.pdf).
Неизвестный год останавливает этот расчёт, не импорт/опросы и не остальные модули.
Runtime не запрашивает интернет.

## Доказательность

Отсутствие команды не доказывает, что терминал не выключался. Неполные журналы,
отключение до начала интервала, архивы без парсера и пропуски не маскируются.
Группы: при наличии наблюдений — нет штатных/предполагаемых событий, только
предположения, ровно одно штатное выключение, два и более. Без событий периода —
«Недостаточно данных». Одна штатная команда = одно выключение, не сумма с паузами.
Время локальное для терминала. Карта показывает наблюдаемые события, не часы
непрерывной работы или доказанного обесточивания. Длительности прежнего раздела
питания и исторические события не меняются.

## Реализация и совместимость

SQL `offhours` возвращает агрегаты, 168 ячеек и страницы <=100. Для export pages
фиксируются БД/ID/revision/условия/точный cutoff; сервер может переиспользовать
до двух компактных кешей итогов по устройствам <=8 МиБ. Если бюджет превышен,
работает SQL paging без обрезания результата. Это не лимит БД или отчёта.
В logs-only диапазоне времени SQL не читает payload ради недостижимой JSON-ветки;
правило UTC/локального времени JSON/all неизменно.

Постоянной миграции, изменения vendor parser/write, оригиналов и повторного чтения
логов нет. Обычный polling и file:// fallback сохраняются. Новый срез доступен
в локальном DB-first режиме. XLSX содержит буквальные строки, числовые показатели
и отдельный лист условий; все страницы относятся к одному cutoff.
