# ADR-0047: единый транспорт и контракт Huawei 310

Дата: 2026-11-10. Статус: реализовано синтетически; новые настройки Box 310/610 ожидают отдельной эксплуатационной проверки.

По уточнению администратора exact Bar 310, Box 310 и Box 610 используют один `huawei_310_rest_v1` и один `huawei-310-rest-v1` на основе проверенного Bar 310. Предыдущие ADR-0024/0025 с тремя transport и contract ID описывают историческое состояние, но не текущую маршрутизацию. В `runtime/device-catalog.json` сохранены три модельных key и exact alias, все направлены к одному транспортному dispatcher. Dispatcher выбирает модельный descriptor до сети; guarded core по-прежнему требует совпадение pre-auth модели до credentials, post-auth exact модели и SN/ESN либо MAC. Суффиксные и другие модели не маршрутизируются.

Bar 310 сохраняет подтверждённое чтение настроек. Box 310/610 используют тот же read-only профиль только при маркерах текущего bundle и строгой схеме, но их новые значения и Site name отдельно помечены `provisional_user_validation` до проверки администратором каждой модели. HTTP opt-in write оставлен по прежним модельным границам; объединение transport не подтверждает Box write. Telnet не получил fallback.

Старые JSON не переписываются: их прежние `adapterKey`, model и vendor contract остаются исходными доказательствами. Модельные key и normalizer сохраняются, поэтому точное сопоставление с SR и исторический HTTP факт не теряются. Старые transport не создают новых сетевых маршрутов. Реальные IP, credentials и ответы устройства в репозитории не сохраняются.
