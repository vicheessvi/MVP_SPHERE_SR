# ADR-0067 — список целей и строго выбранные действия плана

Дата: 2026-11-24. Статус: принято по подтверждённой задаче администратора.

## Требование

Отдельный XLSX существующей SR-структуры должен задавать цели JSON-опросов,
выгрузки логов и уже доступных изменений параметров. Выполняется только явно
выбранное перед запуском. Несколько листов требуют выбора одного/нескольких,
не автоматического первого листа или всех листов.

## Решение

Источник `sr`/`device_list` выбирается явно. Загруженный список не заменяет SR,
не публикуется в аналитическую БД и не получает fallback. Каждый выбранный лист
валидируется целиком; повторные IP между листами, отсутствующие обязательные
колонки и credential-колонки блокируют импорт. Выбранные строки объединяются
только после успешной проверки. Колонки настроек остаются данными, не командами.
Смена источника/файла очищает прежние действия и подтверждение нулевого интервала.

Новая форма начинает с JSON/logs=false и «Не менять» у настроек. Plan v4 содержит
оба boolean, managementTasks/параметры, exact selectedActions, source digest,
выбранные sheets/sourceTargetIps и снимок целей. UI показывает счётчики и до
100 строк preview; перед запуском подтверждаются действия, значения и число
целей. Runtime проверяет согласованность/membership до ping/adapter, job глубоко
копирует план. Один лишь изменённый флаг не может добавить операцию к прежнему
selectedActions. Это проверка согласованности локального плана, не криптографическое
подписание враждебно изменённого клиентского кода.

collect_json=false теперь исключает обычное чтение ресурсов/настроек/Site name,
а не только сохранение файла. Auth/bundle/exact model и serial/MAC gates остаются
обязательными. Logs-only выполняет экспорт; write-only — выбранные pre-read,
максимум one-write и post-read. Совместимость write, ограничения single target,
одного Answer action ID, TLS/admin/Origin/CSRF не расширяются. Несовместимый набор
блокируется целиком до сети, а не пропускается с подменой задачи.

Без JSON/logs требуется явно выбранная папка служебного журнала. Только
polling-recovery.json хранит безопасные результаты действий и ACK, не штатные
JSON-опросы устройств. При JSON/logs журнал остаётся в папке соответствующего
запуска. Recovery подтверждает прежние sheets/source/actions и не повторяет
неясную запись автоматически. Старый v3 совместим, `device_list` требует v4.

## Проверка и границы

Синтетические XLSX с несколькими листами и независимый Artifact Tool roundtrip;
матрица семи JSON/log/write комбинаций; request spies настоящих guarded adapters;
реальный авторизованный loopback job в браузере с временной SQLite и fake adapter.
Write-only UI-тест доказывает отсутствие файлов обычного JSON/логов и выполнение
только выбранного Answer mode на IP выбранных листов. Реальные устройства и
vendor network не использовались. Новых команд/API/transport/событийных парсеров
не добавлено, DB-first история и аналитика не менялись.
