# ADR-0042: Локальный сбор и импорт логов устройств

Статус: синтетически реализовано, полный live workflow TE20 ожидает эксплуатации, 2026-11-05.

Администратор запросил независимые режимы только JSON, только логи и оба, отдельную папку логов и импорт общей папки для аналитики. Первой моделью выбран exact Huawei TE20. Текущий live read-only bundle после model/identity показал кнопку экспорта `/log?actkn=<session-token>?rmd=<nonce>`. Контрольный GET дал HTTP 200, `application/x-octet-stream`, XML root `LogModule`, размер более 4 МиБ без Content-Length. Реальный файл, credentials, токен, IP и содержимое лога в репозиторий не сохранялись.

Поскольку размер заранее неизвестен, runtime держит только один pending stream и передаёт XML чанками через авторизованный loopback API; браузер пишет их прямо в явно выбранную timestamp-папку. ACK подтверждает сохранение или отдельную ошибку. Нет base64 в JSON, server spool, CDN или внешней передачи. Логи TE20 требуют точной модели и identity; для прочих моделей статус `protocol_required` без угаданного endpoint. Опция выключена по умолчанию. В режиме только логов служебный recovery manifest хранится в папке логов, а JSON-файлы устройств не создаются.

Ручной импорт общей папки читает максимум 2 КиБ каждого файла, определяет TE20 XML/ZIP/текст/неизвестный формат и строит метаданные. Архивы не распаковываются, XML не исполняется, содержимое не отображается. События перезагрузок/ошибок из логов не интерпретируются до отдельных образцов и проверенных правил. При обрыве частичный файл не считается сохранённым; ошибки логов не меняют успех JSON-опроса. Границы и fail-closed расширение описаны в feature 039.

Дополнение 2026-11-10: на exact TE40 после pre/post-auth model и identity gate текущий bundle показал кнопку `exportLogFile`, но её URL использует `?Token=` вместо TE20 `?actkn=`. Контрольный GET по точному адресу вернул HTTP 200, `application/x-octet-stream` и XML-префикс `LogModule`; прочитаны только первые 4 КиБ, полный файл не сохранялся. TE30/40/50/60 получают отдельный marker-gated вариант потока через существующий loopback/ACK и выбранную папку; TE30/50/60 остаются предварительными до пользовательской проверки. TE20 сохраняет свой TLS1.1/actkn-контракт. Никакого общего fallback на другие модели нет.
