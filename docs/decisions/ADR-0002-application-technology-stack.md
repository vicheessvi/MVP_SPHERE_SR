# ADR-0002: Технологический стек приложения

## Статус

Заменено ADR-0003

Решение исторически принято 2026-08-03, но отменено в тот же день после явного требования запускать приложение напрямую через `index.html` и использовать browser-only стек эталонного проекта `drthalas/MVP_DEMO`.

## Дата

2026-08-03

## Контекст

MVP должен принимать JSON-снимки Extron, нормализовать данные, сопоставлять проекты и устройства, хранить историю, выявлять изменения и предоставлять закрытый интерфейс для одной организации. Контрольный объём невелик: до 100 проектов, 1 000 устройств и 10 снимков на проект.

Требуются роли администратора и AV-инженера, неизменяемое хранение исходных снимков, серверный HTML-интерфейс и минимальная сложность эксплуатации. Отдельный frontend/backend и распределённая обработка на этапе MVP не обоснованы.

## Решение

- Использовать Python 3.14.
- Использовать Django 5.2 LTS как серверный web-фреймворк.
- Использовать PostgreSQL 18 для постоянного хранения.
- Реализовать интерфейс серверными HTML-шаблонами Django без отдельного SPA-фреймворка.
- Использовать встроенные механизмы Django для аутентификации, ролей, разрешений, форм и административных операций.
- Строить приложение как модульный монолит.
- Выполнять импорт и сравнение внутри приложения на этапе MVP; очередь фоновых задач добавлять только при подтверждённой необходимости.
- Не фиксировать платформу деплоя до технического планирования.

## Последствия

- Backend, HTML-интерфейс, роли и административные функции остаются в одном приложении.
- Нормализация JSON и правила сравнения могут быть реализованы на одном языке.
- Количество runtime-компонентов и зависимостей MVP остаётся ограниченным.
- Масштабирование отдельных частей независимо друг от друга не является целью MVP.
- Длительные операции импорта потребуют повторной оценки; при превышении согласованных временных ограничений понадобится отдельное решение о фоновой обработке.
- Обновления должны оставаться в поддерживаемых patch-версиях выбранных major/minor-линий.

## Рассмотренные альтернативы

### .NET 10 LTS + ASP.NET Core + PostgreSQL

Подход имеет длительную поддержку и хорошо подходит для Windows/IIS, но обязательной привязки к Windows или существующей C#-команде нет.

### Node.js 24 LTS + TypeScript + PostgreSQL

Подход даёт единый язык для browser и server code, но отдельный сложный frontend для согласованного HTML-интерфейса не требуется.

### FastAPI + отдельный SPA

Подход удобен для API-first приложений, но разделение frontend/backend увеличивает количество контрактов, tooling и runtime-компонентов без необходимости для MVP.
