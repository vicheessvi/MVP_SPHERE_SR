# ADR-0061: Фоновый массовый импорт и явная локальная рабочая база

**Дата**: 2026-11-18
**Статус**: принято по разрешению администратора; эксплуатационная проверка 200–400 ГБ остаётся на рабочем ПК.

## Контекст

При импорте 5 000 Huawei XML по 40–80 МБ повторная полная перерисовка и синхронный разбор делали UI неотзывчивым; лог-индексы очищались до завершения нового импорта. Рассчёт длительности питания искал запуск линейно для каждого выключения. Кроме того, текущая память вкладки терялась при закрытии браузера. Администратор разрешил постоянную рабочую базу в выбранной папке, распространяющуюся на SR, JSON-опросы, все логи и будущие модели, но без device credentials и копий исходных логов.

## Решение

Huawei scanner исполняется в одном Web Worker, читает 64 КиБ порциями и возвращает только markers/bootGaps; Worker периодически перераздаётся для ограничения памяти. В `file://` применяется порционный yielding fallback. Прогресс обновляет лишь лёгкий DOM-узел, отмена не публикует частичный индекс. События накапливаются по файлу; повторные доказательства сохраняют до 16 точных ссылок и `sourceCount`. Длительность до следующего запуска ищется бинарно, неизменённые сводки кешируются.

Рабочая база — SQLite из Python stdlib в явно выбранной отдельной папке. Путь запоминается вне Git в профиле Windows; `localStorage`/`IndexedDB` не используются. После admin gate локальный loopback API защищён Host/session, Origin и CSRF. Сохраняется только проверенная безопасная проекция без `rawText`, секретных ключей, inline авторизации и полных логов. Каждая ревизия атомарна и требует совпадения базовой ревизии; отсутствующая/повреждённая БД не превращается молча в пустую.

Registry файлов общ для Huawei XML, Polycom TGZ и будущих типов. Повторный выбор той же папки быстро пропускает неизменённый path/size/mtime/prefix SHA-256 как cache-оптимизацию, не как доказательство полного криптографического равенства. Новые файлы разбираются, события дедуплицируются по содержательным модельным ключам; изменённый старый файл требует полной перепроверки. JSON-опросы после быстрого отбора проходят прежний полный SHA-256 перед добавлением. Пользователь может потребовать полную перепроверку. Исторические исходники и результаты не переписываются.

## Последствия и ограничения

Первое чтение 200–400 ГБ ограничено диском и CPU, поэтому не обещается мгновенным; UI остаётся отзывчивым, после завершения база восстанавливается без перечитывания исходников. Выключение браузера во время незавершённого первого импорта сохраняет предыдущую завершённую ревизию, но не все промежуточные файлы текущей попытки. Прямой `file://` остаётся сеансовым и без автосохранения. Polycom TGZ не получает событийный парсер до отдельного evidence review. База содержит чувствительные инфраструктурные данные в открытом локальном формате и должна лежать в папке с Windows ACL текущего пользователя.
