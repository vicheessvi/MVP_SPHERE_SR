# ADR-0006: Закреплённый portable runtime и единый каталог продукта

**Статус**: принято

**Дата**: 2026-08-10

## Контекст

Проект должен запускаться после скачивания с GitHub на новом Windows-ПК без ручной установки зависимостей, но прежняя локальная граница защиты не должна ослабляться. Одновременно модульные описания Справочника не должны расходиться с навигацией и пользовательскими статусами при изменении проекта.

DPAPI CurrentUser намеренно делает рабочие данные зависимыми от Windows-профиля. Поэтому переносимость кода/запуска нельзя смешивать с переносимостью credential vault или аналитической базы. Автоматическое смысловое описание произвольного кода также небезопасно: инструмент не должен придумывать определения SR, GCPlus, перезагрузок или vendor API.

## Решение

1. Поддерживать Windows 10/11 x64 и ARM64 с PowerShell 5.1+.
2. Закрепить официальный Node.js 24.19.0 LTS ZIP и SHA-256 отдельно для каждой архитектуры в `portable-runtime.json`.
3. При отсутствии совместимой среды выполнять только HTTPS GET точного артефакта с `nodejs.org`, проверять hash до распаковки/исполнения и атомарно устанавливать его в `.runtime/` без elevation и изменения PATH.
4. Сохранять новый независимый DPAPI store/vault на каждом Windows-профиле. Не переносить данные через GitHub.
5. Хранить доступные модули, UI terminology, status descriptors и tooltips в `product-catalog.js`.
6. Строить навигацию, модульный раздел Справочника, контекстную помощь, inventory route metadata и статусный раздел из одного каталога во время загрузки.
7. Блокировать дубли, потерянные ссылки, неизвестные renderer и пустые русские подписи локальной и GitHub-проверкой.
8. Оставлять неподтверждённые narrative definitions явными и не генерировать смысл из имён функций или raw-кодов.

## Последствия

Положительные:

- чистая копия запускается без системной установки;
- runtime update проходит явный review изменения version/hash;
- повторный запуск не требует сети;
- модульная навигация и Справочник не расходятся;
- текущая DPAPI/AES/loopback граница сохраняется.

Ограничения:

- первый запуск без Node требует доступа к точному официальному URL или заранее помещённого проверенного ZIP;
- `.runtime/` занимает локальное место и не должен попадать в Git;
- рабочая база остаётся непереносимой между Windows-профилями;
- новое поведение всё ещё требует честного явного описания в каталоге.

## Отклонённые варианты

- бинарник Node в Git — размер и непрозрачные обновления;
- MSI/winget — системные изменения, elevation и зависимость от политики ПК;
- moving `latest` — непроверенное обновление исполняемого кода;
- общий ключ или vault в Git — нарушение constitution;
- AI-генерация Справочника на каждом запуске — недетерминированность и риск выдуманных определений.

## Проверка

- hash/URL manifest contract;
- PowerShell 5.1 parsing;
- cached/no-download resolution;
- catalog add/rename/remove and negative validation;
- 101/101 regression, 12/12 runtime/bootstrap, 1/1 server integration;
- browser acceptance модульных проекций;
- secret/runtime artifact scan.
