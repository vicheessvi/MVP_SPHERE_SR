# ADR-0021: Каноническая 42-колоночная схема выгрузки SR

**Статус**: принято
**Дата**: 2026-09-08

## Контекст

SR переименовал пятнадцать существующих заголовков и добавил одиннадцать новых полей. Немедленный отказ от прежних названий сделал бы ранее сохранённые выгрузки непригодными, а идентификация по изменяемым названию, адресу, IP или MAC могла создавать дубликаты.

## Решение

Новые 42 заголовка образуют канонический контракт. Каждое переименованное смысловое поле читается через централизованный canonical-first alias registry; отсутствие обоих имён обязательного поля отклоняет импорт атомарно. Интерфейс, фильтры и Справочник используют новые названия.

Исходная строка сохраняется без изменения. Отдельная нормализованная проекция включает новые статусы, комментарии, contractor/warranty, interface/protocol и `802.1x`. `SmartRoom ID локации` и `SmartRoom ID оборудования` получают высший приоритет в идентичности соответствующих сущностей, а `ID устройства` предшествует изменяемым сетевым реквизитам.

## Последствия

- Новые и прежние выгрузки можно использовать в переходный период.
- При наличии двух вариантов одного заголовка новое имя имеет приоритет.
- Переименование локации или смена сетевых реквизитов не создаёт дубликат при стабильных SmartRoom ID.
- `Описание локации` и equipment `Описание` не смешиваются.
- Основная SR и отдельный список целей управления используют один parser и один контракт.
- Новых зависимостей, сетевых вызовов, постоянного хранения или secret-bearing данных нет.
