# ADR-0029 — HTTP-only управление Huawei 310

**Дата**: 2026-10-17

**Статус**: принято для guarded implementation; Box live validation pending

## Контекст

Подтверждён обычный HTTPS-опрос точных Bar 310, Box 310 и Box 610. Администратор уточнил, что в их текущих web-интерфейсах нет управления Telnet, и отдельно подтвердил одинаковое backend-значение `enable_http=0` для отключения HTTP на обеих Box-моделях. Историческая документация Huawei перечисляет Telnet как протокол семейства Box, поэтому отсутствие web-контрола нельзя выдавать за измерение TCP/23.

## Решение

- Сохранить три самостоятельных exact-model public contract и обычный read-only опрос без opt-in.
- Разрешить существующую задачу `disable_insecure_management_services` только для точных Bar 310, Box 310 и Box 610 плюс ранее подтверждённых TE. В пользовательском тексте явно разделять HTTP-only 310 и HTTP/Telnet TE.
- На 310-моделях не отправлять запросы чтения или записи Telnet. В результате `not_exposed` означает отсутствие web-управления, а не закрытие порта.
- Для каждого Box применить exact pre/post model, stable identity и текущие bundle/config-schema gates. Только `enable_http=1` допускает один минимальный `enable_http=0` PUT; успех требует post-read `0`. Любой drift завершает задачу без неподтверждённой записи.
- Отмечать Box action `provisional_user_validation` до независимых контролируемых тестов на реальных Box 310 и Box 610. Подтверждённый Bar result не подтверждает Box action.
- Не сохранять credentials, cookie, token, raw config body и приватные идентификаторы в результате или репозитории.

## Последствия

Обычные опросы Box не меняют настройки. При явном управлении доступен guarded HTTP-only путь с модельным fail-closed; реальная Box write-проверка остаётся открытой задачей. Версия с суффиксом и неизвестная прошивка без ожидаемых признаков не получают успешного результата изменения.
