# ADR-0037: Независимое управление HTTP и Telnet Huawei TE20

Статус: подтверждено администратором на рабочем ПК после синтетической проверки, 2026-11-02.

## Контекст

Прежняя opt-in задача выключала HTTP и Telnet одновременно. Администратору нужен отдельный выбор «Не менять», «Открыть» или «Закрыть» для каждого параметра. Контракты других моделей не дают оснований переносить на них коды открытия TE20.

## Решение

Добавлены четыре фиксированных action ID для exact TE20, по одному на параметр и целевое состояние. Источник — текущая SR; разрешён ровно один IP, выбранный адресным режимом. Нулевой выбор не создаёт action. Два действия разных портов могут выполняться в одном плане последовательно, но не сочетаются с прежней групповой задачей или Answer mode. При неудаче первого второе не пытается писать. До действия действуют existing pre-auth/post-auth model и stable identity gates. Затем читается ровно один конфигурационный ID, допускается только строгий integer 0/1; если цель уже достигнута, записи нет. Иначе отправляется максимум один одноэлементный `WEB_SaveCfgParamAPI` и проверяется точный post-read. Результаты и ошибки у портов раздельны, повтор неясной записи при восстановлении запрещён.

`0` на TE20 означает отключённый HTTP/Telnet, `1` — включённый. Администратор сообщил об успешной проверке открытия HTTP и Telnet на рабочем ПК; закрытие было подтверждено ранее. Это пользовательская эксплуатационная проверка, а не повторный доступ агента к устройству. HTTP transport fallback не добавляется; проверка TCP listener не входит в критерий успеха.

## Последствия

Старый сценарий массового закрытия и read-only опрос сохраняются. UI требует отдельного подтверждения, особенно при открытии сервиса. Для TE30–TE60, Bar/Box и Polycom новый контракт недоступен до самостоятельного evidence review.
