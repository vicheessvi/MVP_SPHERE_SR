# ADR-0048: отдельное управление Answer mode Huawei 310

Дата: 2026-11-10. Статус: Bar 310 подтверждён контролируемой записью в обоих направлениях; Box 310/610 write предварителен.

Для exact Bar 310, Box 310 и Box 610 введены две отдельные задачи общего `huawei_310_rest_v1`: автоматический ответ и ручной ответ. «Не менять» не создаёт write-задачу. План допускает только один IP из актуальной SR, не совмещает Answer mode с HTTP и другими write-задачами, показывает отдельное предупреждение о влиянии на входящие вызовы. Runtime повторно проверяет план и точную модель.

После pre-auth model gate до credentials и post-auth model/identity gate исполнитель проверяет текущие bundle-маркеры read/save для `autoreply`, читает только это поле в `{0,1}` (`1=automatic`, `0=manual`), при необходимости отправляет максимум один PUT `/v1/om/config` с единственным `CfgItemInt` и пустым `CfgItemString`, затем требует точный post-read. Совпадение до записи даёт `already_compliant` без PUT. Ошибка, drift либо несовпадение после записи не становятся успехом и не повторяются автоматически. Обычный опрос остаётся read-only.

Администратор отдельно разрешил контрольный переход на подключённом Bar 310. Машинное чтение и обновлённое web-меню подтвердили `automatic → manual` (`1→0`), затем по отдельному согласию `manual → automatic` (`0→1`). Исходный автоматический режим восстановлен. Сырые ответы, адрес, credentials и токен не сохранялись в проекте. Bar action получил `confirmed_local_validation`; тот же алгоритм для exact Box 310/610 сохраняет `provisional_user_validation` до независимой проверки каждой модели. Прежняя отдельная HTTP write-задача и её статусы не изменялись.

Позднее feature 047 / ADR-0049 расширила только способ выбора Answer mode: вместо обязательного одного IP разрешены совместимые группы по фильтрам SR с отдельным массовым подтверждением. Per-device guarded write и модельные статусы этого решения не изменены.
