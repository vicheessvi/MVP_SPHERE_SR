# ADR-0030: продолжение опроса и Site Name

Дата: 2026-10-19. Статус: принято локально; live-проверка Huawei mailbox ещё ожидается.

Изолированный отказ записи JSON не является причиной прекращать остальные сетевые опросы. Python job записывает безопасное событие и счётчик, продолжая после ACK(false). Если браузер исчез, ожидание ACK ограничено пятью минутами: задание заканчивается и очищает пары credentials.

Для восстановления после перезапуска создаётся видимый `polling-recovery.json` только в выбранной папке результатов. Он содержит порядок устройств и прогресс, но не логины, пароли, их SHA-256, cookie, session или CSRF. После запуска пользователь снова выбирает папку, вводит пары и нажимает «Продолжить опрос». Уже сохранённые JSON сверяются по точному IP. Неясный исход write-задачи исключается из автоматического повтора и требует проверки администратором. Полностью unattended восстановление сознательно не поддерживается: оно требовало бы сохранения секретов или разрешения папки.

Site Name не равен имени локации SR. Для TE30/40/50/60 выполняется только optional mailbox-read, когда текущий web-bundle содержит оба документированных action-маркера, а точная модель и устойчивая идентичность уже подтверждены. Отсутствие метода или корректного ответа не меняет базовый результат опроса. Live-проверка на прошивках пользователя остаётся отдельным этапом.

Уточнение администратора от 2026-10-20: искомое поле расположено в `System Settings → Display → Site name` на TE20/TE30/TE40/TE50/TE60 и в `Настройки → Графический экран → Имя сайта (Site name)` на Bar 310/Box 310. Эти пути определяют семантику поля и место ручной сверки. Для Box 610 путь меню не подтверждён.

После прямого запроса администратора включить реальное значение в текущие JSON существующие exact-model pollers дополнены отдельным условным чтением mailbox. TE20 остаётся на своём TLS 1.1 и legacy login contract; 310-модели сохраняют пять фиксированных GET-ресурсов. Новый POST разрешён только как документированная подписка/чтение текущей сеансовой mailbox state после post-auth identity и при наличии двух action-маркеров в текущем bundle. Запросов изменения Site Name нет. Значение принимается только из строкового `state.sitename`; отсутствие метода или ответной схемы сохраняет неизвестный статус. Синтетические тесты проходят, а live-подтверждение на прошивках пользователя ещё не выполнено.
