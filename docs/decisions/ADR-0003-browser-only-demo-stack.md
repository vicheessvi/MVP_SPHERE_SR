# ADR-0003: Browser-only стек локального MVP

## Статус

Заменено ADR-0005 для рабочих и чувствительных данных. Сохранено как историческое решение для раннего demo.

## Дата

2026-08-03

## Контекст

Пользователь указал эталон `drthalas/MVP_DEMO` и потребовал, чтобы MVP_SPHERE_SR запускался тем же способом: прямым открытием `index.html` двойным кликом и на таком же стеке.

Эталон реализован как автономное browser-only приложение из `index.html`, `styles.css` и `app.js`, не имеет backend, package manager, build step или runtime-зависимостей и хранит versioned state в `localStorage` с JSON import/export.

Это решение несовместимо с ранее принятым Django/PostgreSQL стеком и не может обеспечить настоящую серверную авторизацию, tamper-resistant audit trail, централизованное хранение или гарантированное трёхлетнее retention.

## Решение

- Реализовать MVP как статическое приложение из `index.html`, `styles.css` и `app.js`.
- Использовать HTML5, CSS3 и Vanilla JavaScript без framework и внешних runtime-зависимостей.
- Запускать приложение прямым открытием `index.html` через `file://`.
- Не добавлять backend, Python, Django, PostgreSQL, package manager или build step.
- Хранить versioned локальное состояние под ключом `mvpSphereSrState.v1` в `localStorage`.
- Использовать JSON для полного backup/restore состояния и переноса между браузерами.
- Читать snapshots только через пользовательский `<input type="file">`; сетевые запросы и прямой опрос оборудования не выполнять.
- Реализовать роли Administrator и AV Engineer только как демонстрационное разделение интерфейса, не как границу информационной безопасности.
- Использовать только синтетические, обезличенные или явно разрешённые для локального анализа снимки.
- Сохранять raw snapshot в локальном state без изменения на уровне приложения и вычислять hash, но не заявлять tamper resistance против пользователя браузера или DevTools.
- Проверять retention при запуске и через явное действие; поддерживать предупреждение active baseline и deletion audit в рамках локального state.

## Временные исключения из constitution

Browser-only runtime не может полностью выполнить принципы I и VI constitution: пользователь браузера может изменить/очистить `localStorage`, а UI-роли не являются реальной авторизацией.

- **Владелец исключения**: владелец проекта MVP_SPHERE_SR.
- **Область**: только локальный демонстрационный MVP.
- **Компенсации**: постоянное предупреждение о локальной небезопасности, sanitized data only, secret detection/redaction, JSON backup, отсутствие сетевой передачи.
- **Условие устранения**: до использования реальных чувствительных инфраструктурных данных, совместной работы нескольких пользователей или production-эксплуатации принять новый ADR и перейти на защищённое server/desktop storage с настоящей авторизацией и audit trail.

## Последствия

- Пользователь запускает приложение двойным кликом без установки компонентов.
- Архитектура и пользовательский опыт соответствуют `MVP_DEMO`.
- Данные привязаны к конкретному browser profile и пути файла; очистка browser storage может удалить их.
- Ёмкость `localStorage` ограничена и зависит от браузера; import должен отклоняться до частичной записи при превышении лимита.
- История, роли, retention и неизменяемость обеспечиваются только логикой приложения и подходят для демонстрации, но не для защищённой эксплуатации.
- Перед работой с реальными снимками требуется production-архитектура и отдельная миграция данных.

## Рассмотренные альтернативы

### Django + PostgreSQL

Обеспечивает настоящую авторизацию, private storage и долгосрочный audit, но отменён явным требованием direct-open `index.html`.

### Локальный server launcher

Сохраняет запуск одним кликом и серверные возможности, но технически открывает приложение по `http://localhost`, а не напрямую через `file://`.

### Electron/Tauri

Позволяет использовать HTML UI и локальное защищённое storage, но добавляет runtime, сборку и упаковку, отсутствующие в эталонном стеке.
