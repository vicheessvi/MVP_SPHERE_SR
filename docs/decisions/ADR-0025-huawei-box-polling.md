# ADR-0025: отдельные provisional-контракты Huawei Box 310 и Box 610

- Статус: принято для контролируемой эксплуатационной проверки
- Дата: 2026-09-20
- Feature: `025-huawei-box-polling`

## Контекст

Подтверждённый Huawei Bar 310 использует новый web-интерфейс `/v1`, отличный от семейства TE. Производитель публикует Box 310, Box 610 и Bar 310 как близкое семейство и предоставляет общую документацию HTTP API, однако это не доказывает, что установленная web-прошивка Box полностью совпадает с проверенным Bar 310. Пользователь запросил два отдельных контракта, чтобы проверить реальные Box 310 и Box 610 на рабочем компьютере.

## Решение

Сохраняем подтверждённый `huawei_bar310_rest_v1` и добавляем два отдельных public transport:

- `huawei_box310_rest_v1` — только exact `Box 310`;
- `huawei_box610_rest_v1` — только exact `Box 610`.

Три public contract используют общий guarded read-only core, но не взаимозаменяемы. Каждый wrapper передаёт собственный contract ID, exact aliases и ожидаемую модель. До первой попытки авторизации устройство обязано вернуть exact-модель и полный набор уже известного `/v1` bundle. После входа exact-модель проверяется повторно вместе с SN/ESN либо валидным MAC. Любое отличие модели, marker, схемы или identity завершает запрос fail-closed; другой auth flow не угадывается и HTTP fallback не применяется.

Box 310 и Box 610 получают `evidenceStatus = provisional_user_validation`. Это означает, что они доступны только для запрошенного контролируемого теста, но не объявляются подтверждёнными. Успешный тест одной модели не подтверждает другую. Варианты с суффиксами `-C`, `-S`, `-K` не входят в exact allowlist и остаются `protocol_required`.

Все три контракта работают только через HTTPS/443, читают фиксированные ресурсы version/specification/time/license/status, очищают cookie/token/credentials и формируют redacted JSON. Ни Box 310, ни Box 610, ни Bar 310 не получают capability изменения настроек или закрытия HTTP/Telnet.

## Последствия

- пользователь может независимо проверить Box 310 и Box 610 через обычный план автоматического опроса;
- mismatch блокируется до credentials, поэтому план для одной модели не авторизуется на другой;
- результат явно показывает отдельный contract ID и предварительный статус;
- после каждого реального теста evidence status меняется только отдельным решением с фиксацией результата, без расширения на непроверенные модели или варианты.
