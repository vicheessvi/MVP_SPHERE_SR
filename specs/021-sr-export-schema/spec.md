# Feature Specification: Актуальная схема выгрузки SR

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-09-08

**Status**: Implemented

**Input**: Принять новые названия и новые столбцы выгрузки SR, не потеряв совместимость с ранее поддержанными файлами.

## User Scenarios & Testing

### User Story 1 — Загрузка актуальной выгрузки SR (Priority: P1)

Администратор МЦТП загружает XLSX с 42 объявленными столбцами и получает полный актуальный перечень локаций и оборудования без ручного переименования колонок.

**Independent Test**: Файл с полным каноническим заголовком проходит атомарную проверку; новые поля доступны в нормализованной записи, а исходная строка сохранена без изменения.

### User Story 2 — Устойчивая идентичность (Priority: P1)

Повторная выгрузка с теми же `SmartRoom ID локации` и `SmartRoom ID оборудования`, но с изменёнными наименованием, адресом и реквизитами устройства, обновляет существующие сущности, а не создаёт дубликаты.

**Independent Test**: После двух импортов остаются одна локация и одно устройство с прежними внутренними ID и обновлёнными полями.

### User Story 3 — Совместимость с прежними выгрузками (Priority: P2)

Ранее поддержанные XLSX продолжают загружаться, пока содержат прежние названия обязательных смысловых полей.

**Independent Test**: Legacy-заголовки проходят тот же импорт, классификацию и построение плана; если присутствуют оба варианта поля, канонический вариант имеет приоритет.

## Edge Cases

- Каноническое и прежнее имя присутствуют одновременно: используется каноническое значение.
- Новый необязательный столбец пуст: строка остаётся допустимой.
- Отсутствует и канонический заголовок, и его старый псевдоним для обязательного смыслового поля: импорт отклоняется до изменения состояния.
- Одинаковый `SmartRoom ID оборудования` встречается с противоречивыми сильными идентификаторами: строка не должна молча объединяться без действующих collision-правил.
- `IP адрес` изменился при том же устойчивом ID: устройство сохраняет идентичность, новый адрес становится текущим, старый остаётся в истории.

## Requirements

- **FR-001**: Приложение MUST принимать 42 канонических заголовка в объявленном порядке.
- **FR-002**: Переименованные прежние заголовки MUST поддерживаться как входные псевдонимы обязательных смысловых полей.
- **FR-003**: Каноническое имя MUST иметь приоритет, если в строке присутствуют оба варианта.
- **FR-004**: Все 42 значения MUST сохраняться в исходной строке без изменения; аналитически значимые значения MUST иметь нормализованную проекцию.
- **FR-005**: `SmartRoom ID локации` MUST быть первым устойчивым ключом локации.
- **FR-006**: `SmartRoom ID оборудования` MUST быть первым устойчивым ключом оборудования; `ID устройства` MUST участвовать до изменяемых сетевых реквизитов.
- **FR-007**: `IP адрес` и `MAC адрес` MUST заменить прежние названия в пользовательском контракте, но старые `IP` и `MAC` MUST продолжить приниматься.
- **FR-008**: Классификация MUST использовать `Класс оборудования` и `Тип`, сохраняя псевдонимы `Тип оборудования` и `Тип модели`.
- **FR-009**: Поля статусов, подрядчика, гарантий, комментариев, интерфейса, протокола и `802.1x` MUST быть доступны нормализованной записи без изменения raw SR.
- **FR-010**: Основная SR и отдельный список целей закрытия портов MUST использовать один контракт заголовков.
- **FR-011**: Отсутствие обязательного смыслового поля MUST отклонять весь импорт атомарно с указанием канонического имени.
- **FR-012**: Изменение MUST NOT добавлять сетевую передачу, постоянное хранение или обработку учётных данных.

## Key Entities

- **Canonical SR header**: текущее официальное имя столбца.
- **SR field alias set**: каноническое имя и допустимые прежние имена одного смыслового поля.
- **Normalized SR row**: локальная проекция значений для inventory, фильтров и аналитики.
- **Raw SR row**: неизменённая исходная строка XLSX.

## Assumptions

- Перечисленные пользователем столбцы образуют текущий полный контракт из 42 уникальных заголовков.
- Старые файлы остаются рабочими для безопасного перехода, но интерфейс и документация используют новые названия.
- Новые столбцы не становятся обязательными для legacy-файла, если они не нужны существующей классификации и идентификации.

## Success Criteria

- **SC-001**: Полный файл с 42 каноническими заголовками импортируется без ошибок.
- **SC-002**: Все существующие legacy regression tests продолжают проходить.
- **SC-003**: Повторный импорт с одинаковыми SmartRoom ID не создаёт дубликат локации или оборудования.
- **SC-004**: 100% JavaScript, Python, reference и syntax checks проходят без добавления секретов или runtime-данных.
