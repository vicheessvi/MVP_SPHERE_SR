## Renamed legacy aliases

`ID комнаты` → `SmartRoom ID локации`; `Название комнаты` → `Наименование локации`; `Состояние комнаты` → `Общий статус локации`; location `Описание` → `Описание локации`; `Адрес комнаты` → `Адрес локации`; `VIP комната` → `Признак VIP`; `Избранное` → `Избранная локация`; `SmartRoomID` → `SmartRoom ID оборудования`; `Тип оборудования` → `Класс оборудования`; `Наименование` → `Наименование оборудования`; `Общий статус` → `Общий статус оборудования`; `Статус аутентификации` → `Статус авторизации`; `Тип модели` → `Тип`; `IP` → `IP адрес`; `MAC` → `MAC адрес`.

При наличии канонического и прежнего заголовка канонический имеет приоритет. `Описание` в новой схеме относится только к оборудованию; location description берётся из `Описание локации`, чтобы не смешивать две сущности.

## Validation

Импорт атомарно требует смысловые поля локации, класса/типа/наименования оборудования, модели, производителя, IP/MAC, SIP, inventory и serial. Для переходного legacy-файла допускаются прежние имена этих полей. Новые дополнительные поля могут быть пустыми, но при наличии сохраняются в raw row и нормализованной проекции.
