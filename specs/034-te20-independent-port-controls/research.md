# Research: TE20 independent port controls

- **Decision**: Сначала только exact TE20. **Rationale**: До входа и после него у модели есть действующие gates; чтение `enable_http`/`enabletelnet` и закрытие подтверждены на реальном устройстве. **Alternative**: Перенести на TE30–TE60/CloudLink — отклонено, потому что значения HTTP у TE-семейств различаются, а CloudLink не раскрывает Telnet.
- **Decision**: Открытие TE20 кодировать как бинарное значение, противоположное подтверждённому закрытию, но пометить эксплуатационную write-проверку как ожидающую. **Rationale**: Текущий read-only контракт принимает только `0/1` и уже трактует `0` как отключение обоих сервисов. **Alternative**: Написать произвольное значение — запрещено.
- **Decision**: Два независимых action ID вместо одного объекта с произвольным payload. **Rationale**: Plan schema v3 принимает только catalog allowlist, а конечное состояние нельзя подменить в произвольном JSON клиента.
- **Decision**: Не выполнять live write в ходе реализации без выбора точного целевого состояния устройства. **Rationale**: Открытие сервиса меняет его экспозицию.
