# Контракт отдельного изменения настройки

Обычный опрос и локальный XLSX-отчёт не отправляют команды изменения. Каждое новое изменение требует точной модели и IP из утверждённого источника, одного целевого значения, отдельного подтверждения администратора, pre-read, максимум одной записи и post-read. Неясный результат записи не повторяется автоматически при восстановлении плана.

## Подтверждённый этап: изменить автоответ Huawei TE20

`set_te20_auto_answer_automatic` и `set_te20_auto_answer_manual` — две взаимоисключающие задачи plan schema v3, доступные только для одного exact TE20, выбранного по IP из загруженной SR. Они не совмещаются с задачей закрытия портов. После проверки модели и устойчивого идентификатора текущий bundle должен содержать `WEB_GetCfgParamAPI`, `WEB_SaveCfgParamAPI` и `autoreply`. Pre-read принимает только `{0,1}`: `0` соответствует «Автоматически», `1` — «Вручную». При необходимости отправляется единственный `CfgItemInt` с `autoreply=0` либо `autoreply=1`, пустым `CfgItemString` и текущим CSRF. Успех фиксируется только при точном post-read целевого значения. Другие коды или drift блокируют запись.

Контролируемые реальные записи `1 → 0` и `0 → 1` выполнены после отдельных согласий администратора; обе подтверждены повторным машинным чтением, автоматический режим дополнительно проверен в web-меню. Обычный опрос остаётся read-only. При восстановлении неясный результат записи не повторяется автоматически.

## Остальные параметры

Для exact TE20 отдельно добавлены ограниченные действия открытия/закрытия каждого порта (feature 034, ADR-0037), отключения автообновления (feature 035, ADR-0038) и включения/отключения SSH (feature 036, ADR-0039). Администратор сообщил об успешной проверке этих действий на рабочем ПК. Настройки NTP exact TE20 (feature 037, ADR-0040) используют отдельное provisional-действие с одним ограниченным write и post-read; реальная запись ещё не подтверждена. Для TE30–TE60 действующий контракт подтверждает только модельные значения закрытия, для Bar 310/Box 310/Box 610 — только закрытие HTTP. Открытие для остальных моделей не является автоматической инверсией задачи закрытия. Для SNMP v2, обновления, SSH и NTP на других моделях, Wi-Fi и питания необходимы отдельные write/post-read контракты для каждой точной модели и целевого значения. Неподтверждённое сочетание остаётся `protocol_required` и не вызывает сетевой записи. Для CloudLink 310 Telnet не предоставлен web-интерфейсом; это не доказательство состояния TCP/23.
