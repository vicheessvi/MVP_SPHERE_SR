# Контракт отдельного изменения настройки (проект, без реализации записи)

Обычный опрос и локальный XLSX-отчёт не должны отправлять команды изменения. В будущем изменение запускается отдельным действием: точная модель и IP из утверждённого списка → один выбранный параметр → явно выбранное целевое значение → отдельное подтверждение администратора → pre-read и проверка идентичности → максимум одна запись по подтверждённому контракту → post-read целевого значения. Несовпадение модели, идентификатора, версии прошивки, схемы ответа или отсутствие подтверждённого значения блокируют запись.

Открытие HTTP/Telnet — не автоматическая инверсия существующей задачи закрытия. Для TE20 и TE30–TE60 действующий контракт подтверждает только модельные значения закрытия, а для Bar 310/Box 310/Box 610 — только закрытие HTTP. Значения открытия и реакция web-сессии после переключения требуют отдельного controlled test для каждой модели. Для CloudLink 310 Telnet не предоставлен web-интерфейсом; сетевой TCP/23 не считается доказанно закрытым. Для CloudLink 300 и Polycom Group пока нет ни одного подтверждённого контракта записи этих настроек.

Для SNMP v2, автоматического обновления, автоответа, NTP, Wi-Fi, SSH и питания сначала нужен read-only контракт. Лишь затем для каждого точного поля и модели можно утверждать допустимые значения, зависимые настройки, риск потери доступа и write/post-read схему. Неподтверждённое сочетание всегда `protocol_required` и не вызывает сетевой записи.

Текущая реализация feature 033 не добавляет нового action в plan schema v3 или каталог доступных write-действий.
