# Feature Specification: Answer mode Huawei CloudLink 300

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-11-15

**Status на 2026-11-24**: администратор подтвердил Answer mode Bar 300/Box 300/Box 600 в обоих направлениях, отдельно по IP и массово; новые write-результаты — confirmed_user_validation

**Input**: Добавить в существующий блок плана автоматического опроса переключение автоответа для Bar 300, Box 300 и Box 600; проверить на подключённом Bar 300.

## User Scenarios & Testing

### User Story 1 — Изменить Answer mode одного устройства (Priority: P1)

Администратор выбирает точное устройство серии CloudLink 300 по IP и указывает «Не менять», «Автоматически — включить автоответ» либо «Вручную — отключить автоответ» в том же месте, где находятся остальные настройки Answer mode. После явного подтверждения инструмент проверяет текущий режим, при необходимости выполняет не более одного изменения и повторно проверяет итог.

**Independent Test**: На проверенном Bar 300 оба направления режима выполняются по отдельности; «Не менять» не отправляет команду изменения.

**Acceptance Scenarios**:

1. **Given** exact Bar 300 в ручном режиме, **when** администратор подтверждает «Автоматически», **then** итоговый режим подтверждён повторным чтением.
2. **Given** exact Bar 300 в автоматическом режиме, **when** подтверждено «Вручную», **then** итоговый режим подтверждён повторным чтением.
3. **Given** уже выбранный целевой режим, **when** запускается задача, **then** запись не отправляется, результат помечается как уже соответствующий цели.

### User Story 2 — Изменить совместимую группу (Priority: P2)

Администратор использует существующие фильтры актуальной SR для выбора только точных Bar 300, Box 300 и Box 600, видит число целей и отдельно подтверждает массовое действие. Каждое устройство проходит собственные проверки модели и обрабатывается независимо.

**Independent Test**: Совместимая группа допускается; группа с иной моделью блокируется до сети. Ошибка одного устройства не запускает повторную запись и не подменяет статус других.

**Acceptance Scenarios**:

1. **Given** только точные модели серии 300, **when** администратор подтверждает групповую задачу, **then** каждое устройство получает не более одной попытки записи с собственным повторным чтением.
2. **Given** смешанная группа либо изменение источника SR после формирования плана, **when** нажато «Запустить», **then** задача блокируется до записи.

### Edge Cases

- Неизвестный код Answer mode, изменённая web-форма или несовпадение модели запрещают запись.
- Неясный результат сетевой записи не повторяется автоматически; нужна отдельная ручная проверка.
- Новая задача не совмещается с изменением HTTP/Telnet, NTP, SSH или другими write-задачами.
- Логины, пароли, токены и сырой ответ устройства не попадают в план, JSON-аналитику или журнал ошибок.
- Подтверждение read-only настроек не доказывает безопасность записи. Отдельное эксплуатационное подтверждение Answer mode Box 300/600 получено от администратора 2026-11-24 вместе с Bar 300: оба направления, по IP и массово; новые write-результаты — confirmed_user_validation.

## Requirements

### Functional Requirements

- **FR-001**: Переключатель MUST находиться в существующем блоке Answer mode плана, с тремя указанными вариантами.
- **FR-002**: «Не менять» MUST не создавать задачу изменения.
- **FR-003**: Запись MUST выполняться только после точной проверки модели, устойчивого идентификатора, текущей схемы и чтения исходного режима.
- **FR-004**: Для каждого устройства допускается максимум одна запись и обязательная проверка целевого значения после неё; неясный результат MUST NOT повторяться автоматически.
- **FR-005**: Одиночный IP и совместимая группа по фильтрам актуальной SR MUST следовать существующим ограничениям и отдельному подтверждению массовой записи.
- **FR-006**: Смешанная группа, неверный digest SR, неоднозначный IP и неподдерживаемая модель MUST блокироваться до записи.
- **FR-007**: Результат MUST быть безопасным и объяснимым без секретов, сырого ответа или обещания изменения сетевого порта.
- **FR-008**: Box 300 и Box 600 MUST сохранять собственные модельные проверки; предварительный write-статус снимается только отдельной проверкой каждой модели. Это условие выполнено подтверждением администратора 2026-11-24; новые write-результаты — confirmed_user_validation.

### Key Entities

- **AnswerModeTask**: выбранная целевая модельная группа, одно направление и явное согласие администратора.
- **DeviceActionResult**: исходное/целевое/повторно прочитанное значение, статус и безопасная причина отказа.

## Success Criteria

### Measurable Outcomes

- **SC-001**: На проверенном Bar 300 оба направления подтверждаются повторным чтением; после контрольного цикла исходный режим восстановлен.
- **SC-002**: В 100% тестов неизвестной модели/схемы, смешанной группы и изменённой SR не отправляется ни одной команды записи.
- **SC-003**: В 100% тестов неясной сетевой ошибки нет автоматического повторения записи.
- **SC-004**: На экране до запуска видны целевой режим, число устройств и отдельное подтверждение массовой операции.
- **SC-005**: Секреты отсутствуют во всех новых результатах и диагностике.

## Assumptions

- «Где все остальные» означает использовать существующий блок Answer mode, а не создавать новый модуль.
- По контролируемому циклу Bar 300 код `0` означает «Автоматически», `1` — «Вручную»; узкий метод записи подтверждён отдельно.
- Подтверждение write на Bar 300 не переносится автоматически на Box 300/600. 2026-11-24 администратор предоставил отдельное эксплуатационное подтверждение всех трёх моделей, обоих направлений и одиночного/массового режимов. Исторические JSON и safety gates не меняются.
