# Feature Specification: Отключение автообновления Huawei TE20

**Feature Branch**: `codex/secure-local-runtime`
**Created**: 2026-11-02
**Status**: Implemented; confirmed by administrator on work PC
**Input**: Администратор выбирает для параметра «Автообновление» на TE20 «Не менять» или «Отключить».

## User Scenarios & Testing

### User Story 1 — Выбор в плане (Priority: P1)

Администратор выбирает один точный Huawei TE20 по IP из актуальной SR и задаёт «Не менять» или «Отключить» для автообновления.

**Why this priority**: Без явного выбора обычный опрос должен оставаться только чтением.

**Independent Test**: Создать два плана с одинаковой целью и убедиться, что задача изменения присутствует только во втором.

**Acceptance Scenarios**:

1. Given выбран вариант «Не менять», when запущен опрос, then автообновление не записывается.
2. Given выбран вариант «Отключить», when создан план для одного TE20 по IP, then перед запуском требуется отдельное подтверждение и выполняется только эта задача изменения.
3. Given выбрана другая модель или массовый режим, when запрошено отключение, then план блокируется до сетевого обращения.

### User Story 2 — Проверяемое отключение (Priority: P1)

Администратор видит, было ли автообновление уже отключено, отключилось после команды либо результат не удалось подтвердить.

**Why this priority**: Ответ на команду сам по себе не доказывает изменение настройки.

**Independent Test**: Синтетические ответы проверяют отсутствие записи при уже отключённом состоянии, одну запись и post-read при включённом, а также fail-closed при ошибках.

**Acceptance Scenarios**:

1. Given текущая настройка уже отключена, when выполняется задача, then новая запись не отправляется.
2. Given текущая настройка включена, when выполнена одна команда отключения, then успех показывается только после точного повторного чтения.
3. Given схема, модель, идентичность или результат повторного чтения не подтверждены, when выполняется задача, then успех не показывается и неопределённая запись не повторяется автоматически.

### Edge Cases

- Отключение не объединяется с задачами управления портами или Answer mode.
- Открытие HTTP/Telnet или смена сетевого адреса не являются частью этой задачи.
- Отсутствующий либо небинарный параметр не трактуется как «отключено».

## Requirements

### Functional Requirements

- **FR-001**: Система MUST показывать только «Не менять» и «Отключить» для автообновления TE20, по умолчанию «Не менять».
- **FR-002**: Система MUST допускать отключение только для одного точного TE20, выбранного по IP из актуальной SR, после подтверждения администратора.
- **FR-003**: Система MUST не отправлять запись при «Не менять» или при уже отключённом значении.
- **FR-004**: Система MUST до и после максимум одной записи проверять точное значение настройки, а до этого — модель и идентичность устройства.
- **FR-005**: Система MUST сообщать безопасный результат без учётных данных и сырых ответов устройства.
- **FR-006**: Система MUST сохранить существующий опрос и остальные задачи изменения без новых команд для других моделей.

### Key Entities

- **Выбор автообновления**: «Не менять» либо «Отключить».
- **Результат задачи**: статус, признак попытки записи, состояние до и после либо безопасная ошибка.

## Success Criteria

### Measurable Outcomes

- **SC-001**: В 100% сценариев «Не менять» команда записи отсутствует.
- **SC-002**: В 100% сценариев изменения выполняется не более одной записи и есть повторная проверка значения.
- **SC-003**: В 100% сценариев неизвестной модели, состояния или несовпавшего post-read успех не показывается.
- **SC-004**: Ранее поддерживаемые планы и опросы проходят регрессионные проверки.

## Assumptions

- Задача относится к Huawei TE20 из текущего этапа работы; другие модели требуют отдельного контракта.
- На этой модели подтверждённое бинарное состояние автообновления имеет значение «отключено» при коде `0`; администратор сообщил об успешной проверке задачи на рабочем ПК.
