# Implementation Plan: Массовый импорт и постоянная рабочая база

**Branch**: `codex/secure-local-runtime` | **Date**: 2026-11-18 | **Spec**: [spec.md](spec.md)

## Summary

Устранить зависания при обработке ~5 000 Huawei XML по 40–80 МБ: перенести разбор в браузерный Worker, убрать полную перерисовку на каждом шаге, держать только компактные результаты и ограничить доказательства повторных событий. Ускорить расчёт питания с квадратичного до индексированного и кешировать неизменённые представления. Добавить явно выбираемую локальную рабочую папку с SQLite-базой Python stdlib: проверенная безопасная проекция SR/JSON/логов, атомарные ревизии, автоматическое восстановление после входа и инкрементальное добавление файлов всех моделей. Polycom TGZ остаётся метаданными без событийного парсера.

## Technical Context

- **Language/Version**: Python 3.11+ stdlib; HTML/CSS/Vanilla JS; Node.js только для тестов.
- **Dependencies**: существующий loopback runtime, File API, текущие три Huawei scanner-контракта; `sqlite3`, `gzip`, `hashlib`, `tkinter` из stdlib.
- **Storage**: SQLite только в явно выбранной рабочей папке; локальный указатель пути вне Git. Без `localStorage`/`IndexedDB`, исходных логов и device credentials.
- **Testing**: Python `unittest` для persistence/API/security/crash; JS regression, synthetic 5k metadata + large virtual file, event-equivalence и perf checks; ручной тест на фактическом объёме.
- **Target Platform**: Windows Chrome/Edge через `START_MVP_SPHERE_SR.py`; `file://` остаётся сеансовым fallback.
- **Project Type**: локальный веб-инструмент с авторизованным Python runtime.
- **Performance Goals**: навигация не ждёт окончания текущего 40–80 МБ файла; 10 000 событий питания без прежнего многосекундного квадратичного расчёта; неизменённые файлы не перечитываются полностью при дозагрузке.
- **Constraints**: 200–400 ГБ исходных файлов, один Worker-сканер с периодическим перезапуском, порционные результаты, no raw payload in DB, exact event rules, no external transfer.
- **Scale/Scope**: 5 000 крупных файлов/папка; общий файловый registry для Huawei XML, Polycom TGZ, JSON-опросов и будущих моделей.

## Constitution Check

- I–V PASS: исходные файлы не меняются, индекс сохраняет SHA-256/содержательный digest и путь/строку; старые события не переписываются и не удваиваются. Неизвестные результаты не становятся подтверждёнными.
- VI PASS по Constitution 5.0.0: только явно выбранная папка, проверенная безопасная проекция, admin-gated same-origin loopback, путь в профиле вне Git, секреты/rawText/полные логи не сохраняются. Прямой `file://` — без автосохранения.
- Gate: повреждённая/недоступная БД не сбрасывается; новая ревизия публикуется транзакционно и только при совпадении базовой ревизии.
- Post-design recheck: ограниченные HTTP-операции и проверка схемы, Worker не обращается к сети и не меняет правила событий, bounded source references с общим счётчиком/доказательством.

## Phase 0 — Research

Результаты в [research.md](research.md): текущий импорт вызывает полный `render()` каждые 8 файлов, прежний индекс очищается до успеха, все промежуточные сканы удерживаются до конца, а расчёт длительности питания выполняет квадратичный поиск. Пять тысяч больших XML могут читаться физически долго; ускорение интерфейса и пропуск ранее принятых файлов важнее обещания фиксированной общей длительности.

## Implementation Strategy

1. Сначала синтетические отказные и эквивалентные тесты. Исправить квадратичный расчёт, ограничить рост источников, заменить progress render на локальное обновление и атомарную публикацию индексов.
2. Добавить Worker без изменения парсеров событий; fallback `file://` остаётся порционным. Сравнить события Worker и прежнего пути на фиксированных логах.
3. Реализовать выбранную SQLite-базу и admin-gated API, безопасную проекцию, ревизии, повреждение/конкуренцию. Подключить автозагрузку после входа и автоматическое сохранение завершённых SR/JSON/лог импортов. Дозагрузку строить по registry: быстрый пропуск неизменённого источника, содержательный digest новых файлов и опция полной перепроверки.
4. Обновить справочник/документацию, полный regression suite, синтетические 5 000 файлов и тест восстановления после перезапуска runtime.

## Complexity Tracking

Изменение хранения — согласованное пользователем исключение Constitution 5.0.0, не скрытый cache. Прежний сеансовый режим остаётся для `file://`. Полная эксплуатационная проверка 200–400 ГБ требует рабочей машины пользователя; локальные тесты используют эквивалентные виртуальные и синтетические файлы без инфраструктурных данных.
