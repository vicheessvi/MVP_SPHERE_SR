# Research: массовый импорт и восстановление

## Решение: фоновый порционный scanner

**Evidence**: `app.js` перестраивает весь shell каждые 8 файлов; три Huawei scanner читают 64 КиБ порциями, но выполняются на основном потоке. Пользователь подтвердил масштаб 5 000 × 40–80 МБ, в основном Huawei XML. Синтетический TE-скан 33 МБ/500 тыс. строк занял ~0,73 с без диска; физическое чтение 200–400 ГБ займёт существенно дольше.

**Decision**: один Web Worker для Huawei XML, порционная передача только компактных markers/bootGaps, лёгкий DOM-progress с throttling, cancel и периодический recycle Worker. При отказе Worker на `file://` — тот же scanner с явным yielding. Не читать архивы Polycom целиком: их контракт только метаданные.

**Alternatives**: полный XML в main thread и прогресс-перерисовка (зависания); параллельные десятки Worker (неограниченная память). Отклонены.

## Решение: bounded in-memory analytics

**Evidence**: `getPowerDurationAnalytics` делал `.find` следующего запуска для каждого shutdown: на 10 тыс. синтетических событий одного устройства ~3,16 с, а рост квадратичный. Index builders удерживают все per-file scans и неограниченные `sources`; импорт очищает прежние индексы до завершения.

**Decision**: бинарный поиск следующего запуска, cache сводок по ревизии/фильтрам, атомарная замена индекса, ограниченное число ссылок на повторные копии события с общим sourceCount. Сканировать один файл за раз, публиковать только компактные проверенные результаты.

**Alternatives**: просто поднять лимит памяти (не устраняет O(N²)), silently truncate events (исказит аналитику). Отклонены.

## Решение: явная локальная рабочая база

**Evidence**: `app.js` использует `createVolatileStorage`; refresh удаляет весь state. `pollingResults` и `snapshots` содержат `rawText` и не могут быть целиком записаны в постоянную базу без риска утечки. SR/JSON успешные пути присваивают state напрямую, минуя `commitState`.

**Decision**: SQLite stdlib в выбранной пользователем папке, путь в локальном профиле Windows, доступ после admin login/Origin/CSRF. Сохранять только валидированную safe projection с исключением rawText/секретов и компактный registry файлов/аналитики. Транзакционная ревизия и optimistic concurrency предотвращают частичную замену/две вкладки. После входа автоматически восстановить последнюю корректную ревизию; повреждение/недоступность — явная ошибка.

**Alternatives**: `localStorage`/`IndexedDB` (запрещены), скрытая база внутри репозитория (запрещена), копирование 200–400 ГБ логов (дорого и запрещено), ручное открытие проектного файла при каждом запуске (не отвечает запросу на комфорт). Отклонены.

## Дозагрузка и идентичность файлов

Registry общ для всех логов и JSON-опросов. Исходный файл остаётся на месте, база хранит путь/метаданные и компактный результат. Для полностью прочитанного Huawei XML Worker вычисляет bounded-memory `sha256-chunk-merkle-v1` (4-МиБ блоки, SHA-256 каждого блока и итоговой последовательности); это содержательный криптографический digest, но не обычный SHA-256 файла. Для Polycom TGZ сохраняется только fingerprint начала и метаданные, без полного digest и событийного парсинга. Кэш-пропуск неизменённого пути/размера/mtime/префикса — только ускорение повторного выбора той же папки, не доказательство полного равенства; полная перепроверка доступна. События дедуплицируются по существующим содержательным ключам.
