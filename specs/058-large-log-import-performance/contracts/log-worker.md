# Контракт фонового разбора логов

`runtime/log-scan-worker.js` загружается только из того же локального источника и импортирует существующие `huawei-*-log-events.js`. Он принимает ровно один `File` за запрос с объявленным `kind=te|huawei310|huawei300`, модельным ключом и номером задания. Вывод — `progress(bytesRead,fileSize)`, затем `result(scan)` либо безопасный `failed(reason)`; строки исходного лога и секреты не передаются в основной поток.

Worker читает файл порциями 64 КиБ через существующий scanner, имеет один активный файл, не копирует весь 40–80 МБ лог, периодически освобождается/перезапускается. Main thread допускает отмену через `terminate()` без публикации частичного индекса. При невозможности создать Worker в `file://` применяется порционный scanner с явным yield и теми же event rules; ошибка во время чтения одного файла не меняет уже опубликованную аналитику.

Прогресс обновляет только `role=status` в текущем экране не чаще одного раза за 200–250 мс, а не заменяет весь app shell. Выходные markers/bootGaps сравниваются в тестах с прежним scanner на тех же синтетических файлах.
