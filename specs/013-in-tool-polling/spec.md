# Feature Specification: Автоматический опрос внутри инструмента

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-09-01

**Status**: Ready

**Input**: После формирования плана автоматически запускать web-опрос устройств внутри инструмента и сохранять готовые JSON в новую папку запуска внутри выбранной общей папки результатов. Ручной импорт остаётся. Для Extron временно допускается HTTPS с явно разрешённым самоподписанным сертификатом; логины и пароли должны оставаться защищёнными.

## User Scenarios & Testing

### User Story 1 - Запуск опроса из плана (Priority: P1)

Администратор МЦТП загружает SR и XLSX с учётными данными, выбирает общую папку результатов, формирует план и запускает его внутри инструмента без скачивания плана и ручного вызова отдельного скрипта.

**Why this priority**: Это основной пользовательский сценарий автоматического опроса.

**Independent Test**: На плане с двумя синтетическими поддерживаемыми устройствами запустить опрос одной кнопкой и подтвердить последовательную обработку без ручных действий между устройствами.

**Acceptance Scenarios**:

1. **Given** загружены SR и допустимый XLSX, выбрана доступная папка и сформирован план, **When** администратор запускает план, **Then** инструмент ожидает заданное время начала и последовательно опрашивает поддерживаемые устройства.
2. **Given** страница открыта без локального исполнителя, **When** администратор пытается запустить опрос, **Then** сеть к устройствам не выполняется, а интерфейс показывает безопасную инструкцию запуска проекта.
3. **Given** план содержит неподдерживаемые устройства, **When** выполняется план, **Then** они учитываются в прогрессе, но не вызывают сетевого обращения.

---

### User Story 2 - Сохранение готовых результатов (Priority: P1)

Администратор выбирает общую папку результатов. Для каждого запуска инструмент создаёт внутри неё отдельную папку `YYYY-MM-DD_HH-mm-ss` и сохраняет в неё JSON каждого обработанного устройства сразу после завершения его опроса.

**Why this priority**: Длительный опрос не должен терять уже полученные результаты, а автоматические и ручные результаты должны иметь одинаковую структуру.

**Independent Test**: Выполнить синтетический опрос двух устройств и проверить новую папку запуска, два валидных JSON и факт записи первого файла до начала интервала.

**Acceptance Scenarios**:

1. **Given** общая папка выбрана, **When** начинается новый запуск, **Then** создаётся ровно одна новая папка с локальными датой и временем старта.
2. **Given** результат устройства готов, **When** его безопасная запись завершилась, **Then** только после этого начинается интервал перед следующим поддерживаемым устройством.
3. **Given** запись очередного результата невозможна, **When** возникает ошибка, **Then** дальнейший опрос останавливается, ранее сохранённые JSON остаются, а секреты не попадают в сообщение.
4. **Given** автоматические JSON сохранены, **When** пользователь выбирает общую папку в ручном импорте, **Then** результаты загружаются тем же существующим способом.

---

### User Story 3 - Защищённая локальная авторизация (Priority: P1)

Администратор использует общий XLSX-пул логинов и паролей только для текущего запуска. Учётные данные не покидают компьютер и не появляются в плане, файлах результатов, аналитике, журналах или постоянном хранилище.

**Why this priority**: Утечка учётных данных оборудования создаёт критический инфраструктурный риск.

**Independent Test**: Выполнить запуск с синтетическим секретом, проверить сериализуемое состояние, ответы, логи и созданные файлы и убедиться, что значение отсутствует во всех артефактах.

**Acceptance Scenarios**:

1. **Given** выбран допустимый XLSX, **When** локальный исполнитель принимает файл, **Then** пары существуют только в памяти текущей авторизованной сессии и очищаются после запуска, отмены или завершения процесса.
2. **Given** Extron использует самоподписанный сертификат, **When** администратор явно разрешает этот режим, **Then** соединение остаётся HTTPS, а отключение проверки сертификата действует только для текущего запуска.
3. **Given** изменение запроса пришло не из активной локальной сессии, **When** оно достигает исполнителя, **Then** запрос отклоняется до обработки XLSX или обращения к устройству.

---

### User Story 4 - Прогресс и отмена (Priority: P2)

Администратор видит состояние запуска, количество обработанных, успешных, ошибочных и неподдерживаемых устройств и может отменить ожидание или дальнейшую обработку.

**Why this priority**: Длительный опрос должен оставаться управляемым и объяснимым.

**Independent Test**: Запустить план с интервалом, отменить его во время ожидания и подтвердить отсутствие новых запросов и сохранность готовых файлов.

**Acceptance Scenarios**:

1. **Given** опрос выполняется, **When** меняется этап, **Then** интерфейс показывает текущий этап и точные безопасные счётчики без учётных данных.
2. **Given** пользователь отменяет запуск, **When** отмена принята, **Then** активное ожидание прерывается и новые устройства не запускаются.

### Edge Cases

- Локальный исполнитель не запущен или остановлен после открытия интерфейса.
- Браузер отозвал разрешение на запись в выбранную папку.
- Папка запуска с тем же именем уже существует; новый запуск не должен перезаписывать старые файлы.
- XLSX изменён после проверки либо не соответствует отпечатку плана.
- Страница закрыта, перезагружена или потеряла локальную сессию во время выполнения.
- Устройство не отвечает на ping, отклоняет все пары или возвращает неизвестный web-контракт.
- Самоподписанный сертификат разрешён, но TLS-соединение всё равно не устанавливается.
- Отмена совпала по времени с готовностью результата: готовый JSON сохраняется не более одного раза.

## Requirements

### Functional Requirements

- **FR-001**: Инструмент MUST запускать сформированный план из пользовательского интерфейса без скачивания плана и ручного запуска отдельного скрипта.
- **FR-002**: Сетевой опрос MUST выполняться только локальным исполнителем, доступным исключительно активной сессии Администратора МЦТП на этом компьютере.
- **FR-003**: Запуск MUST блокироваться до загрузки допустимого XLSX, выбора доступной общей папки и формирования плана с хотя бы одним поддерживаемым устройством.
- **FR-004**: План MUST оставаться неизменяемым снимком и MUST NOT содержать логины, пароли, cookie, токены или заголовки авторизации.
- **FR-005**: Исполнитель MUST принимать только IP-адреса из неизменяемого allowlist плана и MUST NOT следовать перенаправлению на другой host.
- **FR-006**: Общая папка результатов MUST выбираться пользователем явно для текущей вкладки и MUST NOT сохраняться в browser storage.
- **FR-007**: Каждый запуск MUST создавать внутри общей папки уникальную папку `YYYY-MM-DD_HH-mm-ss`, соответствующую локальному времени фактического старта.
- **FR-008**: Каждый результат MUST сохраняться отдельным JSON непосредственно после обработки устройства и до ожидания интервала.
- **FR-009**: Существующий ручной импорт общей папки MUST оставаться доступным и совместимым с автоматическими результатами.
- **FR-010**: Учётные данные MUST существовать только в памяти текущей локальной сессии и MUST удаляться после завершения, отмены, ошибки или остановки runtime.
- **FR-011**: Учётные данные MUST NOT попадать в DOM, основной state, план, JSON результатов, аналитику, stdout/stderr, диагностику, backup, Git или постоянное хранилище.
- **FR-012**: Локальные mutating-запросы MUST требовать действующую одноразовую сессию, точный loopback Host, same-origin и CSRF-подтверждение.
- **FR-013**: XLSX MUST проверяться по существующей схеме «Логин» и «Пароль», а его SHA-256 MUST совпадать с отпечатком сформированного плана до первого сетевого обращения.
- **FR-014**: Extron MUST опрашиваться через подтверждённый HTTPS web-контракт; обычный HTTP MUST NOT использоваться.
- **FR-015**: Отключение проверки самоподписанного TLS-сертификата MUST включаться явно для конкретного запуска, отображаться в интерфейсе и MUST NOT изменять глобальные TLS-настройки.
- **FR-016**: Исполнитель MUST последовательно обрабатывать устройства, соблюдать заданные дату начала и интервал и не ждать до первого или после последнего поддерживаемого устройства.
- **FR-017**: UI MUST показывать этап, общее и обработанное количество, успешные, ошибочные и неподдерживаемые результаты без секретов.
- **FR-018**: Отмена MUST прекращать ожидание и последующие опросы, не удаляя уже записанные результаты.
- **FR-019**: Ошибка записи MUST останавливать пакет до следующего устройства и MUST NOT маскироваться успешным статусом.
- **FR-020**: При отсутствии локального исполнителя интерфейс MUST запрещать автоматический запуск и объяснять необходимость запуска через штатный локальный launcher.
- **FR-021**: Внешние сервисы, telemetry, CDN, non-loopback bind и постоянное browser storage MUST отсутствовать.
- **FR-022**: Прямое открытие `index.html` MAY оставаться режимом ручного анализа, но MUST NOT имитировать возможность автоматического сетевого опроса.

### Key Entities

- **LocalPollingSession**: одноразовая локальная сессия запуска, связанная с CSRF-защитой, пулом учётных данных и текущей операцией.
- **OutputDirectoryGrant**: временное разрешение пользователя на запись в общую папку результатов, существующее только в текущей вкладке.
- **AutomaticPollingJob**: неизменяемый план, режим TLS, состояние, прогресс, отмена и безопасная сводка выполнения.
- **PendingPollingResult**: очищенный результат одного устройства, который должен быть записан и подтверждён до продолжения плана.
- **PollingRunFolder**: уникальная папка конкретного запуска с готовыми JSON, совместимая с ручным импортом.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Администратор запускает готовый план не более чем одним действием после его формирования и выбора общей папки.
- **SC-002**: Для 100% обработанных устройств существует не более одного JSON, сохранённого до начала интервала перед следующим устройством.
- **SC-003**: В 100% тестов с синтетическим секретом значение отсутствует в состоянии, плане, ответах статуса, результатах, журналах и постоянном хранилище.
- **SC-004**: 100% сетевых целей принадлежат IP-адресам неизменяемого плана; неподдерживаемые устройства вызывают ноль сетевых запросов.
- **SC-005**: Отмена во время интервала предотвращает запуск следующего устройства и сохраняет все ранее подтверждённые JSON.
- **SC-006**: Автоматически созданную общую папку можно импортировать вручную без преобразования файлов.
- **SC-007**: При недоступном runtime, недействительной папке, несовпадающем XLSX или ошибке записи пользователь получает явный безопасный статус до продолжения опроса.

## Assumptions

- Основная рабочая среда — Windows и Chromium-браузер, поддерживающий выбор каталога с разрешением на запись.
- Штатный автоматический режим запускается через `start.ps1`; прямой `index.html` сохраняется только для ручного анализа и импорта.
- Вкладка и локальный runtime остаются открыты до завершения запланированного запуска.
- Общая папка находится на доступном пользователю локальном или разрешённом сетевом диске; защита самого исходного XLSX обеспечивается правами Windows владельца файла.
- В текущем объёме автоматический vendor-опрос реализован только для устройств с подтверждённым Extron web-контрактом; остальные устройства остаются `protocol_required`.
