# Feature Specification: Чтение настроек Huawei Box 310 и Box 610

**Feature Branch**: `codex/secure-local-runtime`
**Created**: 2026-11-10
**Status**: Реализовано предварительно — ожидает отдельной проверки администратором на двух моделях
**Input**: На основе работающего опроса Bar 310 добавить фактические настройки в JSON точных Box 310 и Box 610; результаты реальной проверки пользователь сообщит позже.

## User Scenarios & Testing

### User Story 1 — Получить настройки Box 310 (Priority: P1)

Администратор выбирает точный Box 310, запускает обычный опрос и получает в JSON применимые настройки по тем же разделам, что и для Bar 310: Site name, HTTP, автоответ, NTP, Wi‑Fi, SSH, питание и возможность обновления прошивки. Доступность и значения этих полей должны быть явно обозначены; до реальной проверки модельный результат остаётся предварительным.

**Independent Test**: Синтетический Box 310 с совпадающим web-контрактом даёт ограниченный read-only результат, а несовпадение модели или схемы не даёт ложных значений.

**Acceptance Scenarios**:

1. **Given** точный Box 310 с подтверждённой моделью и совместимыми признаками текущего интерфейса, **When** обычный опрос завершён, **Then** известные поля включены в JSON с источником и предварительным статусом проверки.
2. **Given** признак или ответ поля не совпал, **When** обычный опрос завершён, **Then** это поле остаётся неизвестным; другие корректные поля сохраняются.

### User Story 2 — Получить настройки Box 610 (Priority: P1)

То же поведение доступно отдельно для точного Box 610 без переноса идентичности Box 310 или Bar 310.

**Independent Test**: Синтетический Box 610 проверяется независимо, а результат другой модели не наследует значения.

**Acceptance Scenarios**:

1. **Given** точный Box 610 и совместимые признаки интерфейса, **When** обычный опрос завершён, **Then** JSON содержит модельно ограниченные настройки и предварительный статус.
2. **Given** модель с суффиксом или другая Box-модель, **When** выбран план, **Then** новый контракт не применяется.

### Edge Cases

- Текущая прошивка Box может отличаться от Bar; совпадение названия параметра не доказывает совпадение кодировки.
- Функция может отсутствовать на модели; это отличается от ошибки чтения.
- Неподтверждённое значение не должно попадать в XLSX как проверенный факт.
- Ответ устройства может содержать адреса, секреты Wi‑Fi и токены; они не включаются в производный результат.

## Requirements

### Functional Requirements

- **FR-001**: Только exact Box 310 и exact Box 610 MUST получать попытку read-only чтения новых настроек после собственных проверок модели и устойчивой идентичности.
- **FR-002**: Каждое поле MUST требовать совместимых признаков web-интерфейса и строгой схемы; drift MUST давать `protocol_required` или `unavailable`, а не подставленное значение.
- **FR-003**: Новые результаты Box MUST быть явно помечены как предварительные до отдельной пользовательской проверки каждой модели; этот статус MUST сохраняться при импорте и в таблице фактических настроек.
- **FR-004**: Обычный опрос MUST оставаться только на чтение; текущие Bar 310, Box 310 и Box 610 контракты изменения HTTP MUST не расширяться.
- **FR-005**: Секреты, токены и сырые ответы MUST оставаться вне JSON, аналитики и репозитория.
- **FR-006**: После пользовательского подтверждения каждой модели её статус MAY стать подтверждённым отдельным изменением без автоматического переноса подтверждения на другую модель.

### Key Entities

- **Модельный результат**: exact модель, идентичность, контракт, статус эксплуатационной проверки.
- **Настройка**: имя, значение или неопределённость, источник, предварительный статус и версия правила.

## Success Criteria

- **SC-001**: Синтетические проверки для обеих точных Box-моделей проходят по всем применимым разделам без запроса настроек другой модели.
- **SC-002**: В 100% отрицательных сценариев неизвестная схема не превращается в подтверждённое значение.
- **SC-003**: До эксплуатации администратор может отличить предварительное значение Box от подтверждённого значения Bar в JSON и отчёте.
- **SC-004**: После передачи изменений администратор может сверить оба Box с их web-меню и отдельно сообщить результат.

## Assumptions

- Первая поставка использует модельно ограждённые кандидаты чтения на основе Bar 310 и остаётся предварительной для каждого Box.
- Никакие настройки оборудования в этой feature не изменяются.
