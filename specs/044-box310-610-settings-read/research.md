# Research: настройки Box 310/610

## Decision

Обычный `/v1` HTTPS-опрос Box 310 и Box 610 уже использует общий guarded core с отдельными exact-model wrappers и был подтверждён администратором на рабочих устройствах. Дополнительное чтение настроек Bar 310 проверено на реальном Bar, но для обоих Box нет отдельного снимка bundle/ответов. По запросу администратора разрешён предварительный общий кандидат чтения: каждый параметр обращается к устройству только если текущий bundle содержит точный read-form marker; ответ проходит строгую модельную схему, а значение маркируется `provisional_user_validation`. Неизвестное остаётся `protocol_required`/`unavailable`.

Семантика `autoreply` и `autoUpdate` на Box не считается доказанной только по Bar. Их значения в JSON будут предварительными до проверки каждого Box; автоматическая таблица фактов не должна показывать их как подтверждённые. Для `autoUpdate` источник — утверждённое администратором правило по типу сервера, но корректность отображения меню и кодов на Box ещё не подтверждена.

## Rationale

Общий код снижает расхождение алгоритмов. Отдельные model/identity и bundle/schema gates предотвращают обращение по произвольным адресам и ложные подтверждения. Пользовательская проверка на обоих Box завершит evidence review.

## Alternatives rejected

Безусловный перенос всех Bar-значений и автоматическое объявление Box подтверждёнными отклонены. Полное дублирование адаптера также не нужно: Box уже разделяют guarded core.

## User validation

Администратор отдельно провёл опросы Box 310 и Box 610 и подтвердил наименования и фактические значения новых параметров и Site name каждой модели. Это закрывает первоначальный read-only provisional статус для новых опросов, но не подтверждает HTTP write. Старые JSON с provisional статусом остаются неизменными.
