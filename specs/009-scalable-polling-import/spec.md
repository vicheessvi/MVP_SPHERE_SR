# Feature Specification: Масштабируемый импорт результатов опроса

**Feature Branch**: `009-scalable-polling-import`

**Created**: 2026-08-10

**Status**: Approved for implementation

**Input**: Ускорить массовый импорт 7 862 и более JSON, сохранить отзывчивость интерфейса, добавить живой прогресс и безопасную отмену без изменения локального запуска через `index.html`.

## User Scenarios & Testing

### User Story 1 - Отзывчивая массовая загрузка (Priority: P1)

Администратор МЦТП выбирает общую папку с несколькими запусками опроса и видит, как результаты обрабатываются небольшими пакетами без зависания страницы.

**Why this priority**: Текущий сценарий 7 862 JSON занимает более 30 минут и вызывает системное предупреждение браузера.

**Independent Test**: Загрузить синтетическую папку с 7 862 JSON через `file://index.html`, наблюдать обновление интерфейса и сравнить итоговые сущности с последовательным эталонным конвейером.

**Acceptance Scenarios**:

1. **Given** корректная иерархия папок запусков, **When** выбрано 7 862 JSON, **Then** интерфейс регулярно получает управление, отображает прогресс и импорт завершается существенно быстрее исходного контура.
2. **Given** смесь корректных, повреждённых и посторонних файлов, **When** выполняется импорт, **Then** ошибка одного JSON не останавливает остальные, а non-JSON игнорируются.
3. **Given** несколько папок `YYYY-MM-DD_HH-MM-SS`, **When** они выбраны одной общей папкой, **Then** запуски обрабатываются хронологически с сохранением относительных путей.

---

### User Story 2 - Понятный прогресс и безопасная отмена (Priority: P1)

Администратор видит этап, число найденных и обработанных файлов, успехи, ошибки, дубликаты, скорость и приблизительное оставшееся время и может остановить загрузку.

**Why this priority**: Долгая операция без обратной связи воспринимается как зависание и неуправляема.

**Independent Test**: Начать синтетический импорт, проверить обновление всех показателей, нажать «Отменить загрузку» и убедиться, что сохранённые результаты корректны, текущий пакет завершён согласованно и показано требуемое сообщение.

**Acceptance Scenarios**:

1. **Given** активный импорт, **When** обрабатываются пакеты, **Then** прогресс обновляется с ограниченной частотой и не запускает пересчёт Dashboard для каждого файла.
2. **Given** активный импорт, **When** пользователь нажимает отмену, **Then** новые файлы больше не начинают обрабатываться, уже принятые результаты сохраняются и показано «Загрузка остановлена пользователем.»

---

### User Story 3 - Быстрые повторные и ежедневные загрузки (Priority: P2)

Администратор повторно выбирает уже импортированные файлы либо добавляет 1 000 новых результатов к большой истории без полного повторного анализа всей базы.

**Why this priority**: История постоянно растёт, а ежедневная стоимость должна зависеть преимущественно от новых данных.

**Independent Test**: Дважды импортировать один набор, затем добавить новый запуск к истории из 50 000 синтетических результатов; проверить идемпотентность, линейное число lookup и отсутствие полного rebuild истории после каждого файла.

**Acceptance Scenarios**:

1. **Given** ранее импортированный неизменный файл, **When** он выбран повторно, **Then** он определяется по индексу дубликатов до JSON.parse, нормализации и diff.
2. **Given** история устройства, **When** добавлен новый или запоздалый результат, **Then** пересчитываются только затронутые соседние пары, сохраняя хронологическую семантику.

---

### User Story 4 - Проверяемая производительность (Priority: P2)

Разработчик воспроизводимо сравнивает старый и новый конвейеры на синтетических наборах без публикации пользовательских данных.

**Independent Test**: Запустить benchmark для 1 000, 5 000, 7 862, 10 000 и вручную 25 000 JSON и получить время, files/sec, задержку event loop и разбивку по стадиям.

**Acceptance Scenarios**:

1. **Given** benchmark-сценарий, **When** он выполнен, **Then** отчёт содержит объём, elapsed, files/sec, parsing, SR matching, change detection, storage, analytics и измеримый UI/event-loop overhead.
2. **Given** performance guard, **When** алгоритм возвращается к `JSON × SR rows` или полному rebuild на файл, **Then** автоматическая проверка обнаруживает нелинейное число операций.

### Edge Cases

- Папка не содержит JSON в корректных dated-папках.
- Одинаковый IP относится к нескольким строкам SR.
- Результаты одного устройства поступают не по хронологии.
- JSON повреждён, очень велик или не содержит ожидаемых полей.
- Отмена происходит во время чтения пакета или сразу перед фиксацией результата.
- Повторный импорт содержит смесь новых файлов, дубликатов и изменённых файлов с тем же именем.
- API `scheduler.yield` или `requestIdleCallback` недоступен при запуске через `file://`.

## Requirements

### Functional Requirements

- **FR-001**: Система MUST сохранить рекурсивный поиск JSON, распознавание dated-папок, хронологический порядок запусков и относительные пути.
- **FR-002**: Система MUST обрабатывать файлы небольшими пакетами и регулярно отдавать управление browser event loop.
- **FR-003**: Система MUST читать файлы с ограниченным параллелизмом; не допускается неограниченный `Promise.all` по всему набору.
- **FR-004**: Система MUST удерживать в памяти тексты и parsed-объекты только текущего ограниченного пакета.
- **FR-005**: Система MUST построить current SR IP index один раз, не включать в него `ipHistory` и выполнять не более одного current-index lookup на обрабатываемый результат.
- **FR-006**: Система MUST построить индексы результатов, дубликатов и соседних исторических записей без полного поиска по SR или истории для каждого JSON.
- **FR-007**: Система MUST выполнять change detection инкрементально только для затронутых соседних пар, включая позднюю вставку.
- **FR-008**: Система MUST пропускать надёжно распознанный дубликат до parse, normalization и diff.
- **FR-009**: Система MUST сохранить исходный JSON и нормализованную проекцию без повторных цепочек stringify/parse/deep-clone.
- **FR-010**: Система MUST показывать этап, найдено/обработано, успешно, ошибки, дубликаты, текущий запуск, скорость и ETA.
- **FR-011**: Система MUST ограничивать частоту UI-render и выполнять Dashboard/analytics aggregation не чаще одного раза после завершения или отмены импорта.
- **FR-012**: Система MUST предоставлять кнопку «Отменить загрузку» и завершать отмену в согласованной границе, сохраняя уже корректно принятые результаты.
- **FR-013**: После отмены система MUST показать «Загрузка остановлена пользователем.»
- **FR-014**: Ошибка отдельного JSON MUST быть зарегистрирована без остановки остальных файлов.
- **FR-015**: Реализация MUST сохранять семантическую эквивалентность существующего последовательного конвейера для запусков, результатов, issues, истории, изменений и дубликатов.
- **FR-016**: Приложение MUST продолжать работать двойным щелчком по `index.html` без Node.js, Python, Docker, localhost, backend или сети.
- **FR-017**: Система MUST не добавлять пользовательские JSON в репозиторий и не передавать загруженные данные наружу.
- **FR-018**: Справочник MUST объяснять пакетную обработку, отображаемые показатели и пропуск дубликатов пользовательским языком.
- **FR-019**: Репозиторий MUST содержать синтетический benchmark и regression guard против O(N²).
- **FR-020**: Текущая работа MUST завершиться без commit, push и deploy.

### Key Entities

- **Import Session**: Временное состояние одной массовой загрузки, включая этап, счётчики, время, скорость, ETA, запрос отмены и итог.
- **Import Batch**: Ограниченный набор файлов одного или нескольких запусков, одновременно находящийся в чтении/обработке.
- **Import Index Context**: Неперсистентные индексы IP, дубликатов, запусков, истории устройств и change-пар, связанные с актуальным state.
- **Polling Result**: Существующий результат опроса с raw JSON, normalized projection, ссылками на запуск и устройство.
- **Adjacent Change Pair**: Изменения между соседними по времени результатами одного устройства.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Синтетический импорт 7 862 JSON завершается существенно быстрее исходных 30+ минут и исходного benchmark lower bound, без регулярного системного предупреждения «Страница не отвечает».
- **SC-002**: Между cooperative yields основной поток не занят непрерывно более 50 мс на контрольном синтетическом наборе, за исключением неделимых browser API операций.
- **SC-003**: SR lookup count растёт как O(new JSON), а не O(JSON × SR rows); guard фиксирует не более одного lookup на файл после построения индекса.
- **SC-004**: Полный rebuild истории/changes на каждый файл отсутствует; число пересчитанных пар не превышает двух на новый результат.
- **SC-005**: Повторный импорт неизменного набора не увеличивает число результатов/изменений и не выполняет parse/diff для дубликатов.
- **SC-006**: UI progress обновляется регулярно, но не чаще 20 render/с; Dashboard пересчитывается не более одного раза на импорт.
- **SC-007**: Автоматические тесты подтверждают семантический паритет, отмену, ошибки, позднюю вставку, дубликаты и линейные operation counts.
- **SC-008**: Benchmark формирует сопоставимые данные для 1 000, 5 000, 7 862 и 10 000 JSON; отдельный сценарий поддерживает 25 000.

## Assumptions

- Профилирование показало, что главный bottleneck — полные deep-clone состояния и rebuild истории на файл; isolated JSON.parse не оправдывает Web Worker на первом этапе.
- Текущее volatile browser storage не создаёт IndexedDB-транзакцию на файл; фиксация выполняется на согласованных границах без обязательного сервера.
- Внутренние batch size и concurrency выбираются консервативно и могут адаптироваться по возможностям браузера без пользовательской настройки.
- Реальные пользовательские данные недоступны для репозитория, поэтому benchmarks используют только синтетические payload.
