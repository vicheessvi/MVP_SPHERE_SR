# Benchmark results: indexed batch import

Дата: 2026-08-10. Среда: bundled Node.js на текущем Windows-ПК. Dataset полностью синтетический; реальные JSON пользователя не копировались.

## До изменений

| JSON | Import pipeline | Files/s | Event-loop lag | Примечание |
|---:|---:|---:|---:|---|
| 1 000 | 11 146,23 мс | 89,72 | 12,24 мс | 1 000 000 SR comparisons, ≥2 003 deep clones, 1 000 rebuilds |
| 5 000 | >180 с | <27,78 | не завершён | protective timeout |
| 7 862 | >45 с | не вычислено | не завершён | protective timeout; пользовательский реальный сценарий сообщал 30+ минут |
| 10 000 | >45 с | не вычислено | не завершён | protective timeout |

Для 1 000 файлов: grouping 9,57 мс; isolated parse 2,13 мс; IP 1,00 мс; full-scan SR matching 8,80 мс; normalization 9,56 мс; отдельная storage serialization 10,20 мс; Dashboard 8,26 мс. Следовательно, bottleneck находился не в parse, а в растущих полных копиях state и повторном rebuild.

25 000 — manual stress scenario. Редкий 55-мс пик связан с GC в Node на 25 000 raw results и 72 000 change records; на целевых 7 862 lag не превысил 16,67 мс. Эксперимент с yield каждые 8 файлов снизил полезную пропускную способность до 950,59 files/s, не устранив GC-пик, поэтому отклонён.

| Change detection | 1,59 | 81,97 | 148,74 | 192,20 | 539,03 мс |
| Progress callback overhead | 0,24 | 0,81 | 1,32 | 1,27 | 2,16 мс |
| Separate storage serialization check | 14,48 | 637,05 | 1 548,10 | 2 567,67 | 17 408,86 мс |
| Dashboard aggregation after import | 9,75 | 41,23 | 50,56 | 63,27 | 154,25 мс |

Все значения — миллисекунды. Storage serialization измеряется отдельно после pipeline и не выполняется UI-контуром массового импорта в volatile file-only режиме. Dashboard также не пересчитывается внутри pipeline.

## Outcome

- На 1 000 JSON pipeline ускорен примерно в 38,7 раза.
- 7 862 синтетических JSON обрабатываются примерно за 2,03 с вместо незавершившегося baseline и пользовательских 30+ минут.
- SR lookup и diff-pair count линейны по новым результатам.
- В памяти одновременно удерживается не более 32 прочитанных текстов текущего пакета.
- Повторный импорт использует hash index и не выполняет parse/SR/diff для дубликатов.
