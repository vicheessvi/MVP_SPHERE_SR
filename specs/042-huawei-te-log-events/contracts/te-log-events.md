# Contract: Huawei TE log event extraction

Только файл `<IP>.xml` с `LogModule` и единственным точным соответствием SR-модели TE30/TE40/TE50/TE60. Чтение частями через browser File API, UTF-8 decoder, одна строка не длиннее 8192 символов; XML как дерево не парсится. Встречаются только допустимые модули `LOG_MOD_MC` и `LOG_MOD_BSP`, строгая локальная дата/время `YYYY-MM-DD HH:mm:ss` и ограниченный номер записи.

- `LOG_MOD_MC` + `System start` → маркер запуска.
- `LOG_MOD_MC` + `normal ... reboot` → явный признак перезагрузки; подтверждённое событие только при связанном запуске в пределах двух минут, один запуск — максимум одно событие.
- `LOG_MOD_BSP` + `Terminal ... powered ... off` → явное зафиксированное отключение.
- Прочие слова power и неясные запуски не становятся перезагрузкой или отключением; неясные запуски показываются отдельно.

Время без часового пояса остаётся локальным временем терминала. Сырой текст, токены и credentials не входят в производные события. Разбор TE30/50/60 условен по точному формату; иные модели не наследуют правило.

TE20 имеет отдельный шаблон строки с дополнительным идентификатором потока после номера записи. `LOG_MOD_MC` и фраза `System ... boot` создают маркер запуска; `LOG_MOD_WEB` с техническим словом `reboots` создаёт reboot-маркер, только если не содержит признака ошибки. Подтверждённая перезагрузка требует этого маркера до нового boot в пределах двух минут; любые одиночные boot остаются `unknown_start`. Остальные слова reboot/restart в командах не считаются. Отдельная `LOG_MOD_WEB` запись `shut ... down ... terminal` без ошибки даёт `power_off` как подтверждённую web-команду штатного отключения; `OFFLINE` и отсутствие маркера не создают события и не доказывают аварийную потерю электропитания.

После отдельного контрольного опыта `LOG_MOD_RC` + `user ... shut ... down ... terminal` без ошибки также даёт `power_off` со способом `remote_control`; web-команда получает способ `web`. Нажатия Power, сон и `OFFLINE` остаются вне правила. Поле способа проходит в производное событие и таблицу, исходная строка не сохраняется.

Низкодостоверная гипотеза потери питания: для каждого точного запуска без подтверждённой причины измеряется максимальная пауза между соседними timestamp-строками, заканчивающаяся не далее 10 минут перед запуском. Дефолтный порог 60 минут, доступный диапазон 15–10080 минут. Если есть явная команда reboot/выключения между началом паузы и запуском, нет нового запуска или пауза превышает 30 дней (возможный скачок часов), предположение не создаётся. Результат отображается отдельно как `suspected_power_loss` с низкой достоверностью и диапазоном отсутствия записей; он не увеличивает подтверждённые счётчики и не указывает точное время/факт физической потери питания. Повторные копии одного запуска объединяются по минимальной наблюдаемой паузе.
