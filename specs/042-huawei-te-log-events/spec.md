# Feature Specification: Аналитика событий логов Huawei TE

**Feature Branch**: `codex/secure-local-runtime`
**Created**: 2026-11-10
**Status**: Implemented; real TE40 parser validation complete, TE30/50/60 pending user checks
**Input**: Импортировать общую папку скачанных логов терминалов Huawei TE20/30/40/50/60 и показывать в модуле «Анализ перезагрузок устройств» только доказанные перезагрузки и отключения питания, а неопределённые запуски отдельно.

## Clarifications

### Session 2026-11-10

- Q: Считать каждый `System start` перезагрузкой или только запуск с явным признаком reboot? → A: Только подтверждённый reboot; остальные запуски показывать отдельно как «Причина не установлена».
- Q: Как трактовать записи `System boot` TE20 без подтверждённой причины? → A: Только как запуски с неустановленной причиной; команда reboot сама по себе не является событием. После контрольного опыта подтверждённая пара «web reboots → новый System boot» считается перезагрузкой.
- Q: Как подтвердить выключение TE20? → A: Администратор сам выполнил штатное web-выключение и последующее включение; только отдельный web-маркер `shut ... down ... terminal` считается записью отключения, не общие сообщения `OFFLINE`.
- Q: Отличается ли выключение TE20 с пульта? → A: Да; администратор выполнил отдельный контрольный опыт, после которого подтверждён `LOG_MOD_RC` с `user ... shut ... down ... terminal`. В событии сохраняется способ «Пульт ДУ».
- Q: Считать долгую паузу в журнале отключением питания? → A: Только отдельное предположение низкой достоверности для TE20/30/40/50/60, без прибавления к подтверждённым отключениям. Начальный настраиваемый порог — 60 минут.

## User Scenarios & Testing

### User Story 1 — Импортировать доказательства (Priority: P1)

Администратор выбирает общую папку логов. Инструмент сохраняет прежние метаданные импорта и дополнительно извлекает только подтверждённые события точных моделей, однозначно связанных с актуальной SR. Сырой лог не сохраняется в состоянии аналитики и не передаётся во внешние сервисы.

**Independent Test**: Импорт папки с вложенными папками запусков и повторными копиями одного лога даёт одинаковый набор событий без дублей.

**Acceptance Scenarios**:

1. **Given** успешный однозначно сопоставленный лог TE40, **When** папка импортирована, **Then** подтверждённые события доступны в модуле аналитики.
2. **Given** архив, неизвестный формат, неоднозначный IP либо другой производитель, **When** папка импортирована, **Then** события не создаются, а причина исключения видна.
3. **Given** два файла с одним и тем же событием, **When** импорт завершён, **Then** событие учитывается один раз с указанием источников.

### User Story 2 — Раздельная аналитика (Priority: P1)

Администратор видит две самостоятельные области: подтверждённые перезагрузки терминалов и зафиксированные отключения питания. Для каждой доступны количество, время, устройство, IP, локация и адрес, распределение по датам/часам и текущие фильтры. Запуски без подтверждённой причины показываются отдельно и не прибавляются к перезагрузкам.

**Independent Test**: Синтетический лог с запуском, двумя строками одной перезагрузки и одним отключением даёт по одному событию каждого подтверждённого типа.

**Acceptance Scenarios**:

1. **Given** рядом с запуском есть явный признак reboot, **When** анализ построен, **Then** засчитывается одна подтверждённая перезагрузка.
2. **Given** есть явная запись об отключении, **When** анализ построен, **Then** она попадает только в область отключений питания.
3. **Given** есть запуск без признака reboot, **When** анализ построен, **Then** он показан как запуск с неустановленной причиной, но не увеличивает счётчик перезагрузок.

### Edge Cases

- Внешний файл может быть недопустимым как XML, хотя содержит пригодные отдельные строки; разбор не должен исполнять XML или зависеть от корректности всего дерева.
- Лог может содержать секреты и личные сведения: в производном событии остаются только тип, локальное время терминала, привязка к SR и ссылка на файл/строку.
- Время без часового пояса остаётся локальным временем устройства; нельзя смешивать его с UTC без явного преобразования.
- Запись об отключении не доказывает внезапную потерю питания или причину отключения.
- Более новые прошивки и TE30/50/60 допускаются только при совпадении проверенной схемы строки; неизвестный вариант не создаёт события.
- TE20 использует отдельную схему строки. После контролируемого web-reboot подтверждена пара `reboots` и нового `System boot`; другие boot остаются неизвестными. После отдельного штатного выключения подтверждена запись web-команды отключения, но она не доказывает аварийную потерю питания.

## Requirements

### Functional Requirements

- **FR-001**: Импорт MUST обрабатывать вложенные папки и повторные файлы без ложных дублей.
- **FR-002**: События MUST строиться только для exact Huawei TE20/30/40/50/60 при единственном точном IP в актуальной SR и модельной схеме строки.
- **FR-003**: Подтверждённая перезагрузка MUST требовать явного признака reboot и связанного с ним запуска; один запуск MUST давать максимум одно событие.
- **FR-004**: Отключение питания MUST требовать собственной явной записи и MUST не трактоваться автоматически как аварийная потеря электричества.
- **FR-005**: Неустановленная причина запуска MUST отображаться отдельно, без прибавления к подтверждённым перезагрузкам.
- **FR-006**: Аналитика MUST показывать события, распределения и контекст SR отдельно от существующего правила Extron.
- **FR-007**: Сырые строки логов, credentials и токены MUST не входить в state, JSON-опросы, резервные копии или Git; импорт MUST работать локально.
- **FR-008**: Записи `System boot` TE20 MUST считаться подтверждённой перезагрузкой только при предшествующей проверенной web-записи `reboots` в пределах двух минут; остальные показываются как запуски с неустановленной причиной. Только проверенные записи `shut ... down ... terminal` из web либо модуля пульта MUST отмечать штатную команду отключения с указанием способа, не доказывая аварийную потерю питания.
- **FR-009**: Длинная пауза между записями MAY давать отдельное «Предполагаемое отключение питания» только при последующем маркере запуска без подтверждённого reboot/выключения. Порог MUST настраиваться, по умолчанию 60 минут; недостоверные скачки часов и паузы без последующего запуска MUST исключаться. Время запуска MUST не представляться как точный момент потери питания.
- **FR-010**: Предполагаемые события MUST иметь низкую достоверность и отдельные счётчики/таблицы; подтверждённые перезагрузки и отключения от них не меняются. Источник должен сохранять только метаданные интервала, без сырых строк.

### Key Entities

- **Лог-файл**: локальный путь в выбранной папке, точный IP из имени, модель и статус сопоставления.
- **Событие**: тип, локальное время устройства, исходный файл и номер строки, точный deviceId и контекст SR.
- **Покрытие**: число проверенных, исключённых и неоднозначных файлов и запусков.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Повторный импорт того же набора файлов не меняет количество событий.
- **SC-002**: В 100% синтетических случаев без явного reboot-маркера запуск не увеличивает счётчик подтверждённых перезагрузок.
- **SC-003**: В 100% синтетических случаев неизвестной схемы и неоднозначного IP события не создаются.
- **SC-004**: Импорт одного большого файла обрабатывается последовательно без хранения полного содержимого в состоянии приложения.
- **SC-005**: В 100% синтетических TE20-логов команды reboot/restart без подтверждённого последующего события не увеличивают счётчик перезагрузок.

## Assumptions

- Администратор подтвердил: неясные запуски не считаются перезагрузками, а отображаются отдельно.
- Для TE30/TE50/TE60 правило предварительное до сравнения их реальных логов с подтверждённым TE40-форматом.
- Анализ причин аварийной потери электропитания и экспорт отчёта не входят в этот этап.
