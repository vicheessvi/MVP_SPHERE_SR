# Data Model

- `LogImportRow`: существующие локальные метаданные файла, точный IP, формат и статус сопоставления с текущей SR.
- `TeLogMarker`: тип `system_start | reboot_marker | power_off`, локальное время устройства, номер строки; без сырого сообщения.
- `TeLogEvent`: `confirmed_reboot | power_off | unknown_start`, deviceId, локальное время, файл и номер строки, модель/локация/адрес по актуальной SR, идентификатор правила.
- `power_off` TE20 дополнительно содержит `shutdownMethod: web | remote_control`; отсутствие способа для иных моделей не подменяется догадкой.
- Для exact TE20 действует отдельная версия правила `huawei-te20-log-v1`: только пара web `reboots` → новый `System boot` даёт `confirmed_reboot`; другие boot — `unknown_start`, web/пульт `shut ... down ... terminal` дают штатное `power_off`.
- `BootGap`: локальное начало/конец паузы, длительность, признаки известной команды и аномалии часов; сырые сообщения не включаются. Только для `unknown_start` при пороге 60 минут (настраивается 15–10080) создаётся представление `suspected_power_loss`, `confidence=low`; сохранённый индекс запуска не меняется. Пауза более 30 дней считается аномалией качества и не классифицируется.
- `Coverage`: число прочитанных, исключённых, неоднозначных файлов/строк и событий.
- Дубликаты события из повторных выгрузок объединяются по exact deviceId + тип + локальное время; исходные файлы не меняются.
