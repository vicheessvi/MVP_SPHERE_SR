# Research: Аналитика перезагрузок устройств

## 1. Доказуемая нижняя граница

Правило `reboot-min-v1` подтверждает максимум одно событие на соседнюю пригодную пару и называет итог «минимум подтверждённых перезагрузок». Одно значение uptime показывает только последний запуск; несколько запусков внутри интервала неразличимы. Простое падение uptime отвергнуто: оно даёт ложную точность и пропускает reboot при длинном интервале.

## 2. Интервальное правило

Для наблюдения используются диапазоны времени и uptime с погрешностью. `Boot₂ = [T₂.low - U₂.high, T₂.high - U₂.low]`. Событие подтверждается только если `Boot₂.low > T₁.high` и `Boot₂.high <= T₂.high`. Равенство границ, перекрытие погрешностей и обратная хронология дают `unknown`, не событие.

## 3. Поддерживаемые uptime-поля

Основной источник — конечное неотрицательное число `webBlocks.Device Status.Uptime Seconds`. Legacy fallback — только строгая строка `Uptime` формата `[Nd ]Hh Mm Ss`. Если оба значения есть и расходятся, наблюдение исключается. Произвольные строки и device Date/Time не используются.

## 4. Provenance времени наблюдения

Автоматический JSON передаёт top-level `uptimeObservedAt`, зафиксированный adapter непосредственно после чтения uptime, как основной `observationAt`; `capturedAt` начала опроса остаётся совместимым fallback с явным source. Для legacy ручного JSON доступный timestamp импорта используется только как ограниченная оценка с пользовательской пометкой; отсутствие времени даёт insufficient data. Существующий `PollingResult.capturedAt` не переопределяется. Device Date/Time и имя файла не используются как скрытые замены времени чтения uptime.

## 5. Полная история до фильтрации

Сначала одним проходом строятся истории всех устройств и события между соседними наблюдениями; фильтры применяются к готовым событиям. Иначе событие у начала периода потеряет предыдущее наблюдение. `Map` и одна сортировка на устройство дают `O(n log n)`.

## 6. Дубликаты и одинаковые timestamps

Точный повтор evidence коллапсируется только в производном индексе. Один timestamp с различающимися значениями считается неоднозначным и не упорядочивается по id. Поздняя загрузка перестраивает соседние пары.

## 7. Организационные поля

IP берётся из точного сопоставления результата и устройства; локация и адрес — из актуальной SR и подписываются «по актуальной SR». Исторический адрес не восстанавливается без версионированной SR.

## 8. Графики

Используются семантические HTML-списки и `progress` с точными подписями для дат, часов, устройств, локаций и адресов. Top-N ограничивает только представление; итоги и максимумы используют полный срез. Внешние зависимости не добавляются.
