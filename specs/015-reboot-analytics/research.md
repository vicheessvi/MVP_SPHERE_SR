# Research: Аналитика перезагрузок устройств

## 1. Расчёт из каждого файла Extron

Правило `extron-reboot-v2` рассчитывает последний запуск непосредственно из одного файла: `webBlocks.Device Status.Date − webBlocks.Device Status.Uptime`. Это соответствует подтверждённому пользовательскому примеру Extron. Один пригодный файл создаёт одно расчётное событие; несколько запусков между опросами, не ставших последним запуском ни в одном файле, остаются неразличимы.

## 2. Объединение повторных наблюдений

Опросы одного и того же периода работы дают одинаковое расчётное время запуска. Значения с расхождением не более пяти секунд объединяются; большее расхождение создаёт следующее событие. Допуск покрывает секундное разрешение и небольшую разницу чтения полей.

## 3. Поддерживаемые uptime-поля

Основной источник — конечное неотрицательное число `webBlocks.Device Status.Uptime Seconds`. Legacy fallback — только строгая строка `Uptime` формата `[Nd ]Hh Mm Ss`. Если оба значения есть и расходятся, наблюдение исключается. Произвольные строки и device Date/Time не используются.

## 4. Provenance времени наблюдения

Основной источник Extron — строгая строка `Device Status.Date` вида `Mon, 01 Jun 2026 09:56:35`. Она трактуется как локальные часы устройства. Если `Time Zone` недоступен, ISO используется как нейтральное wall-clock представление и UI не переводит его в часовой пояс компьютера. `uptimeObservedAt`, `capturedAt` и timestamp файла остаются явно помеченными fallback только при отсутствии Date.

## 5. Полная история до фильтрации

Сначала одним проходом вычисляются boot timestamps, затем они группируются по устройству и кластеризуются. Фильтры применяются к готовым событиям. `Map` и одна сортировка на устройство дают `O(n log n)`.

## 6. Дубликаты и одинаковые timestamps

Точный повтор evidence коллапсируется только в производном индексе. Один `Device Status.Date` с различающимися uptime считается неоднозначным. Поздняя загрузка полностью перестраивает непостоянные кластеры без дублей.

## 7. Организационные поля

IP берётся из точного сопоставления результата и устройства; локация и адрес — из актуальной SR и подписываются «по актуальной SR». Исторический адрес не восстанавливается без версионированной SR.

## 8. Графики

Используются семантические HTML-списки и `progress` с точными подписями для дат, часов, устройств, локаций и адресов. Top-N ограничивает только представление; итоги и максимумы используют полный срез. Внешние зависимости не добавляются.
