# Research: CloudLink 300 log events

- Existing exact Bar 300/Box 300/Box 600 log collection is confirmed and produces XML `LogModule`; no new network contract is needed.
- Authorized read-only in-memory Bar 300 full-log scans completed without saving the file or raw lines. Before a user-controlled web restart, the ~41 MB journal contained 12 `LOG_MOD_MC` `System boot` occurrences; afterward it contained 13. Generic `reboot`/`restart` lines appeared one second earlier, but the same pair accompanied earlier starts, so it cannot distinguish a deliberate restart from a start after shutdown. No validated explicit web/remote reboot-command pattern was found.
- Bar 300 log lines start with a bracketed timestamp containing fractions and an offset, followed by two bracketed fields and `LOG_MOD_*`. They do not use the TE line order. The parser is bound to this observed structural format, with device-local seconds retained for existing analytics.
- Several gaps precede boot, including a long gap. Silence is not proof of lost power, only a low-confidence observation after a next boot; clock jumps and known actions suppress it.
- The existing TE and Huawei 310 parsers use separate model-specific signatures. The 300 series needs its own parser and rule version.
- Box 300/600 export and settings were validated earlier by the administrator. On 2026-11-15 the administrator separately reported checking the event analytics on both models and asked to include them. The agent did not receive raw Box logs; this is a user-validation boundary, not independent agent inspection. Exact model/format/IP gates remain mandatory.
- The controlled Bar 300 restart is observed but its cause marker remains ambiguous. A separate user-controlled web shutdown/start cycle added a 14th `System boot` and one distinct `LOG_MOD_WEB` command with the safe signature `web user shut down terminal` between the last two starts. The strict parser expression matched exactly one such command in the full journal; it was absent from the earlier restart window. This confirms a Bar 300 *normal web shutdown* and subsequent start, not an emergency power loss or a reboot. Box 300/600 use this rule after the administrator's separate operational validation; no Box log contents were published.
- End-to-end in-memory verification with the production JavaScript parser on the complete device log returned 15 safe markers: 14 boots and one web-shutdown action. Event derivation returned 13 unknown starts, one confirmed normal shutdown and one start after shutdown. The raw XML was not written to a file.
