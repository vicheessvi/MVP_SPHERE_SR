# Feature Specification: Сбор логов Huawei CloudLink 300

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-11-13

**Status**: Реализовано; администратор подтвердил формирование опросов и логов всех трёх моделей

**Input**: Добавить сбор логов Bar 300, Box 300 и Box 600 в существующий автоматический опрос, используя подключённый Bar 300 для проверки.

## User Scenarios & Testing

### User Story 1 — Получить лог Bar 300 (Priority: P1)

Администратор выбирает сбор логов в существующем плане опроса точного Bar 300, указывает папку и запускает задание. Оригинальный файл журнала появляется в папке времени запуска, а интерфейс показывает безопасный результат сохранения.

**Independent Test**: В режиме только логов создаётся один сохранённый оригинал Bar 300 и не создаётся JSON-опрос устройства; в совместном режиме сохраняются оба результата.

**Acceptance Scenarios**:

1. **Given** подтверждённый Bar 300 и выбранная папка логов, **when** запущен сбор, **then** журнал сохраняется только в выбранной папке и доступен существующему ручному импорту.
2. **Given** режим только логов, **when** задание завершено, **then** JSON устройства не сохраняется, а возможность продолжения задания сохраняется.
3. **Given** ошибка экспорта или сохранения, **when** устройство завершено, **then** ошибка показана без содержимого журнала и остальные устройства продолжаются.

### User Story 2 — Подготовить Box 300 и Box 600 (Priority: P2)

Для точных Box 300 и Box 600 сбор логов использует проверенную схему семейства и собственную проверку модели каждого устройства. Администратор подтвердил успешное формирование их опросов и логов; новые результаты сбора имеют подтверждённый статус.

**Independent Test**: Синтетическая проверка каждой модели блокирует чужую модель и неподходящий web-интерфейс; эксплуатационная проверка администратора подтверждает создание файлов обеих Box.

**Acceptance Scenarios**:

1. **Given** точный Box и совпадающие проверенные признаки экспорта, **when** включён сбор логов, **then** оригинал сохраняется с подтверждённым пользователем статусом.
2. **Given** отсутствие нужного признака или неопределённый ответ, **when** включён сбор логов, **then** результат явно показывает, что контракт требует подтверждения, без ложного файла.

### Edge Cases

- Лог может содержать внутренние адреса, имена и секреты; содержимое не включается в JSON, API-статус, аналитику, резервную копию или Git.
- Файл может быть большим: приложение не создаёт скрытую серверную копию и передаёт его потоково до выбранной папки.
- Ошибка одного файла не останавливает опрос остальных устройств.
- Оригинал не распаковывается, не исполняется и не превращается в события без отдельного проверенного формата.
- Самоподписанный сертификат допустим только по явному разрешению текущего запуска; иначе сетевое чтение отклоняется.

## Requirements

### Functional Requirements

- **FR-001**: Сбор MUST запускаться существующей независимой опцией логов в режимах только логи и JSON+логи.
- **FR-002**: Экспорт MUST выполняться только после точной проверки модели и устойчивого идентификатора, при подтверждённой схеме текущего интерфейса.
- **FR-003**: Оригинал MUST сохраняться только в выбранной администратором папке запуска; скрытые копии запрещены.
- **FR-004**: Статус MUST быть безопасным и не содержать содержимое лога, пароли, cookie или токены.
- **FR-005**: Box 300/600 MUST сохранять отдельные модельные проверки; статус сбора становится подтверждённым только после отдельной эксплуатационной проверки обеих моделей.
- **FR-006**: Ручной импорт папки логов MUST продолжать показывать существующие метаданные без новой событийной классификации.
- **FR-007**: Неподтверждённый экспорт MUST завершаться явным безопасным отказом без угадывания URL или обходного протокола.

### Key Entities

- **LogArtifact**: выбранный локальный оригинал, имя файла, точная модель, IP и время загрузки.
- **LogCollectionResult**: безопасный статус сохранения и степень подтверждения модели без содержимого.

## Success Criteria

### Measurable Outcomes

- **SC-001**: На проверенном Bar 300 один успешный запуск сбора даёт один импортируемый оригинал в выбранной папке.
- **SC-002**: Во всех трёх режимах вывода сохраняется ожидаемое число файлов: только JSON, только лог либо оба.
- **SC-003**: В 100% тестов чужой модели, изменённой схемы и ошибки сохранения не возникает ложного лога или внешней передачи.
- **SC-004**: Оба Box проходят синтетические модельные проверки; администратор подтвердил успешное формирование опросов и логов на каждой модели.

## Assumptions

- Используются существующие план, выбранная папка, потоковая запись, подтверждение сохранения и ручной импорт; новый модуль интерфейса не нужен.
- Первый этап ограничен оригиналом и метаданными. Разбор событий журнала — отдельная задача после проверки содержимого.
- Сходство меню семейства не является достаточным доказательством совпадения сетевого экспорта; неизвестный способ отмечается как требующий подтверждения.
