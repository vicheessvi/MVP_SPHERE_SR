# Feature Specification: Общий опрос Huawei TE30, TE40, TE50 и TE60

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-09-05

**Status**: In progress — ожидается проверка на реальных TE30, TE50 и TE60

**Input**: Проверить гипотезу, что подтверждённый алгоритм Huawei TE40 подходит Huawei TE30, TE50 и TE60, и объединить четыре модели в один безопасный алгоритм опроса.

## User Scenarios & Testing

### User Story 1 — Один алгоритм для TE30, TE40, TE50 и TE60 (Priority: P1)

Администратор МЦТП включает TE30, TE40, TE50 и TE60 в один план. Все четыре модели направляются в один алгоритм, который сохраняет прежние группы JSON: идентификация, прошивка, время, сеть и возможности.

**Independent Test**: Синтетические TE30, TE40, TE50 и TE60 проходят одинаковую последовательность входа и чтения, возвращая собственную подтверждённую модель.

**Acceptance Scenarios**:

1. **Given** актуальная SR содержит любую из четырёх моделей, **When** формируется план, **Then** устройство помечается как поддерживаемое одним общим алгоритмом.
2. **Given** web-контракт модели совместим, **When** опрос завершён, **Then** итоговый JSON имеет прежнюю структуру и содержит фактическую ожидаемую модель.
3. **Given** смешанный план TE30/TE40/TE50/TE60, **When** выполняется опрос, **Then** результаты не смешиваются между IP и сохраняются последовательно.

### User Story 2 — Проверка модели до и после входа (Priority: P1)

До передачи учётных данных система проверяет объявленную терминалом модель, а после входа подтверждает её данными версии. Несовпадение не считается совместимостью.

**Independent Test**: План одной поддерживаемой модели, получивший pre-auth признак другой модели или post-auth неизвестную модель, завершается безопасной ошибкой; в первом случае пароль не отправляется.

**Acceptance Scenarios**:

1. **Given** цель плана обозначена одной из четырёх моделей, **When** до входа устройство сообщает другую модель, **Then** учётные данные не передаются.
2. **Given** pre-auth модель совпала, **When** данные версии после входа не содержат ожидаемую модель, **Then** результат отклоняется как неподтверждённая схема.
3. **Given** устройство обозначено как TE20 или неизвестная Huawei, **When** выполняется план, **Then** сетевой запрос не начинается.

### User Story 3 — Проверка гипотезы на реальных моделях (Priority: P2)

Администратор запускает адресный опрос доступных TE30, TE50 и TE60 из актуальной SR и передаёт полученные локальные JSON для сверки совместимости. TE40 уже подтверждён ранее.

**Independent Test**: Каждая доступная новая модель с разрешённым локальным TLS-исключением возвращает подтверждённый JSON либо точную безопасную стадию несовместимости без раскрытия секретов.

## Edge Cases

- Строка модели может содержать дополнительные обозначения семейства, но должна содержать отдельный токен ожидаемой модели.
- TE30, TE50 или TE60 могут иметь другую версию firmware и неполный набор разрешённых ресурсов; частичные ресурсы сохраняются только при подтверждённых модели и идентичности.
- Активная интерактивная сессия, неизвестный bundle, таймаут и ошибка TLS сохраняют прежнее fail-closed поведение.

## Requirements

- **FR-001**: TE30, TE40, TE50 и TE60 MUST использовать один transport и один набор разрешённых read-only действий.
- **FR-002**: Каталог MUST распознавать только точные модели TE30, TE40, TE50 и TE60 как поддерживаемые этим transport.
- **FR-003**: До передачи credentials система MUST подтвердить токен ожидаемой модели в pre-auth ответе.
- **FR-004**: После входа система MUST повторно подтвердить ожидаемую модель по версии устройства и наличие serial или валидного MAC.
- **FR-005**: Несовпадение pre-auth модели MUST завершаться до запроса сертификата/пароля.
- **FR-006**: TE20 и все остальные Huawei MUST оставаться `protocol_required` без сетевой попытки.
- **FR-007**: Структура результата, redaction, exact-IP allowlist, TLS, timeout, ACK и локальное сохранение MUST не измениться.
- **FR-008**: Справочник MUST различать подтверждённый TE40 и TE30/TE50/TE60, для которых итоговая проверка на реальных устройствах ещё ожидается.

## Key Entities

- **Huawei TE target**: точная модель TE30, TE40, TE50 или TE60, exact IP из плана и ожидаемый model token.
- **Pre-auth identity**: безопасное объявление типа терминала до передачи credentials.
- **Post-auth identity**: модель версии плюс serial или валидный MAC.

## Assumptions

- Официальный Huawei HTTP API reference V600R019C00 для TE30/TE40/TE50/TE60/TX50 подтверждает общий API family и authentication flow.
- Реальная проверка ранее выполнена только на TE40; совместимость конкретных прошивок TE30, TE50 и TE60 остаётся гипотезой до адресного запуска.
- Расширение ограничено TE30, TE40, TE50 и TE60; TX50 не включается автоматически.

## Success Criteria

- **SC-001**: Синтетические TE30, TE40, TE50 и TE60 выполняют один и тот же порядок входа и шесть разрешённых чтений.
- **SC-002**: 100% тестов несовпадения модели блокируют неверную цель; pre-auth mismatch выполняет ноль credential requests.
- **SC-003**: TE20 и неизвестная Huawei выполняют ноль сетевых запросов.
- **SC-004**: Полная Python и frontend регрессия остаётся успешной.
- **SC-005**: Реальные TE30, TE50 и TE60 либо формируют совместимый redacted JSON, либо возвращают диагностируемую безопасную стадию; критерий закрывается для каждой модели после предоставления доступной цели.
