# Feature Specification: Answer Mode Huawei TE30/40/50/60

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-11-06

**Status**: Draft

**Input**: Добавить для точной модели Huawei TE40 отдельное изменение Answer Mode по аналогии с проверенным сценарием TE20: «Не менять», «Автоматически» и «Вручную».

**Extension**: По прямому запросу администратора добавить тот же условный контракт для TE30, TE50 и TE60; эксплуатационные результаты он предоставит позже.

## Clarifications

### Session 2026-11-06

- Q: Какой режим сейчас показывает подключённый TE40 и какое первое изменение разрешено? → A: Сейчас «Вручную»; первым установить «Автоматически».
- Q: Доступен ли TE40 по прежнему адресу с прежними учётными данными? → A: Да, доступен; адрес и секреты не фиксируются в спецификации.
- Q: Можно ли принять самоподписанный сертификат и совместимый TLS для текущего TE40? → A: Да, только для этой проверки.

## User Scenarios & Testing

### User Story 1 — Выбрать режим ответа для одного TE-терминала (Priority: P1)

Администратор выбирает один точный Huawei TE30/40/50/60 по IP из актуальной выгрузки SR и указывает желаемый режим ответа. Изменение выполняется отдельно от иных задач управления и только после явного подтверждения влияния на входящие вызовы.

**Why this priority**: Нужен управляемый способ менять поведение терминала, не затрагивая остальные устройства и настройки.

**Independent Test**: Выбрать один точный TE40, установить режим, повторно проверить его в меню устройства и в результате задачи.

**Acceptance Scenarios**:

1. **Given** выбран точный TE40 с подтверждённой идентичностью и режимом «Вручную», **When** администратор выбирает «Автоматически» и подтверждает действие, **Then** изменяется только Answer Mode, повторное чтение подтверждает «Автоматически».
2. **Given** выбран точный TE40 с режимом «Автоматически», **When** администратор выбирает «Вручную» и подтверждает действие, **Then** повторное чтение подтверждает «Вручную».
3. **Given** выбран «Не менять», **When** строится план опроса, **Then** задача изменения Answer Mode не создаётся.

### User Story 2 — Безопасный отказ при неопределённости (Priority: P2)

Администратор получает понятный результат, если модель, текущий режим или подтверждение результата не совпадают с ожидаемым контрактом. Обычный опрос по-прежнему не изменяет настройку.

**Why this priority**: Ошибочная запись может непреднамеренно включить автоматический ответ на входящие вызовы.

**Independent Test**: Смоделировать неизвестное значение, смену модели, ошибку чтения и несовпадение после записи; проверить отсутствие лишних записей.

**Acceptance Scenarios**:

1. **Given** текущий режим невозможно однозначно определить, **When** запускается задача, **Then** настройка не изменяется, причина отказа видна в результате.
2. **Given** после единственной записи повторное чтение не подтвердило целевой режим, **When** формируется результат, **Then** задача отмечена неуспешной, а прочие параметры не записываются.

### Edge Cases

- Режим уже совпадает с целевым: запись не отправляется.
- TE20 и модели с суффиксом не наследуют новое действие; TE30/TE50/TE60 предварительны до реальной проверки.
- Нельзя сочетать изменение Answer Mode с отключением портов или другими задачами записи.
- Закрытие браузера после попытки записи не должно автоматически повторять её без проверки администратором.

## Requirements

### Functional Requirements

- **FR-001**: План MUST предлагать для точных TE30/40/50/60 три варианта Answer Mode: «Не менять», «Автоматически», «Вручную».
- **FR-002**: Изменение MUST быть доступно только для одного точного TE30/40/50/60, выбранного по IP из подтверждённой актуальной SR.
- **FR-003**: Перед выполнением MUST требоваться явное подтверждение влияния на входящие вызовы.
- **FR-004**: Система MUST проверять точную модель и устойчивую идентичность до изменения, читать текущий режим, при необходимости менять только его один раз и повторно проверять результат.
- **FR-005**: При неизвестном контракте или значении система MUST отказаться от записи и указать безопасный статус; другие модели не должны получать это действие.
- **FR-006**: Обычный опрос MUST оставаться только читающим; учётные данные не должны попадать в план, результат или постоянное хранилище.
- **FR-007**: Тот же выбор MUST предоставляться для exact TE30/TE50/TE60 только при совпадении текущего web-контракта; статус этих моделей предварительный до отдельной проверки на каждом устройстве.

### Key Entities

- **Выбор Answer Mode**: точное устройство, целевой режим либо отсутствие изменения, подтверждение администратора.
- **Результат действия**: исходный и итоговый режимы, статус применения и безопасная причина отказа при неуспехе.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Для каждого из двух направлений изменения достаточно не более одной записи в устройство; уже установленный режим не вызывает запись.
- **SC-002**: В 100% тестов неизвестной модели или ответа запись отсутствует.
- **SC-003**: В контрольной проверке на реальном TE40 итоговое значение в инструменте совпадает с меню устройства после изменения.
- **SC-004**: Пользователь может сформировать план для одного TE40 и подтвердить изменение менее чем за две минуты без изменения существующих режимов TE20.

## Assumptions

- Текущий подключённый TE40 показывает «Вручную»; первое разрешённое администратором контрольное значение — «Автоматически».
- Возврат к «Вручную» реализуется как отдельный выбор, но реальная запись в обратную сторону требует отдельной контрольной проверки.
- До подтверждения точной схемы управления TE40 любое предполагаемое соответствие внутренних кодов режимам считается предварительным, и запись блокируется.
