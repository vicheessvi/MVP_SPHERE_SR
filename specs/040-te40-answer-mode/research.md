# Research: Huawei TE Answer Mode

## Decision

Использовать только существующий exact-model HTTPS web-CGI transport. На подключённом TE40 текущая web-форма показывает пары `1 → Manual`, `0 → Automatic` и сохраняет `autoreply` как целое поле; отдельное чтение вернуло `1`, совпавшее с меню «Вручную». Контрольная запись `0` после model/identity gate и повторное чтение подтвердили «Автоматически». Реальное значение в JSON не сохранялось в репозитории.

## Boundaries

Для TE30/50/60 используется тот же общий transport только при наличии точных маркеров формы и ответе `autoreply` в {0,1}; при drift запись блокируется. Успех для этих моделей предварителен до пользовательской проверки. TE20 остаётся на собственном подтверждённом контракте. Обычный опрос только читает. Официальная документация Huawei подтверждает два пользовательских режима, но не wire-коды: https://info.support.huawei.com/network/ptmngsys/Web/tsrev_vc/cn/content/vc/43_vc_call_ep_fail/vc_call_ep_fail_edesk002.html

Позднее администратор отдельно подтвердил оба направления на TE30/50/60, а также TE40, как при выборе одного IP, так и в массовом режиме. Новые write-результаты TE-family имеют `confirmed_user_validation`; прежние ограничения model/identity/bundle/schema и отдельный контракт TE20 остаются.

## Alternatives

Перенос TE20 действия без модельного и bundle gate отклонён из-за риска неверного автоматического ответа; массовая запись отклонена из-за риска для входящих вызовов.
