# Feature 062 — независимое от инициатора выключение ВКС

Дата: 2026-11-24. Ветка: codex/secure-local-runtime. Статус: implemented for supported Huawei; Polycom deferred by administrator.

## Specify / clarify

Администратор нашёл в журналах пропущенные выключения от контроллера и утвердил
следующее предложение: регистрировать команду Shut down всего терминала без
требования Web/пульта, исключать ошибки/отмену/настройки/компоненты, не угадывать
инициатора, не удваивать событие, учитывать выключение при следующем запуске.
Правило применяется к общей аналитике, нерабочему времени, карте и XLSX.

Новая команда сети/изменения настроек не требуется. Источники только явно
импортированные журналы. Старые raw-файлы, SR и JSON не переписывать.

## US1 — общая семантика выключения (P1)

Для известных форматов Huawei TE20/30/40/50/60, Bar/Box310/610 и Bar/Box300/600
положительный маркер команды выключения терминала даёт один power_off независимо
от модуля/инициатора. Слово success не обязательно, явный отказ/ошибка/отмена
исключаются. Простое упоминание shutdown в настройках/меню, у интерфейса или
компонента не становится выключением устройства. Неоднозначная запись остаётся
неизвестной, не нормализуется в подтверждённое выключение.

## US2 — версия и продолжение перепроверки (P1)

Новый parser ruleset исключает reuse старых результатов. При обновлении правил
администратор заново выбирает полную прежнюю папку логов. Перепроверка потоковая,
до двух Worker, 1 МиБ чтение, checkpoints по версии/SR/файлу. После сбоя готовые
новые результаты восстанавливаются без чтения тела; старые checkpoints не
выдаются за новые. Неполная/ошибочная перепроверка не подменяет опубликованную
аналитику. До успешного finish старая ревизия доступна. Есть прогресс, скорость,
отмена и явное сообщение об обновлении правил.

## US3 — другие семейства (отдельный будущий этап)

Смысл правила общий для всех ВКС. Но Polycom TGZ и неизвестные форматы не получают
выдуманный парсер. Для активации требуются образец, проверяемая схема времени и
идентичности, безопасный bounded разбор архива и контрольный тест. Запрошен путь
к образцу Polycom и к журналу с пропущенной командой. До получения образца
Polycom остаётся metadata-only, ограничение видно в UI/документации.
Уточнение администратора: образец предоставить невозможно; Polycom RPG отдельно
подключит позже, тогда будет выполнен анализ его журналов. Этот этап явно
исключён из текущей реализации Huawei, не объявляется проверенным.

## Acceptance

- Текст команды терминала, регистр/пробелы, controller/API/unknown module,
  отсутствие кнопки пульта и дубли одного события — положительные тесты.
- Failed/denied/cancelled, отрицание, меню/таймер/настройки/компонент, sleep,
  невалидное время, неполный XML — отрицательные тесты.
- Старые модели/IP/SR gates, границы confidence и раздельные предположения не
  ослабляются. Последующий известный запуск не считается новым подтверждённым
  reboot из-за отсутствия прежнего узкого маркера.
- Версии registry/checkpoints, остановка/продолжение и atomic publish проверяются
  синтетически; UI и все агрегаты видят новое событие без отдельной сети.
- Поддержка неизвестного формата не объявляется завершённой без evidence.

## Validation

261 Python + 257 JavaScript tests passed; shared suite covers all 11 Huawei models.
Реальный изолированный Python/SQLite/Chrome сценарий обновления браузера после
первого checkpoint подтвердил сохранение старой аналитики и восстановление
готового файла без повторного чтения тела; после продолжения прочитан только
второй файл, команда включена в power_off. Проверены offhours/отдельный power
export, late insertion/reversible link и приоритет явного reboot. На 100 000
synthetic events публикация/links/summary 3,391 с, 208 progress updates.
Ни рабочая БД, ни реальные устройства/журналы не использовались.
