# Feature 063 — список целей и строго выбранные действия

Дата: 2026-11-24. Ветка: codex/secure-local-runtime. Статус: implemented, synthetic validation passed.

## Specify / clarify

Администратор подтвердил XLSX существующей SR-структуры списка работы с портами.
Новый список — отдельный источник целей раздела 4, не замена основной SR/БД.
Критическое правило: только устройства выбранного источника/листов/фильтра и
только явно выбранные JSON, логи, доступные изменения параметров. Содержимое
столбцов настроек не создаёт задач. Пустой выбор не запускается. При нескольких
листах требуется явный выбор одного/нескольких, не первый/все автоматически.

## US1 — цели (P1)

Явный источник SR либо загруженный XLSX; отсутствие списка/неподтверждённые листы
не дают fallback на SR. Выбранные листы перечислены до импорта и в плане.
Пустые/неверные выбранные листы, секретные колонки, неоднозначные/повторные IP
отклоняются, ничего не пропускается молча. Новая загрузка сбрасывает старые
действия и подтверждения, не запускает сеть. Основная SR/аналитика не меняется.

## US2 — действия (P1, safety invariant)

JSON-only: обычный JSON-опрос, без логов/записей. Logs-only: identity/auth/bundle
gates и экспорт логов, без полного опроса/настроек. Write-only: те же gates,
нужные pre-read/максимум одна запись/post-read, без обычного JSON и логов.
Комбинации выполняют только выбранное, сохраняя действующие ограничения write
совместимости/одного action ID/одного IP для остальных TE20 настроек. Новых
vendor API/моделей/transport не добавляется. Несовместимые выбранные write/logs
блокируются до сети, а не превращаются в другие операции.

## US3 — фиксация и продолжение (P1)

Перед запуском видны источник/листы/число целей/точные задачи и значения. Новый
plan v4 содержит explicit selectedActions, boolean collectJson/collectLogs,
managementTasks/параметры, digest источника и sourceTargetIps. Runtime сверяет
набор и membership до credentials/network. PollingJob глубоко копирует план;
последующие изменения формы его не меняют. Recovery фиксирует тот же набор и
не добавляет операции, неизвестный исход write не повторяет автоматически.

Без JSON/логов выбранная папка нужна только для видимого служебного журнала
polling-recovery.json. Он явно указан в UI, не является JSON-опросом устройства.
В журнале нет паролей/токенов. Write confirmation, TLS/admin/Origin/CSRF и
source/model/identity gates остаются обязательными.

## Acceptance

- Матрица 7 непустых комбинаций JSON/log/write; ноль задач блокируется.
- Spy request tests: невыбранные resource/config/log/write маршруты не вызываются.
- Multi-sheet: явный выбор, только выбранные строки, дубли между листами,
  неверный лист, перезагрузка файла, отсутствие source fallback и внешней записи.
- Мутация v4 флагов/actions/параметров/membership отклоняется до сети; совместимость
  старых v3 recovery сохраняется только по прежним правилам, новый список требует v4.
- UI, служебный журнал write-only, preview, reset/invalidations и resume проверены
  headless, Python/JS regressions; реальные устройства/данные не используются.
