# Research: Polycom Group settings

## Decision — использовать существующий guarded core

Обычный read-only опрос Group 310 прошёл с точной моделью и устойчивым идентификатором. Первичная попытка остановилась на недоверенном сертификате до credentials; администратор разрешил принять его только в текущем исследовании. Production по умолчанию продолжает проверять TLS. Четыре точных wrappers и model routing уже существуют; HTTP fallback для Group 300 запрещён. Альтернатива «новый transport» отклонена как дублирование и расширение сетевой поверхности.

## Decision — только узкие имена из текущего bundle

После проверок модели/идентичности исследованы текущие `main.js` и объявленный им `data/settingdata.json`, без сохранения ответов. Web-формы связывают девять групп полей с конкретными config FQ names; существующий `POST /rest/config` с `names:[...]` проверен на отдельных разрешённых ключах. Ответы имеют `vars` с точным именем и строковым значением. Второй NTP-адрес формируется подтверждённым правилом `instanceName:"1"`, добавляющим `1` к последнему сегменту. Широкий запрос и соседние поля с паролями, SNMP community, адресами trap-target не разрешены.

Схема и диапазон значений должны быть проверены для каждого поля отдельно; на неподтверждённой прошивке — `protocol_required` либо `unavailable`. Группы: Telnet, HTTPS-only, SNMP service + v2, automatic update polling, два answer mode, time-server mode/primary/secondary, SSH, long-press action; Wi-Fi не экспонируется в данной серии. Текущие значения устройства не записаны в исследовательские файлы.

Первая последовательная сверка завершена: администратор подтвердил, что код `False` у `Enable Telnet Access` совпадает с выключенным пунктом меню Group 310. Для этого точного модельного контракта поле Telnet получает `confirmed_user_validation`; остальные поля пока проверяются отдельно.

## Decision — не расширять смысл параметров

Вторая последовательная сверка завершена: после первоначального противоречивого ответа администратор уточнил, что выключенный `Restrict to HTTPS` означает разрешённый HTTP. Снимок меню показал отдельные `Enable Web Access` и `Web Access Port`; повторное узкое чтение подтвердило точные имена этих двух параметров в текущем bundle. Итоговый факт HTTP требует три поля и описывает только настройку web-доступа, не TCP listener. `SNMPv2` требует и `versiontwo`, и `enabled`. На этом же снимке подпись `Enable Legacy API Over SSH` показала, что её нельзя автоматически называть общей службой SSH. Длительное нажатие кнопки отбоя не равно режиму сна. Точное толкование кодов NTP/питания и отображение фактов сверяются с администратором по очереди. На этом этапе Group 500/700 получили условный общий reader, а Group 300 оставался предварительным; позднейшее подтверждение администратора зафиксировано ниже.

Третья сверка: на присланном экране `Enable SNMP Access` выключен и новый узкий опрос подтвердил это; поэтому SNMPv2 не активен. Администратор сообщил, что выбор v2c в текущем меню не показан. Отдельный машинный флаг версии 2 при этом существует, поэтому нельзя делать вывод «SNMPv2 отсутствует/не поддерживается»; корректный аудиторский факт — «отключён при выключенной службе». Для этого факта Group 310 получено пользовательское подтверждение; сам флаг хранится отдельно как диагностическое основание, не как доказательство активного протокола.

Четвёртая сверка: администратор подтвердил, что `Automatic Software Updates` выключено, когда узкий машинный код `softupdate.pollingenabled` имеет значение `False`. Это подтверждает read-only бинарное толкование поля Group 310, не утверждая ничего о факте ранее выполненного обновления.

Пятая сверка: администратор подтвердил отдельные машинные значения `Yes` для одноточечного и `No` для многоточечного автоответа в соответствующих пунктах Call Settings. Группу нельзя сводить к одному бинарному состоянию.

Шестая сверка: администратор подтвердил режим Time Server `Manual`, наличие основного адреса и отсутствие дополнительного, как показало узкое чтение. Второй адрес читается по подтверждённому `instanceName:"1"`; имена серверов не выводились в диагностику или исследовательские файлы.

Седьмая сверка: администратор подтвердил отсутствие пункта Wi‑Fi в web-меню Group 310. Существующий `not_exposed` сохранён; он не подменяется утверждением о сетевом радиоинтерфейсе.

Восьмая сверка: администратор подтвердил, что на Group 310 показан только пункт `Enable Legacy API Over SSH`; отдельного `Enable SSH Service` в меню нет. Машинный код этого пункта прочитан, но он не доказывает включение всей службы SSH. В JSON это разные понятия: признак Legacy API подтверждён, статус SSH service остаётся неизвестным.

Девятая сверка: администратор подтвердил, что машинный код `Power_Off` соответствует действию `Hung-up Button Long Press → Power Off`. Это не содержит информации о спящем режиме терминала; он остаётся неизвестным.

После поэтапной ручной сверки выполнен полный read-only опрос Group 310 действующим адаптером в памяти. Все девять групп дали ожидаемые статусы, ошибка отдельного чтения не обнаружена; идентичность и exact модель подтверждены. NTP-адреса, учётные данные и сырые ответы не сохранялись в проект и не выводились. Контракт Site name не менялся и остаётся под прежними регрессионными тестами.

Новые настройки Group 300/500/700 реализованы тем же guarded reader условно по собственным exact model gates и текущим bundle markers. Администратор 2026-11-15 отдельно сообщил об успешной проверке новых полей каждой из трёх моделей на рабочих устройствах. Новые успешные результаты теперь получают `confirmed_user_validation`; прежние импортированные файлы с `provisional_user_validation` сохраняют исходный статус и в XLSX остаются «Требует проверки». Агент не получил сырые журналы или JSON этих трёх проверок. У Group 300 прежний случай HTTPS-несовместимой прошивки остаётся отдельным ограничением, HTTP fallback не добавлен.
