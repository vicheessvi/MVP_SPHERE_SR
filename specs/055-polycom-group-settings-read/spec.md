# Feature Specification: Новые параметры опроса Polycom Group

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-11-15

**Status**: Дополнение SSH: основной `Enable SSH Service` условен до проверки прошивки с этим пунктом; резервный путь подтверждён на Group 310

**Input**: На подключённом Polycom RealPresence Group 310 проверить и добавить в обычный опрос девять групп настроек из общей задачи; подготовить общий read-only контракт для exact Group 300/310/500/700 без снятия точных модельных ограничений.

## User Scenarios & Testing

### User Story 1 — Получить фактические настройки Group 310 (Priority: P1)

Администратор запускает обычный опрос Group 310 и видит фактические значения Telnet, HTTP/HTTPS-only, SNMPv2, автообновления, двух режимов автоответа, NTP, Wi-Fi, SSH и заданного действия кнопки питания. Site name продолжает браться из System Name. Каждое значение указывает источник и отдельно показывает «неизвестно», если чтение не доказано.

**Independent Test**: Сверить каждое прочитанное значение с тем же полем web-меню подключённого Group 310; неподтверждённые поля остаются неизвестными, опрос не меняет устройство.

**Acceptance Scenarios**:

1. **Given** доступный exact Group 310 и разрешённая сессия, **When** выполняется опрос, **Then** в результате есть отдельные статусы всех девяти групп параметров, а подтверждённые значения совпадают с меню.
2. **Given** SNMPv2 указан как разрешённая версия, но служба SNMP выключена, **When** формируется результат, **Then** SNMPv2 не объявляется работающим.
3. **Given** неизвестный код, отсутствие поля или ошибка одного чтения, **When** формируется результат, **Then** только это поле остаётся неизвестным, без подмены на «отключено» и без потери прочих полей.
4. **Given** прошивка с видимым `Enable SSH Service`, **When** выполняется опрос, **Then** SSH определяется по нему; `Enable Legacy API Over SSH` не заменяет успешный основной источник.
5. **Given** прошивка без `Enable SSH Service`, но с видимым `Enable Legacy API Over SSH`, **When** выполняется опрос, **Then** SSH определяется по резервному пункту с явной пометкой основания.

---

### User Story 2 — Применить общие правила к четырём точным моделям (Priority: P2)

Администратор выбирает exact Group 300, 310, 500 или 700 в актуальной SR. Одинаковые правила чтения применяются лишь при подтверждении текущего интерфейса и идентичности именно выбранной модели. Администратор отдельно проверил новые поля всех четырёх моделей; прежние предварительные результаты сохраняют свой исторический статус.

**Independent Test**: Для каждой точной модели допустимый ответ даёт свои факты; несовпадение модели, иной вариант Group и неподдерживаемая версия интерфейса не порождают ложных значений.

**Acceptance Scenarios**:

1. **Given** точная модель и совпадающий интерфейс, **When** опрос завершён, **Then** используются общие поля с правильной моделью и её статусом проверки.
2. **Given** Group 300, доступный только по HTTP, **When** защищённый опрос по HTTPS не проходит, **Then** учётные данные не отправляются по HTTP и результат отмечает ограничение.

---

### User Story 3 — Использовать факты в существующей аналитике (Priority: P2)

Администратор импортирует новые результаты опросов и получает фактические значения в существующей таблице настроек без раскрытия паролей, ключей, SNMP community или иных соседних секретов. Исторические результаты не переписываются.

**Independent Test**: Новый валидный результат проходит точное сопоставление с SR; импорт с чужой моделью или неподтверждённым источником не добавляет прочитанных фактов.

**Acceptance Scenarios**:

1. **Given** успешный новый результат exact модели, **When** он импортирован, **Then** девять групп отображаются по тем же правилам, что и у других терминалов.
2. **Given** результат с неподтверждёнными либо секретными соседними полями, **When** он импортирован, **Then** они не попадают в таблицу, аналитику и экспорт.

### Edge Cases

- Факт HTTP зависит одновременно от `Enable Web Access`, `Restrict to HTTPS` и настроенного номера web-порта; эти поля не доказывают фактическое состояние TCP listener.
- Разрешённая версия SNMPv2 не равна включённой службе; оба признака проверяются отдельно.
- Два режима автоответа могут различаться; единый показатель не должен скрывать это различие.
- `Wi-Fi` не представлен в проверенном меню Group 310; этот факт не превращается в результат сетевого сканирования или утверждение о физическом радиомодуле.
- `Enable SSH Service` и `Enable Legacy API Over SSH` не равнозначны: второй используется только как обозначенный резервный аудиторский признак, когда первый отсутствует в текущем интерфейсе.
- Если основной пункт есть, но его значение не прочиталось или код неизвестен, резервный не подставляется вместо ошибки.
- Действие длительного нажатия кнопки завершения вызова не приравнивается к настройке сна устройства.
- Имя NTP-сервера является чувствительным инфраструктурным значением и сохраняется только в явно выбранном пользователем результате.
- Неполный ответ одного параметра не отменяет валидный результат остальных.

## Requirements

### Functional Requirements

- **FR-001**: Опрос MUST быть read-only и MUST принимать только exact Group 300/310/500/700 с проверкой выбранной модели и устойчивого идентификатора.
- **FR-002**: Результат MUST содержать девять уже принятых групп полей настроек с исходным доказательством и состоянием `read`, `unavailable`, `not_exposed` либо `protocol_required`.
- **FR-003**: Значения MUST поступать только из модельно подтверждённых источников и допустимых ответов; неизвестный код MUST NOT интерпретироваться как выключение.
- **FR-004**: HTTP MUST учитывать разрешение Web Access, ограничение HTTPS-only и настроенный web-порт, не заявляя факт открытого или закрытого TCP listener.
- **FR-005**: SNMPv2 MUST учитывать и выбранную версию, и включение службы; автоответ MUST сохранять отдельные значения для одноточечных и многоточечных вызовов.
- **FR-006**: NTP MUST отражать режим и доступные адреса серверов, не выводя их в диагностические сообщения.
- **FR-007**: Отсутствующий Wi-Fi MUST быть отмечен отдельно; SSH MUST предпочитать фактическое `Enable SSH Service` и применять `Enable Legacy API Over SSH` только при доказанном отсутствии основного пункта с явной пометкой резервного основания. Включённый пункт MUST давать «Включено», выключенный — «Выключено». Резервный признак MUST NOT называться прямым измерением всей SSH-службы. Питание MUST описывать только доступное действие длительного нажатия, не состояние сна.
- **FR-008**: Новые успешные результаты точных Group 300/310/500/700 MUST иметь пользовательски подтверждённый статус после отдельной проверки каждой модели. Старые предварительные результаты MUST сохранять свой статус; Group 300 MUST NOT использовать HTTP-fallback с учётными данными.
- **FR-009**: Новый результат MUST проходить существующее точное сопоставление с актуальной SR и безопасный импорт; исторические исходные результаты MUST NOT переписываться.
- **FR-010**: Учётные данные, токены, сертификаты, SNMP community и другие соседние секреты MUST NOT попадать в результат, аналитику, backup, документацию или Git.

### Key Entities

- **Устройство SR**: точная модель, IP и устойчивый идентификатор для сопоставления.
- **Снимок настроек**: девять групп полей, каждое со статусом, значением, источником и степенью подтверждения.
- **Факт аудита**: выбранное устройство, время опроса, поле, прочитанное значение и ссылка на результат без соседних секретов.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Все девять групп имеют явный статус в 100% результатов четырёх точных моделей.
- **SC-002**: В контрольных сценариях Group 310 каждое `read` значение совпадает с соответствующим пунктом меню; несовпадение блокирует утверждение факта.
- **SC-003**: В 100% негативных тестов несовпадения модели и неподтверждённого интерфейса нет новых прочитанных настроек.
- **SC-004**: Ни один тестовый результат и экспорт не содержит пароль, токен, SNMP community или полный соседний блок конфигурации.
- **SC-005**: Ошибка одного поля оставляет остальные факты пригодными для анализа и помечает именно ошибочное поле неизвестным.
- **SC-006**: Во всех тестах при наличии подтверждённого основного пункта SSH резервный не читается; при доказанном отсутствии основного читается только явно помеченный резервный. Ошибка видимого основного пункта не подменяется резервным значением.

## Assumptions

- Это этап чтения и аналитики; изменение настроек Polycom будет отдельной задачей с собственными контрактами и согласием.
- Общие правила возможны при совпадении текущей модели, интерфейса и схемы; отсутствие такого совпадения даёт `protocol_required`.
- Подтверждение опроса проверенного Group 300 не означает поддержку всех прошивок: прежняя проблема HTTPS на 4.1.5 остаётся ограничением, а не основанием переходить на HTTP.
- Отдельное устройство с видимым `Enable SSH Service` сейчас недоступно. Основной путь может стать фактом только при точном объявлении поля и read-only ключа текущим web-интерфейсом; до эксплуатации на такой прошивке его статус предварительный.
