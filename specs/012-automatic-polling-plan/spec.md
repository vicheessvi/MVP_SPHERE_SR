# Feature Specification: Загрузка и план автоматического опроса

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-09-01

**Status**: Ready

> Runtime note (2026-09-01): требования формирования plan v2 остаются действующими, но ручная передача плана отдельному скрипту в FR-025 заменена автоматическим loopback workflow из `specs/013-in-tool-polling/` и ADR-0013.

**Input**: Переработать модуль «Загрузка», добавить каскадный выбор оборудования, общий XLSX-пул учётных данных, интервал между устройствами и безопасное последовательное выполнение локального опроса.

## User Scenarios & Testing

### User Story 1 - Точный план из актуальной SR (Priority: P1)

Администратор МЦТП загружает SR и последовательно выбирает один, несколько или все типы оборудования, производителей и модели. Интерфейс немедленно показывает точное количество выбранных, поддерживаемых и неподдерживаемых устройств.

**Why this priority**: Ошибка состава плана приводит к опросу не тех устройств или пропуску оборудования.

**Independent Test**: На синтетической SR проверить все варианты «Все»/один/несколько и равенство счётчика длине итогового массива.

**Acceptance Scenarios**:

1. **Given** загружена SR с несколькими типами, производителями и моделями, **When** меняется верхний фильтр, **Then** нижние варианты пересчитываются, а недопустимые выбранные значения удаляются.
2. **Given** выбрано «Все» на каждом уровне, **When** строится план, **Then** в него входят все устройства актуальной SR, а поддержка опроса рассчитана отдельно.
3. **Given** отклонено ноль строк SR, **When** импорт завершён с диагностическими предупреждениями, **Then** статус импорта остаётся полным успехом.

---

### User Story 2 - Безопасный пул учётных данных (Priority: P1)

Администратор загружает XLSX только с колонками «Логин» и «Пароль». Интерфейс показывает лишь количество принятых, отклонённых и повторяющихся строк, а локальный исполнитель использует этот же файл как единственный пул пар для текущего запуска.

**Why this priority**: Секреты не должны попасть в состояние приложения, результаты, диагностику, логи или репозиторий.

**Independent Test**: Импортировать синтетический XLSX с валидными, пустыми и повторяющимися строками; проверить счётчики и отсутствие секретных значений во всех сериализуемых результатах.

**Acceptance Scenarios**:

1. **Given** XLSX содержит обязательные колонки, **When** он загружен, **Then** валидные уникальные пары доступны только в памяти текущей операции, а UI показывает безопасные счётчики.
2. **Given** отсутствует обязательная колонка, **When** выполняется импорт, **Then** весь файл отклоняется с понятной ошибкой.
3. **Given** поддерживаемые устройства выбраны, но файл учётных данных не передан локальному исполнителю, **When** начинается запуск, **Then** запуск блокируется без fallback-учётных данных.

---

### User Story 3 - Последовательный локальный опрос (Priority: P1)

Администратор задаёт дату и время начала, неотрицательный интервал в секундах и локальный корень результатов. Локальный исполнитель фиксирует неизменяемый снимок плана, сохраняет отдельный JSON после каждого устройства и только затем ждёт перед следующим устройством.

**Why this priority**: Результаты должны сохраняться сразу и не теряться при длительном запуске или отмене.

**Independent Test**: С подменёнными часами и записью проверить порядок `опрос → сохранение → ожидание → следующий опрос`, отсутствие задержки до первого и после последнего устройства и прерывание ожидания.

**Acceptance Scenarios**:

1. **Given** два поддерживаемых устройства и интервал N, **When** первый JSON атомарно сохранён, **Then** второе устройство запускается не раньше чем через N секунд.
2. **Given** выбранное устройство не поддерживается, **When** выполняется план, **Then** к нему не выполняется сетевой запрос, а в прогрессе оно отмечено как неподдерживаемое.
3. **Given** пользователь отменяет выполнение во время ожидания, **When** отмена принята, **Then** следующие устройства не запускаются, а ранее сохранённые JSON остаются.
4. **Given** запись JSON в выбранный корень не удалась, **When** результат уже сформирован, **Then** ошибка не маскируется и пакет прекращается до следующего устройства.

---

### User Story 4 - Операционный экран и Справочник (Priority: P2)

Администратор видит в «Загрузке» четыре коротких операционных раздела, а подробные форматы и правила читает в «Справочнике».

**Independent Test**: Открыть `index.html`, проверить русские названия четырёх разделов и наличие перенесённых пояснений в локальном Справочнике.

**Acceptance Scenarios**:

1. **Given** открыт модуль «Загрузка», **When** отображается экран, **Then** длинные технические пояснения у SR и общей папки отсутствуют.
2. **Given** открыт «Справочник», **When** пользователь ищет SR, папку результатов, учётные данные или план, **Then** он получает полное локальное объяснение.

### Edge Cases

- Пустая SR, пустой результат каскада или отсутствие хотя бы одного поддерживаемого устройства блокируют формирование исполняемого плана.
- Значения «Все» не могут одновременно храниться с частным набором; при изменении родителя устаревшие дочерние значения удаляются.
- Модель или производитель с разным регистром/пробелами объединяются по существующей нормализации, но исходные подписи SR не изменяются.
- Интервал `0` допустим; отрицательное, бесконечное, дробное или нечисловое значение отклоняется.
- Точный дубль пары учётных данных учитывается отдельно и не создаёт повторную попытку; пустые строки игнорируются, частично заполненные строки отклоняются.
- Из-за ограничений браузерного `file://` HTML не запускает процессы и не получает абсолютный путь выбранной папки. Фактический сетевой запуск и запись выполняет существующий локальный скрипт, которому явно передаются скачанный план, тот же XLSX и корень результатов.

## Requirements

### Functional Requirements

- **FR-001**: «Загрузка» MUST содержать разделы «Выгрузка SR», «Общая папка результатов опросов», «Учётные данные оборудования», «План автоматического опроса».
- **FR-002**: Основной экран MUST не показывать длинные технические пояснения форматов; эти сведения MUST находиться в Справочнике.
- **FR-003**: Импорт SR MUST иметь полный успех при `rejectedCount = 0`; диагностические предупреждения MUST NOT сами превращать его в частичный успех.
- **FR-004**: Частичный успех MUST означать, что хотя бы одна строка действительно отклонена при наличии принятых строк; ошибка MUST означать отсутствие успешного импорта.
- **FR-005**: План MUST строиться только из устройств актуальной SR и существующего единого классификатора категорий.
- **FR-006**: Тип оборудования, Производитель и Модель MUST поддерживать один, несколько и все доступные варианты с видимым выбранным набором.
- **FR-007**: Производители MUST вычисляться из выбранных типов, модели — из выбранных типов и производителей, а `selectedDevices` — пересечением всех трёх фильтров.
- **FR-008**: Изменение родительского фильтра MUST удалять недопустимые дочерние значения и сразу пересчитывать варианты и итоговый набор.
- **FR-009**: UI MUST показывать `selectedDevices.length`, число поддерживаемых и число неподдерживаемых устройств.
- **FR-010**: План MUST содержать корректную дату и время начала и целый интервал от 0 секунд.
- **FR-011**: План MUST использовать стабильный порядок: порядок категорий каталога, затем производитель, модель, IP и стабильный идентификатор.
- **FR-012**: Экспортируемый план MUST быть неизменяемым снимком без секретов и содержать все выбранные устройства с признаком поддержки, дату начала и интервал.
- **FR-013**: Неподдерживаемые устройства MUST быть отражены явно и MUST NOT вызывать ping или vendor-запрос.
- **FR-014**: Локальный исполнитель MUST требовать XLSX для запуска поддерживаемых устройств и MUST NOT использовать старый vault, hardcoded или иной fallback.
- **FR-015**: XLSX MUST принимать только заголовки «Логин» и «Пароль» как обязательную схему общего пула; дополнительные области привязки MUST NOT требоваться.
- **FR-016**: Импорт учётных данных MUST изолировать некорректные строки, удалять точные дубли и возвращать только безопасные счётчики.
- **FR-017**: Логины и пароли MUST NOT попадать в UI, сериализуемое состояние, план, JSON результатов, stdout/stderr, диагностику, backup или Git.
- **FR-017a**: План MUST содержать только SHA-256 отпечаток выбранного XLSX, а локальный исполнитель MUST отклонить другой файл до первого сетевого обращения.
- **FR-018**: Для каждого устройства локальный исполнитель MUST завершить опрос, атомарно сохранить JSON и лишь затем ждать интервал перед следующим устройством.
- **FR-019**: До первого и после последнего обрабатываемого устройства задержки MUST NOT быть; отмена MUST прерывать ожидание и не удалять уже сохранённые файлы.
- **FR-020**: Ошибка сохранения MUST попытаться создать локальную recovery-копию вне выбранного корня, остановить переход к следующему устройству и вернуть безопасную явную ошибку.
- **FR-021**: Корень результатов MUST задаваться явно или использовать существующий локальный default; внутри MUST создаваться папка запуска `YYYY-MM-DD_HH-mm-ss`.
- **FR-022**: Ручной импорт общей папки MUST остаться доступным и совместимым с созданными JSON.
- **FR-023**: Единственным режимом интерфейса MUST оставаться прямое открытие `index.html`; постоянное browser storage, CDN, telemetry и внешний обмен MUST отсутствовать.
- **FR-024**: HTML MUST только валидировать выбранный XLSX в памяти текущей вкладки и не передавать его содержимое в экспортируемый план.
- **FR-025**: Фактический сетевой запуск MUST выполняться существующим локальным скриптом, поскольку браузерный `file://` не уполномочен запускать процессы или записывать по абсолютному пути.

### Key Entities

- **PollingFilterSelection**: выбранные типы, производители и модели с канонической семантикой «Все».
- **SelectedDevice**: неизменяемая запись из актуальной SR с категорией, производителем, моделью, IP и подтверждённой polling capability.
- **CredentialPool**: уникальные пары логин/пароль только в памяти локального запуска и безопасная статистика импорта.
- **AutomaticPollingPlan**: дата старта, интервал, стабильный массив выбранных устройств и сводка поддержки без секретов.
- **PollingRunProgress**: всего, обработано, успешно, ошибки, неподдерживаемые, текущее устройство и ожидание.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Во всех 13 сценариях каскадной фильтрации счётчик равен фактической длине `selectedDevices` и ни одно устройство вне фильтра не включается.
- **SC-002**: При `rejectedCount = 0` 100% успешных импортов SR получают положительный, а не частичный статус.
- **SC-003**: Во всех тестах интервала второе устройство начинается только после успешной записи первого JSON и заданной задержки; лишних задержек нет.
- **SC-004**: Поиск синтетического секрета после полного тестового запуска даёт 0 совпадений в UI-state, планах, JSON, логах и отслеживаемых файлах.
- **SC-005**: 100% неподдерживаемых выбранных устройств завершаются без сетевого вызова и учитываются в сводке.
- **SC-006**: Прямое открытие `index.html` сохраняет импорт SR, ручной импорт папки, создание плана и сброс данных после reload.

## Assumptions

- Единственная роль — «Администратор МЦТП».
- Подтверждённый автоматический adapter сейчас имеется для контроллеров и панелей Extron с поддерживаемым динамическим web-контрактом; остальные устройства остаются `protocol_required`.
- Выбранный в UI файл учётных данных не может быть безопасно передан процессу из `file://`; оператор передаёт тот же локальный XLSX параметром `-Credentials` существующему скрипту.
- Выбор папки в HTML предназначен для ручного чтения результатов. Абсолютный корень записи передаётся локальному скрипту параметром `-Output` либо используется существующий default в `%LOCALAPPDATA%`.
