# Feature Specification: Прямой запуск index.html

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-08-10

**Status**: Approved for implementation

**Input**: Пользователь должен открывать проект двойным щелчком по `index.html`; три указанных защитных уведомления должны исчезнуть.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Открытие без установки (Priority: P1)

Администратор МЦТП скачивает проект, открывает корневой `index.html` и сразу получает рабочий интерфейс без Node.js, PowerShell и локального сервера.

**Why this priority**: Это явный основной способ запуска, запрошенный пользователем.

**Independent Test**: Открыть `index.html` через `file://` в чистом профиле браузера и убедиться, что отображается главный экран и доступны все семь модулей.

**Acceptance Scenarios**:

1. **Given** локальная копия репозитория, **When** пользователь открывает `index.html`, **Then** приложение загружает локальные ресурсы и показывает главный экран.
2. **Given** отсутствие Node.js и сети, **When** открыт `index.html`, **Then** интерфейс остаётся работоспособным для импорта и аналитики текущего сеанса.

---

### User Story 2 - Безопасная граница двух режимов (Priority: P1)

Администратор использует прямой запуск для сеансового анализа, а защищённый запуск — для постоянной базы и учётных данных оборудования.

**Why this priority**: Прямой запуск не должен незаметно ослаблять ранее принятую защиту чувствительных данных.

**Independent Test**: Импортировать данные в файловом режиме, перезагрузить страницу и подтвердить отсутствие сохранённого рабочего состояния; затем запустить `start.ps1` и подтвердить прежнее зашифрованное хранилище и vault.

**Acceptance Scenarios**:

1. **Given** файловый режим, **When** пользователь импортирует SR или результаты опроса, **Then** данные доступны только в текущем сеансе и не записываются в browser storage.
2. **Given** файловый режим, **When** пользователь открывает загрузку учётных данных, **Then** импорт секретов недоступен и файл с паролями не читается.
3. **Given** запуск через `start.ps1`, **When** пользователь работает с данными и vault, **Then** сохраняются AES-256-GCM, DPAPI CurrentUser, loopback-сессия и CSRF-защита.

---

### User Story 3 - Чистый интерфейс и актуальный Справочник (Priority: P2)

Администратор видит рабочий интерфейс без трёх повторяющихся защитных уведомлений, а Справочник и документация объясняют реальные различия режимов.

**Why this priority**: Удаляет визуальный шум и предотвращает ложные заявления о шифровании в файловом режиме.

**Independent Test**: Проверить исходный DOM и отрисованный интерфейс на отсутствие трёх заданных текстов и найти в Справочнике описание файлового и защищённого режимов.

**Acceptance Scenarios**:

1. **Given** любой режим запуска, **When** открыт интерфейс, **Then** три указанных уведомления отсутствуют.
2. **Given** открытый Справочник, **When** пользователь ищет сведения о запуске и хранении, **Then** он получает точное описание обоих режимов без утверждения, что файловый режим зашифрован.

### Edge Cases

- Браузер запрещает `localStorage` или `sessionStorage` для `file://`.
- `runtime-config.js` открыт как локальный файл и не должен пытаться обращаться к серверу.
- Файловый режим открыт после ранее использовавшейся browser-only версии с данными в `localStorage`.
- Пользователь выходит из интерфейса в файловом режиме и должен иметь возможность снова войти как единственный администратор.
- Пользователь пытается импортировать файл учётных данных в файловом режиме.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Корневой `index.html` MUST открывать рабочий интерфейс непосредственно через `file://` без установки зависимостей и без сети.
- **FR-002**: Файловый режим MUST загружать только локальные ресурсы репозитория.
- **FR-003**: Файловый режим MUST использовать только непостоянное состояние текущей вкладки и MUST NOT читать или записывать рабочие данные в browser storage.
- **FR-004**: Закрытие или перезагрузка файловой вкладки MUST удалять импортированные в этом режиме рабочие данные.
- **FR-005**: Файловый режим MUST NOT принимать, читать или сохранять файлы учётных данных оборудования.
- **FR-006**: Защищённый режим через `start.ps1` MUST сохранять существующие свойства шифрования, vault, loopback-сессии и CSRF.
- **FR-007**: Приложение MUST выбирать адаптер хранения по подтверждённому режиму запуска и MUST NOT откатываться с ошибочного HTTP-запуска на browser storage.
- **FR-008**: Интерфейс MUST удалить три заданных пользователем защитных уведомления во всех режимах.
- **FR-009**: Экран локального хранилища MUST показывать свойства фактически активного режима и не заявлять о DPAPI/AES в файловом режиме.
- **FR-010**: Справочник, README, архитектура, правила агента и журнал реализации MUST быть обновлены вместе с поведением.
- **FR-011**: Автоматические проверки MUST подтверждать прямой запуск, отсутствие заданных текстов, запрет секретов в файловом режиме и неизменность защищённого режима.

### Key Entities

- **Режим запуска**: подтверждённый контекст `file` или `secure`, определяющий хранение и доступность vault.
- **Сеансовое состояние**: рабочие данные файлового режима, существующие только в памяти текущей страницы.
- **Защищённое состояние**: постоянные рабочие данные серверного режима в шифрованном хранилище Windows.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В чистой локальной копии главный экран появляется не позднее 3 секунд после открытия `index.html` без Node.js и сети.
- **SC-002**: Все 7 модулей доступны при прямом открытии.
- **SC-003**: Ни один импортированный в файловом режиме IP, снимок или результат опроса не остаётся после перезагрузки страницы.
- **SC-004**: 100% попыток импорта учётных данных в файловом режиме блокируются до чтения содержимого файла.
- **SC-005**: Все три заданных уведомления отсутствуют в статическом и отрисованном интерфейсе.
- **SC-006**: Существующие функциональные, runtime и server-наборы тестов проходят без регрессий.

## Assumptions

- Целевые браузеры — актуальные Chromium/Edge на Windows 10/11.
- «Открываться при запуске index.html» означает полноценную аналитику текущего сеанса; постоянное хранение и секреты требуют `start.ps1`.
- Автоматический сетевой опрос оборудования остаётся функцией отдельного локального runtime и не выполняется из `file://`.
- Файловый режим не мигрирует и не читает исторические значения прежнего browser `localStorage`, чтобы исключить скрытое использование чувствительных данных.
