# Research: Прямой запуск index.html

## Decision 1: Непостоянное состояние файлового режима

**Decision**: Использовать синхронный in-memory storage adapter, совместимый с текущими `loadState`/`saveState`, и не обращаться к `localStorage`.

**Rationale**: Прямой `file://` не имеет доступа к DPAPI. Constitution 2.0.0 запрещает сохранять SR, IP, снимки и аналитику в browser storage. Сеансовая память позволяет сохранить рабочий импорт/аналитику без ложного заявления о защите данных на диске.

**Alternatives considered**:

- `localStorage`: отклонён как незашифрованное постоянное хранилище чувствительных данных.
- Web Crypto с ключом рядом с ciphertext: отклонён, потому что не создаёт OS-bound защиту.
- Обязательная парольная фраза: отдельная большая функция с восстановлением/ротацией, не запрошенная пользователем.
- Автоматический запуск PowerShell из HTML: браузеры не разрешают безопасно выполнять локальные процессы.

## Decision 2: Два подтверждённых режима без неявного fallback

**Decision**: `file://` подтверждается статическим `runtime-config.js`; защищённый HTTP-режим подтверждается существующим динамическим `/runtime-config.js`. Любой другой HTTP-контекст без secure marker остаётся заблокирован.

**Rationale**: Это разрешает двойной щелчок, сохраняет CSRF/сессионную границу сервера и не допускает незаметного перехода с ошибочного server runtime на browser storage.

**Alternatives considered**:

- Проверять только `location.protocol`: недостаточно для защиты произвольного HTTP-хостинга.
- Встроить весь config в `index.html`: потеря отдельного server-issued CSRF marker.

## Decision 3: Секреты только в защищённом runtime

**Decision**: Не показывать file input учётных данных в файловом режиме и дополнительно отклонять обработку до `FileReader`.

**Rationale**: Это обеспечивает fail-closed поведение и выполняет прямой запрет Constitution на credentials в browser storage/state/backup.

## Decision 4: Удаление уведомлений без удаления честной диагностики режима

**Decision**: Удалить заданные banner/topbar/security-notice тексты; свойства активного storage показывать только на целевом экране «Локальное хранилище», отдельно для file и secure modes.

**Rationale**: Пользователь просил убрать повторяющиеся оповещения, но интерфейс не должен сообщать ложные сведения о шифровании.
