# Проверка и эксплуатация

После установки исправления завершить текущие опросы/запись базы, перезапустить
Python runtime через START_MVP_SPHERE_SR.py, войти и выбрать прежнюю полную папку
логов. Сброс/удаление БД и исходных файлов не нужны.

Ошибочный файл больше не прерывает остальные. Таблица показывает path/code/action,
число проверенных/готовых файлов и блокеров. При metadata/старом parse-error без
доказательств результат публикуется с предупреждениями. Если не подтверждён
прежний успешный файл, старая ревизия остаётся активной; после восстановления
именно указанного источника продолжение берёт готовые scans из checkpoints.
Повреждённый исходник не нужно вручную дописывать или переименовывать для
совпадения. Если восстановить его нельзя, исключение доказательств — отдельное
решение, не скрытая автоматическая потеря истории.

Разработчик: `node scripts/test-resilient-log-recheck.js`, `node tests.js`,
`python -m unittest discover -s python_tests -q`, `node scripts/validate-reference.js`.
Real SQLite/browser: `python scripts/check-real-db-filters.py --recheck`, также
прежний `--shutdown` и `scripts/check-explicit-plan-ui.py`. Для браузерных тестов
нужен bundled Playwright через SPHERE_PLAYWRIGHT_MODULE и Chrome; все профили,
данные и логи временные и синтетические, реальные устройства не опрашиваются.
