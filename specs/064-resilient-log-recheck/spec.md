# Feature 064 — перепроверка логов без остановки на одном файле

Статус: implemented; synthetic validation passed (268 Python, 259 JS, real SQLite/browser).

Дата: 2026-11-24. Основание: повторная загрузка после feature 062 каждый раз
обрывается log_recheck_incomplete без имени файла и без обработки остальных.
Пользователь подтвердил, что папка недоступна на этом ПК; точная причина его
конкретного файла пока не подтверждена. Проверка — на синтетических данных.

## Требования

1. Ошибка одного файла не останавливает проверку остальных. Успешные scans
   сохраняются прежними checkpoints и используются при продолжении без тела.
2. Старые metadata-only/ранее не разобранные файлы не блокируют обновление,
   потому что не содержали принятой событийной аналитики. Не выдавать ошибку
   или отсутствие сопоставления за успешный scan.
3. Если не удалось заново проверить файл с прежней аналитикой, нельзя молча
   удалить его доказательства или опубликовать частичную замену. После проверки
   всех файлов показать число, пути и коды проблем; старая ревизия остаётся активной.
4. Объяснять конкретные причины и дальнейшее действие, не предлагать бесконечный
   слепой повтор. Показывать сколько файлов обработано/сохранено и ошибки по ходу.
5. Завершающий тег XML с длинным допустимым пробельным хвостом не является
   оборванным файлом. Реально отсутствующий тег и посторонний хвост отклоняются.

## Границы и проверки

Никаких raw строк, копий логов, скрытой публикации частичной базы, ослабления
IP/model/SR gates или изменений vendor API/опросов/management writes. До двух
Worker/1 МиБ и SQL bounded UI сохраняются. Таблица проблем <=100 строк; total
считается по всей папке. Для неизвестного legacy registry — консервативная защита.
Матрица: metadata-only + upgrade; старый parse-error; настоящий старый evidence
read failure + последующие файлы; repaired-file resume; unsupported replacement;
XML padding/real truncation; real Python/SQLite/browser без пользовательских данных.
