# Plan

## Исследование

prepareDeviceLogImport немедленно бросает log_recheck_incomplete на любом старом
пути с unmatched/read/scan error, включая файлы без прежних событий. Сообщение не
содержит path/reason. Huawei scanFile требуют закрывающий LogModule в фиксированном
хвосте 512/2048 символов, поэтому длинный пробельный XML-хвост ложно отклоняется.

## Реализация

Сначала тесты. Отдельный predicate прежних доказательств использует успешный digest,
статус маркеров и консервативный fallback для неизвестной legacy записи. Заведомые
metadata/error записи не требуют замены доказательств. Errors собираются по файлам,
успешные scans checkpoint/staging продолжаются; только после полного обхода блокеры
дают structured error с bounded metadata. При отсутствии блокеров обычный atomic
finish публикует полный результат с явными предупреждениями качества.

Worker, упавший на файле, заменяется для следующего файла, без автоматического
повтора того же чтения в рамках попытки. DB/checkpoint failure и cancel остаются
глобальными остановками. Registry не помечает ошибку как новую версию успешного
анализа. UI показывает проблемы и статические объяснения, не raw исключения.

Completeness tail ограничен прежними 512/2048 завершающими символами после trimEnd при каждом
feed; event rules не меняются, успешные текущие checkpoints совместимы.
Bootstrap logRulesets исключает явно не разобранные записи, не создавая ложного
предупреждения о постоянной перепроверке на metadata/error файлах.
