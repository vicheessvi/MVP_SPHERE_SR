# Feature Specification: DB-first аналитика и отзывчивые рабочие экраны

**Created:** 2026-11-19 · **Branch:** `codex/secure-local-runtime`

**Status:** Implemented; эксплуатационная проверка реальной базы и устройств остаётся у администратора.

## User Scenarios & Testing

### US1 — Миллион событий без загрузки всей истории (P1)

Администратор открывает модуль событий/перезагрузок после импорта. Сразу видит рабочий экран, состояние запроса и затем общие показатели, кольца и карту. Списки раскрываются отдельными страницами. Миллион событий — контрольный масштаб, не потолок базы.

**Acceptance:** первая страница содержит не более 100 строк; сводка считает всю область фильтра; переключение модуля не запускает клиентский обход всех событий.

### US2 — SR, JSON и логи из базы (P1)

После входа инструмента рабочие представления запрашивают только нужные данные: актуальный инвентарь, последние/исторические опросы выбранного устройства, версии, ошибки и метаданные логов. Старая база открывается с однократной контролируемой подготовкой индексов без перечитывания исходных файлов.

**Acceptance:** восстановление не скачивает все порции всей истории в браузер. Импорты и план опроса не затирают историю, не загруженную в клиент.

### US3 — Удобное исследование (P2)

Разные задачи получают ясную иерархию: обзор, события, оборудование и источники. Фильтры сохраняют контекст, клики на диаграмме и ячейке уточняют выборку. Видны ожидание, ошибка/повтор, пустой результат и страница выдачи. В ходе запроса можно уйти в другой раздел.

## Requirements

### US4 — ВКС «Учёт» в нерабочее время (P2)

Администратор сравнивает терминалы без зарегистрированных штатных выключений и
с ровно одним выключением за два месяца в нерабочее время. Только актуальная
SR/ВКС/«Учёт», календарь РФ с переносами (подтверждено), 18:00–07:00 в рабочие
дни. Кольца, карта, фильтры и отдельный XLSX используют один срез. Отсутствие
событий/полноты журнала не доказывает непрерывную работу. Подробные определения,
проверки и Full SpecKit design: `offhours.md`.

- База — источник рабочих данных в локальном режиме. Прямой index.html сохраняет сеансовый fallback.
- SQL-запросы и ответы ограничены по размеру страницы, не по суммарной истории. Кольца, TOP и карта — серверные агрегаты по всей области.
- Подтверждённые перезагрузки, штатные выключения, неизвестные запуски и предполагаемые паузы не смешиваются. Прежние model/IP/SR/validation gates сохраняются. Polycom TGZ не получает событийную аналитику.
- Новые и существующие данные остаются в выбранной рабочей папке, без секретов и оригиналов логов. Ошибка подготовки не удаляет опубликованные ревизии.
- Устаревший ответ запроса после смены маршрута/фильтра не подменяет экран.
- Существующие опросы, сбор логов и opt-in изменение параметров сохраняют transport/model/identity/confirmation gates. Аналитика не инициирует команды устройств; непубликованный контекст не используется для запуска.

## Success Criteria

- Контрольная база 1 000 000 событий: первая страница <= 100 строк; ответ сводки не содержит массив исходных событий и остаётся < 256 КиБ.
- После входа клиент не восстанавливает миллион записей в память. Деталь выбранного устройства не загружает историю других.
- В контрольных сценариях итоги SQL совпадают с действующими правилами, скрытый неполный импорт не подменяет готовые данные.

## Clarifications

- Пользователь подтвердил сотни тысяч и возможный миллион событий только ВКС, дальнейший рост SR, JSON и логов.
- «Анализ событий» трактуется как существующий модуль перезагрузок/питания; название модуля без отдельного запроса не меняется.
