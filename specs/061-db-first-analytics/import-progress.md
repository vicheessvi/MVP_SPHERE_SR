# SpecKit-lite: проценты, ETA и результат импорта

Дата: 2026-11-19.

## Цель

В импортах SR, JSON и логов вместо одного «Выполняется» показать меняющийся процент, примерное оставшееся время и явное успешное завершение после подтверждения записи в БД.

## Входит

- Оценочный общий прогресс с подписанным текущим этапом. Фазы имеют фиксированные веса; внутри фаз используются только фактически обработанные строки/файлы/байты и подтверждённые порции. Время само по себе не увеличивает процент.
- ETA по измеренной скорости; до достаточного измерения — «Рассчитывается». Для этапов неизвестной длительности нельзя обещать точное время. Видны прошедшее время и обновление статуса, чтобы отличать ожидание ответа БД.
- Публикация SQLite остаётся одной атомарной транзакцией. Копирование staging партиями даёт прогресс записей; существующий JSON rebuild получает только callback счётчика. Короткий progress endpoint использует память сеанса и не читает миллион строк или занятую БД.
- 100% и «Успешно завершено» только после ACK commit и bootstrap. Ошибки, отмена и частичный импорт имеют собственные подписи и не объявляются полным успехом. Итоги остаются на экране.
- Защита session/admin/Origin/CSRF, точные модельные правила и checkpoints сохраняются; прямой file:// остаётся сеансовым.

## Не входит

Изменение опросов устройств, vendor API, формата логов, классификации событий, схемы файлов, скрытое хранение источников или паролей.

## Критерии и проверки

JS: реальные work counters, неизвестный ETA, отсутствие 100 до commit, ошибка/отмена/частичный импорт. Python: монотонность progress, rollback и старый опубликованный срез при ошибке, status без доступа к занятой БД и session isolation. Изолированный Chrome: задержанная публикация SR/JSON/logs, проценты/ETA/успех видны локально и при навигации. Проверки не используют рабочую БД и реальные логи администратора.
