# SpecKit-lite: кнопка импорта логов

**Дата:** 2026-11-19

## Цель

После выбора 3192 файлов пользователь не видит никакой реакции на submit. Требуется не терять выбранные данные и объяснять каждый отказ/ожидание рядом с кнопкой, не только сообщением вверху длинной страницы.

## Подтверждённые проверки

Headless Chrome: 3192 синтетических XML, form validity=true, submit=1, прогресс дошёл до 1920/3192 за первые 400 мс. Количество файлов само по себе не воспроизводит проблему. В коде есть silent return при другом импорте и обращение к nullable POLLING_RECOVERY до try.

## Изменения и критерии

- Отдельный видимый guard reason для другой загрузки/базы; никакого сброса сохранённой аналитики.
- Подготовка списка файлов и запуск защищены от pre-try исключений; ручной импорт не зависит от наличия модуля polling-recovery.
- Этап проверки прежних результатов в БД обозначается до чтения новых логов.
- Успешный запуск, отсутствие recovery module и ошибки API покрываются браузерным сценарием. Конкретная причина на ПК администратора требует его статуса/скриншота; не приписывать её одному только количеству файлов.
- Контракты опросов и изменения настроек устройств не меняются.

## Дополнительные требования и результат

Возвращён каскад «Домен → Тип устройства → Производитель → Модель → Локация → Адрес». Значения берутся из устройств SR с учётом вышестоящих выбранных условий; вымышленные категории и несовместимые производители не добавляются. Инвентарный раздел сохраняет собственную категорию. Изменение списков не запускает тяжёлые событийные расчёты до «Применить».

SR/JSON не показывают завершённые 100% до ACK публикации в БД: сохранение имеет отдельный неопределённый индикатор. Общая строка операций видна при смене модулей; логовый статус и ошибки остаются рядом с кнопкой. Экспорт показывает получение строк и формирование XLSX. Для текстового фильтра зарезервировано место под статус: blur не сдвигает кнопку и не поглощает следующий клик.

Проверено в изолированном Chrome: запуск/остановка 3192 небольших синтетических XML; запуск без polling-recovery; видимая ошибка подготовки БД; JSON с задержанной публикацией; каскад и порядок фильтров; отсутствие тяжёлого запроса до Apply; переход в питание одним кликом после ввода текста; диаграммы, тепловая карта и узкий экран. Это не замер времени анализа реальных 102,64 ГиБ. Реальная рабочая БД администратора не открывалась.
