# SpecKit-lite: отдельные XLSX ВКС «Учёт»

Дата: 2026-11-20.

Пользователь сообщил, что оба XLSX содержат совместные показатели. DB-first уже выбирал разные когорты, но возвращал и отображал в обоих файлах reboots/confirmed/suspected. Ручной file:// exporter уже разделён.

Нужно: reboot-файл содержит только подтверждённые по журналу перезагрузки, power-файл — только штатные выключения и предполагаемые паузы без записей, строго отдельными показателями и с достоверностью. Общие SR-данные сохраняются. Устройство с обоими видами событий может присутствовать в обоих файлах, но только с соответствующими показателями. Unknown_start сам по себе не является подтверждением reboot или power_off и не добавляется в их показатели. JSON Date−Uptime и журналы не смешиваются; источник этих двух когортных отчётов остаётся logs.

Backend жёстко ограничивает эти отчёты текущими ВКС «Учёт», возвращает только поля нужного вида, сохраняет период/доменные/модельные/SR/IP gates и дневной/часовой drilldown. Клиент сохраняет выбранные фильтры на старте и выгружает все страницы одной revision. Count cells числовые, исходные строки буквальные и без формул. Site name export и manual fallback не менять, кроме проверок сохранения поведения. Нового импорта, изменения исходников или событийных правил нет.

Проверки: both/reboot-only/power-only/unknown-only и исключённый SR-статус, отсутствие чужих колонок и API-полей, даты, отдельная достоверность, empty results, все страницы, формульная безопасность и смена фильтров во время экспорта. Локальные синтетические XLSX визуально проверить; не публиковать QA-артефакты или пользовательские данные.

Реализация: экспорт работает по снимку применённых фильтров и ожидаемой revision; рабочая БД/доступ дополнительно сравниваются по sourceIdentity, чтобы разные БД с одинаковым номером revision не смешались. Переход между обычными модулями не отменяет самостоятельный export read. При смене БД/revision/доступа файл не выдаётся. Site name export сохраняет прежнюю схему. Имена файлов `vcs-reboot.xlsx`/`vcs-power.xlsx` остаются, вкладки стали «Перезагрузки»/«Питание». В каждом отчёте только свои показатели плюс общие SR-поля и «Статус SR».

Проверены настоящие XLSX, сформированные текущим SheetJS-экспортёром на синтетических строках; Artifact Tool использован для независимого импорта, проверки значений и просмотра изменённых диапазонов до/после. Даты сохраняют существующий буквальный device-local формат, числовые счётчики не преобразуются в текст, формулы из пользовательских строк не создаются. Формирование приложения остаётся на vendored SheetJS согласно контракту проекта; новые авторские файлы/зависимости в production не добавлены. Нативное поведение Microsoft Excel отдельно не автоматизировалось.
