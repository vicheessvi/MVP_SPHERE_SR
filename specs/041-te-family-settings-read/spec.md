# Feature Specification: Чтение настроек Huawei TE30/40/50/60

**Feature Branch**: `codex/secure-local-runtime`
**Created**: 2026-11-06
**Status**: Draft
**Input**: Дополнить обычные JSON-опросы TE30/40/50/60 фактическими значениями SNMPv2, автообновления, автоответа, NTP, Wi‑Fi, SSH и управления питанием. TE20 не менять.

## Clarifications

### Session 2026-11-06

- Q: Какова область изменений? → A: Только TE30/TE40/TE50/TE60; TE20 работает корректно.
- Q: Можно ли выполнить безопасную проверку TE40 с его сертификатом? → A: Да, только чтение.
- Q: Совпадают ли общие параметры с TE20? → A: Да; SNMPv2 и Wi‑Fi отличаются и используют отдельные меню.

## User Scenarios & Testing

### User Story 1 — Получить фактические настройки (Priority: P1)

Администратор запускает обычный опрос точного TE30/40/50/60 и видит доступные значения семи параметров в JSON без изменения настроек устройства.

**Independent Test**: Опросить одну модель, сверить каждое прочитанное значение с её web-меню.

**Acceptance Scenarios**:

1. **Given** устройство предоставляет проверенный ответ, **When** опрос завершён, **Then** значение и источник отражены в соответствующем поле.
2. **Given** часть настроек недоступна, **When** опрос завершён, **Then** известные поля заполнены, а неизвестные не подменены догадками.
3. **Given** устройство показывает плановое включение и отключение, **When** опрос завершён, **Then** каждое расписание имеет отдельный статус включения и время только если оно включено; общего «Планового перезапуска» для этой группы нет.

### User Story 2 — Безопасная неполнота (Priority: P2)

Различия прошивок и моделей не должны превращаться в ложное «отключено».

**Independent Test**: Смоделировать отсутствующий метод, неверный код и повреждённый ответ, проверить неизвестный статус без изменения устройства.

**Acceptance Scenarios**:

1. **Given** неизвестный код Wi‑Fi или SNMPv2, **When** результат строится, **Then** поле остаётся неизвестным.
2. **Given** нет настройки расписания питания, **When** доступен режим сна, **Then** известная часть читается без выдуманного расписания.

### Edge Cases

- На старой прошивке отсутствует часть маркеров: остальные поля всё равно читаются.
- SNMP-ответ содержит community и пароли: в JSON включаются только статус сервиса и SNMPv2.
- Wi‑Fi может работать как клиент, точка доступа, оба режима или быть выключенным.
- Обычный опрос не меняет настройки и не создаёт сетевые запросы к другим IP.

## Requirements

### Functional Requirements

- **FR-001**: Точное устройство TE30/40/50/60 MUST проверяться до и после входа перед дополнительными запросами.
- **FR-002**: Система MUST читать доступные общие поля SSH, автообновления, автоответа, NTP и питания независимо друг от друга.
- **FR-003**: SNMPv2 и Wi‑Fi MUST читаться из собственных источников этих моделей, без переноса правил TE20.
- **FR-004**: Неизвестный метод, схема или код MUST оставлять поле неизвестным, а не объявлять отключённым.
- **FR-005**: Результат MUST исключать пароли, community, ключи, токены и сырые ответы SNMP/Wi‑Fi.
- **FR-006**: TE20 и отдельные задачи изменения настроек MUST сохранять прежнее поведение.
- **FR-007**: Для TE30/40/50/60 питание MUST содержать независимые «Плановое включение» и «Плановое отключение» с временем при включённом расписании; legacy «Плановый перезапуск» MUST не выводиться.

### Key Entities

- **Поле настройки**: статус чтения, нормализованное значение, подтверждённый источник.
- **Устройство**: точная модель и устойчивая идентичность, проверенные до чтения.

## Success Criteria

### Measurable Outcomes

- **SC-001**: На проверенном TE40 как минимум шесть из семи групп полей получают значения, если устройство предоставляет их.
- **SC-002**: В 100% синтетических случаев неизвестной схемы не возникает ложного «выключено» и нет записи настройки.
- **SC-003**: Для каждой TE30/50/60 результат можно сверить с меню по одной контрольной проверке; администратор подтвердил корректные обычные опросы всех трёх моделей 2026-11-10.

## Assumptions

- На TE40 отдельно подтверждены текущие методы чтения общих настроек, SNMP и Wi‑Fi; на других моделях они используются только при маркерах текущей прошивки и точной схеме.
- Администратор подтвердил корректные обычные опросы TE30/50/60 на рабочем ПК 2026-11-10; проверка write-задач и логов остаётся отдельной.
