# Read-only contract: TE30/40/50/60

После exact pre/post-auth model и identity gate:

1. При маркере `WEB_GetCfgParamAPI` запрашивать только присутствующие в текущем bundle подтверждённые конфигурационные ID. Схема полей строго типизируется; значения разных полей независимы.
2. При `WEB_GetSnmpCfgAPI` выполнить POST с текущим CSRF, принять только целые `snmpv2` и `IsEnableSnmp` в {0,1}; отбросить весь остальной ответ.
3. При `WEB_GetWifiStatModeAPI` выполнить POST с текущим CSRF, принять только `ucWifiMode` в {0,1,2,3}; получить два флага клиента и точки доступа.
4. Неизвестный ответ не прерывает базовый опрос. Ни один запрос не изменяет настройку. Администратор подтвердил корректные обычные опросы TE30/40/50/60 на рабочем ПК; неизвестные варианты прошивок всё равно отклоняются по схеме.

5. Питание: при маркерах текущего bundle допускается read-only чтение `rp_shutdown`, `enable_poweron/off`, `poweron/off_hour/minute` вместе со сном. Бинарные флаги только 0/1, время только 00:00–23:59. Два независимых поля `scheduledPowerOn` и `scheduledPowerOff` заменяют прежний «Плановый перезапуск»; время выключенного расписания — `null`. Legacy `scheduledRestartCode` для TE30/40/50/60 не запрашивается и не проецируется.
