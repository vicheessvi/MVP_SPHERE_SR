# Feature 065 — один Answer mode план для разных контрактов

Статус: implemented, synthetic validation passed — Python 274/274, JS 260/260,
real loopback/SQLite/browser mixed и legacy-compatible UI. Vendor writes не выполнялись.

Дата: 2026-11-24. Администратор явно одобрил общий смешанный список с отдельным
действием соответствующего контракта для каждого устройства. Это заменяет
ограничение одного action ID на весь новый Answer mode план, не на другие writes.

## Требования

- Пять существующих групп (TE20, TE30/40/50/60, Huawei 310, Huawei 300, Polycom Group)
  выбираются прежними отдельными переключателями. Могут иметь разные целевые режимы.
- Только exact модели существующего каталога. Неизвестные/неподдерживаемые модели
  не получают команд и блокируют смешанный write-план до сети, а не исчезают молча.
- «Не менять» означает отсутствие write для данной группы. Если JSON/logs тоже
  выключены, устройство получает явный результат «Нет выбранных действий» без
  ping/login/read/write/интервала; оно не считается успешно изменённым.
- JSON/logs остаются отдельными глобальными действиями, только по выбору. Другие
  management writes с Answer mode не совмещаются. Никакого выбора команд из XLSX.
- До запуска показываются source/sheets, число целей, распределение по контрактам
  и ограниченная таблица per-device actions. Требуется явное согласие.
- Runtime перепроверяет все bindings до сети; wrong/extra/missing/двойной action,
  неизвестный контракт, дубли IP/source mismatch не допускают частичного запуска.
- Обработка последовательная, интервалы только между реальными обращениями;
  exact model/identity/bundle/TLS gates и pre-read/one-write/post-read прежние.
- Job/recovery фиксируют исходные bindings. Неясный write не повторяется, а
  неизменяемые строки не требуют ручной write-проверки. Старые v3/v4 не расширяются.
  Наличие незакрытого review остаётся completed_with_errors, а не скрытым успехом.

## Приёмка

Смешанный план всех пяти контрактов в обоих направлениях; один/два Polycom поля;
No-change + JSON/log matrix; неизвестные/подменённые bindings до сети; frozen job;
resume и legacy; UI mult-sheet XLSX с сохранённым FileList; fake adapters/request
spies, реальный loopback/SQLite/browser без устройств/секретов. Новых vendor API нет.
