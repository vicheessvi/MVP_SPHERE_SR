# Feature Specification: Локальный веб-опрос Extron

**Feature Branch**: `011-extron-web-polling`

**Created**: 2026-08-31

**Status**: Approved for implementation

**Input**: Использовать подтверждённый алгоритм веб-опроса для контроллеров и панелей управления Extron, интегрировать его в инструмент и предусмотреть безопасное локальное сохранение итоговых JSON.

## User Scenarios & Testing

### User Story 1 - Опросить совместимое устройство Extron (Priority: P1)

Администратор МЦТП передаёт локальному polling-скрипту план с IP-адресами контроллеров и панелей Extron. Скрипт подключается только к этим адресам, аутентифицируется, определяет актуальные URI ресурсов из загруженного устройством web bundle и получает доступные сведения об устройстве, проекте, сети и подключённых панелях.

**Why this priority**: Это основная прикладная ценность функции и источник JSON, который затем анализирует интерфейс.

**Independent Test**: Запустить опрос против синтетического HTTPS-transport с изменяемыми resource URI и убедиться, что сформирован один совместимый JSON без жёстко заданных hash/URI.

**Acceptance Scenarios**:

1. **Given** поддерживаемый web contract контроллера или панели Extron, **When** устройство успешно отвечает и принимает учётные данные, **Then** скрипт извлекает динамические URI из текущего `/www/main.js`, опрашивает доступные ресурсы в той же сессии и формирует итоговый JSON.
2. **Given** модель Extron отличается от ранее проверенной, но предоставляет тот же подтверждённый contract, **When** она опрашивается, **Then** применяется тот же generic adapter без списка жёстко разрешённых моделей.
3. **Given** bundle не содержит достаточных подтверждённых маркеров либо ответы имеют неизвестную схему, **When** выполняется опрос, **Then** скрипт завершает устройство с безопасным статусом `unsupported_web_contract`/`protocol_required`, не выдумывает команды и не подменяет отсутствие доказательств пустыми значениями.
4. **Given** resource URI получен из bundle, **When** запрашиваются сведения о проекте, **Then** используется точный путь `/api/swis/resource<uri>` без добавления query-параметров.

### User Story 2 - Безопасно использовать учётные данные (Priority: P1)

Администратор отдельно передаёт локальному polling-скрипту Excel-файл (`.xlsx`/`.xls`) со стандартными учётными данными для сочетания типа и производителя; JSON/CSV остаются совместимыми форматами. При необходимости запись уточняется моделью или IP. Записи сразу импортируются в зашифрованное Windows-хранилище текущего пользователя. Во время опроса пароль выдаётся адаптеру только для подходящего устройства из явно указанного плана и никогда не попадает в результаты, логи или Git.

**Why this priority**: Компрометация паролей оборудования недопустима.

**Independent Test**: На синтетических значениях выполнить импорт, успешный и неуспешный login, затем проверить result/log tree и repository scan на отсутствие пароля, Basic header и session cookie.

**Acceptance Scenarios**:

1. **Given** локальный Excel credential-файл с колонками тип устройства/производитель/логин/пароль и доступное Windows DPAPI, **When** данные импортируются, **Then** первая таблица безопасно читается без выполнения формул, записи сохраняются только в локальном зашифрованном vault текущего пользователя, а исходный файл не копируется в проект.
2. **Given** несколько credential scopes, **When** опрашивается устройство, **Then** запись выбирается однозначно в порядке точный IP → тип+производитель+модель → тип+производитель, а запросы не уходят на адреса вне plan.
3. **Given** ошибка входа или transport, **When** формируется диагностика, **Then** пароль, Authorization, cookie и тело login не сохраняются и не выводятся.
4. **Given** сервер использует self-signed certificate, **When** администратор явно разрешил локальный небезопасный TLS для плана, **Then** это разрешение применяется только к указанным устройствам текущего запуска и отражается безопасным булевым признаком без секретов.

### User Story 3 - Получить импортируемую папку результатов (Priority: P1)

После одного запуска администратор получает папку с датой и временем, содержащую отдельный итоговый JSON для каждого IP. Затем он вручную выбирает общую папку `poll-results` или конкретную папку запуска в модуле «Загрузка» при прямом открытии `index.html`. Существующая ручная загрузка общей папки с готовыми JSON остаётся доступной без обязательного запуска polling-скрипта.

**Why this priority**: Опрос должен завершаться данными, которые инструмент уже умеет пакетно импортировать и анализировать.

**Independent Test**: Запустить два синтетических устройства без `--out`, проверить путь `%LOCALAPPDATA%\MVP_SPHERE_SR\poll-results\YYYY-MM-DD_HH-mm-ss\<IP>.json`, затем передать descriptors существующему batch importer.

**Acceptance Scenarios**:

1. **Given** `--out` не указан, **When** начинается запуск, **Then** создаётся одна папка `%LOCALAPPDATA%\MVP_SPHERE_SR\poll-results\YYYY-MM-DD_HH-mm-ss` и JSON каждого устройства сохраняется в ней атомарно.
2. **Given** администратор явно указал иной локальный `--out`, **When** путь доступен, **Then** результаты сохраняются в указанной папке запуска без внешней передачи.
3. **Given** один IP завершился ошибкой, **When** остальные устройства опрошены, **Then** для каждого IP существует отдельный итоговый JSON с `ok`/`failedStage` и безопасной диагностикой, а успешные результаты не теряются.
4. **Given** итоговая папка выбрана в HTML-интерфейсе, **When** выполняется пакетный импорт, **Then** существующая аналитика распознаёт firmware/project/LAN/connected devices без отдельного server-runtime.
5. **Given** у администратора уже есть готовые файлы опросов, **When** он использует существующие элементы ручной загрузки, **Then** файлы анализируются как прежде и автоматизированный polling не является обязательным шагом.

### User Story 4 - Понять порядок работы из Справочника (Priority: P2)

Администратор открывает «Справочник» и видит, как подготовить план, импортировать credentials, запустить локальный опрос, найти папку результатов и загрузить её в интерфейс.

**Why this priority**: Polling выполняется отдельным локальным процессом, поскольку `file://index.html` не может безопасно выполнять Node.js или хранить пароли.

**Independent Test**: Проверить catalog/reference validator и наличие русскоязычных инструкций с default path и запретом хранения secrets в браузере.

**Acceptance Scenarios**:

1. **Given** открыт Справочник, **When** пользователь читает раздел «Загрузка», **Then** указан полный локальный workflow и расположение результатов.
2. **Given** интерфейс запущен через `index.html`, **When** credentials ещё не импортированы, **Then** UI не предлагает сохранить пароль в браузере и не использует `localStorage`/`IndexedDB`.

### Edge Cases

- Устройство доступно по ping, но HTTPS/web contract отсутствует или изменён.
- Устройство возвращает HTML login page вместо JSON ресурса либо session истекла между bundle и resource GET.
- В bundle встречается несколько похожих URI; используются только подтверждённые ключи и структурно валидные ответы.
- В plan повторяется IP или присутствует невалидный/неразрешённый адрес.
- Нет `%LOCALAPPDATA%`, нет доступа на запись, недостаточно места или процесс прерван во время записи.
- Модель/производитель в plan не Extron либо категория не `controller`/`panel`.
- Один контроллер сообщает подключённую панель; это не означает отдельный сетевой опрос панели без её IP в plan.
- Дата/время устройства неверны; capture time берётся от локального запуска, а device time сохраняется отдельно как полученное значение.

## Requirements

### Functional Requirements

- **FR-001**: Система MUST предоставлять generic Extron web adapter для категорий `controller` и `panel`, применимый ко всем моделям с подтверждённым web contract независимо от названия модели.
- **FR-002**: Adapter MUST сначала открыть `/www/index.html`, затем выполнить login через `POST /api/login?rnd=<timestamp>` с Basic authorization и подтверждёнными браузерными заголовками Extron, сохранить session cookie только в памяти процесса и не раскрывать её наружу.
- **FR-003**: Adapter MUST загрузить `/www/main.js` после login и динамически извлечь только подтверждённые resource URI; hardcoded session-bound URI запрещены.
- **FR-004**: Resource GET MUST использовать точный `/api/swis/resource<uri>`; для project resources запрещено добавлять `rnd` или иные query-параметры.
- **FR-005**: Adapter MUST нормализовать доступные поля в совместимую legacy-структуру `webBlocks`, сохраняя полученные raw scalar/structured values без изменения исходных файлов.
- **FR-006**: Неизвестные contract/schema MUST завершаться fail-closed статусом и диагностикой `protocol_required`/`unsupported_web_contract`, а не фиктивными значениями.
- **FR-007**: Polling orchestrator MUST обращаться только к IP из явно переданного plan и MUST ограничить Extron adapter производителем Extron и категориями controller/panel.
- **FR-008**: Credentials MUST получаться из существующего DPAPI vault по однозначному scope устройства непосредственно перед login; секреты MUST NOT включаться в JSON, stdout/stderr, diagnostics, fixtures или Git.
- **FR-009**: CLI MUST поддерживать безопасный импорт `.xlsx`/`.xls` credentials из первой таблицы с колонками тип устройства/производитель/логин/пароль и необязательными моделью/IP, а также совместимые JSON/CSV, в vault без выполнения формул и копирования исходного файла в workspace.
- **FR-009A**: Credential resolver MUST использовать приоритет точный IP → тип+производитель+модель → тип+производитель и MUST отклонять duplicate scope при импорте.
- **FR-010**: CLI MUST сохранять отдельный итоговый `<IP>.json` для каждого устройства, включая контролируемые ошибки, чтобы batch не терял частичные результаты.
- **FR-011**: Без `--out` CLI MUST использовать `%LOCALAPPDATA%\MVP_SPHERE_SR\poll-results\<YYYY-MM-DD_HH-mm-ss>`; `--out` MUST разрешать явную локальную папку.
- **FR-012**: Запись результата MUST быть атомарной через временный файл в той же папке с последующим rename; временный файл MUST удаляться при ошибке.
- **FR-013**: Default/runtime output directories MUST быть исключены из Git и не использоваться как fixtures.
- **FR-014**: Единственный UI runtime MUST оставаться `file://index.html`; browser UI MUST NOT выполнять polling, принимать credentials или добавлять persistence/network calls.
- **FR-015**: «Загрузка» MUST импортировать созданную папку существующим batch-folder workflow без нового server mode.
- **FR-015A**: Существующая ручная загрузка общей папки с готовыми JSON опросов MUST сохраняться без регрессий; автоматизированный polling MUST быть дополнительным, а не единственным источником данных.
- **FR-016**: Справочник MUST описывать команды, безопасность, default path, структуру папок и порядок «опрос → выбор папки → аналитика» на русском языке.
- **FR-017**: Реализация MUST иметь synthetic tests dynamic URI, session cookie, exact resource URL, redaction, unsupported contract, default/explicit output и partial failure без реальных IP/credentials.

### Key Entities

- **Polling plan item**: Разрешённый IP, категория, производитель, модель/описание и явное разрешение self-signed TLS при необходимости.
- **Credential entry**: Локальная связь IP с username/password, зашифрованная DPAPI и недоступная browser UI.
- **Extron web session**: Краткоживущие cookie и обнаруженные URI в памяти одного device poll.
- **Polling result**: Итог конкретного IP с `ok`, этапами/диагностикой и `webBlocks`, но без секретов.
- **Polling run folder**: Локальная папка capture time с набором `<IP>.json`, совместимая с batch importer.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 100% synthetic моделей Extron с подтверждённым contract опрашиваются одним adapter без model-specific hardcoding.
- **SC-002**: 100% проверок неизвестного bundle/schema завершаются fail-closed и не создают вымышленные сведения.
- **SC-003**: Secret scan результатов, логов, tests и Git обнаруживает 0 passwords, Authorization headers и session cookies.
- **SC-004**: Для batch из N plan items создаётся N итоговых JSON, даже если часть устройств завершилась контролируемой ошибкой.
- **SC-005**: Default output всегда соответствует `poll-results\YYYY-MM-DD_HH-mm-ss\<IP>.json` и принимается существующим folder importer.
- **SC-006**: Основной, runtime и reference test suites проходят без добавления external dependencies, CDN, telemetry или browser persistence.

## Assumptions

- Производитель и категория поступают из доверенного локального plan/SR projection; неизвестные значения не активируют adapter.
- Поддержка «всех моделей» означает contract-based compatibility: модель поддерживается, если её web UI предоставляет подтверждённый Extron contract; неизвестные поколения не опрашиваются догадками.
- Windows DPAPI текущего пользователя остаётся обязательным механизмом credential vault.
- Self-signed HTTPS типичен для локального оборудования и разрешается только явным флагом плана/CLI.
- `%LOCALAPPDATA%` является предпочтительным локальным корнем; при его отсутствии CLI требует явный `--out`.
- Интерфейс анализирует только файлы, которые пользователь вручную выбрал через browser File API; автоматическое чтение local output из `file://` невозможно и не требуется.
