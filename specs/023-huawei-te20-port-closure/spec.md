# Feature Specification: Закрытие HTTP/Telnet на Huawei TE20

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-09-08

**Status**: Ready

**Input**: Пользователь подтвердил успешный автоматический опрос Huawei TE20 и потребовал добавить для exact Huawei TE20 существующую явную задачу закрытия HTTP/80 и Telnet/23 по аналогии с другими терминалами Huawei. Контролируемая проверка на реальном устройстве подтвердила чтение параметров, приём минимальной безопасной записи и повторное чтение отключённого состояния.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Закрыть HTTP и Telnet на TE20 (Priority: P1)

Администратор МЦТП выбирает точный Huawei TE20 в отдельном списке целей, явно включает задачу закрытия HTTP/Telnet и запускает автоматический опрос. Инструмент сначала подтверждает модель и идентичность устройства, затем переводит оба параметра меню в безопасное состояние и сообщает результат только после повторной проверки.

**Why this priority**: Это основная пользовательская ценность feature и операция, изменяющая конфигурацию устройства.

**Independent Test**: На совместимом TE20 с явно выбранной задачей безопасное состояние обоих параметров подтверждается повторным чтением; при уже безопасном состоянии операция завершается без лишней записи.

**Acceptance Scenarios**:

1. **Given** точный TE20 прошёл проверку модели, идентичности и совместимости, а хотя бы одна небезопасная служба включена, **When** администратор явно запускает задачу, **Then** изменяются только параметры HTTP и Telnet, а результат считается успешным только после подтверждения обоих безопасных значений.
2. **Given** точный TE20 уже сообщает безопасные значения HTTP и Telnet, **When** запускается задача, **Then** результат имеет состояние «уже соответствует», а запись не выполняется.
3. **Given** модель, идентичность, текущая схема или признаки поддерживаемого меню не подтверждены, **When** запускается задача, **Then** запись не выполняется и возвращается безопасная диагностическая причина.

---

### User Story 2 - Выбрать TE20 теми же фильтрами (Priority: P2)

Администратор формирует план по отдельной таблице целей закрытия портов и может выбрать TE20 каскадом фильтров либо точным IP так же, как уже поддерживаемые Huawei TE30/TE40/TE50/TE60.

**Why this priority**: Новая capability должна быть частью существующего плана, а не отдельным несогласованным сценарием.

**Independent Test**: Exact Huawei TE20 учитывается как поддерживаемая цель задачи; неизвестная модель Huawei и устройство другого производителя остаются неподдерживаемыми.

**Acceptance Scenarios**:

1. **Given** отдельный список содержит exact Huawei TE20, **When** включена задача закрытия портов, **Then** TE20 входит в число поддерживаемых целей и отображается в карточке выбора.
2. **Given** в списке присутствует неизвестная либо приблизительно совпадающая модель, **When** строится план, **Then** она пропускается без сетевой write-операции.

---

### User Story 3 - Сохранить безопасный отчёт (Priority: P3)

Администратор получает обычный JSON результата опроса с состояниями задачи до и после, не содержащий учётных данных, cookie, CSRF, необработанные ответы устройства или скрытые копии исходных файлов.

**Why this priority**: Результат должен быть пригоден для локального контроля и не ослаблять существующую защиту данных.

**Independent Test**: Успех, уже безопасное состояние и безопасный отказ формируют только разрешённые поля отчёта; сканирование результата не обнаруживает секретов.

**Acceptance Scenarios**:

1. **Given** задача завершилась, **When** JSON передан на сохранение, **Then** он содержит статус, факт попытки записи и безопасные состояния HTTP/Telnet до и после без секретов.
2. **Given** авторизация, транспорт или проверка контракта завершились ошибкой, **When** формируется результат, **Then** он содержит только нормализованный безопасный код ошибки.

### Edge Cases

- TE20 доступен только через подтверждённый для него профиль защищённого соединения и самоподписанный сертификат явно разрешён на текущий запуск.
- В плане указана модель TE20, но после входа устройство сообщает другую модель либо не сообщает устойчивую идентичность.
- Меню устройства не содержит всех ожидаемых признаков чтения, сохранения и обоих параметров.
- Один из двух параметров отсутствует, имеет неизвестный тип или после записи не принимает целевое значение.
- Сеанс прерывается после записи до повторного чтения: операция не объявляется успешной.
- Галочка задачи выключена: write-путь не вызывается, даже если цель поддерживает capability.
- Пользовательский список содержит дубликат либо некорректный IP: план блокируется существующей валидацией до сети.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Exact Huawei TE20 MUST быть допустимой целью существующей задачи `disable_insecure_management_services`.
- **FR-002**: Поддержка MUST требовать отдельный список целей, точный opt-in задачи и существующее подтверждение перед запуском.
- **FR-003**: До любой записи MUST быть подтверждены точный TE20, устойчивый идентификатор устройства, совместимый интерфейс, признаки чтения/сохранения и оба параметра конфигурации.
- **FR-004**: Задача MUST изменять только состояние HTTP и Telnet на безопасное; другие параметры устройства MUST NOT входить в запрос.
- **FR-005**: Если оба параметра уже безопасны, задача MUST завершаться без записи со статусом «уже соответствует».
- **FR-006**: После записи MUST выполняться повторное чтение обоих параметров; без точного подтверждения безопасного состояния успех запрещён.
- **FR-007**: Проверка доступности TCP-портов MUST NOT определять результат задачи; источником результата остаются значения меню кодека.
- **FR-008**: Неизвестная модель, несовпадение модели или идентичности, изменение схемы, ошибка входа, транспорта, чтения, записи либо проверки MUST завершаться безопасно и не маскироваться как успех.
- **FR-009**: Отключённая задача MUST сохранять прежний read-only опрос TE20 без write-запросов.
- **FR-010**: Учётные данные, cookie, CSRF, необработанные ответы и внутренние адреса MUST NOT попадать в план, DOM, постоянное хранилище, аналитику, диагностику, Git или пользовательский JSON результата.
- **FR-011**: Интерфейс и Справочник MUST перечислять TE20 в одном ряду с TE30/TE40/TE50/TE60 для этой задачи и описывать реальное подтверждение TE20 без расширения на другие модели.
- **FR-012**: Существующая схема плана, выбор по домену/типу/производителю/модели и точному IP MUST сохраняться без несовместимых изменений.

### Key Entities

- **Поддерживаемая цель управления**: точная строка отдельного списка с классом, производителем, моделью и валидным IP, для которой каталог разрешает конкретную задачу.
- **Задача управления**: явный идентификатор действия, выбранный администратором для одного запуска.
- **Результат задачи**: безопасный статус, признаки фактической записи и состояния HTTP/Telnet до и после.
- **Доказательство совместимости**: подтверждённые модель, идентичность, признаки интерфейса и схема обоих параметров текущего сеанса.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% exact Huawei TE20 в отдельном списке отображаются как поддерживаемые цели при включённой задаче; неизвестные и неточные модели не получают write-capability.
- **SC-002**: В контролируемом тесте TE20 принимает единственную безопасную операцию и повторно сообщает HTTP и Telnet отключёнными.
- **SC-003**: В 100% тестов несовпадения модели, идентичности, признаков интерфейса или схемы запись не выполняется.
- **SC-004**: В 100% тестов уже безопасного TE20 задача завершается без записи.
- **SC-005**: Все существующие автоматические проверки Python, интерфейса и Справочника проходят без регрессий.
- **SC-006**: Ни один тестовый или реальный результат, отслеживаемый файл и диагностический ответ не содержит логин, пароль, cookie, CSRF, реальный IP, MAC или серийный номер контрольного устройства.

## Assumptions

- Используется существующая задача, отдельный XLSX-список целей и схема плана версии 3.
- TE20 продолжает использовать свой отдельный подтверждённый transport и точный профиль TLS; общий transport TE30–TE60 не расширяется.
- Контролируемая проверка 2026-09-08 подтвердила на реальном TE20 наличие ожидаемых признаков, чтение обоих параметров, приём минимальной безопасной записи и повторное чтение безопасных значений.
- Текущий контрольный TE20 уже находился в безопасном состоянии; для доказательства write-контракта повторно отправлялись только те же безопасные значения, без включения HTTP или Telnet.
- Другие Huawei-модели не получают capability автоматически.
