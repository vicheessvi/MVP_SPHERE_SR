# Feature Specification: Аналитика логов Huawei 310

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-11-11

**Status**: Bar 310 confirmed locally; Box 310/610 analytics confirmed by administrator 2026-11-13

**Input**: Подготовить аналитику импортированных логов Bar 310, Box 310 и Box 610 по аналогии с аналитикой Huawei TE.

## User Scenarios & Testing

### User Story 1 — Сопоставить и проверить журналы (Priority: P1)

Администратор импортирует общую папку логов. Для точной модели Bar 310, Box 310 или Box 610 с единственным IP в актуальной SR инструмент показывает, сколько журналов прошло проверку формата и сколько исключено, не сохраняя сырые строки в состоянии приложения.

**Independent Test**: Повторный импорт той же папки даёт одинаковые метаданные; нераспознанный формат и неоднозначный IP не дают событий.

**Acceptance Scenarios**:

1. **Given** корректный журнал точной 310-модели, **When** папка импортирована, **Then** устройство и файл сопоставлены, статус разбора виден.
2. **Given** чужая модель, неоднозначный IP или неподтверждённая схема, **When** файл импортирован, **Then** события не создаются и причина исключения видна.

### User Story 2 — Раздельные события (Priority: P1)

Администратор видит подтверждённые перезагрузки, зафиксированные отключения и запуски с неустановленной причиной отдельно от TE и Extron, с датой, временем, устройством, IP и контекстом SR. События создаются только по доказанным модельным маркерам.

**Independent Test**: Журнал с проверенной парой признаков перезагрузки даёт ровно одно событие; запуск без такого доказательства не увеличивает подтверждённый счётчик.

**Acceptance Scenarios**:

1. **Given** подтверждённая модельная пара «перезагрузка → запуск», **When** журнал проанализирован, **Then** показана одна перезагрузка.
2. **Given** только запуск, **When** журнал проанализирован, **Then** он показан как причина не установлена.
3. **Given** явная запись о выключении, **When** журнал проанализирован, **Then** она не смешивается с перезагрузкой и не называется аварийной потерей питания.

### Edge Cases

- Повторные выгрузки одного журнала не удваивают события; источники фиксируются без сырых строк.
- Локальное время терминала не превращается автоматически в UTC при неизвестном часовом поясе.
- Пауза между строками сама по себе не доказывает потерю питания.
- Совпадение корня XML `LogModule` с TE не означает совпадение схемы событий.
- Данные разных моделей и неподтверждённых прошивок не смешиваются.

## Requirements

### Functional Requirements

- **FR-001**: Анализ MUST принимать только точные Bar 310, Box 310, Box 610 при однозначном сопоставлении с актуальной SR.
- **FR-002**: Подтверждённое событие MUST требовать проверенного на реальном журнале модельного маркера; правила TE не наследуются автоматически.
- **FR-003**: Повторный импорт MUST быть детерминированным и не удваивать события.
- **FR-004**: Сырые строки, учётные данные и идентификаторы сеанса MUST не входить в состояние, JSON-опросы и отчёты.
- **FR-005**: Неподтверждённые запуски и паузы MUST оставаться отдельными от подтверждённых перезагрузок и отключений.
- **FR-006**: Покрытие, причины исключения, время и контекст SR MUST быть видны администратору.
- **FR-007**: Для Bar 310 действия через web и пульт ДУ MUST различаться по отдельным проверенным маркерам; одиночное нажатие пульта и внутренний restart MUST NOT считаться перезагрузкой.
- **FR-008**: После отдельного пользовательского подтверждения Box 310/610 MUST использовать точные модельные версии общего правила при совпадении модели, IP и схемы XML; подтверждённые события входят в таблицы, кольцевую диаграмму и тепловую карту. Старые предварительные результаты не переписываются.

### Key Entities

- **Импортированный журнал**: файл, модель, точный IP, статус сопоставления и проверки.
- **Событие**: тип, локальное время устройства, версия правила, устройство и метаданные источника.
- **Покрытие**: количество проверенных и исключённых файлов и неопределённых запусков.

## Success Criteria

- **SC-001**: 100% неподтверждённых схем не увеличивают подтверждённые счётчики.
- **SC-002**: Повторный импорт одних и тех же файлов сохраняет то же число событий.
- **SC-003**: Большой журнал обрабатывается последовательно без сохранения полного содержимого в состоянии приложения.
- **SC-004**: Для каждого показанного события доступны тип, локальное время, устройство и источник.

## Assumptions

- Первым исследован Bar 310. Администратор позднее отдельно подтвердил корректность аналитики Box 310 и Box 610 на рабочем ПК; модельные версии правил и строгие проверки остаются.
- Подтверждённой аналитикой считаются только перезагрузки и явные отключения; причины аварийного пропадания питания вне этого этапа.

## Validation evidence

- После самостоятельной web-перезагрузки администратором в полном Bar-журнале найдены успешная команда reboot terminal и новый System boot через ~70 секунд.
- После отдельного штатного web-выключения администратор подтвердил команду shut down terminal; при последующем включении появился System boot.
- После команды «Перезагрузить» с пульта выявлены два события кнопки питания и следующий boot; после команды «Выключение» — одно событие кнопки и отдельная команда shut down terminal. Администратор подтвердил оба действия.
- Внутренние restart компонентов не являются событиями перезагрузки. Реальные строки не сохранялись.
- 2026-11-13 администратор подтвердил правильность анализа Box 310 и Box 610; агент не сохранял их реальные журналы в проекте.
