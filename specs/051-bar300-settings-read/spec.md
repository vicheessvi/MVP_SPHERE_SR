# Feature Specification: Чтение настроек Huawei CloudLink 300

**Feature Branch**: `codex/secure-local-runtime`
**Created**: 2026-11-13
**Status**: Администратор подтвердил успешные опросы и совпадение новых значений с меню Bar 300, Box 300 и Box 600
**Input**: Добавить в обычный JSON-опрос Bar 300 новые фактические настройки и подготовить те же read-only чтения для Box 300/600 без изменения устройств.

## User Scenarios & Testing

### User Story 1 — Получить фактические настройки (Priority: P1)

Администратор запускает обычный опрос точного Bar 300, Box 300 или Box 600 и получает в JSON значения HTTP, Telnet, SNMP v2, автообновления, автоответа, NTP, Wi-Fi, SSH и питания, если текущий bundle и строгая схема конкретной модели это подтверждают. Администратор сверил новые значения Box 300/600 с меню; новые результаты подтверждены, исторические предварительные файлы не переписываются. Неизвестное показывается явно, не подменяется «Отключено».

**Independent Test**: Для проверенного HTTP состояние меню и JSON совпадает; отсутствие маркера текущей прошивки не создаёт ложного факта.

### User Story 2 — Использовать факты в локальной аналитике (Priority: P2)

Подтверждённые поля из последнего успешного JSON сохраняются при импорте и могут попасть в локальную таблицу фактических настроек. Неподтверждённые поля не становятся фактами.

**Independent Test**: Подтверждённый HTTP остаётся после импорта, а чужая модель или неподтверждённый источник исключаются.

### Edge Cases

- Только exact Box 300/600 используют общий read-only reader после собственных pre-/post-auth model/identity gates; после пользовательской проверки новые значения помечаются `confirmed_user_validation`, старые provisional-файлы сохраняют исходный статус. Суффиксные и прочие модели не наследуют чтение.
- Неполный ответ, неизвестный код или изменение текущего web-интерфейса оставляют поле неизвестным.
- Учётные данные, CSRF, SSID и чувствительные строки не входят в аналитический результат.
- Опрос остаётся только на чтение; переключение настроек не входит в эту feature.

## Requirements

- **FR-001**: Новое поле MUST читаться только после точной проверки модели и устойчивой идентичности.
- **FR-002**: Каждый параметр MUST иметь подтверждённый способ чтения и схему значения перед добавлением в JSON; неподтверждённые параметры MUST сохранять `protocol_required`/`unavailable`/`not_exposed` по доказательствам.
- **FR-003**: Поля MUST проверяться и вводиться последовательно, без переноса семантики Bar 310/TE20 по названию.
- **FR-004**: Импорт MUST сохранять только модельно допустимые источники и не принимать выдуманные факты.
- **FR-005**: Обычный опрос MUST оставаться read-only и не сохранять секреты.

### Key Entities

- **SettingFact**: поле, статус, нормализованное значение, точный источник и модель.
- **SettingEvidence**: маркер текущего web-интерфейса, прочитанный код и проверенное значение в меню.

## Success Criteria

- Все добавленные подтверждённые значения совпадают с меню в контрольном опросе Bar 300.
- При отсутствующем маркере или неизвестном коде подтверждённый факт не создаётся.
- Box 300/600 получают предварительные поля только при точной модели, собственных gates и текущих bundle-маркерах; другие модели и неподтверждённые поля их не получают.
- Секреты отсутствуют во всех новых результатах и фикстурах.

## Assumptions

- Под «новыми параметрами» понимаются девять ключей текущего `deviceSettings`; Site name уже реализован отдельно.
- Для exact Bar 300 текущие значения всех девяти ключей `deviceSettings` поочерёдно проверены: часть переключателей прошла ручные обратные циклы, а включённые состояния питания и альтернативные серверы пока подтверждены схемой web-интерфейса и синтетическими тестами, без изменения устройства. Администратор сообщил об аналогичной структуре Box 300/600; их фактические новые значения и схемы на реальных устройствах ещё не проверены.
