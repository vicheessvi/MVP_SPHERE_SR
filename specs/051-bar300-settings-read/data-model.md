# Модель данных

`deviceSettings.fields.<key>`: `status`, `value`, `source`. Для HTTP, Telnet, SSH и autoAnswer exact Bar 300 допустимы `read/enabled`, `read/disabled`, `protocol_required` либо `unavailable`. У autoAnswer `enabled=Авто`, `disabled=Вручную`. При импорте read-факт принимается только при совпадении точной модели и разрешённого источника. Остальные ключи сохраняют прежнее неизвестное состояние до собственного подтверждения.

`deviceSettings.fields.ntp.value`: `enabled` (boolean), `modeCode` (0/1), `mode` (`automatic`/`manual`), `server` (строка, локальные инфраструктурные данные). В результате и локальном отчёте строка допускается только при точном модельном источнике; в инструментах диагностики, документации и фикстурах реальные имена серверов не сохраняются.

`deviceSettings.fields.wifi.value`: `modeCode` (целое 0–3), `clientEnabled`, `accessPointEnabled` (boolean). Источник только `WEB_GetWifiStatModeAPI:ucWifiMode` после exact Bar 300 model/identity. При импорте комбинация boolean должна точно соответствовать коду: 0 — оба выключены, 1 — точка доступа, 2 — клиент, 3 — оба включены. Коды 0/1/2 сверены независимыми ручными циклами с возвратом к 0; код 3 пока подтверждён только текущим bundle. SSID, MAC и пароли из ответа не копируются.

`deviceSettings.fields.snmpV2` для exact Bar 300: `status=not_exposed`, `value=null`, `reason=version_not_supported`. Основание — подтверждение администратора, что в меню этой модели SNMP v2 отсутствует, а SNMP v3 указан по умолчанию. Это не утверждение о работе службы SNMP v3, открытом порте или применимости к Box 300/600.

`deviceSettings.fields.autoUpdate` для exact Bar 300: `status=read`, `value=disabled` при `serverTypeCode=7` либо `enabled` при другом коде из текущего списка `{2,5,6,8,10,11}`; `source=WEB_GetCfgParamAPI:cloudType`, `basis=server_type_audit_rule`, `ruleVersion=bar300-cloud-type-audit-v1`, `meaning=firmware_update_capability`. Ручной код 7 подтверждён живым опросом и меню «Руководство» (= «Вручную»); другие варианты пока проверены синтетически. Неизвестный код/изменённый bundle не становится фактом. Это возможность обновления прошивки, не факт уже выполненного обновления.

`deviceSettings.fields.powerManagement` для exact Bar 300 содержит `sleepTimeCode` из `{0,1,5,10,15,30,60}` и `sleepMode=never|interval`; при отдельном успешном чтении добавляются boolean `networkWakeEnabled`, `faceWakeEnabled`, `clearMemoryInSleepEnabled`, `automaticRestartEnabled`. Источник начинается с `WEB_GetCfgParamAPI:sleepTime`, затем перечисляет только реально прочитанные ID в порядке `enable_wol,faceWakeUp,sleepCloseAPP,autoReboot`; `unconfirmedFields` выводится из отсутствующих фактов, не доверяется содержимому файла. На контрольном Bar 300 код сна 10 = 10 минут, все четыре switch-кода 0 совпали с меню «Запрещать». Коды 1 следуют форме без реальных циклов. Если автоперезапуск включён, `automaticRestartIntervalDays` остаётся неподтверждённым, пока не будет отдельно прочитан `autoRebootVal`; при выключенном режиме период неактивен и не запрашивается. Скрытый `suppotReboot` не подменяется видимыми полями.

Для exact Box 300/Box 600 те же read-only поля доступны только после собственных model/identity gates и маркеров их текущего bundle. У `deviceSettings` и каждого `status=read` поля выставляется `validationStatus=provisional_user_validation`; импорт принимает их только при точной Box-модели и совпадении обоих маркеров. Обычные опросы и Site name этих моделей ранее подтверждены отдельно, но это не подтверждает новые настройки. `snmpV2` остаётся `not_exposed` без уточнённой причины Bar 300 до проверки на каждой Box.
