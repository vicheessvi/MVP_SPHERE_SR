# Проверка

1. В локальном runtime выбрать exact Bar 300 в актуальной SR и выполнить обычный JSON-опрос.
2. Сверить `deviceSettings.fields.http`: `status=read`, `value=disabled` при текущем «HTTP выключено», источник `WEB_GetCfgParamAPI:enable_http`.
3. Убедиться, что Box 300/600 не наследуют поле, а отсутствие marker/неизвестный код не создают факт.
4. После подтверждения администратором следующего параметра повторить модельную проверку и обновить контракт.
5. Контрольный цикл на Bar 300 завершён: администратор вручную включил HTTP, read-only опрос показал код 1/«Включено», затем вернул «Выключено», что повторный опрос подтвердил кодом 0. Инструмент настройки не менял.
6. Telnet проверен полным контрольным циклом: администратор вручную включил его, read-only опрос дал `enabletelnet=1`/`enabled`, затем администратор выключил, обновил страницу, повторный опрос дал `0`/`disabled`. Инструмент не отправлял команд записи и не читал соседние пароли.
7. SSH проверен полным контрольным циклом: администратор вручную выключил его, read-only опрос дал `enable_ssh=0`/`disabled`, затем администратор вернул «Включено», обновил страницу, повторный опрос дал `1`/`enabled`. Инструмент не отправлял команд записи и не читал соседние пароли.
8. Автоответ проверен полным контрольным циклом: администратор вручную выбрал «Вручную», read-only опрос дал `autoreply=1`/`disabled`, затем вернул исходное «Авто», повторный опрос дал `0`/`enabled`. Инструмент не отправлял команд записи.
9. NTP Bar 300: синхронизация и режим проверены отдельными ручными циклами `1→0→1`; read-only опрос после возврата даёт `enabled=true`, `modeCode=1`, прежний сервер присутствует. Администратор сверил адрес в меню; сам адрес в чат не выводить. Инструмент не отправлял команд записи.
10. Wi‑Fi Bar 300: при двух «Запрещать» статусный read-only запрос с CSRF даёт `modeCode=0`, `clientEnabled=false`, `accessPointEnabled=false`. Клиент проверен циклом `0→2→0`, точка доступа — отдельным циклом `0→1→0`; каждое восстановление подтверждено повторным чтением. Код 3 ещё не проверен. Широкий Wi‑Fi config endpoint с SSID/паролем не вызывать.
11. SNMP v2 Bar 300: по подтверждению администратора в меню этой модели версия отсутствует, по умолчанию указан SNMP v3. Проверить в JSON `snmpV2.status=not_exposed`, `reason=version_not_supported`; не трактовать это как состояние SNMP v3 или порта.
12. Автообновление Bar 300: при «Тип сервера: Вручную» (на снимке «Руководство») живой read-only опрос даёт `autoUpdate.status=read`, `value=disabled`, `serverTypeCode=7`, `meaning=firmware_update_capability`. Другие коды текущего списка проверены синтетически как `enabled`; не переключать сервер на действующем терминале ради этой проверки без отдельного разрешения.
13. Питание Bar 300: сохранённый интервал сна подтверждён как 10 минут; итоговый JSON содержит `powerManagement.value.sleepTimeCode=10`, `sleepMode=interval`. Другие переключатели не трактовать по снимку как прочитанные — для них нужны отдельные узкие чтения.
14. Wake-on-LAN Bar 300: при меню «Запрещать» узкий запрос `enable_wol` и итоговый JSON дали `networkWakeEnabled=false`. Если чтение WOL отсутствует, сон остаётся прочитанным, а WOL — в `unconfirmedFields`; код 1 пока только в web-форме.
15. Пробуждение по лицу, очистка во сне и автоперезапуск: три отдельных read-only кода 0 совпали со снимком; контрольный JSON содержит три `false`. При будущем `autoReboot=true` период в днях не считать подтверждённым без отдельного `autoRebootVal`.
16. Box 300/600: выбрать каждую модель отдельно по актуальной SR и выполнить обычный JSON-опрос на реальном устройстве. Сверить HTTP, Telnet, SSH, автоответ, NTP, Wi‑Fi, тип сервера и питание с меню; до такой проверки новые поля имеют `provisional_user_validation` и в аналитике показываются как «Требует проверки». Site name и обычный статус опроса сохраняют свой ранее подтверждённый статус.
