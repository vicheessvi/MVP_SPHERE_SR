# Research: Адресный опрос и фильтр домена

## Decision 1: Два явных режима выбора

**Decision**: Использовать `filters` и `single_ip` как взаимоисключающие режимы одного плана.

**Rationale**: Адресная цель и массовое пересечение имеют разные правила валидности. Явный режим исключает ситуацию, когда введённый IP незаметно пересекается с выбранными фильтрами или расширяет их.

**Alternatives considered**: Постоянное поле IP поверх каскада отклонено из-за неясной семантики AND/OR; отдельный модуль отклонён как дублирование расписания, credentials и output workflow.

## Decision 2: Только точный unique current-SR lookup

**Decision**: Нормализовать введённый IPv4 существующим правилом и искать строгое равенство `ipNormalized` только среди актуальных устройств. Ровно одно совпадение выбирается; ноль или несколько блокируют план.

**Rationale**: Это сохраняет exact-IP allowlist и исключает уже исправленную ошибку сопоставления соседних или исторических адресов.

**Alternatives considered**: Произвольный IP вне SR отклонён как расширение сетевых полномочий; historical IP и fuzzy matching отклонены как риск ошибочного устройства; автоматический выбор первой duplicate-строки отклонён как нарушение идентичности.

## Decision 3: Карточка строится из memory SR

**Decision**: Показывать карточку найденного устройства и связанной локации без обращения к устройству. Карточка содержит SR identity/network/location/domain и текущий capability descriptor.

**Rationale**: Пользователь проверяет цель до сети, а чувствительные данные не покидают локальную вкладку.

**Alternatives considered**: Предварительный ping/web discovery отклонён, потому что ввод IP не должен сам запускать сетевую операцию.

## Decision 4: Домен — первый каскадный уровень

**Decision**: Массовый порядок становится Домен → Тип оборудования → Производитель → Модель. Каждый уровень сохраняет прежнюю модель multi-select и `Все`; пустое значение представляется существующим `__not_specified__`.

**Rationale**: Домен сужает все последующие варианты и естественно дополняет текущий алгоритм без изменения пересечения измерений.

**Alternatives considered**: Домен после модели отклонён как неудобный поздний фильтр; независимый фильтр без пересчёта дочерних options отклонён из-за возможности скрытых пустых выборок.

## Decision 5: Plan v2 и Python-runtime не меняются

**Decision**: В memory plan сохранять `selection.mode`, а для массового режима также `selection.domains`; адресная строка IP не дублируется. `deviceIds` и экспортируемый `devices[]` остаются единственным источником сетевых целей.

**Rationale**: Server уже строит exact allowlist из `devices[]`, rejects duplicate IP и не зависит от UI selection metadata. Это минимальное совместимое расширение.

**Alternatives considered**: Plan v3 отклонён — runtime-контракт не требует изменения; отдельный endpoint lookup отклонён как ненужная сеть и дополнительная поверхность атаки.
