# Feature Specification: Адресный опрос и фильтр домена

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-09-05

**Status**: Implemented

**Input**: User description: "Добавить в План автоматического опроса выбор конкретного устройства по IP с карточкой устройства и фильтрацию устройств по столбцу «Домен» выгрузки SR без изменения существующей логики фильтров."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Опрос одного устройства по IP (Priority: P1)

Администратор МЦТП переключает План автоматического опроса в режим конкретного устройства, вводит IP-адрес из актуальной выгрузки SR, проверяет открывшуюся ниже карточку и запускает опрос только найденного устройства.

**Why this priority**: Адресный запуск позволяет быстро проверить или повторно опросить одно устройство, не строя широкий набор фильтров.

**Independent Test**: Загрузить SR с несколькими устройствами, ввести точный уникальный IP поддерживаемого устройства и убедиться, что показана его карточка, а сформированный план содержит ровно это устройство.

**Acceptance Scenarios**:

1. **Given** актуальная SR содержит одно устройство с введённым IP, **When** администратор вводит полный корректный адрес, **Then** ниже поля появляется карточка этого устройства с данными SR и статусом поддержки опроса.
2. **Given** карточка показывает поддерживаемое устройство, выбраны папка результатов и учётные данные, **When** администратор формирует план, **Then** план содержит ровно это устройство и использует существующий порядок запуска, сохранения JSON и подтверждения записи.
3. **Given** IP некорректен или отсутствует в актуальной SR, **When** администратор завершает ввод, **Then** интерфейс сообщает причину, не показывает чужое устройство и не позволяет сформировать сетевой план.
4. **Given** один IP указан у нескольких актуальных устройств, **When** администратор вводит этот IP, **Then** система сообщает о неоднозначности и не выбирает ни одно устройство автоматически.

### User Story 2 - Фильтрация плана по домену (Priority: P2)

Администратор МЦТП формирует массовый план и ограничивает устройства одним, несколькими или всеми доменами из столбца «Домен» актуальной SR, после чего продолжает использовать существующие фильтры типа оборудования, производителя и модели.

**Why this priority**: Домен позволяет запускать опрос по организационным или инфраструктурным сегментам без ручного выбора отдельных устройств.

**Independent Test**: Загрузить SR как минимум с двумя доменами, выбрать один домен и убедиться, что варианты и итоговый набор последующих уровней содержат только устройства этого домена.

**Acceptance Scenarios**:

1. **Given** актуальная SR содержит несколько доменов, **When** выбран один домен, **Then** типы, производители, модели и итоговые устройства ограничиваются его устройствами.
2. **Given** выбрано несколько доменов, **When** остальные уровни установлены в «Все», **Then** план содержит объединение устройств выбранных доменов без дублей.
3. **Given** выбран пункт «Все», **When** формируется план, **Then** поведение по числу устройств совпадает с прежним массовым планом без доменного ограничения.
4. **Given** в SR есть устройства без значения домена, **When** выбран вариант «Не указано», **Then** в итог входят только такие устройства.
5. **Given** изменение домена исключает ранее выбранного производителя или модель, **When** каскад пересчитывается, **Then** недоступные дочерние значения очищаются по прежнему правилу.

### User Story 3 - Сохранение прежней логики и безопасности (Priority: P3)

Администратор может переключаться между адресным и массовым режимами без изменения существующих правил поддержки адаптеров, exact-IP allowlist, учётных данных, расписания, интервала, TLS-разрешения и локального сохранения результатов.

**Why this priority**: Новые способы выбора цели не должны расширять сетевые полномочия или нарушать уже работающие алгоритмы Extron и Huawei TE40.

**Independent Test**: Сформировать эквивалентный план через массовые фильтры и через адресный режим, проверить одинаковое описание выбранного устройства и отсутствие секретов в обоих экспортируемых планах.

**Acceptance Scenarios**:

1. **Given** пользователь возвращается в массовый режим, **When** выбирает «Все» на всех уровнях, **Then** прежний сценарий формирования массового плана работает без изменения результата.
2. **Given** найденное по IP устройство не имеет подтверждённого адаптера, **When** показана карточка, **Then** статус «не поддерживается» видим, а запуск не выполняет сетевой запрос.
3. **Given** план сформирован любым режимом, **When** он передаётся локальному исполнителю, **Then** в нём отсутствуют логины, пароли и иные секреты.

### Edge Cases

- Ввод содержит пробелы вокруг IP или ведущие нули в октете.
- IP относится к исторической записи, но отсутствует среди устройств актуальной SR.
- Один нормализованный IP встречается более одного раза в актуальной SR.
- После повторного импорта SR выбранный IP или домен исчезает.
- Домен отличается только регистром или лишними пробелами.
- Устройство имеет домен на записи устройства и/или на связанной локации.
- В домене присутствуют символы, требующие безопасного HTML-экранирования.
- Выбранный домен содержит только неподдерживаемые устройства или устройства без IP.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: План автоматического опроса MUST предоставлять взаимоисключающие режимы «По фильтрам» и «По IP-адресу».
- **FR-002**: Адресный режим MUST принимать один IPv4-адрес и нормализовать его по тем же правилам, что и IP из SR.
- **FR-003**: Адресный режим MUST искать совпадение только среди устройств актуальной SR и только по точному нормализованному IP.
- **FR-004**: При одном совпадении MUST отображаться карточка с названием, категорией, производителем, моделью, IP/MAC, доменом, локацией/адресом, инвентарным/серийным номером и статусом поддержки опроса.
- **FR-005**: При отсутствии, некорректности или неоднозначности IP MUST отображаться безопасное объяснение, а выбранный набор MUST быть пустым.
- **FR-006**: План, сформированный в адресном режиме, MUST содержать ровно идентификатор единственного найденного устройства и MUST NOT включать введённый IP как отдельную дублирующую сохранённую настройку.
- **FR-007**: В массовом режиме MUST появиться уровень «Домен» перед существующими уровнями «Тип оборудования», «Производитель» и «Модель».
- **FR-008**: Доменный уровень MUST поддерживать один, несколько, «Все» и «Не указано» по тем же правилам выбора, что и остальные уровни.
- **FR-009**: Значения домена MUST сравниваться после безопасной нормализации регистра и пробелов, при этом исходное отображаемое значение MUST сохраняться.
- **FR-010**: Доменный выбор MUST ограничивать доступные значения всех последующих уровней и итоговый набор устройств.
- **FR-011**: Изменение родительского уровня MUST очищать недоступные дочерние значения и не создавать пустые или скрытые цели.
- **FR-012**: Выбор «Все домены» MUST сохранять прежний результат массового плана при одинаковых остальных фильтрах.
- **FR-013**: После повторного импорта SR выбор MUST пересчитываться по актуальным устройствам; исчезнувшие IP и домены MUST безопасно сбрасываться.
- **FR-014**: Оба режима MUST использовать существующие правила поддержки адаптеров, расписания, интервала, учётных данных, TLS, exact-IP allowlist и сохранения JSON.
- **FR-015**: Прямой запуск `index.html` MUST оставаться ручным режимом без сетевого опроса.
- **FR-016**: Сформированный план и его диагностические данные MUST NOT содержать логины, пароли, cookie, токены или иные секреты.
- **FR-017**: Пользовательская документация и «Справочник» MUST описывать адресный режим и доменный уровень фильтрации.

### Key Entities

- **Режим выбора плана**: Определяет массовый каскад или точный выбор по IP; существует только в текущем локальном сеансе и в безопасном описании плана.
- **Адресная цель**: Результат точного поиска в актуальной SR со статусом пусто, некорректно, не найдено, неоднозначно или найдено.
- **Доменный фильтр**: Нормализованный набор доменных значений, ограничивающий последующий каскад массового плана.
- **Карточка цели**: Непостоянное представление уже загруженных данных SR и статуса адаптера без сетевого запроса.
- **План автоматического опроса**: Существующая локальная сущность с набором device ID, расписанием, интервалом и обезличенной ссылкой на источник учётных данных.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: После ввода полного уникального IP карточка правильного устройства появляется не позднее 300 мс для SR до 25 000 устройств.
- **SC-002**: Адресный план всегда содержит ровно одно выбранное устройство; некорректный, отсутствующий или неоднозначный IP приводит к нулю целей и нулю сетевых обращений.
- **SC-003**: Для каждого набора доменных фильтров итоговое число устройств в 100% контрольных сценариев равно пересечению домена, типа, производителя и модели.
- **SC-004**: Выбор «Все домены» даёт тот же набор и порядок устройств, что и прежний массовый план, в 100% регрессионных сценариев.
- **SC-005**: Пересчёт четырёхуровневого каскада для 25 000 устройств завершается менее чем за 2 секунды на контрольной рабочей станции.
- **SC-006**: В 100% адресных и доменных планов отсутствуют логины, пароли, cookie, токены и прочие секреты.
- **SC-007**: Все существующие проверки Extron, Huawei TE40, ручного импорта, последовательного выполнения и записи JSON остаются успешными.

## Assumptions

- IP, отсутствующий в актуальной SR, не может быть введён как произвольная новая сетевая цель.
- Несколько актуальных устройств с одним IP считаются конфликтом данных и не выбираются автоматически.
- Домен берётся из нормализованного поля устройства; значение локации используется только для отображения и не расширяет выбор за пределы строки SR.
- Переключение режима не запускает сеть и не загружает дополнительные данные; карточка строится только из текущей SR.
- Фильтры массового режима сохраняются в памяти при временном переключении на адресный режим.
- Поддержка IPv6 не входит в эту feature.
