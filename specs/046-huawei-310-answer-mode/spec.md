# Feature Specification: Управление Answer mode Huawei 310

**Feature Branch**: `codex/secure-local-runtime`
**Created**: 2026-11-10
**Status**: Реализовано; оба направления Bar 310 подтверждены, Box 310/610 write ожидает проверки
**Input**: Добавить для exact Huawei CloudLink Bar 310, Box 310 и Box 610 отдельное управление Answer mode: «Не менять», «Автоматически — включить автоответ», «Вручную — отключить автоответ». Контрольный опыт проводится на подключённом Bar 310.

## User Scenarios & Testing

### User Story 1 — Выбрать режим ответа (Priority: P1)

Администратор выбирает один точный терминал по IP из текущей SR и одно из трёх состояний. «Не менять» оставляет обычный read-only опрос. При выборе изменения инструмент показывает последствия, требует отдельного согласия и фиксирует результат.

**Independent Test**: Формирование плана для каждой точной модели даёт ноль задач при «Не менять» и ровно одну модельную задачу для каждого направления.

**Acceptance Scenarios**:

1. **Given** «Не менять», **When** запускается опрос, **Then** настройки устройства не записываются.
2. **Given** один выбранный exact Bar 310/Box 310/Box 610 и явное согласие, **When** выбран новый режим, **Then** выполняется не более одной ограниченной записи и повторное чтение подтверждает нужное значение.
3. **Given** текущее значение уже равно целевому, **When** выполняется задача, **Then** запись не отправляется, а статус «уже соответствует» виден.

### User Story 2 — Не изменить чужое устройство (Priority: P1)

Управление недоступно для другой модели, нескольких устройств или несовместимого web-интерфейса. Сбой чтения или подтверждения не превращается в успех.

**Independent Test**: Неверная модель, неподтверждённая схема, неоднозначный IP и конфликт задач блокируют запись.

**Acceptance Scenarios**:

1. **Given** другая либо суффиксная модель, **When** выбрана задача, **Then** она не включается в план и запись невозможна.
2. **Given** данные устройства или схема ответа изменились, **When** исполнитель пытается выполнить задачу, **Then** запись блокируется либо отмечается ошибка проверки без повтора.

### Edge Cases

- Изменение режима ответа влияет на обработку входящих вызовов.
- Две противоположные задачи или совмещение с HTTP/другими write-задачами запрещены.
- Если связь пропала после записи, автоматически повторять неясную операцию нельзя.
- Исторические JSON и обычный read-only опрос остаются неизменными.
- Bar 310 проверяется отдельно; Box 310 и Box 610 сохраняют предварительный статус write-задачи до своих испытаний.

## Requirements

### Functional Requirements

- **FR-001**: Интерфейс MUST предлагать для точной группы Huawei 310 «Не менять», «Автоматически» и «Вручную», сохраняя «Не менять» по умолчанию.
- **FR-002**: Write-задача MUST требовать один exact IP из актуальной SR, одну модель, отдельное согласие и несовместимость с другими write-задачами.
- **FR-003**: Исполнитель MUST проверять модель и идентичность до записи, читать только выбранный параметр до изменения, отправлять максимум одну минимальную запись и проверять значение после неё.
- **FR-004**: Неверный код, отсутствующий маркер, неподтверждённая схема или неясный post-read MUST давать безопасный отказ, не успех.
- **FR-005**: Box 310 и Box 610 MUST иметь независимый предварительный статус записи до пользовательской проверки; обычные read-only значения, уже подтверждённые на Box, не понижаются.
- **FR-006**: Пароли, токены и сырые ответы MUST не сохраняться в JSON, логах или репозитории.

### Key Entities

- **Answer mode action**: точная модель, целевой режим, статус записи и результат проверки.
- **План одного устройства**: IP из SR, один выбранный write action и согласие администратора.

## Success Criteria

- **SC-001**: Для каждой точной модели три варианта выбора формируют ожидаемые планы; непроверенные варианты не создают write.
- **SC-002**: В тестах на одно действие приходится не более одной команды записи, а несовпадение post-read никогда не выдаётся за успех.
- **SC-003**: Неверная/суффиксная модель и конфликт задач блокируются до записи в 100% негативных сценариев.
- **SC-004**: Контрольное изменение Bar 310 подтверждается текущим web-меню и машинным чтением; Box остаются предварительными до отдельных проверок.

## Assumptions

- Точная схема чтения `autoreply` и её семантика на Bar 310 уже проверены; запись должна пройти отдельный evidence review текущего bundle.
- Пользователь отдельно укажет первый целевой режим для контрольной записи, прежде чем она будет отправлена.
