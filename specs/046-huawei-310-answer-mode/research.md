# Research: Answer mode Huawei 310

## Decision

Exact Bar 310 уже имеет проверенный read-only `POST /v1/om/config` с `CfgIDString=["autoreply"]`. Администратор ранее провёл контролируемый цикл web-меню «Автоматически → Вручную → Автоматически»; три машинных чтения дали `1 → 0 → 1` после сохранения и обновления страницы. Это модельная кодировка Huawei 310, не кодировка TE. В текущем Bar bundle дополнительно подтверждены `reqSaveCfgUrl="/v1/om/config"` и точный `CfgItemID:"autoreply"`; перед записью исполнитель повторно проверит эти маркеры, модель и идентичность.

Планируетcя только PUT `CfgItemInt=[{CfgItemID:"autoreply",CfgItemInfo:0|1}]`, `CfgItemString=[]`, после точного pre-read и только при отличии. Значение post-read обязано совпасть; ошибка или drift — отказ, повтор write автоматически запрещён. Обычный опрос сохраняет read-only режим.

## Validation boundary

Read-only проверка Bar после явного разрешения администратора подтвердила точную модель, исходное «Автоматически» и маркеры read/save. Затем администратор отдельно разрешил `automatic → manual` и после проверки web-меню — обратный `manual → automatic`. Каждый переход дал одну запись и точный post-read, оба значения подтверждены администратором после обновления web-страницы. Исходный автоматический режим восстановлен. Сырые ответы, реальный адрес и credentials не сохранялись в проекте. Box 310/610 используют тот же общий transport, но их write-семантика остаётся `provisional_user_validation` до отдельных опытов.

## Alternatives rejected

Использовать TE-коды 0=автоматически/1=вручную, массовый write, совмещать с HTTP или записывать без pre/post-read — отклонено из-за риска неправильного режима входящих вызовов.
