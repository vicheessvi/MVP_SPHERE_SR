# Feature Specification: Фактические настройки Huawei CloudLink Bar 310

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-11-10

**Status**: Confirmed read fields implemented and cross-checked on one exact Bar 310; other firmware variants remain untested

**Input**: При обычном опросе Huawei CloudLink Bar 310 все применимые новые параметры должны считываться с устройства и попадать в JSON с фактическими значениями; отсутствие функции и невозможность прочитать её должны различаться.

## User Scenarios & Testing

### User Story 1 — Полный фактический снимок настроек (Priority: P1)

Администратор запускает обычный опрос точного Bar 310 и получает в результате значения HTTP, режима ответа, синхронизации времени и адреса сервера, Wi‑Fi, SSH и управления питанием. Для каждого значения видны источник и статус чтения. Site name считывается как отдельное поле.

**Why this priority**: Только фактические значения пригодны для сверки настроек и аналитики.

**Independent Test**: На подключённом Bar 310 сверить каждое поле нового результата с соответствующим пунктом его web-интерфейса, не изменяя настройки.

**Acceptance Scenarios**:

1. **Given** успешный опрос точного Bar 310, **When** устройство отвечает по подтверждённому контракту, **Then** все применимые поля содержат фактическое значение и источник чтения.
2. **Given** поле недоступно в текущей прошивке или ответ не соответствует ожидаемой схеме, **When** опрос завершён, **Then** значение остаётся неизвестным и причина видна без подстановки значения по умолчанию.

### User Story 2 — Безопасная модельная граница (Priority: P1)

Администратор может доверять, что учётные данные направляются только выбранному Bar 310 после проверки модели, а обычный опрос не меняет его настройки.

**Independent Test**: При другой модели или несовместимом web-интерфейсе опрос прекращается без чтения новых ресурсов и без записи настроек.

**Acceptance Scenarios**:

1. **Given** по выбранному адресу отвечает не Bar 310, **When** начинается опрос, **Then** новые значения не формируются и учётные данные не отправляются этому устройству.
2. **Given** корректный Bar 310, **When** выполняется обычный опрос, **Then** не происходит команд изменения настроек.

### Edge Cases

- Отсутствующая у модели функция отличается от ошибки чтения существующей функции.
- Разные версии прошивки могут возвращать разные схемы; непроверенная схема не даёт вымышленного значения.
- Секреты, токены, беспроводные ключи и учётные данные не входят в результат.
- Независимое поле может оказаться недоступным без потери уже прочитанных полей.

## Requirements

### Functional Requirements

- **FR-001**: Обычный опрос точного Bar 310 MUST читать все доступные на модели фактические параметры из согласованного набора: HTTP, автоответ, NTP с режимом и сервером, Wi‑Fi, SSH, управление питанием и Site name.
- **FR-002**: Для Telnet и SNMP v2 MUST сохраняться явный модельный статус отсутствия только там, где отсутствие функции подтверждено; статус отсутствия не равен измеренному состоянию порта или протокола. Для exact Bar 310 «Автообновление» MUST вычисляться по выбранному типу сервера: «Вручную» — возможность обновления прошивки отключена, другой подтверждённый вариант меню — включена. Это подтверждённый администратором признак возможности обновления, но не доказательство того, что обновление уже выполнялось.
- **FR-003**: Каждое прочитанное значение MUST иметь подтверждённый источник и проверенную схему; неизвестное MUST оставаться неизвестным.
- **FR-004**: Опрос MUST быть только на чтение и MUST сохранять проверки точной модели и идентичности до чтения новых полей.
- **FR-005**: Устройство, учётные данные, токены и исходные ответы MUST оставаться локальными; секреты MUST не попадать в результат.
- **FR-006**: Существующие результаты обычного опроса и чтение HTTP MUST продолжать работать при частичной недоступности новых полей.

### Key Entities

- **Настройка устройства**: имя поля, фактическое значение, статус чтения, источник.
- **Результат опроса**: модель и подтверждённая идентичность, набор настроек, время чтения, диагностические статусы без секретов.

## Success Criteria

- **SC-001**: На подключённом Bar 310 значения каждого применимого поля совпадают с web-интерфейсом в контрольном read-only опросе.
- **SC-002**: Для неподтверждённого или отсутствующего поля результат не содержит догадки; в 100% таких случаев виден статус неопределённости или отсутствия.
- **SC-003**: Регрессионные проверки подтверждают отсутствие изменений настроек и сохранение прежних полей опроса.

## Assumptions

- Область первого этапа — только точная модель Bar 310; Box 310/610 не наследуют новые запросы без отдельной проверки.
- Термины «все параметры» означают все применимые параметры из согласованного ранее набора, а не произвольные поля web-интерфейса.
