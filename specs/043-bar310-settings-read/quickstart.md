# Quickstart / acceptance

1. На точном Bar 310 с согласованным HTTPS-сеансом выполнить обычный read-only опрос; не включать задачи изменения настроек.
2. Сверить каждое фактически прочитанное поле JSON с соответствующим пунктом web-меню устройства. Отдельно сверить Site name и составные значения NTP/Wi‑Fi/питания.
3. Проверить, что `null` не отображается как «Отключено», а источник и статус каждого значения видны.
4. Проверить дрейф схемы, другую модель по выбранному IP, частичную недоступность и отсутствие маркера в bundle: новые поля не угадываются, существующий HTTP сохраняется.
5. Проверить отсутствие write-запросов, секретов в JSON, логах и fixtures.
6. Запустить Python-регрессию, `node tests.js`, `node scripts/validate-reference.js` и синтаксические проверки.
7. Для «Автообновления» на exact Bar 310 сверить меню «Сервер → Основные службы → Тип сервера»: «Вручную» даёт `disabled` с `basis=server_type_audit_rule` и `meaning=firmware_update_capability`. Ветка SMC/SMC2.0 синтетически проверяется без переключения рабочего устройства. Значение подтверждает возможность обновления прошивки по принятому правилу, но не факт уже выполненного обновления.
