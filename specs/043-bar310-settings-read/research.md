# Research: фактические настройки Bar 310

## Current evidence

- Контролируемый обычный опрос exact Bar 310 прошёл успешно; HTTP прочитан как `disabled`, основные ресурсы без ошибок. Site name и остальные применимые новые поля сохранились как `protocol_required`/`null`.
- В коде подтверждён только запрос `enable_http` через текущий management contract. Он не доказывает значения других полей.
- Официальная [страница Huawei](https://e.huawei.com/pl/products/enterprise-collaboration/cloudlink/cloudlink-bar-310) подтверждает наличие встроенного Wi‑Fi у Bar 310, но не публикует схемы машинного чтения остальных настроек.
- Ранее администратор вручную указал разделы web-интерфейса для автоответа, NTP, Wi‑Fi, SSH и питания. Пути меню не являются подтверждением идентификаторов машинного API.

## Decision

Новые поля читать только после exact Bar 310 model/identity gate. Для каждого поля установить точный параметр и схему по текущему bundle и контролируемому ответу, затем сверить семантику с web-меню. Не копировать названия параметров или запросы из TE/Box без доказательства.

Контролируемое чтение на точном Bar 310 подтвердило read-form `POST /v1/om/config` с узким `CfgIDString`: `sitename`, `autoreply`, `synSerTime`/`ntpGetMode`/`ntpServerAddr`, `enableWifi`/`apEnable`/`isWifiPriority`, `enable_ssh`, `suppotReboot`/`sleepTime`/`autoReboot`/`sleepCloseAPP`/`autoRebootVal`/`savePowerMode`. Все группы вернули `success=1` и прямой объект с запрошенными ключами; сырые ответы, имена сайта/сервера, адрес и учётные данные не сохранены в проекте. Для NTP текущий bundle показывает `synSerTime` 1=включено/0=выключено и `ntpGetMode` 0=авто/1=вручную; SSH показывает 1=включено/2=выключено (не переносить код TE); `sleepTime` 0=никогда либо 1/5/10/15/30/60 минут. Для Wi‑Fi используются отдельные клиент/AP/приоритетные флаги, для питания — отдельные подтверждённые флаги и периодический перезапуск. Обычный опрос до изменения кода не читал эти значения.

Отдельный контролируемый опыт администратора выявил, что статические опции `autoreply` в китайской части bundle нельзя использовать как семантику текущего русскоязычного интерфейса. На одном exact Bar 310 после обновления страницы: «Авто» → read `1`, затем администратор вручную переключил на «Вручную» → read `0`, затем вернул «Авто» → read `1`. Поэтому для подтверждённого Bar 310 `1=автоматический ответ`, `0=ручной`; это отличается от TE и не переносится на Box. Все изменения настройки выполнил только администратор через web, агент посылал только read-запросы.

Последующая поэтапная сверка: по скриншоту NTP синхронизация включена и выбран ручной режим, что совпало с read-only кодами; имя сервера сравнивалось посимвольно только в памяти и совпало, без вывода или сохранения строки. По скриншоту Wi‑Fi клиент, приоритет сети и точка доступа выключены — все три значения совпали с отдельными машинными флагами. Администратор подтвердил включённый SSH, что совпало с `enable_ssh=1`, и отключённый HTTP, что совпало с `enable_http=0`. Ранее присланный снимок питания подтвердил три видимых параметра: сон 10 минут, очистка в спящем режиме и автоперезагрузка выключены. Имя сайта по отдельному скриншоту сравнено посимвольно с read-only ответом только в памяти: полное совпадение; само значение не сохранялось и не повторялось в документации.

## Open evidence

- Администратор указал «Настройки → Сервер → Основные службы → Тип сервера» как собственный аудиторский признак «Автообновление». Раскрытый список текущего Bar 310 содержит «Вручную», «SMC2.0», «SMC», но не отдельное «Авто». Администратор подтвердил правило: «Вручную» = отключено, любой другой доступный вариант = включено. Текущие `GET /v1/om/config/service` и `GET /v1/om/config/auto-config` оба возвращают `serverType=-1` при видимом «Вручную»; bundle при таком состоянии выбирает первый доступный вариант меню. `cloudType=1` относится к облачной платформе, а `autoUpgFlag` — к подтверждению перед обновлением, поэтому оба исключены из правила. Для exact Bar 310 добавлен узкий read-only вывод с `basis=server_type_audit_rule`, а не утверждение фактической работы обновления прошивки. Текущий ручной режим подтверждён обычным опросом как `disabled`; SMC/SMC2.0 проверены синтетически и не включались на устройстве. Box не наследует правило.
- Вручную сверить текущие числовые значения с меню администратора после добавления JSON; без этой сверки эксплуатационная семантика остаётся предварительной.
- Администратор предоставил снимок раздела «Общие → Управление питанием» подключённого Bar 310. На нём доступны переход в сон, очистка памяти в спящем режиме и автоперезагрузка; машинные значения 10 минут, выключено и выключено совпадают с меню. Отдельные «очистка после перезагрузки» и «включение/отключение по расписанию» на этом экране отсутствуют и в подтверждённой группе чтения не найдены. Не подменять их периодической автоперезагрузкой и не распространять этот вывод на все прошивки без отдельной проверки.
- Определение отсутствия функции автообновления и SNMP v2 по модели, а не по неудаче отдельного запроса.
- Безопасное исключение возможных секретов (включая Wi‑Fi и серверные учётные данные) из производного JSON.

## Alternatives rejected

Широкая выгрузка всей конфигурации, перебор неизвестных action ID, перенос TE-контракта или трактовка `null` как «Отключено» отвергнуты: это либо нарушает границу доступа, либо создаёт ложные фактические данные.
