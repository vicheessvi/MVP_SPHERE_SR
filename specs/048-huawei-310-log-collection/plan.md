# План: сбор логов Huawei 310

**Ветка**: `codex/secure-local-runtime`
**Спецификация**: [spec.md](spec.md)
**Дата**: 2026-11-11

## Цель и подход

Подключить экспорт оригинального XML-журнала точных Bar 310, Box 310, Box 610 к существующей независимой опции «Собирать логи устройств». Производственный код использует только стандартную библиотеку Python 3.11+, текущий модельный REST-контракт, защищённую loopback-передачу в выбранную папку и не сохраняет содержимое на сервере.

## Конституционные ограничения

- Только exact модель и устойчивый SN/ESN/MAC после авторизации; IP берётся из явного плана.
- Только подтверждённый текущим bundle экспорт `POST /v1/om/log/export`; никакого обхода на другой протокол.
- Самоподписанный сертификат принимается лишь по явному разрешению запуска.
- Учётные данные, токен, cookie и сырой лог не попадают в результат, состояние, Git или диагностический статус.
- Box 310/610 остаются `provisional_user_validation` до независимых эксплуатационных проверок.
- Новая событийная аналитика для 310-журналов не включается без отдельно проверенных образцов.

## Технический контекст

- Python 3.11+, стандартная библиотека; browser HTML/CSS/Vanilla JS.
- Runtime: `mvp_runtime/adapters/huawei_bar310.py`, `mvp_runtime/polling.py`, существующий поток `polling_job.py` → same-origin browser.
- Данные: только выбранная пользователем timestamp-папка логов, никакого скрытого spool.
- Проверки: Python `unittest`, JS `tests.js`, справочник, синтаксис, проверка секретов.

## Этапы

1. Зафиксировать read-only evidence Bar 310 и границы переноса на Box.
2. Добавить потоковый экспорт после exact model/identity gates и проверить XML-префикс/тип ответа.
3. Передавать логи в существующий callback, изолировать ошибку сохранения от JSON-опроса и последующих устройств.
4. Добавить синтетические contract/integration тесты для всех трёх моделей и отказных сценариев.
5. Обновить справочник, ADR, журнал реализации и выполнить регрессию.
