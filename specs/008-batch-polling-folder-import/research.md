# Research: Пакетный импорт папок опросов

## Decision 1: Группировать по ближайшей датированной родительской папке

- **Decision**: Для каждого JSON путь просматривается от непосредственной родительской папки вверх; первая папка, строго соответствующая `YYYY-MM-DD_HH-MM-SS`, определяет сеанс.
- **Rationale**: Поддерживает как непосредственные JSON, так и дополнительные подпапки производителей внутри одного сеанса, не привязываясь к имени общей папки.
- **Alternatives considered**: Только первый сегмент пути не работает для общей папки; только непосредственный родитель не допускает вложенных каталогов.

## Decision 2: Стандартный ISO-порядок даты

- **Decision**: `2026-06-01` трактуется как 1 июня 2026 года; календарные переполнения запрещены.
- **Rationale**: Это существующий контракт проекта, международный порядок ISO и однозначная сортировка строк.
- **Alternatives considered**: Пользовательский локальный порядок и эвристики отклонены как неоднозначные и опасные для временной аналитики.

## Decision 3: Хронологическая обработка групп

- **Decision**: Группы сортируются по `capturedAt`, затем по относительному пути.
- **Rationale**: Расчёт изменений между результатами должен быть детерминированным независимо от порядка файлов, возвращённого браузером.
- **Alternatives considered**: Порядок FileList не является достаточным контрактом для аналитики.

## Decision 4: Частичный импорт вместо общей транзакционной отмены

- **Decision**: Корректные группы и файлы сохраняются в состоянии сеанса; ошибки пути, чтения и JSON показываются отдельно.
- **Rationale**: Большие наборы опросов не должны полностью теряться из-за одного повреждённого устройства.
- **Alternatives considered**: Полная отмена безопаснее технически, но противоречит требованию массового импорта и принципу работы с неполными данными.

## Decision 5: Один режим `file://`

- **Decision**: Пользовательская инициализация принимает только прямой запуск `index.html`; состояние всегда volatile.
- **Rationale**: Соответствует требованию переносимого запуска без установки и исключает расхождение поведения двух режимов.
- **Alternatives considered**: Параллельный loopback runtime отклонён как второй пользовательский режим. Его исторические технические файлы не участвуют в инициализации интерфейса и подлежат последующей очистке отдельно, если больше не нужны для разработки.
