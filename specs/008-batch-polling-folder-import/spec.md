# Feature Specification: Пакетный импорт папок опросов

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-08-10

**Status**: Ready

**Input**: Пользователь выбирает одну общую папку, содержащую несколько папок сеансов вида `YYYY-MM-DD_HH-MM-SS` с JSON-результатами опросов устройств. Инструмент имеет один режим и запускается через `index.html`.

## User Scenarios & Testing

### User Story 1 - Импорт всех сеансов одной папкой (Priority: P1)

Администратор МЦТП выбирает общую папку с несколькими датированными подпапками и одним действием загружает все JSON-результаты из всех найденных сеансов.

**Why this priority**: Это основной способ передачи результатов автоматизированного опроса в аналитику без поочерёдного выбора каждого сеанса.

**Independent Test**: Выбрать общую папку с двумя корректными датированными подпапками и убедиться, что созданы два отдельных запуска с собственными датами и результатами.

**Acceptance Scenarios**:

1. **Given** общая папка содержит `2026-06-01_09-41-28` и `2026-06-02_10-15-00`, **When** пользователь выбирает общую папку, **Then** инструмент создаёт два запуска опроса и относит каждый JSON к его папке.
2. **Given** JSON находится во вложенной подпапке внутри датированной папки, **When** выполняется импорт, **Then** файл относится к ближайшей родительской папке сеанса.
3. **Given** папки перечислены файловой системой не по времени, **When** выполняется импорт, **Then** сеансы обрабатываются хронологически для корректной аналитики изменений.

---

### User Story 2 - Понятный результат частичного импорта (Priority: P2)

Администратор получает итог по каждой папке и видит файлы, которые нельзя отнести к сеансу или прочитать, при этом корректные папки не теряются.

**Why this priority**: Одна ошибка в большой выгрузке не должна блокировать полезные результаты остальных устройств и сеансов.

**Independent Test**: Добавить корректную папку, папку с недопустимой датой, повреждённый JSON и посторонний файл; проверить раздельный итог и сохранение корректных данных.

**Acceptance Scenarios**:

1. **Given** часть JSON находится вне папок требуемого формата, **When** выполняется импорт, **Then** эти файлы отмечаются как отклонённые, а корректные сеансы импортируются.
2. **Given** один JSON повреждён, **When** выполняется импорт, **Then** запуск помечается частичным, ошибка видна пользователю, остальные JSON этого запуска обрабатываются.
3. **Given** в общей папке нет пригодных JSON, **When** пользователь запускает импорт, **Then** состояние аналитики не изменяется и показывается понятная ошибка.

---

### User Story 3 - Единственный запуск через HTML (Priority: P3)

Администратор открывает корневой `index.html` двойным щелчком и выполняет пакетный импорт без отдельного сервера и второго режима интерфейса.

**Why this priority**: Единый способ запуска нужен для переносимой работы на любом поддерживаемом ПК.

**Independent Test**: Открыть `index.html` через `file://`, выбрать общую папку и проверить импорт двух сеансов без сетевых запросов приложения.

**Acceptance Scenarios**:

1. **Given** локальная копия репозитория, **When** открыт `index.html`, **Then** доступен полный интерфейс импорта и аналитики текущего сеанса.
2. **Given** страница открыта через неподдерживаемый протокол, **When** приложение инициализируется, **Then** оно не объявляет второй рабочий режим.

### Edge Cases

- Одинаковое имя датированной папки в разных ветвях общей папки сохраняет раздельный относительный путь и не смешивает происхождение файлов.
- Невозможные календарные даты, например `2026-02-30_09-41-28`, отклоняются.
- Расширение JSON сопоставляется без учёта регистра; не-JSON файлы игнорируются и учитываются в итоге.
- Пустые датированные папки не создают фиктивные запуски, поскольку браузер не передаёт пустые каталоги через выбранные файлы.
- Повторная загрузка тех же файлов использует существующую дедупликацию результатов.

## Requirements

### Functional Requirements

- **FR-001**: Инструмент MUST позволять выбрать одну общую локальную папку одним действием.
- **FR-002**: Инструмент MUST рекурсивно находить JSON-файлы во всех её подпапках.
- **FR-003**: Инструмент MUST определять сеанс по ближайшей родительской папке с именем строго `YYYY-MM-DD_HH-MM-SS`.
- **FR-004**: Каждая найденная датированная папка MUST формировать отдельный запуск опроса со временем из имени папки.
- **FR-005**: Запуски MUST обрабатываться по возрастанию времени независимо от порядка файлов браузера.
- **FR-006**: Для каждого результата MUST сохраняться исходное имя файла и относительный путь происхождения.
- **FR-007**: Файлы без корректной родительской папки сеанса MUST отклоняться без отмены корректных импортов.
- **FR-008**: Повреждённый или нечитаемый JSON MUST давать локальную ошибку файла и не отменять остальные файлы.
- **FR-009**: Итог MUST показывать число найденных папок, обработанных JSON и ошибок.
- **FR-010**: Не-JSON файлы MUST игнорироваться без попытки прочитать их содержимое.
- **FR-011**: Инструмент MUST иметь один пользовательский режим, запускаемый прямым открытием корневого `index.html`.
- **FR-012**: Рабочие данные MUST оставаться в памяти текущей вкладки и не передаваться во внешнюю сеть.
- **FR-013**: Справочник и пользовательская документация MUST описывать пакетную структуру папок и единый способ запуска.
- **FR-014**: Автоматические тесты MUST покрывать группировку, календарную валидацию, хронологический порядок, частичный импорт и единственный режим запуска.

### Key Entities

- **Общая папка импорта**: выбранное пользователем дерево локальных файлов.
- **Папка сеанса опроса**: каталог с корректным временным именем и одним или несколькими JSON-результатами.
- **Запуск опроса**: аналитическая запись одного датированного каталога с количеством успешных и ошибочных файлов.
- **Результат опроса**: неизменённый JSON и производные поля, связанные с запуском и относительным путём источника.
- **Ошибка импорта**: причина отклонения пути, чтения или разбора отдельного файла.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Одна операция выбора общей папки импортирует 100% корректных датированных подпапок как раздельные запуски.
- **SC-002**: Для набора из 10 папок и 1 000 JSON пользователь получает итог без ручного повторного выбора папок.
- **SC-003**: Ошибка одного файла не препятствует обработке остальных корректных файлов в 100% проверенных сценариев.
- **SC-004**: 100% файлов вне корректной папки сеанса исключаются из аналитики и перечисляются в результате импорта.
- **SC-005**: Прямое открытие `index.html` позволяет завершить пакетный импорт без Node.js, локального сервера и интернет-соединения.
- **SC-006**: Все существующие и новые автоматические проверки проходят без регрессий.

## Assumptions

- Формат даты трактуется как стандартный ISO-порядок `год-месяц-день`; `2026-06-01_09-41-28` означает 1 июня 2026 года, 09:41:28. Для 1 июля имя должно быть `2026-07-01_09-41-28`.
- Целевой браузер — актуальный Chromium/Edge на Windows с поддержкой выбора каталога через файловое поле.
- Время папки — время выполнения соответствующего опроса, а фактическое время импорта фиксируется отдельно.
- Сетевой опрос выполняется внешними локальными скриптами; HTML-инструмент импортирует и анализирует готовые JSON.
- После закрытия или перезагрузки вкладки сеансовые данные удаляются, что сохраняет локальную модель защиты без скрытого постоянного хранилища.
