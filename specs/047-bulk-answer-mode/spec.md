# Feature Specification: Массовое изменение режима ответа

**Feature Branch**: `codex/secure-local-runtime`
**Created**: 2026-11-10
**Status**: Реализовано и проверено синтетически; реальная массовая запись не выполнялась
**Input**: Дать возможность менять Answer mode не только одного устройства по IP, но и набора, выбранного фильтрами SR; распространяется на TE20, TE30/40/50/60 и Bar 310/Box 310/Box 610.

## User Scenarios & Testing

### User Story 1 — Выбрать группу по фильтрам (Priority: P1)

Администратор выбирает домен, класс, производителя и модели, затем задаёт «Автоматически», «Вручную» или «Не менять» для одной модельной группы. Инструмент показывает число затронутых устройств и отдельно подтверждает массовое изменение.

**Independent Test**: Группа из нескольких совместимых устройств создаёт план с нужной задачей; «Не менять» не создаёт write.

**Acceptance Scenarios**:

1. **Given** несколько точных устройств одной поддерживаемой группы, **When** выбран режим и дано согласие, **Then** план содержит все выбранные IP и одну модельную задачу.
2. **Given** выбранные устройства разных несовместимых групп, **When** формируется план, **Then** массовое изменение блокируется с понятным объяснением.

### User Story 2 — Безопасное исполнение (Priority: P1)

Каждое устройство опрашивается и изменяется отдельно, с точной проверкой модели/идентичности и чтением до и после записи. Отказ одного устройства не превращается в успех других и не вызывает повтор неясной записи.

**Independent Test**: Синтетический план с двумя устройствами сохраняет отдельные результаты; сбой одного не отправляет повторную write-команду.

**Acceptance Scenarios**:

1. **Given** подтверждённый массовый план, **When** выполняется опрос, **Then** каждое устройство получает максимум одну модельно разрешённую запись и собственный результат.
2. **Given** несовпадение post-read либо обрыв связи, **When** результат неясен, **Then** автоматический повтор write запрещён.

### Edge Cases

- TE20, TE30–60 и Huawei 310 используют разные кодировки и действия, их нельзя смешивать в одном массовом write-плане.
- Неподдерживаемая, суффиксная или неоднозначная модель блокирует весь write-план до сети.
- Для записи по одному IP прежний сценарий остаётся рабочим.
- HTTP, NTP, SSH и другие задачи управления не совмещаются с массовым Answer mode.

## Requirements

### Functional Requirements

- **FR-001**: Для TE20, TE30/40/50/60 и Huawei 310 MUST поддерживаться оба способа выбора — один IP и фильтры актуальной SR.
- **FR-002**: Массовый write MUST требовать не менее одного выбранного устройства, единственного action ID и совместимости всех целей с ним.
- **FR-003**: Перед запуском MUST показываться число целей и предупреждение об изменении обработки входящих вызовов; без подтверждения план не запускается.
- **FR-004**: Runtime MUST повторно проверять source SR, точность моделей, отсутствие конфликтов и каждое целевое устройство до передачи credentials и записи.
- **FR-005**: Модельные pre-read/one-write/post-read, статусы Bar/Box и политика неопределённого результата MUST не меняться.
- **FR-006**: Учётные данные и исходные ответы MUST оставаться только в памяти задания и не попадать в JSON/аналитику/репозиторий.

### Key Entities

- **Группа целей**: список точных IP и моделей из текущей SR после фильтров.
- **Массовый план**: один модельный action ID, число целей, подтверждение пользователя.
- **Результат устройства**: отдельные before/after/status и сохранённый JSON.

## Success Criteria

- **SC-001**: Фильтрация 2+ устройств каждой из трёх групп создаёт корректный план; смешанная группа блокируется.
- **SC-002**: В 100% негативных сценариев неподдерживаемая модель не получает команду записи.
- **SC-003**: Отказы отдельных устройств не препятствуют сохранению результатов остальных и не вызывают автоматического повтора write.
- **SC-004**: Режим одного IP и обычный read-only опрос сохраняют прежнее поведение.

## Assumptions

- «Серия TE» включает exact TE20 и exact TE30/TE40/TE50/TE60; они остаются двумя разными контрактами.
- Один массовый план применяет одну выбранную модельную задачу, без смешения групп.
