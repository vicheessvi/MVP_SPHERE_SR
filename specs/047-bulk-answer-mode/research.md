# Research: массовое изменение Answer mode

## Decision

Код текущего проекта фактически требовал `single_ip` для TE20, TE30/40/50/60 и Huawei 310 Answer mode. Пользователь уточнил, что write должен работать также через общий каскад фильтров SR. Существующий `run_plan` уже обрабатывает список устройств по одному, сохраняет отдельный результат и не повторяет неясные write-задачи при восстановлении; протоколы устройств менять не нужно.

Один план применяет ровно один action ID. Для него все выбранные из SR устройства должны поддерживать этот action; смешанные TE20/TE-family/Huawei310 и посторонние модели блокируются до сети. Один IP остаётся допустимым. Интервал и обработка ошибок отдельных устройств сохраняются.

## Alternatives rejected

Автоматически пропускать несовместимые устройства в массовой write-группе — риск изменения непредвиденного поднабора. Одновременный запуск разных модельных action в одном плане — менее прозрачное согласие и дополнительная логика восстановления.

## User validation

Администратор подтвердил оба направления «Вручную ↔ Автоматически» в одиночном и массовом режимах для exact TE20, TE30, TE40, TE50, TE60, Bar 310, Box 310 и Box 610. Проверка относится только к Answer mode; портовые и прочие write-задачи сохраняют прежние статусы.
