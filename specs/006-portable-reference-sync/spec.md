# Feature Specification: Переносимый запуск и синхронизация Справочника

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-08-10

**Status**: Draft

**Input**: После скачивания проекта с GitHub инструмент должен безопасно запускаться на любом поддерживаемом ПК, а изменения модулей и терминологии должны автоматически отражаться в Справочнике.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Первый запуск на новом ПК (Priority: P1)

Администратор МЦТП скачивает чистую копию проекта на поддерживаемый Windows-ПК и запускает её одной командой без предварительной ручной установки зависимостей и без прав администратора ОС.

**Why this priority**: Без воспроизводимого первого запуска проект нельзя использовать на другом рабочем месте.

**Independent Test**: На чистом Windows-профиле без Node.js запуск подготавливает проверенную локальную среду, открывает loopback-интерфейс и создаёт новое зашифрованное хранилище текущего пользователя.

**Acceptance Scenarios**:

1. **Given** поддерживаемый Windows-ПК без подходящей локальной среды, **When** пользователь запускает `start.ps1`, **Then** инструмент загружает только закреплённый официальный runtime, проверяет его контрольную сумму, распаковывает в исключённый из Git локальный каталог и запускает приложение без повышения прав.
2. **Given** на ПК уже есть совместимая среда, **When** пользователь запускает проект, **Then** повторная загрузка не выполняется и приложение запускается с найденной средой.
3. **Given** загруженный архив повреждён или его контрольная сумма не совпадает, **When** выполняется подготовка, **Then** запуск прекращается до исполнения архива, временные файлы удаляются и пользователь получает безопасное русское сообщение.
4. **Given** проект запущен на новом ПК, **When** создаются или загружаются рабочие данные, **Then** они сохраняются только в новом локальном зашифрованном хранилище с ключом DPAPI текущего пользователя и не синхронизируются через GitHub.

---

### User Story 2 - Справочник следует за проектом (Priority: P1)

Разработчик добавляет, переименовывает или удаляет доступный модуль, пользовательский статус либо подсказку в едином каталоге продукта, после чего интерфейс и Справочник используют обновлённые сведения без повторного ручного копирования текста.

**Why this priority**: Дублирование навигации и справочных карточек неизбежно приводит к устаревшим или противоречивым инструкциям.

**Independent Test**: В тестовой копии каталога добавление и удаление модуля одновременно меняет навигационную и справочную проекции; проверка отклоняет маршрут без справочного описания и справочную карточку без действующего модуля.

**Acceptance Scenarios**:

1. **Given** модуль объявлен в едином каталоге, **When** строятся навигация и Справочник, **Then** обе проекции получают одинаковые название, назначение и ключевые слова.
2. **Given** модуль удалён из каталога, **When** приложение перерисовывается, **Then** он отсутствует и в навигации, и в разделе модулей Справочника.
3. **Given** пользовательский статус или подсказка изменены в каталоге терминологии, **When** открываются рабочий экран и Справочник, **Then** оба используют новое русское значение.
4. **Given** разработчик добавил доступный маршрут в обход каталога либо создал потерянную справочную запись, **When** запускаются обязательные проверки, **Then** проверка завершается ошибкой с указанием рассинхронизированного идентификатора.

### User Story 3 - Объяснимая и безопасная подготовка (Priority: P2)

Администратор видит, какая локальная среда выбрана, когда требуется сетевое скачивание и почему подготовка не выполнена, не раскрывая при этом пути к секретам или рабочие данные.

**Why this priority**: Прозрачная диагностика облегчает эксплуатацию на изолированных корпоративных ПК и не должна ослаблять защиту.

**Independent Test**: Сценарии отсутствия сети, неподдерживаемой архитектуры, недостатка прав на каталог и несовпадения hash дают разные безопасные сообщения и не запускают сервер.

**Acceptance Scenarios**:

1. **Given** официальный источник недоступен, **When** подходящая среда отсутствует, **Then** пользователь получает инструкцию по разрешённой офлайн-установке без изменения системных настроек.
2. **Given** архитектура ПК не поддерживается, **When** выполняется запуск, **Then** подготовка прекращается до сетевого запроса.
3. **Given** подготовка завершена, **When** приложение запускается повторно, **Then** используется ранее проверенная локальная среда и внешний запрос не выполняется.

### Edge Cases

- Каталог проекта расположен в пути с пробелами или кириллицей.
- Проект скачан повторно, но локальный runtime отсутствует, повреждён или имеет другую закреплённую версию.
- На ПК есть устаревший или неподдерживаемый Node.js, который нельзя использовать безопасно.
- Соединение прерывается во время скачивания; частичный архив не должен считаться установленным.
- На диске недостаточно места для архива или распаковки.
- Одновременно запущены две подготовки одной копии проекта.
- В каталоге модулей повторяются route/id либо отсутствует русское описание.
- Справочный термин имеет технический raw-код, который нельзя изменять ради локализации.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Проект MUST запускаться из чистой GitHub-копии на поддерживаемых Windows 10/11 x64 и ARM64 без прав администратора ОС.
- **FR-002**: Подготовка MUST сначала использовать совместимую уже доступную среду и MUST NOT выполнять сетевой запрос при её наличии.
- **FR-003**: При отсутствии совместимой среды подготовка MUST загружать только заранее закреплённый официальный LTS-артефакт по HTTPS для фактической архитектуры ПК.
- **FR-004**: Архив MUST пройти проверку заранее закреплённой SHA-256 до распаковки или исполнения; несовпадение MUST прекращать подготовку fail-closed.
- **FR-005**: Локальная среда MUST размещаться внутри исключённого из Git каталога проекта без изменения системного PATH и без системной установки.
- **FR-006**: Частичные загрузки и распаковки MUST использовать временную staging-область и MUST NOT заменять ранее рабочую среду до полной проверки.
- **FR-007**: Рабочий runtime MUST сохранить loopback-only, одноразовый launch token, CSP, CSRF, AES-256-GCM, DPAPI CurrentUser и отдельный write-only credential vault.
- **FR-008**: Bootstrap MUST NOT читать, отправлять или включать в диагностику SR, результаты опросов, аналитику, учётные данные либо содержимое локального хранилища.
- **FR-009**: Каждый новый Windows-профиль MUST получать независимые мастер-ключ, хранилище и credential vault; GitHub MUST содержать только код и несекретные метаданные установки.
- **FR-010**: Пользователь MUST получать русские безопасные сообщения для неподдерживаемой ОС/архитектуры, отсутствия сети, несовпадения hash, недостатка места и ошибки распаковки.
- **FR-011**: Система MUST иметь единый декларативный каталог доступных модулей с route, русским названием, назначением, подробным описанием, ключевыми словами, порядком и признаком контекстной помощи.
- **FR-012**: Основная навигация и раздел «Модули инструмента» Справочника MUST формироваться из одного каталога, а не из независимых копий.
- **FR-013**: Категории, пользовательские статусы и подсказки MUST иметь единый presentation dictionary; справочные записи для них MUST формироваться из того же источника либо явно ссылаться на него.
- **FR-014**: Обязательная проверка MUST отклонять повторяющиеся идентификаторы, доступный маршрут без справочного описания, потерянную модульную карточку, пустую русскую подпись и необработанный внутренний статус.
- **FR-015**: Изменение, добавление или удаление записи каталога MUST отражаться в навигации и соответствующей части Справочника при следующем запуске/перерисовке без отдельной генерации или ручного копирования.
- **FR-016**: Описательные материалы, которые невозможно достоверно вывести из каталога, MUST оставаться явными записями; проверка MUST требовать их обновления только при изменении связанного стабильного идентификатора.
- **FR-017**: Raw SR/JSON, внутренние enum-коды, идентичность устройств, история и API-контракты MUST оставаться неизменными.
- **FR-018**: Автоматические проверки MUST выполняться локально и в GitHub-проверке изменений без доступа к рабочим данным или секретам.
- **FR-019**: Решение MUST документировать границу автоматизации: оно синхронизирует зарегистрированные модули, статусы и подсказки, но не генерирует неподтверждённый смысл произвольного нового кода.

### Key Entities

- **Portable Runtime Manifest**: Закреплённая версия официальной среды, поддерживаемые архитектуры, URL артефактов, SHA-256 и локальная целевая версия.
- **Module Descriptor**: Стабильный route/id, русское название, порядок, назначение, подробности, ключевые слова и настройки контекстной помощи.
- **Presentation Term**: Внутренний неизменяемый код и безопасная русская подпись с необязательным справочным пояснением.
- **Reference Projection**: Детерминированный набор справочных разделов и карточек, полученный из каталогов модулей/терминов и явных описательных материалов.
- **Consistency Report**: Результат проверки уникальности, полноты и отсутствия потерянных ссылок без рабочих данных.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: На чистом поддерживаемом Windows-ПК пользователь запускает скачанный проект одной командой без прав администратора и получает рабочий интерфейс не более чем за 5 минут при доступном официальном источнике.
- **SC-002**: 100% исполняемых загруженных артефактов проходят закреплённую SHA-256 проверку; повреждённый или подменённый архив исполняется в 0% случаев.
- **SC-003**: После первого успешного запуска повторный запуск не выполняет внешних запросов и открывает интерфейс не более чем за 15 секунд на типовом рабочем ПК.
- **SC-004**: Все рабочие данные и секреты остаются локальными; bootstrap выполняет 0 операций отправки и 0 чтений из локального защищённого хранилища.
- **SC-005**: Добавление, переименование или удаление зарегистрированного модуля отражается в навигации и Справочнике за один запуск без второй ручной правки.
- **SC-006**: Автоматическая проверка выявляет 100% тестовых случаев дублирующегося id, маршрута без справки, потерянной карточки и пустой русской подписи.
- **SC-007**: Все существующие regression, secure-runtime и server integration проверки продолжают проходить; raw compatibility SR/JSON сохраняется.
- **SC-008**: Новый пользователь может понять по сообщению причину каждого предусмотренного отказа и безопасное следующее действие без просмотра исходного кода.

## Assumptions

- «Любой ПК» означает Windows 10/11 x64 или ARM64 с Windows PowerShell 5.1+ и возможностью записи в каталог скачанного проекта.
- Интернет нужен только для скачивания проекта и однократного получения официального portable runtime, если совместимый Node.js отсутствует; эксплуатация и работа с данными остаются локальными.
- Данные между ПК не синхронизируются. Перенос зашифрованной базы или общий многопользовательский доступ являются отдельной feature.
- Корпоративная политика может запретить прямой доступ к официальному источнику; в этом случае допускается заранее размещённый проверенный архив или совместимая среда, но ослабление hash-проверки не допускается.
- Автоматизация Справочника основана на явном каталоге и проверяемых связях. Она не может безопасно угадывать назначение произвольного нового кода.

## Out of Scope

- Синхронизация рабочих данных и credential vault между компьютерами.
- Хранение runtime-архивов, ключей, данных или учётных файлов в GitHub.
- Поддержка macOS/Linux и системная установка программ.
- Автоматическое сочинение справочных определений без явных метаданных разработчика.
- Изменение протоколов опроса оборудования или добавление неподтверждённых vendor API.
