# Feature Specification: Настройки NTP Huawei TE20

**Branch**: `codex/secure-local-runtime`
**Date**: 2026-11-05
**Status**: Implemented; pending live write validation

## User Scenarios & Testing

### User Story 1 — Независимый выбор NTP (Priority: P1)

Администратор выбирает один exact Huawei TE20 по IP из текущей SR и задаёт три поля: синхронизация «Без изменений/Включить/Отключить», режим адреса «Без изменений/Авто/Вручную», имя сервера «Без изменений/Ввести значение».

**Independent Test**: Пустой выбор создаёт read-only план; каждый непустой выбор создаёт одну NTP-задачу с точным набором выбранных полей.

**Acceptance Scenarios**:

1. Все три «Без изменений» не создают команду записи.
2. Ввод имени сервера требует непустого допустимого значения и ручного режима — выбранного или уже установленного на устройстве.
3. Нельзя совместить отключение синхронизации с изменением режима/сервера или режим «Авто» с вводом сервера.
4. Чужая модель, массовый режим и сочетание с другими задачами записи блокируются до подключения.

### User Story 2 — Проверяемая запись (Priority: P1)

Перед изменением система подтверждает модель и идентичность устройства, читает все три текущих значения, сохраняет только выбранные изменения и проверяет итог повторным чтением.

**Independent Test**: Синтетические ответы покрывают no-op, числовую и строковую запись, неверную схему, несовпавший post-read и отсутствие повтора неясной записи.

**Acceptance Scenarios**:

1. Если целевые значения уже установлены, запись не выполняется.
2. Если значения отличаются, выполняется максимум одна запись с выбранными полями и post-read всех трёх.
3. При неполном чтении, неподтверждённой схеме или несовпадении после записи результат не объявляется успешным.

### Edge Cases

- Смена NTP может изменить отображаемое время устройства; реальный тест требует отдельного выбора целевых значений.
- Имя сервера не является паролем, но считается чувствительными инфраструктурными данными и остаётся локальным.
- Действие не переносится на другие модели Huawei без отдельной проверки.

## Requirements

- **FR-001**: Три поля имеют «Без изменений» по умолчанию.
- **FR-002**: Запись доступна только одному exact TE20 по IP из актуальной SR после подтверждения администратора.
- **FR-003**: Невозможные сочетания и недопустимое имя сервера блокируются до сети.
- **FR-004**: Успех возможен только после точного повторного чтения, без автоматического повтора неизвестного результата.
- **FR-005**: Обычный опрос остаётся read-only; сведения и секреты не уходят во внешние сервисы.

## Success Criteria

- **SC-001**: Во всех трёх вариантах «Без изменений» сетевых команд записи нет.
- **SC-002**: Во всех синтетических сценариях изменение ограничено одной записью только выбранных параметров.
- **SC-003**: Все отрицательные проверки модели, сочетаний, схемы и post-read дают отказ до записи либо неуспех.
- **SC-004**: Ранее поддержанные сценарии проходят полный регрессионный набор.

## Assumptions

- Текущая задача относится только к exact TE20. Устройство уже подтверждённо отдаёт три значения NTP; web-bundle текущей прошивки показал числовые и строковое поля сохранения. Реальная запись в этом этапе не выполняется без конкретного выбора пользователя.
