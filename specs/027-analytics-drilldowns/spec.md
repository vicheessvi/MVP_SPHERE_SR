# Feature Specification: Аналитические таблицы опросов

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-10-14

**Status**: Complete — synthetic regression passed

**Input**: Требования пользователя к раскрываемым таблицам перезагрузок, сравнению версий проектов и прошивок и разделению ошибок авторизации и сети.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Раскрыть аналитику перезагрузок (Priority: P1)

Администратор видит короткие итоговые карточки. Нажатие открывает только соответствующую таблицу или график с данными текущих фильтров; таблица событий по умолчанию скрыта.

**Why this priority**: Большая таблица больше не оттесняет обзор, а каждый показатель ведёт к проверяемым строкам.

**Independent Test**: Два устройства с несколькими событиями в одной локации дают разные значения «перезагрузки» и «перезагруженные устройства»; карточки открывают правильные ранжированные строки.

**Acceptance Scenarios**:

1. **Given** история содержит три события двух устройств одной локации, **When** открыт обзор, **Then** показано три перезагрузки, два устройства и одна локация без открытой таблицы.
2. **Given** применён фильтр периода и адреса, **When** администратор открывает любую карточку, **Then** её строки соответствуют тем же фильтрам и отсортированы по количеству.
3. **Given** у двух событий одной даты совпадает адрес, **When** открывается TOP 5 дат, **Then** адрес показан один раз с количеством событий по нему.

---

### User Story 2 - Сравнить версии проектов и прошивок (Priority: P2)

Администратор видит таблицы версий из последовательных файлов опроса одного точно сопоставленного устройства. Неизвестные поля не превращаются в версию.

**Why this priority**: История показывает реальные смены конфигурации и программного обеспечения без ручного сравнения JSON.

**Independent Test**: Два результата одного устройства с разными версиями показывают предыдущую и текущую версии и признак изменения; результат другого устройства не влияет на сравнение.

**Acceptance Scenarios**:

1. **Given** два точно сопоставленных опроса с версиями проекта, **When** открыт модуль проектов, **Then** видны устройство, время, текущая и предыдущая версии и изменение.
2. **Given** версия прошивки отсутствует или опрос неоднозначен, **When** открыт модуль прошивок, **Then** такой результат не создаёт ложной версии.

---

### User Story 3 - Разделить ошибки подключения (Priority: P3)

Администратор видит отдельно устройства с подтверждённой ошибкой авторизации и с подтверждённой сетевой недоступностью, с количеством случаев и временем последнего случая.

**Why this priority**: Для сетевой аварии и неверных учётных данных нужны разные действия.

**Independent Test**: Синтетические результаты с двумя разными статусами попадают в разные таблицы; ошибка обработки не попадает ни в одну.

**Acceptance Scenarios**:

1. **Given** устройство не ответило по сети, **When** открыт модуль ошибок, **Then** оно показано только в сетевой таблице.
2. **Given** устройство ответило, но отказало в авторизации, **When** открыт модуль ошибок, **Then** оно показано только в таблице авторизации; пароль не отображается.

### Edge Cases

- Одинаковые имена разных устройств не объединяются.
- События без локации или MAC сохраняются с пометкой «Не указано».
- Запоздавшие результаты версий сортируются по времени опроса до сравнения.
- Отсутствующее поле версии и неоднозначная связь с SR не считаются изменением.
- Пустая выборка показывает пустое состояние, а не фиктивный ноль по неизвестным данным.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Итоговые карточки и TOP 5 MUST открывать соответствующее детальное представление по нажатию и поддерживать возврат к обзору.
- **FR-002**: Все таблицы перезагрузок MUST использовать единую отфильтрованную выборку событий.
- **FR-003**: «Количество перезагруженных устройств» MUST считать уникальные идентификаторы устройств; показатель локаций MUST считать уникальные локации.
- **FR-004**: Рейтинг устройств MUST группировать по идентификатору устройства, локаций — по идентификатору локации, а не по отображаемому имени.
- **FR-005**: TOP 5 локаций по устройствам MUST считать уникальные устройства, а остальные рейтинги перезагрузок — события.
- **FR-006**: Детализация MUST показывать IP, MAC, VIP, локацию и адрес там, где это доступно из актуальной SR.
- **FR-007**: Версии проектов MUST читаться только из подтверждённого поля проекта в успешных однозначно сопоставленных результатах; прошивки — из поля прошивки.
- **FR-008**: Сравнение версий MUST выполняться отдельно для каждого устройства в хронологическом порядке и показывать предыдущую версию и результат сравнения.
- **FR-009**: Ошибки авторизации и сетевой недоступности MUST отображаться отдельно; неизвестная или иная ошибка MUST не классифицироваться догадкой.
- **FR-010**: Новая аналитика MUST быть производной от данных текущей вкладки и MUST не записывать секреты или дополнительные файлы.
- **FR-011**: Модули и Справочник MUST получать актуальные описания из единого каталога.

### Key Entities

- **Событие перезагрузки**: время, устройство, место, доказательства, версия правила.
- **Строка рейтинга**: стабильный идентификатор, количество событий или уникальных устройств, сведения SR.
- **Наблюдение версии**: устройство, время опроса, версия, предыдущая версия, статус сравнения.
- **Ошибка подключения**: устройство, вид подтверждённой ошибки, количество случаев, последний случай.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Каждая из 13 карточек открывает правильные строки одним нажатием.
- **SC-002**: Сумма строк события по дате и часу равна общему количеству событий выбранных фильтров.
- **SC-003**: На синтетической истории с одинаковыми именами разных устройств рейтинги сохраняют обе строки.
- **SC-004**: На 5 000 устройств и 25 000 результатов обзор перезагрузок рассчитывается за 2 секунды в тестовой среде проекта.
- **SC-005**: Ни одна таблица не показывает учётные данные или непроверенный вывод об ошибке авторизации.

## Assumptions

- Рейтинг TOP 5 дат считает события; совпавшие адреса внутри даты объединяются с собственным количеством.
- Рейтинг TOP 5 локаций считает уникальные устройства, имеющие хотя бы одно событие в выбранном периоде.
- Таблицы версий включают только актуальные устройства SR и успешные однозначно сопоставленные результаты.
- Таблицы ошибок объединяют случаи по устройству и виду ошибки, показывая число случаев и последнее время.
