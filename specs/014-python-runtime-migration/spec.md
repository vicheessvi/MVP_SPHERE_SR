# Feature Specification: Переносимый runtime без установки

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-09-01

**Status**: Draft

**Input**: User description: "Переделать проект на Python, сохранить текущее поведение и возможность развития; на целевом компьютере разрешён python.exe, но Node.js не установлен, CMD/PowerShell и произвольные EXE ограничены."

## Clarifications

### Session 2026-09-01

- Q: Установлен ли Python на целевом компьютере? → A: Python установлен, `python.exe` разрешён.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Запуск установленным Python без команд (Priority: P1)

Администратор МЦТП скачивает или копирует проект на поддерживаемый Windows-компьютер с уже установленным и разрешённым Python и запускает автоматический режим двойным щелчком по стартовому Python-файлу. Интерфейс открывается в браузере без Node.js, CMD, PowerShell, прав администратора или установки дополнительных пакетов.

**Why this priority**: Без воспроизводимого запуска на ограниченном компьютере автоматический опрос недоступен независимо от остальных функций.

**Independent Test**: Распаковать проект на Windows 10/11 x64 с совместимым установленным Python и без Node.js, дважды щёлкнуть стартовый `.py` и подтвердить открытие рабочей одноразовой локальной сессии.

**Acceptance Scenarios**:

1. **Given** распакованный проект и установленный разрешённый `python.exe`, **When** пользователь открывает `START_MVP_SPHERE_SR.py` двойным щелчком, **Then** локальный runtime привязывается только к loopback и автоматически открывает интерфейс.
2. **Given** пакет находится в произвольной пользовательской папке с пробелами и кириллицей, **When** пользователь запускает `python.exe`, **Then** проект находит собственные ресурсы без абсолютных путей и запускается корректно.
3. **Given** пакет повреждён или неполон, **When** пользователь запускает `python.exe`, **Then** runtime не начинает опрос и показывает понятную локальную ошибку без раскрытия чувствительных данных.

---

### User Story 2 - Совместимый автоматический опрос (Priority: P1)

Администратор МЦТП использует существующий интерфейс «Загрузка», загружает актуальную SR и XLSX с учётными данными, выбирает общую папку, формирует план и запускает опрос. Поддерживаемые устройства опрашиваются последовательно, результаты сохраняются в прежнем JSON-формате и сразу участвуют в аналитике.

**Why this priority**: Миграция не имеет ценности, если меняет существующий рабочий сценарий, результаты или защиту секретов.

**Independent Test**: Запустить synthetic Extron endpoint, выполнить полный workflow из интерфейса и сравнить API, progress lifecycle и безопасный JSON с действующим контрактом feature 013.

**Acceptance Scenarios**:

1. **Given** SR, корректный XLSX и выбранная папка результатов, **When** пользователь формирует и запускает план, **Then** runtime проверяет файл учётных данных, опрашивает только разрешённые IP и ждёт подтверждения записи каждого JSON перед интервалом.
2. **Given** поддерживаемое Extron-устройство с самоподписанным сертификатом и явное разрешение пользователя, **When** выполняется опрос, **Then** исключение проверки сертификата действует только для текущего задания и только для выбранного устройства.
3. **Given** отмена, ошибка сети, ошибка авторизации или ошибка записи, **When** задание переходит в терминальное состояние, **Then** прогресс и ошибка совместимы с текущим интерфейсом, а пул учётных данных очищается.
4. **Given** сформированный результат, **When** браузер сохраняет его в выбранную общую папку, **Then** имя папки и JSON соответствуют действующему контракту ручного импорта.

---

### User Story 3 - Сохранение ручного режима и аналитики (Priority: P2)

Администратор МЦТП может по-прежнему открыть корневой `index.html`, вручную загрузить SR и общую папку JSON, использовать Главный экран, оборудование, фильтры, таблицы, историю и Справочник без запущенного runtime.

**Why this priority**: Ручная загрузка является обязательным резервным сценарием и не должна зависеть от автоматизации.

**Independent Test**: Открыть `index.html` через `file://`, импортировать synthetic SR и несколько датированных папок JSON, проверить прежние показатели, сопоставление и сброс состояния после reload.

**Acceptance Scenarios**:

1. **Given** прямой запуск `index.html`, **When** пользователь загружает SR и результаты вручную, **Then** импорт и аналитика работают без локального runtime.
2. **Given** прямой файловый режим, **When** пользователь пытается сформировать автоматический опрос, **Then** интерфейс явно сообщает о необходимости запуска через поставляемый `python.exe` и не выполняет сеть.

---

### User Story 4 - Развитие и проверяемость runtime (Priority: P2)

Разработчик может добавлять новые подтверждённые модели, производителей и протоколы через изолированные адаптеры, не меняя пользовательский контракт, общий lifecycle задания и защиту данных.

**Why this priority**: Переписывание не должно создать монолит или заблокировать развитие продукта.

**Independent Test**: Добавить synthetic adapter через документированную точку расширения, выполнить контрактные тесты и убедиться, что существующий Extron workflow не изменился.

**Acceptance Scenarios**:

1. **Given** подтверждённый новый протокол, **When** разработчик добавляет отдельный adapter и его fixtures, **Then** общий план, allowlist, progress, result ACK и redaction переиспользуются без дублирования.
2. **Given** изменение runtime-контракта, **When** выполняются автоматические проверки, **Then** несовместимость с интерфейсом или JSON выявляется до выпуска пакета.

### Edge Cases

- Пакет перемещён после первого запуска или расположен по длинному пути с пробелами и кириллицей.
- Пользователь запускает несколько экземпляров; каждый использует отдельный случайный loopback-порт и отдельную одноразовую сессию.
- Архитектура или версия Windows не поддерживается поставляемым runtime.
- Браузер не удалось открыть автоматически; runtime показывает локальный URL без токенов в постоянных логах.
- XLSX повреждён, превышает лимит, содержит формулы, пустые/частичные строки или не совпадает с SHA-256 плана.
- Устройство недоступно, возвращает неподтверждённый контракт, меняет динамические URI или предъявляет недоверенный сертификат без явного разрешения.
- Пользователь отменяет ожидание даты старта, активный запрос, подтверждение записи или межустройственный интервал.
- Папка результатов теряет разрешение на запись в середине задания.
- Перезагрузка/закрытие вкладки уничтожает сеансовое состояние и не оставляет учётные данные на диске.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Проект MUST запускать автоматический режим двойным щелчком по `START_MVP_SPHERE_SR.py` через уже установленный разрешённый `python.exe`, без Node.js, CMD, PowerShell, инсталлятора, прав администратора или установки дополнительных Python-пакетов.
- **FR-002**: Пакет MUST быть переносимым между пользовательскими каталогами и MUST NOT содержать абсолютные пути конкретного компьютера.
- **FR-003**: Runtime MUST принимать соединения только на случайном loopback-порту и MUST сохранять одноразовую HttpOnly/CSRF сессию и действующие проверки Host/Origin.
- **FR-004**: Интерфейс и runtime MUST сохранить совместимость действующих API plan v2, загрузки XLSX, статуса, результата, ACK и отмены.
- **FR-005**: Runtime MUST проверять XLSX и его SHA-256 до обращения к устройствам, держать нормализованные пары только в памяти текущего задания и очищать их во всех терминальных и подготовительных ошибках.
- **FR-006**: Runtime MUST опрашивать только exact IP из неизменяемого плана и MUST сохранять последовательный порядок, дату старта, интервалы только после подтверждённой записи и отмену.
- **FR-007**: Подтверждённый Extron web-adapter MUST сохранить HTTPS-only поведение, динамическое обнаружение ресурсов, scoped self-signed исключение и fail-closed неизвестного контракта.
- **FR-008**: Каждый результат MUST проходить прежнюю redaction, не содержать логины, пароли, cookie, токены или заголовки авторизации и MUST быть совместим с ручным импортом и аналитикой.
- **FR-009**: Корневой `index.html` MUST сохранить непостоянный ручной режим, пакетный импорт общей папки, аналитику и сброс при reload без runtime.
- **FR-010**: Пользовательские названия, Справочник и инструкции MUST автоматически отражать запуск через `START_MVP_SPHERE_SR.py` и не предлагать Node.js, CMD или PowerShell как пользовательскую зависимость.
- **FR-011**: Runtime MUST иметь общий lifecycle задания и изолированный adapter contract, чтобы новые подтверждённые протоколы добавлялись без ослабления allowlist, redaction, credential isolation и result ACK.
- **FR-012**: Проект MUST проверять совместимую версию установленного Python до старта и MUST работать только на стандартной библиотеке без `pip`, виртуальной среды и сторонних runtime-зависимостей.
- **FR-013**: Production runtime MUST NOT выполнять внешние обращения, кроме явных IP оборудования, и MUST NOT скачивать интерпретатор, библиотеки или обновления при запуске.
- **FR-014**: Исторические Node runtime-компоненты MAY оставаться только как временный migration oracle до доказательства паритета и MUST NOT быть пользовательским production entrypoint.

### Key Entities

- **Project Package**: Полный комплект исходного приложения, локальных ресурсов и manifest совместимости без интерпретатора и внешних runtime-зависимостей.
- **Local Session**: Одноразовая браузерная сессия, привязанная к одному loopback runtime и CSRF-токену.
- **Polling Job**: Неизменяемый план, временный пул учётных данных, состояние выполнения, pending result и подтверждение записи.
- **Device Adapter**: Изолированная реализация подтверждённого протокола, получающая только scoped target и credential pair и возвращающая нормализованный результат.
- **Polling Result**: Очищенный JSON одного устройства с provenance и совместимостью ручного импорта.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: На поддерживаемом Windows 10/11 x64 с совместимым установленным Python и без Node.js проект открывает рабочий интерфейс не более чем за 15 секунд после двойного щелчка по `START_MVP_SPHERE_SR.py`.
- **SC-002**: 100% действующих contract/security сценариев feature 013 дают семантически эквивалентные состояния, статусы и JSON после миграции.
- **SC-003**: В synthetic заданиях с завершением, отменой и ошибками ни один секрет не обнаруживается в JSON, DOM, state, логах, временных или постоянных файлах.
- **SC-004**: Прямой `index.html` проходит полный текущий regression-набор ручного импорта и аналитики без запущенного runtime.
- **SC-005**: Пакет успешно запускается минимум из трёх разных путей: обычного, с пробелами и с кириллицей, без редактирования файлов.
- **SC-006**: Повреждение любого обязательного файла пакета обнаруживается до первого сетевого обращения к оборудованию.
- **SC-007**: Synthetic последовательный план из 100 устройств сохраняет порядок, выполняет не более одного активного опроса и не начинает следующий до ACK предыдущего результата.
- **SC-008**: Новый synthetic adapter может быть добавлен с контрактным fixture и зарегистрирован без изменения общего job lifecycle или пользовательского API.

## Assumptions

- Целевой рабочий компьютер использует Windows 10 или Windows 11 x64, имеет совместимый установленный Python и разрешает запуск `python.exe` и локальных `.py`-файлов.
- Runtime использует только стандартную библиотеку Python; `pip`, виртуальная среда, установка и изменение системного PATH проектом не требуются.
- Пользовательский интерфейс остаётся на HTML5/CSS3/Vanilla JavaScript; мигрируется локальный runtime, polling и production tooling.
- Поддержка устройств остаётся evidence-based: подтверждён только текущий Extron web contract, остальные protocol adapters остаются `protocol_required`.
- Реальные SR, JSON, IP и XLSX учётных данных не используются в fixtures, сборке или Git.
- Корпоративная политика может отдельно требовать разрешение хеша или издателя конкретного официального `python.exe`; проект не обходит эту политику.
