# Feature Specification: Закрытие HTTP и Telnet на Huawei TE40

**Feature Branch**: `codex/secure-local-runtime`

**Created**: 2026-09-06

**Status**: Implemented with fail-closed verification; live acceptance pending because the tested TE40 keeps TCP/80 open

**Input**: Добавить в раздел «4. План автоматического опроса» модуля «Загрузка» отдельную задачу «Закрыть порты 80, 23 (http, telnet)», использующую отдельный XLSX «Список устройств для закрытия портов 80 и 23 (http, telnet)» той же структуры, что и выгрузка SR, и подтвердить процедуру на Huawei TE40.

## User Scenarios & Testing

### User Story 1 — Явное добавление задачи в план (Priority: P1)

Администратор МЦТП загружает отдельный список устройств, формирует по нему план существующими фильтрами и отдельно включает задачу закрытия HTTP и Telnet. По умолчанию задача выключена и не меняет прежний опрос по основной SR.

**Independent Test**: При выключенной задаче цели берутся только из актуальной SR; при включённой — только из отдельного списка, который не изменяет inventory или аналитику.

**Acceptance Scenarios**:

1. **Given** открыт раздел плана, **When** пользователь ничего не менял, **Then** задача закрытия портов выключена.
2. **Given** задача выключена, **When** запускается план, **Then** выполняется прежний read-only опрос без команд изменения конфигурации.
3. **Given** задача включена, **When** пользователь подтверждает запуск, **Then** интерфейс показывает число поддерживаемых и пропускаемых целей до отправки плана.
4. **Given** отдельный список не загружен или содержит отсутствующий/некорректный/повторяющийся IP, **When** пользователь формирует write-план, **Then** план блокируется целиком.

### User Story 2 — Безопасное закрытие сервисов на TE40 (Priority: P1)

После успешного опроса и подтверждения идентичности Huawei TE40 инструмент читает текущее состояние HTTP и Telnet, изменяет только необходимые параметры и повторно проверяет их через HTTPS.

**Independent Test**: Синтетический TE40 с включёнными сервисами получает ровно одну подтверждённую команду с двумя разрешёнными параметрами, после чего повторное чтение показывает HTTP и Telnet выключенными.

**Acceptance Scenarios**:

1. **Given** TE40 успешно опрошен и идентичность подтверждена, **When** оба сервиса включены, **Then** инструмент выключает HTTP и Telnet, не изменяя HTTPS.
2. **Given** оба сервиса уже выключены, **When** выполняется задача, **Then** инструмент не отправляет команду сохранения и фиксирует соответствие.
3. **Given** опрос, идентификация, чтение текущих значений или проверка результата неуспешны, **When** выполняется задача, **Then** изменение не считается успешным, причина скрывает секреты, а обработка остальных целей продолжается.

### User Story 3 — Проверяемый локальный результат (Priority: P2)

В JSON результата устройства администратор видит, была ли задача применена, уже выполнена, пропущена или завершилась ошибкой, а также подтверждённые состояния до и после. Учётные данные и сырые ответы устройства туда не попадают.

**Independent Test**: Все исходы операции сериализуются в безопасный JSON, проходят redaction и сохраняются тем же последовательным ACK-механизмом, что и результаты опроса.

## Edge Cases

- План содержит TE40 вместе с другими моделями: обычный опрос выполняется для всех поддерживаемых целей, а изменение конфигурации применяется только к подтверждённому TE40.
- В основной SR и отдельном списке разные устройства: при включённой задаче используются только устройства отдельного списка.
- До входа или после входа модель не совпадает с планом: команда изменения не отправляется.
- Один из сервисов уже выключен: сохраняются только целевые безопасные значения, результат остаётся идемпотентным.
- Ответ сохранения успешен, но повторное чтение не подтверждает оба значения: операция считается ошибочной и требует ручной проверки; автоматическое повторное открытие портов запрещено.
- Соединение по HTTPS теряется после изменения: операция не считается подтверждённой.
- Прямой запуск `index.html` сохраняет ручной режим без сетевых запросов и не может выполнить задачу.
- Устройство сообщает `enable_http=1`, но TCP/80 остаётся доступен: задача MUST завершиться ошибкой проверки и не выдавать ложный успех.

## Requirements

- **FR-001**: В разделе «4. План автоматического опроса» MUST быть отдельный checkbox с подписью «Закрыть порты 80, 23 (http, telnet)»; его начальное состояние MUST быть выключено.
- **FR-002**: При выключенной задаче существующие фильтры, адресный выбор, состав целей и обычный опрос MUST работать без изменения по актуальной SR.
- **FR-003**: Включение задачи MUST требовать отдельного подтверждения перед созданием плана с указанием числа поддерживаемых и пропускаемых целей.
- **FR-004**: План и runtime MUST использовать версионированный явный идентификатор задачи; runtime старой версии не должен молча игнорировать запрошенное изменение.
- **FR-005**: Первая подтверждённая область поддержки MUST быть ограничена точной моделью Huawei TE40 и подтверждённым HTTPS web-CGI contract.
- **FR-006**: Для неподдерживаемой модели обычный опрос MUST продолжиться, а задача MUST получить безопасный статус `skipped_unsupported` без сетевой команды изменения.
- **FR-007**: Изменение MUST выполняться только после успешного опроса, pre-auth и post-auth проверки ожидаемой модели и подтверждения идентичности.
- **FR-008**: Перед записью MUST быть прочитаны текущие значения `enabletelnet` и `enable_http`; неизвестные или некорректные значения MUST блокировать запись.
- **FR-009**: Команда MUST содержать только подтверждённые параметры отключения Telnet и HTTP и MUST NOT изменять HTTPS, SSH или иные параметры.
- **FR-010**: Повторный запуск на устройстве с целевыми параметрами и фактически закрытыми TCP/23 и TCP/80 MUST обходиться без команды сохранения; рассинхронизация параметров и listener MAY вызвать одну повторную безопасную запись.
- **FR-011**: После записи runtime MUST повторно прочитать оба параметра через HTTPS и считать операцию успешной только при точном подтверждении целевых значений.
- **FR-012**: При ошибке проверки runtime MUST NOT автоматически открывать HTTP или Telnet; результат MUST требовать ручной проверки.
- **FR-013**: Результат MUST содержать только идентификатор задачи, безопасный статус, подтверждённые состояния до/после и безопасную стадию ошибки; credentials, cookies, CSRF, сырые ответы и Authorization запрещены.
- **FR-014**: Ошибка операции на одном устройстве MUST NOT останавливать обработку остальных устройств; ошибка записи выходного JSON сохраняет прежнее fail-stop поведение ACK.
- **FR-015**: XLSX credentials MUST оставаться только в памяти текущего job и очищаться по существующим правилам.
- **FR-016**: В модуле «Загрузка» MUST быть отдельное XLSX-поле «Список устройств для закрытия портов 80 и 23 (http, telnet)» со структурой выгрузки SR.
- **FR-017**: При включённой задаче фильтры и адресный поиск MUST использовать только устройства отдельного списка, а основную выгрузку SR MUST игнорировать как источник целей этой задачи.
- **FR-018**: Отдельный список MUST существовать только в памяти вкладки/плана и MUST NOT добавлять строки в SR inventory, locations, аналитику или историю устройств.
- **FR-019**: Строка без корректного полного IPv4 и повторяющийся IPv4 MUST атомарно блокировать отдельный список; прежний успешно загруженный список MAY оставаться активным.
- **FR-020**: План MUST фиксировать безопасный тип источника и SHA-256 отдельного XLSX, но MUST NOT содержать raw-строки файла.

## Key Entities

- **Management task**: версионированная opt-in операция, добавленная к плану без изменения его набора целей.
- **Port-closure target list**: отдельный сеансовый XLSX-набор целей, не являющийся выгрузкой SR для аналитики.
- **Capability decision**: решение каталога о допустимости операции для точной модели и transport.
- **Action result**: безопасный итог `applied`, `already_compliant`, `skipped_unsupported` или `failed` с проверяемыми состояниями.

## Assumptions

- Управляющий HTTPS/443 остаётся включённым и является единственным transport операции.
- На подтверждённом firmware TE40 отключение Telnet задаётся `enabletelnet = 0`, а отключение HTTP — `enable_http = 1` через `WEB_SaveCfgParamAPI`.
- Контролируемая проверка показала, что `enable_http = 1` может не закрывать TCP-listener 80 на тестовом firmware; до отдельного подтверждения инструмент обязан считать такой исход ошибкой, а не выполнением задачи.
- Поддержка TE30, TE50 и TE60 не выводится автоматически из общего read-only алгоритма и требует отдельного evidence review изменения конфигурации.

## Success Criteria

- **SC-001**: При выключенном checkbox 100% прежних plan/polling regression tests сохраняют прежнее поведение без вызова write endpoint.
- **SC-002**: В тестах TE40 команда сохранения содержит ровно два разрешённых параметра и ноль значений credentials/session.
- **SC-003**: 100% mismatch/unknown-state сценариев выполняют ноль команд сохранения.
- **SC-004**: Повторный запуск после успешного изменения выполняет ноль команд сохранения.
- **SC-005**: Реальный тестовый TE40 подтверждает закрытое состояние HTTP и Telnet повторным чтением через HTTPS, а итоговый JSON не содержит секретов.
- **SC-006**: План закрытия портов успешно формируется без загруженной основной SR при наличии корректного отдельного списка и не создаёт ни одного inventory device.
