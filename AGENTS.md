# AGENTS.md

## Статус проекта

Проект подготовлен к дальнейшему редактированию через ИИ-агента и GitHub SpecKit.

- Видение: `docs/project-vision.md`. Текущая feature: `specs/060-resumable-log-import/` (порционное сохранение растущей базы, checkpoints импорта логов и скорость).
- Интерфейс: Windows, HTML5, CSS3, Vanilla JavaScript, browser File/System Access API, vendored SheetJS CE 0.20.3.
- Production runtime автоматического опроса: установленный Python 3.11+ и только стандартная библиотека; `START_MVP_SPHERE_SR.py` открывает авторизованную loopback-сессию.
- Node.js используется только при разработке для JavaScript regression/reference checks и не требуется пользователю.
- Прямой `file://index.html` — ручной импорт и аналитика без сетевого опроса.
- Хранение: после явного выбора рабочей папки безопасная проекция SR/JSON и индексы логов пишутся в локальную SQLite-базу для восстановления; полный сырой текст, логи и пароли в неё не копируются. Прямой `file://` остаётся сеансовым; `localStorage`/`IndexedDB` не используются.
- Роль: только «Администратор МЦТП».
- Constitution: версия 5.0.0 в `.specify/memory/constitution.md`.
- Аналитика feature 059 / ADR-0062 использует только категорию ВКС и статус оборудования «Учёт» в актуальной SR. Подтверждённые перезагрузки, штатные выключения и предполагаемые паузы без логов считать раздельно; предположение не доказывает аварийного отключения или текущего состояния устройства. Кольца, отдельные TOP-5, карта 7×24 и два локальных XLSX работают по общим фильтрам и уже проверенным Huawei TE/310/300 индексам. Polycom TGZ остаётся метаданными, без событийного вывода; серый сектор не означает исправность. Текст XLSX — буквальные строки без формул, исходные логи/JSON не переписывать.
- Текущая feature: `specs/060-resumable-log-import/` (возобновляемый импорт, порции БД и фактическая скорость).

## Правила работы агента

- Feature 060 / ADR-0063 заменяет общий потолок снапшота feature 058: текущий клиент отправляет и восстанавливает безопасную историю порциями, неизменные порции переиспользуются по SHA-256, новая ревизия публикуется атомарно. Ограничение HTTP относится только к одной порции, не к суммарной БД. Legacy-маршрут оставлен для совместимости старых клиентов; клиент новой версии его для сохранения не использует. В выбранной БД отдельно хранятся контрольные точки успешно разобранных файлов: область SR+версия/режим, ключ путь/size/mtime/prefix SHA-256/format/device/model. После сбоя администратор выбирает папку заново; тело неизменённого готового файла не читается, сохраняются исходные event rules. Полный незавершённый импорт не заменяет опубликованную аналитику. До двух Worker, 1 МиБ чтение, скорость только по фактическим байтам. В `file://` нет постоянного восстановления.

- Актуальное уточнение feature 047 / ADR-0049 заменяет прежний предел «один IP» только для Answer mode exact TE20, TE30/40/50/60 и Bar 310/Box 310/Box 610: допустим один IP либо фильтры актуальной SR. Один план содержит один action ID, все выбранные устройства обязаны его поддерживать; смешанная группа блокируется до сети. UI показывает число целей и требует отдельное согласие. Runtime повторно проверяет SR digest, уникальность IP и модели; каждый write остаётся per-device pre-read/максимум one-write/post-read без автоматического повтора неясного исхода. Остальные write-задачи сохраняют single-IP/модельные ограничения. Администратор подтвердил оба направления в одиночном и массовом режимах на всех восьми моделях.

- Сначала прочитать этот файл и использовать `docs/context-map.md`.
- Feature 058 / ADR-0061: при локальном запуске рабочая база выбирается администратором явно и хранится только в этой папке; Python runtime запоминает вне Git лишь путь. Доступ к `/api/workspace/*` требует session/admin gate, Origin/CSRF для записи. База содержит только валидированную безопасную проекцию без `rawText`, паролей, токенов и копий полных логов; завершённая ревизия заменяется атомарно, конфликт двух вкладок и повреждение блокируют запись. Huawei XML разбирается порционно в Worker, `file://` использует безопасный fallback; Polycom TGZ и неизвестные модели входят в registry только как метаданные до отдельного подтверждения событийного парсера. Инкрементальный пропуск прежнего файла опирается на путь/размер/mtime/хэш префикса как cache-оптимизацию; содержательные события дедуплицируются по существующим правилам. Полная перепроверка доступна явно. Никаких скрытых копий источников или внешней передачи.
- Не загружать весь репозиторий без необходимости и не менять несвязанные файлы.
- Не выдумывать vendor API, команды, transport или схемы ответов; неизвестное отмечать `TBD`/`protocol_required`.
- Для Extron controller/panel разрешён только подтверждённый контракт `mvp_runtime/adapters/extron.py`: HTTPS/443, dynamic URI из текущего bundle и exact resource URL.

Для точных Huawei TE30/TE40/TE50/TE60 разрешён общий guarded transport `huawei_te_web_cgi_v1` с проверкой модели до credentials и после входа. Все пять моделей подтверждены контролируемыми опросами реальных устройств. Дополнительное read-only чтение Site Name выполняется только после post-auth проверки модели/идентичности: при двух mailbox action-маркерах принимается только `state.sitename`; для exact TE20 и exact TE40, когда mailbox-подписка отсутствует, контролируемым опросом каждой модели подтверждён fallback `WEB_GetCfgParamAPI` с единственным `CfgIDString=["sitename"]` и строгой строковой схемой. Отсутствие подтверждённого метода или ответа сохраняет `protocol_required`/`unavailable`. Для exact TE30/TE50/TE60 после отдельного evidence review общего read-only контракта этот же fallback включён условно по маркерам текущего bundle и строгой строковой схеме; его эксплуатационный статус предварительный до проверки администратором на каждой модели.
- Exact Huawei Bar 310, Box 310 и Box 610 используют один transport `huawei_310_rest_v1` и contract ID `huawei-310-rest-v1` на базе проверенного Bar 310; три model-key в SR/JSON остаются отдельными для истории. Общий dispatcher до сети выбирает только exact модель, guarded core `mvp_runtime/adapters/huawei_bar310.py` выполняет HTTPS/443, pre-auth model/bundle gates до credentials, session/account с `X-Access-Token`, bounded ресурсы и post-auth модель плюс SN/ESN либо MAC. Обычный опрос трёх моделей подтверждён эксплуатацией и остаётся read-only. Администратор отдельно подтвердил названия и значения настроек и Site name на обеих Box; новые read-only результаты имеют `confirmed_user_validation`, исторические предварительные JSON не переписывать. Отдельные write-задачи: HTTP `enable_http=0` с post-read и Answer mode `autoreply=1|0`; HTTP write Box ещё ожидает проверки, а оба направления Answer mode в одиночном и массовом режимах подтверждены администратором на всех трёх моделях. Telnet не читается/не пишется; `not_exposed` не доказывает закрытый TCP/23. Суффиксные и иные варианты остаются `protocol_required`. Решения ADR-0046/0047/0048/0049.
- Для exact Huawei 310 после model/identity gates разрешены узкие `POST /v1/om/config` + `CfgIDString` для `sitename`, `autoreply`, `synSerTime/ntpGetMode/ntpServerAddr`, `enableWifi/apEnable/isWifiPriority`, `enable_ssh`, `suppotReboot/sleepTime/autoReboot/sleepCloseAPP/autoRebootVal/savePowerMode`. Текущий bundle и строгая схема обязательны, читать только эти ID, не запрашивать Wi‑Fi пароль/SSID. SSH кодирует `1=включён`, `2=выключен`; автоответ после контролируемого цикла Bar «Авто → Вручную → Авто» кодирует `1=автоматический`, `0=ручной`, вопреки статической подписи в части bundle. Неизвестные расписания питания и очистку после перезагрузки не подменять `autoReboot`. Администратор отдельно подтвердил названия и значения новых read-only полей Box 310/610; новые результаты имеют `confirmed_user_validation`, исторические provisional JSON не переписывать. Это доказательство возможности обновления, но не факт уже выполненного обновления. Read-only `GET /v1/om/config/service` и при `serverType=-1` `GET /v1/om/config/auto-config` выполняются только после model/identity/bundle gates; UI fallback `-1 → Вручную` подтверждён на Bar, Box 310/610 администратор проверил отдельно. - Для exact Bar 310/Box 310/Box 610 отдельные `set_huawei_310_auto_answer_automatic/manual` доступны одному IP либо совместимому набору по фильтрам SR и не сочетаются с HTTP или другими write-задачами. «Не менять» не создаёт action. Обычный опрос остаётся read-only, статус HTTP write не меняется. Решения ADR-0048/0049.

Box 310/610 участвуют после отдельного пользовательского подтверждения событийной аналитики. Кольцевая диаграмма берёт 100% от устройств текущего фильтра SR и одно максимальное завершённое наблюдение на устройство, остальные входят в серый сектор. Восемь непересекающихся интервалов длительности: до часа, суток, недели, месяца, 3 месяцев, 6 месяцев, года и более года; месяц = 30 суток, год = 365. Начальный интервал — более года. Подтверждённый интервал от команды выключения до следующего boot и предположительная тишина логов должны иметь разные подписи. Это не текущее состояние питания и не доказательство аварийного отключения. Решение ADR-0052.
- Тепловая карта feature 050: в разделе питания показывать 7×24 ячейки по уникальным устройствам текущих фильтров и выбранного периода. Подтверждённые штатные выключения и предполагаемые паузы переключаются отдельно; число событий и число устройств не смешивать. При нажатии раскрывать SR-устройства, локации, адреса и только метаданные файлов/строк, без сырого текста. День и час брать из локального времени каждого терминала без конверсии или предположения об общем часовом поясе. Совпадение времени не доказывает общую причину.
- После отдельного контролируемого выключения TE20 с пульта администратором подтверждён `LOG_MOD_RC` + `user ... shut ... down ... terminal`; это второй модельный маркер штатной команды отключения с `shutdownMethod=remote_control`, отличимый от `LOG_MOD_WEB` с `shutdownMethod=web`. Нажатия Power, сон, `OFFLINE` и последующий boot сами по себе не являются событием отключения. Полный лог проверен в памяти, реальные строки не сохранялись.
- Новый adapter регистрировать через `mvp_runtime/polling.py` и `runtime/device-catalog.json` только после evidence review, описанного в `docs/development-workflow.md`.
- Не изменять raw SR/JSON и внутренние enum-коды ради локализации; русские подписи брать из централизованного presentation dictionary в `app.js`.
- Термины SR, GCPlus и перезагрузок не трактовать без подтверждения; использовать «Требует уточнения» и «В разработке».
- Для exact Huawei TE20/30/40/50/60 длительная пауза в импортированном журнале перед неизвестным запуском даёт только отдельное низкодостоверное «Предполагаемое отключение питания» при настраиваемом пороге (60 минут по умолчанию). Это не подтверждение физической потери питания, не точное время её начала и не часть подтверждённых счётчиков; TE30/50/60 требуют проверки по реальным логам. Exact Bar 310 использует собственную схему такого предположения по feature 050; остальные модели правило не наследуют.
- Доступные модули, их названия, справочные описания, пользовательские статусы и подсказки изменять через `product-catalog.js`; после правки обязательно запускать `node scripts/validate-reference.js`.
- Не добавлять новый доступный маршрут в обход `MODULE_CATALOG` и не дублировать модульные карточки вручную в `app.js`.
- Никогда не помещать реальные логины, пароли, токены, ключи, IP-выгрузки или runtime data в Git, fixtures, логи, state, аналитику и ответы API.
- Учётные данные вводятся пользователем в форме текущей вкладки и передаются только в same-origin loopback runtime. После передачи поля очищаются; пары нельзя помещать в state, plan, browser storage или постоянное хранилище.
- Runtime сверяет SHA-256 переданных пар, очищает пул во всех terminal paths и выдаёт redacted JSON по одному до ACK записи. Vault и fallback credentials запрещены.
- Доступ к плану на каждом ПК настраивается при первом запуске: локальный scrypt-verifier хранится только в профиле текущего пользователя Windows вне Git, открытый пароль не сохраняется. Python runtime проверяет вход до любого `/api/polling/*`; браузерное скрытие формы не считается границей защиты. Пароли оборудования по-прежнему только в памяти задания.
- Не добавлять внешнюю передачу, CDN, телеметрию, third-party Python dependency или non-loopback bind без явного решения пользователя и security review.
- Не делать commit/push без явного указания пользователя.
- Значимые решения фиксировать в `docs/decisions`, этапы — в `docs/implementation-log.md`.
- При изменении архитектуры, workflow или поведения обновлять документацию и тесты.

## Workflow

Подробности находятся в `docs/development-workflow.md`.

- Full SpecKit — крупные, рискованные или неоднозначные задачи.
- SpecKit-lite — средние задачи.
- Короткий prompt — небольшие локальные правки.

## Проверки

- Python runtime/API/security: `python -m unittest discover -s python_tests -v`.
- Python syntax/import: `python -m compileall -q mvp_runtime python_tests START_MVP_SPHERE_SR.py`.
- Интерфейс и регрессия: `node tests.js`.
- Справочник: `node scripts/validate-reference.js`.
- Синтаксис изменённых `.js`: `node --check`.
- Secret/artifact/IP scan обязателен перед commit.
- Acceptance: `START_MVP_SPHERE_SR.py` проверяет полный автоматический workflow; прямой `index.html` — ручной пакетный импорт, сеансовую аналитику и блокировку сети.
