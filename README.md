# MVP_SPHERE_SR

Локальный инструмент инвентаризации, опроса и аналитики терминалов ВКС, контроллеров и панелей управления. Рабочий интерфейс доступен только через защищённый runtime на `127.0.0.1`; файлы, состояние и учётные данные не отправляются во внешние сервисы.

## Запуск

На Windows запустите:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Runtime сам откроет одноразовую локальную сессию в браузере. Прямое открытие `index.html` не является рабочим защищённым режимом и блокируется приложением. Если совместимая Node.js 24+ отсутствует, `start.ps1` однократно скачает закреплённый официальный Node.js 24 LTS для x64/ARM64, проверит SHA-256 и распакует его в локальный каталог `.runtime/` без прав администратора и изменения системного PATH. Повторные запуски используют уже проверенную среду без сети.

На новом Windows-ПК каждая скачанная копия проекта создаёт отдельное хранилище в `%LOCALAPPDATA%\MVP_SPHERE_SR` и отдельный DPAPI-ключ текущего пользователя. Рабочие данные, аналитика и учётные данные не загружаются из GitHub и не передаются между компьютерами.

Остановка — `Ctrl+C` в окне PowerShell.

## Интерфейс

Доступна единственная роль — «Администратор МЦТП». Основные разделы:

- «Главный экран» с аналитикой и фильтрами;
- «Терминалы ВКС»;
- «Контроллеры»;
- «Панели управления»;
- «Загрузка»;
- «Локальное хранилище»;
- «Справочник» с поиском по терминам, сокращениям и определениям.

Модули «Проекты аудита», «События», «Сопоставления» и «Снимки» из навигации и маршрутизации удалены.

## Главный экран

Дашборд строится только из актуальной SR и сохранённой истории опросов. Он не генерирует демонстрационные значения и явно разделяет два контекста:

- «Текущее состояние» — по одному самому новому результату на устройство: инвентарь, успешные и неуспешные состояния, доступность по сети, отсутствие опроса и неподдерживаемые модели;
- «Выбранный период» — активность за выбранный период: результаты, ошибки, отсутствие ответа по сети, устройства с изменениями, записи изменений и ошибки данных.

Глобальная область анализа включает период, категорию, производителя, модель, локацию, VIP и текущий статус. Показатели и списки проблем открывают соответствующий раздел оборудования с уже применёнными фильтрами. Отдельно показаны последний запуск, VIP-инфраструктура, приоритетные локации, последние проблемы и изменения, а также распределения по производителям, моделям и категориям.

Метрики авторизации, перезагрузок, GCPlus и просроченности не подменяются нулями: пока источник или порог не подтверждены, интерфейс показывает «Недостаточно данных» или «Порог не настроен».

## Терминология и Справочник

Пользовательская часть интерфейса русифицирована без изменения исходных значений SR, JSON и внутренних кодов. Категории всегда отображаются как «Терминалы ВКС», «Контроллеры» и «Панели управления», а недоступность по ping — как «Нет ответа по сети».

«Справочник» содержит десять тематических разделов, локальный поиск и контекстные переходы «О модуле» с Главного экрана и из трёх разделов оборудования. Неопределённые понятия SR и GCPlus помечены как требующие уточнения, а сведения о перезагрузках — как находящиеся в разработке; неподтверждённые трактовки не добавляются.

Модули, пользовательские статусы и подсказки объявлены в едином `product-catalog.js`. Навигация и соответствующие карточки Справочника строятся из этого каталога: добавление, переименование или удаление зарегистрированного модуля автоматически отражается в обоих местах. `node scripts\validate-reference.js` и обязательные тесты блокируют дубли, потерянные карточки и отсутствующие русские подписи.

## Загрузка данных

В разделе «Загрузка» можно импортировать:

1. XLSX-выгрузку SR согласно `specs/002-sr-inventory-analytics/contracts/sr-xlsx-import.md`.
2. Результаты опроса — JSON-файлы с именами по IP устройства.
3. Файл учётных данных — JSON или CSV.

JSON учётных данных:

```json
{
  "credentials": [
    { "ip": "10.10.1.15", "login": "operator", "password": "example-only" }
  ]
}
```

CSV может использовать запятую или точку с запятой и заголовки `IP`, `Логин`, `Пароль`. Импорт заменяет vault целиком и выполняется атомарно: при ошибке или повторяющемся IP прежний vault остаётся неизменным. Исходный незашифрованный файл после успешного импорта следует удалить или поместить в одобренное организацией защищённое хранилище.

## Хранение и защита

- Runtime слушает только `127.0.0.1` и не включает CORS, телеметрию, CDN или облачные интеграции.
- Все объекты на диске шифруются AES-256-GCM с отдельным случайным nonce и проверкой целостности.
- Главный ключ защищён Windows DPAPI в области `CurrentUser`.
- Учётные данные находятся в отдельном зашифрованном vault; API возвращает только число записей, hash источника, дату и маскированные IP.
- Пароли не входят в состояние, аналитику, polling JSON, UI, backup или журнал.
- Искусственной квоты приложения нет: объём ограничен только свободным местом и возможностями локальной файловой системы.
- Данные по умолчанию находятся в `%LOCALAPPDATA%\MVP_SPHERE_SR` и исключены из Git.

Это защищает данные «на диске» от чтения вне текущего Windows-профиля и от внешнего web-доступа. Защита не может противостоять уже скомпрометированной учётной записи Windows, администратору ОС, вредоносному ПО в пользовательской сессии или чтению памяти запущенного процесса.

## Опрос устройств

`runtime/model-catalog.js` содержит переданный каталог производителей и моделей. `scripts/poll-devices.js` принимает явный allowlist-план, проверяет адреса, выполняет ограниченный по времени ping и пишет отдельный безопасный JSON на каждый IP:

```powershell
node .\scripts\poll-devices.js --plan .\polling-plan.json --out .\polling-output --timeout 3000
```

Минимальный план:

```json
{
  "devices": [
    { "ip": "10.10.1.15", "category": "vcs", "manufacturer": "Cisco", "model": "Webex Room Kit" }
  ]
}
```

Для известных моделей без подтверждённого vendor-протокола результат имеет статус `protocol_required`. Это намеренная fail-closed граница: реальные HTTPS/SSH/SNMP-команды и схемы ответов будут добавлены только по документации производителя или проверенным примерам, а не на основании догадок по названию модели.

## Ключевые файлы

- `server.js`, `start.ps1` — локальный loopback runtime и запуск;
- `portable-runtime.json`, `scripts/ensure-node.ps1` — закреплённый официальный portable runtime, hash-проверка и локальная подготовка;
- `product-catalog.js`, `scripts/validate-reference.js` — единый каталог интерфейса/Справочника и проверка согласованности;
- `runtime/security.js`, `runtime/secure-store.js` — DPAPI и зашифрованное хранилище;
- `runtime/credential-vault.js` — импорт и write-only vault;
- `runtime/model-catalog.js`, `runtime/polling.js`, `scripts/poll-devices.js` — каталог и каркас опроса;
- `app.js`, `styles.css`, `index.html` — UI, чистая Dashboard-проекция и аналитика;
- `specs/003-secure-local-polling/` — защищённый runtime и polling boundary;
- `specs/004-analytics-dashboard/` — спецификация, контракты, план и проверки Dashboard;
- `specs/005-russian-ui-reference/` — спецификация, словарь терминологии, Справочник и проверки русской пользовательской части;
- `specs/006-portable-reference-sync/` — переносимый защищённый запуск и автоматическая синхронизация Справочника;
- `docs/decisions/ADR-0005-secure-local-runtime.md` — архитектурное решение.
