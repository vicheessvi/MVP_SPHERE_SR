# MVP_SPHERE_SR

Статус: MVP реализован; automated и ручной direct-open acceptance завершены, задачи `T001`–`T060` закрыты.

Локальный browser-only MVP для анализа изменений проектов и оборудования между периодическими JSON-снимками.

## Запуск

Откройте `index.html` двойным кликом. Backend, база данных, package manager и установка зависимостей не требуются.

Demo-учётные записи:

- AV-инженер: `engineer` / `engineer`
- Администратор: `admin` / `admin`

Demo-сессия хранится только в `sessionStorage`: перезагрузка текущей вкладки сохраняет вход, а новое открытие после закрытия вкладки снова показывает форму входа. Проекты и snapshots продолжают храниться отдельно в `localStorage`.

Dependency-free проверки открываются через `tests.html`.

## Первый сценарий

1. Войдите как AV-инженер или администратор.
2. На экране «Загрузка» выберите один или несколько synthetic/sanitized JSON-файлов.
3. Первый Extron v1 snapshot создаст проект и оборудование; следующий снимок того же проекта создаст comparison.
4. Legacy snapshot без стабильного projectId потребует ручной связи с существующим или новым логическим проектом.
5. Откройте snapshot и comparison, чтобы увидеть статус, полноту, проблемы данных, old/new values, severity, confidence и безопасные evidence paths.

Поддерживаются Extron v1 и распознаваемый legacy-профиль. Повтор тех же байтов определяется по SHA-256, а formatting-only различия не создают событий.

На экране «Проекты» доступны текущий inventory, timeline по `capturedAt`, отдельное время загрузки и сравнение любой пары дат. При поздней загрузке старый несмежный ChangeSet сохраняется как `superseded`, а активная цепочка автоматически перестраивается.

В карточке проекта можно назначить или заменить утверждённый baseline, просмотреть накопленный drift и историю назначений. Замена и завершение требуют подтверждения; baseline со статусом `expiration_pending` нельзя завершить неявно.

Экран «События» фильтрует изменения по проекту, периоду, сущности, категории, типу, важности, confidence и review status. Решения review сохраняются append-only. Экран «Сопоставления» позволяет выбрать Asset, создать новый, подтвердить замену или оставить случай нерешённым с контролируемым пересчётом производной истории.

Retention по умолчанию составляет 1095 дней, проверяется при старте и запускается вручную администратором на экране «Хранилище». Обычные устаревшие snapshots удаляются вместе с зависимыми расчётами и минимальной записью `RetentionAudit`; это не создаёт событие изменения оборудования. Устаревший активный baseline сохраняется со статусом `expiration_pending` до явного решения пользователя.

## Важно про безопасность

Browser-only MVP предназначен для synthetic/sanitized demo data. `sessionStorage`, `localStorage`, локальные роли и history не обеспечивают настоящую информационную безопасность или tamper-resistant audit trail. Реальные чувствительные инфраструктурные данные требуют отдельной production-архитектуры.

Временные исключения из принципов I и VI constitution, их владелец, компенсации и условие устранения зафиксированы в `docs/decisions/ADR-0003-browser-only-demo-stack.md`.
