# MVP_SPHERE_SR

Локальный инструмент инвентаризации, автоматического опроса и аналитики терминалов ВКС, контроллеров, панелей управления и другого мультимедийного оборудования. Внешняя передача данных, телеметрия, CDN и облачные сервисы не используются.

## Требования и запуск

Для полного режима нужен установленный **Python 3.11 или новее**. Node.js, PowerShell, CMD, `pip`, виртуальное окружение, инсталлятор и права администратора не требуются.

1. Скачайте или скопируйте весь проект в любую локальную папку.
2. Дважды щёлкните `START_MVP_SPHERE_SR.py`.
3. Не закрывайте открывшееся окно Python во время работы: локальный исполнитель действует только пока оно открыто.

Если Windows впервые спрашивает, чем открыть `.py`, один раз выберите установленный `python.exe`. Скрипт проверит версию Python и целостность обязательных файлов, запустит случайный адрес `127.0.0.1` и откроет браузер с одноразовой локальной сессией.

Прямой двойной щелчок по `index.html` сохраняется как отдельный ручной режим: загрузка SR, общей папки JSON и аналитика работают, автоматический сетевой опрос недоступен.

## Интерфейс и данные

Доступна одна роль — «Администратор МЦТП». Основные разделы: «Главный экран», анализ перезагрузок, версий проектов и прошивок, ошибки при подключении, «Оборудование» с семью категориями, «Загрузка данных и опрос устройств», «Локальное хранилище» и «Справочник». Анализ перезагрузок раскрывает таблицы по нажатию на карточки; версии сравниваются по истории точно сопоставленного устройства, а ошибки авторизации и сети показываются раздельно. «Сравнение полей файлов опроса с параметрами SR» остаётся в разработке. Модули «Проекты аудита», «События», «Сопоставления» и «Снимки» в навигации отсутствуют.

Оборудование всегда строится из актуальной выгрузки SR. Все строки SR сохраняются, включая неполные записи без inventory, serial, MAC или IP. Разные устройства не объединяются по похожему адресу или имени: новый JSON автоматически привязывается только к точному текущему IP из актуальной SR. Исторические IP используются лишь для диагностики.

Актуальная выгрузка SR содержит 42 столбца: от `SmartRoom ID локации` до `802.1x`. Основные новые названия — `Наименование локации`, `Адрес локации`, `Класс оборудования`, `Наименование оборудования`, `Тип`, `IP адрес` и `MAC адрес`. Прежние заголовки принимаются как совместимые псевдонимы. Если в строке есть `SmartRoom ID локации` или `SmartRoom ID оборудования`, они используются как устойчивые идентификаторы при последующих загрузках; исходная строка XLSX сохраняется без изменения.

Результаты ручного опроса загружаются общей папкой. Внутри неё ожидаются одна или несколько папок запусков:

```text
polling-export/
├── 2026-06-01_09-41-28/
│   ├── 192.0.2.10.json
│   └── 192.0.2.11.json
└── 2026-06-02_10-15-00/
    └── 192.0.2.12.json
```

Имя `2026-06-01_09-41-28` означает 1 июня 2026 года, 09:41:28. JSON ищутся рекурсивно. Время отдельного результата берётся из `File.lastModified`, а не подменяется временем папки.

## Автоматический опрос

В модуле «Загрузка данных и опрос устройств»:

1. загрузите актуальную SR;
2. выберите общую папку для результатов;
3. введите пары логина и пароля в нужном порядке; при необходимости добавьте или удалите строки и передайте пары локальному исполнителю;
4. сформируйте план Домен → Класс оборудования → Производитель → Модель, задайте время и границы случайного интервала в секундах (например, от 5 до 10 включительно); для трёх и более поддерживаемых устройств границы должны различаться, кроме режима 0–0 без пауз;
5. при диапазоне 0–0 прочитайте предупреждение и подтвердите запуск без пауз; затем нажмите «Сформировать и запустить опрос».

Python-runtime сверяет SHA-256 переданных пар, держит их только в памяти одного задания и очищает после завершения, отмены или ошибки. Поля ввода очищаются сразу после передачи; итоговые JSON, журнал восстановления и аналитика секретов не содержат. Каждый redacted JSON сохраняется браузером в выбранную папку `YYYY-MM-DD_HH-mm-ss`. Если один JSON записать не удалось, ошибка фиксируется и остальные устройства продолжают опрашиваться. Если браузер закрылся или компьютер перезагрузился, заново запустите инструмент, выберите прежнюю общую папку, повторно загрузите исходную SR (для задачи закрытия портов — тот же отдельный список целей), снова введите пары и нажмите «Продолжить опрос». Сохранённые файлы проверяются по точному IP и не опрашиваются повторно. Неясный исход задачи изменения настроек автоматически не повторяется и требует отдельной проверки. Видимый `polling-recovery.json` создаётся в папке запуска и не импортируется как опрос устройства.

Подтверждены локальные автоматические контракты для контроллеров/панелей Extron и терминалов Huawei TE20/TE30/TE40/TE50/TE60/Bar 310/Box 310/Box 610. TE20 использует отдельный HTTPS/443 transport с точным legacy TLS 1.1, проверкой legacy login-схемы до пароля и точной проверкой модели после входа. TE30/TE40/TE50/TE60 используют общий guarded web-CGI transport с проверкой модели до и после входа. Bar 310, Box 310 и Box 610 имеют три самостоятельных подтверждённых read-only `/v1` contract: они требуют точную модель до credentials и после входа и не переходят на другой протокол при несовпадении. Самоподписанный сертификат разрешается только явным флагом текущего задания. HTTP fallback отсутствует. Остальные модели остаются `protocol_required` и не получают учётные данные или сетевой запрос по выдуманному протоколу. Выключенная по умолчанию задача закрытия HTTP/Telnet доступна точным TE20/TE30/TE40/TE50/TE60 и по модельным правилам 310-серии через отдельный список целей; серия 300 остаётся только read-only.

Для терминалов Huawei дополнительное значение Site Name считывается после проверки точной модели и идентичности, только модельно подтверждённым способом: mailbox для прежних TE/310-контрактов либо точный config read для серии 300. При успехе оно находится в `siteName.value` и `webBlocks.Device Info.Site Name` готового JSON. Если метод или ответ не подтверждены, записывается `protocol_required` либо `unavailable`; имя локации SR не подставляется. Для TE20 и серии 310 требуется контрольная проверка на рабочей прошивке.

Huawei CloudLink Bar 300 использует отдельный подтверждённый read-only HTTPS web-CGI опрос: модель проверяется до и после входа, затем читаются сведения об устройстве, прошивке, сети, времени, возможностях и Site name. Box 300 и Box 600 подключены к общему core через собственные exact-model проверки; их результаты предварительны до контроля на реальных устройствах. Для этих трёх моделей нет задачи изменения HTTP/Telnet или переноса REST-контракта серии 310.

## Хранение и защита

- state интерфейса, разрешение папки, задания и учётные данные существуют только в памяти текущих процессов/вкладки; в выбранной папке хранится лишь видимый несекретный журнал восстановления;
- `localStorage`, `IndexedDB` и скрытое runtime-хранилище не используются;
- исходные SR/JSON не изменяются;
- готовые JSON пишутся только в явно выбранную пользователем папку;
- loopback принимает только текущий `127.0.0.1|localhost` порт, одноразовую HttpOnly-сессию и CSRF для изменений;
- сетевые обращения к оборудованию ограничены точными IP из неизменяемого плана;
- искусственной квоты данных приложения нет; фактический предел — память браузера и свободное место выбранного диска.

Сеансовая модель не защищает от компрометации текущей учётной записи Windows, вредоносного ПО или чтения памяти запущенного процесса.

## Справочник и развитие

Названия модулей, пользовательские статусы и справочные описания находятся в `product-catalog.js`. Общие производители, модели и статусы протоколов — в `runtime/device-catalog.json`. Новый vendor adapter допускается только после документального или проверенного на устройстве подтверждения endpoint, transport, аутентификации и схем ответов; граница регистрации находится в `mvp_runtime/polling.py`.

Node.js не является частью пользовательского запуска. Он используется разработчиком/CI только для тестов Vanilla JavaScript и проверки Справочника.

## Проверки разработчика

```text
python -m unittest discover -s python_tests -v
python -m compileall -q mvp_runtime python_tests START_MVP_SPHERE_SR.py
node tests.js
node scripts/validate-reference.js
```

## Ключевые файлы

- `START_MVP_SPHERE_SR.py`, `mvp_runtime/` — Python 3.11+ launcher, loopback API, XLSX, polling job и Extron adapter;
- `runtime/device-catalog.json` — общий каталог устройств/протоколов;
- `index.html`, `app.js`, `styles.css`, `runtime-config.js` — интерфейс и прямой ручной режим;
- `runtime/credential-pool.js`, `vendor/xlsx.full.min.js` — проверка XLSX в браузере без CDN;
- `product-catalog.js`, `scripts/validate-reference.js` — единый Справочник и контроль согласованности;
- `python_tests/`, `tests.js` — Python API/security и интерфейсная регрессия;
- `specs/014-python-runtime-migration/`, `docs/decisions/ADR-0014-python-runtime-migration.md` — актуальное архитектурное решение.
