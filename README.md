# MVP_SPHERE_SR

Локальный инструмент инвентаризации и аналитики результатов опроса терминалов ВКС, контроллеров, панелей управления и других устройств. Инструмент имеет один режим работы: прямое открытие `index.html`. Внешней передачи данных нет.

Интерфейс содержит раскрывающийся модуль «Оборудование» с семью категориями: Терминалы ВКС, Контроллеры, Панели управления, Коммутаторы, Матричные коммутаторы, Скалеры и Аудио процессоры. Все категории формируются из SR и используют общие фильтры, карточки, историю и Dashboard.

Дата и время отдельного результата опроса берётся только из доступного браузеру `File.lastModified` и показывается как время последнего изменения файла. Имя папки запуска не подставляется вместо времени результата. Значимые изменения ограничены централизованным перечнем подтверждённых параметров; raw JSON сохраняется полностью в памяти текущей вкладки.

Все строки SR сохраняются в перечне, включая пассивное оборудование без inventory/serial/MAC/IP. В таком случае интерфейс показывает предупреждение и использует локальную составную идентичность. JSON-файл сопоставляется только с текущим IP устройства из актуальной SR; `ipHistory` сохраняется для истории и диагностики, но не участвует в автоматической привязке. Подтверждённый внутренний IP JSON и надёжно определённая категория проверяются до назначения `deviceId`: конфликтный результат сохраняется отдельно и не меняет статус или историю оборудования. Для любого однозначно сопоставленного устройства Extron точное `error = No credentials were accepted` отображается как «Ошибка авторизации»; другие ошибки не переименовываются.

Категории определяются точными правилами SR: Контроллеры — по `Тип оборудования = controller`, Терминалы ВКС — по `Тип модели = Video Conference`, Скалеры — по `Тип модели = Скалер`. Разные строки одной актуальной SR не схлопываются только из-за совпавшего fallback-идентификатора: конфликт сохраняет обе записи и создаёт диагностику. Только точный повтор строки с теми же идентификаторами и описанием считается подтверждённым дублем. Без пользовательских фильтров карточка и таблица показывают одинаковый перечень актуальной SR.

## Запуск

Откройте корневой `index.html` двойным щелчком. Для просмотра, импорта и аналитики Node.js, PowerShell и сеть не требуются. Импортированные SR/JSON, аналитика и временно проверенный XLSX-пул существуют только в памяти открытой вкладки и исчезают после перезагрузки или закрытия.

## Интерфейс

Доступна единственная роль — «Администратор МЦТП». Основные разделы:

- «Главный экран» с аналитикой и фильтрами;
- «Терминалы ВКС»;
- «Контроллеры»;
- «Панели управления»;
- «Загрузка»;
- «Локальное хранилище»;
- «Справочник» с поиском по терминам, сокращениям и определениям.

Модули «Проекты аудита», «События», «Сопоставления» и «Снимки» из навигации и маршрутизации удалены.

## Главный экран

Дашборд строится только из актуальной SR и сохранённой истории опросов. Он не генерирует демонстрационные значения и явно разделяет два контекста:

- «Текущее состояние» — по одному самому новому результату на устройство: инвентарь, успешные и неуспешные состояния, доступность по сети, отсутствие опроса и неподдерживаемые модели;
- «Выбранный период» — активность за выбранный период: результаты, ошибки, отсутствие ответа по сети, устройства с изменениями, записи изменений и ошибки данных.

Глобальная область анализа включает период, категорию, производителя, модель, локацию, VIP и текущий статус. Показатели и списки проблем открывают соответствующий раздел оборудования с уже применёнными фильтрами. Отдельно показаны последний запуск, VIP-инфраструктура, приоритетные локации, последние проблемы и изменения, а также распределения по производителям, моделям и категориям.

Метрики авторизации, перезагрузок, GCPlus и просроченности не подменяются нулями: пока источник или порог не подтверждены, интерфейс показывает «Недостаточно данных» или «Порог не настроен».

## Терминология и Справочник

Пользовательская часть интерфейса русифицирована без изменения исходных значений SR, JSON и внутренних кодов. Категории всегда отображаются как «Терминалы ВКС», «Контроллеры» и «Панели управления», а недоступность по ping — как «Нет ответа по сети».

«Справочник» содержит десять тематических разделов, локальный поиск и контекстные переходы «О модуле» с Главного экрана и из трёх разделов оборудования. Неопределённые понятия SR и GCPlus помечены как требующие уточнения, а сведения о перезагрузках — как находящиеся в разработке; неподтверждённые трактовки не добавляются.

Модули, пользовательские статусы и подсказки объявлены в едином `product-catalog.js`. Навигация и соответствующие карточки Справочника строятся из этого каталога: добавление, переименование или удаление зарегистрированного модуля автоматически отражается в обоих местах. `node scripts\validate-reference.js` и обязательные тесты блокируют дубли, потерянные карточки и отсутствующие русские подписи.

## Загрузка данных

Раздел «Загрузка» содержит:

1. «Выгрузка SR» — XLSX согласно `specs/002-sr-inventory-analytics/contracts/sr-xlsx-import.md`.
2. «Общая папка результатов опросов» — ручной пакетный импорт JSON.
3. «Учётные данные оборудования» — общий XLSX с колонками `Логин` и `Пароль`, проверяемый только в памяти вкладки.
4. «План автоматического опроса» — каскад Тип оборудования → Производитель → Модель, дата начала и интервал в секундах.

Ручной выбор общей папки остаётся доступен независимо от автоматизированного опроса Extron. Автоматизация только создаёт совместимые JSON и не заменяет существующий импорт.

Структура общей папки:

```text
polling-export/
├── 2026-06-01_09-41-28/
│   ├── 10.10.1.15.json
│   └── 10.10.1.16.json
└── 2026-06-02_10-15-00/
    └── vendor/
        └── 10.10.1.17.json
```

Каждая папка `YYYY-MM-DD_HH-MM-SS` становится отдельным запуском опроса. JSON находятся рекурсивно, поэтому внутри неё допустимы дополнительные подпапки. Запуски обрабатываются по времени. `2026-06-01_09-41-28` означает 1 июня 2026 года, 09:41:28; для 1 июля используйте `2026-07-01_09-41-28`.

Файлы вне корректной датированной папки показываются как ошибки, не-JSON игнорируются, а повреждение одного JSON не отменяет остальные корректные результаты.

Массовый импорт выполняется пакетами по 32 файла с ограниченным параллельным чтением. На экране показываются этап, обработано/всего, успешные результаты, ошибки, дубликаты, скорость и примерное оставшееся время. Кнопка «Отменить загрузку» останавливает начало новых пакетов и сохраняет уже корректно обработанные результаты. Повторно выбранные неизменившиеся файлы пропускаются до повторного разбора и аналитики.

## Хранение и защита

- На каждую загрузку страницы создаётся новый непостоянный адаптер памяти.
- Рабочие данные не записываются приложением в `localStorage`, `IndexedDB` или файлы на диске.
- Интерфейс проверяет явно выбранный XLSX credentials только в памяти вкладки; пары не сериализуются, не отображаются и не включаются в план.
- Телеметрия, CDN, облачные интеграции и продуктовые сетевые запросы отсутствуют.
- Фактический объём ограничен только доступной памятью браузера; искусственной квоты приложения нет.
- После перезагрузки или закрытия страницы рабочие данные удаляются.

Исходные файлы остаются в выбранной пользователем папке и не изменяются инструментом. Защита сеансовой памяти не может противостоять скомпрометированной учётной записи Windows, вредоносному ПО или чтению памяти запущенного процесса.

## Опрос устройств

`runtime/model-catalog.js` содержит переданный каталог производителей и моделей. Для контроллеров и панелей Extron добавлен contract-based HTTPS adapter: после входа он получает текущий `/www/main.js`, извлекает session-bound URI подтверждённых ресурсов и опрашивает их в той же локальной сессии. Поддержка определяется web-контрактом, а не жёстким списком моделей; неизвестный контракт завершается `unsupported_web_contract` без догадок.

Рабочий порядок:

1. Загрузить актуальную SR в `index.html`, выбрать один/несколько/все типы, производителей и модели, проверить счётчики поддержки, дату и интервал и скачать JSON-план. В плане нет логинов и паролей; сохраняется только SHA-256 отпечаток выбранного XLSX для проверки файла перед запуском.
2. Подготовить отдельный XLSX с первой таблицей и колонками `Логин`, `Пароль`. Каждая заполненная строка — одна возможная пара для всех поддерживаемых устройств текущего запуска.
3. Запустить локальный скрипт:

```powershell
.\poll-extron.ps1 -Plan "C:\local\extron-polling-plan.json" -Credentials "C:\private\credentials.xlsx" -Output "C:\local\poll-results" -AllowInsecureTls
```

`-AllowInsecureTls` нужен только для явно выбранного локального оборудования с self-signed certificate. XLSX передаётся явно для каждого запуска и существует как нормализованный пул только в памяти polling-процесса; старый vault и другие fallback credentials не используются.

Отдельный безопасный JSON на каждый результат записывается атомарно в явно выбранный корень:

```text
C:\local\poll-results\YYYY-MM-DD_HH-mm-ss\<IP>.json
```

Корень задаётся обязательным параметром `-Output`. JSON каждого устройства сохраняется до отсчёта интервала; после последнего устройства задержки нет. После опроса созданная папка или общий корень вручную выбирается в модуле «Загрузка».

Эквивалентный низкоуровневый CLI:

```powershell
node .\scripts\poll-devices.js --plan .\polling-plan.json --credentials C:\private\credentials.xlsx --output-root C:\local\poll-results --timeout 7000 --allow-insecure-tls
```

Минимальный план:

```json
{
  "schemaVersion": 2,
  "scheduledAt": "2026-09-01T10:00:00.000Z",
  "intervalSeconds": 10,
  "devices": [
    { "ip": "192.0.2.10", "category": "controller", "manufacturer": "Extron", "model": "IPCP Pro", "pollingSupported": true, "allowInsecureTls": false }
  ]
}
```

Для остальных производителей и для Extron с неподтверждённым поколением интерфейса результат имеет `protocol_required` или `unsupported_web_contract`. Это намеренная fail-closed граница: HTTPS/SSH/SNMP-команды и схемы ответов не выводятся из названия модели.

## Ключевые файлы

- `product-catalog.js`, `scripts/validate-reference.js` — единый каталог интерфейса/Справочника и проверка согласованности;
- `runtime/model-catalog.js`, `runtime/polling.js`, `runtime/extron-web-poller.js`, `scripts/poll-devices.js`, `poll-extron.ps1` — каталог, Extron adapter и локальный запуск опроса;
- `app.js`, `styles.css`, `index.html`, `runtime-config.js` — единственный файловый интерфейс, пакетная загрузка, Dashboard-проекция и аналитика;
- `specs/003-secure-local-polling/` — защищённый runtime и polling boundary;
- `specs/004-analytics-dashboard/` — спецификация, контракты, план и проверки Dashboard;
- `specs/005-russian-ui-reference/` — спецификация, словарь терминологии, Справочник и проверки русской пользовательской части;
- `specs/006-portable-reference-sync/` — переносимый защищённый запуск и автоматическая синхронизация Справочника;
- `specs/007-direct-index-launch/` — прямой непостоянный запуск;
- `specs/008-batch-polling-folder-import/` — пакетный импорт общей папки и единственный файловый режим;
- `specs/009-scalable-polling-import/` — индексированный массовый импорт, прогресс, отмена и performance evidence;
- `specs/011-extron-web-polling/` — контракт, хранение, Excel credentials и проверки локального Extron web-опроса;
- `docs/decisions/ADR-0005-secure-local-runtime.md`, `docs/decisions/ADR-0007-direct-index-session-mode.md` — архитектурные решения.
