# MVP_SPHERE_SR

Локальный инструмент инвентаризации, автоматического опроса и аналитики терминалов ВКС, контроллеров, панелей управления и другого мультимедийного оборудования. Внешняя передача данных, телеметрия, CDN и облачные сервисы не используются.

## Требования и запуск

Для полного режима нужен установленный **Python 3.11 или новее**. Node.js, PowerShell, CMD, `pip`, виртуальное окружение, инсталлятор и права администратора не требуются.

1. Скачайте или скопируйте весь проект в любую локальную папку.
2. Дважды щёлкните `START_MVP_SPHERE_SR.py`.
3. Не закрывайте открывшееся окно Python во время работы: локальный исполнитель действует только пока оно открыто.

Если Windows впервые спрашивает, чем открыть `.py`, один раз выберите установленный `python.exe`. Скрипт проверит версию Python и целостность обязательных файлов, запустит случайный адрес `127.0.0.1` и откроет браузер с одноразовой локальной сессией.

При первом открытии раздела «Загрузка данных и опрос устройств» на каждом ПК задайте собственные логин и пароль для плана опроса (пароль от 12 символов). При следующих запусках войдите с ними; кнопка «Закрыть доступ к плану» завершает доступ текущего запуска. Проверку выполняет локальный Python runtime: до входа он не принимает учётные данные оборудования и не запускает опрос. В профиле текущего пользователя Windows, `%LOCALAPPDATA%\MVP_SPHERE_SR\admin-access.json`, хранится только соль и проверочное значение пароля; открытый пароль не записывается в проект или Git. На другом ПК пароль задаётся заново. Для сброса забытого пароля необходимо отдельное явное действие с локальным файлом; автоматического обходного входа нет.

Прямой двойной щелчок по `index.html` сохраняется как отдельный ручной режим: загрузка SR, общей папки JSON и аналитика работают, автоматический сетевой опрос недоступен.

## Интерфейс и данные

Доступна одна роль — «Администратор МЦТП». Основные разделы: «Главный экран», анализ перезагрузок, версий проектов и прошивок, ошибки при подключении, «Оборудование» с семью категориями, «Загрузка данных и опрос устройств», «Локальное хранилище» и «Справочник». Анализ перезагрузок раскрывает таблицы по нажатию на карточки; версии сравниваются по истории точно сопоставленного устройства, а ошибки авторизации и сети показываются раздельно. «Сравнение полей файлов опроса с параметрами SR» остаётся в разработке. Модули «Проекты аудита», «События», «Сопоставления» и «Снимки» в навигации отсутствуют.

Оборудование всегда строится из актуальной выгрузки SR. Все строки SR сохраняются, включая неполные записи без inventory, serial, MAC или IP. Разные устройства не объединяются по похожему адресу или имени: новый JSON автоматически привязывается только к точному текущему IP из актуальной SR. Исторические IP используются лишь для диагностики.

Актуальная выгрузка SR содержит 42 столбца: от `SmartRoom ID локации` до `802.1x`. Основные новые названия — `Наименование локации`, `Адрес локации`, `Класс оборудования`, `Наименование оборудования`, `Тип`, `IP адрес` и `MAC адрес`. Прежние заголовки принимаются как совместимые псевдонимы. Если в строке есть `SmartRoom ID локации` или `SmartRoom ID оборудования`, они используются как устойчивые идентификаторы при последующих загрузках; исходная строка XLSX сохраняется без изменения.

Результаты ручного опроса загружаются общей папкой. Внутри неё ожидаются одна или несколько папок запусков:

```text
polling-export/
├── 2026-06-01_09-41-28/
│   ├── 192.0.2.10.json
│   └── 192.0.2.11.json
└── 2026-06-02_10-15-00/
    └── 192.0.2.12.json
```

Имя `2026-06-01_09-41-28` означает 1 июня 2026 года, 09:41:28. JSON ищутся рекурсивно. Время отдельного результата берётся из `File.lastModified`, а не подменяется временем папки.

## Автоматический опрос

Для точных Huawei Bar 310, Box 310 и Box 610 в плане одного IP доступны три варианта Answer mode: «Не менять», «Автоматически — включить автоответ», «Вручную — отключить автоответ». Изменение запускается отдельно от HTTP и других write-задач, требует подтверждения и проверяется чтением до и после максимум одной записи. На Bar 310 оба направления проверены с восстановлением исходного режима; на Box 310/610 запись пока предварительна до отдельных испытаний. Обычный опрос настройку не меняет.

Для точного Huawei Bar 310 поле `autoUpdate` в JSON отражает подтверждённую администратором **возможность обновления прошивки** по меню «Сервер → Основные службы → Тип сервера»: «Вручную» — отключено, другой доступный вариант — включено. В результате сохраняются источник и `meaning=firmware_update_capability`; это не запись о том, что обновление уже выполнялось. Администратор отдельно подтвердил имена и значения параметров Box 310 и Box 610; новые результаты обеих моделей теперь подтверждены, старые предварительные файлы остаются без изменений.

В плане можно независимо включить «Формировать JSON-опросы» и «Собирать логи устройств»: только JSON, только логи или оба режима. Для логов выбирается отдельная папка; внутри неё создаётся папка времени запуска и исходные XML-файлы поддерживаемых TE20/TE30/TE40/TE50/TE60 по IP. Режим только логов не требует папки JSON и не создаёт файлы опросов JSON; служебный `polling-recovery.json` остаётся в папке логов. TE40 проверен по заголовкам и XML-префиксу; администратор подтвердил корректные запросы логов TE20/TE30/TE40/TE50/TE60 на рабочем ПК. Другие модели не имеют подтверждённого автоматического экспорта логов. В модуле «Загрузка данных и опрос устройств» можно вручную импортировать общую папку логов: инструмент показывает тип, размер, устройство по точному IP и ошибки сопоставления, не раскрывает содержимое и не распаковывает ZIP. Для XML-логов точных Huawei TE20/30/40/50/60 дополнительно доступна локальная событийная аналитика без сохранения сырых строк в состоянии.

После «Импортировать папку логов» модуль «Анализ перезагрузок устройств» отдельно показывает подтверждённые перезагрузки, зафиксированные отключения и предполагаемые отключения питания точных Huawei TE20/30/40/50/60. Предположение имеет низкую достоверность: перед неизвестным запуском долго не было записей, по умолчанию 60 минут; порог можно изменить. Это не доказательство потери питания, и предполагаемые случаи не входят в подтверждённые итоги. Повторные выгрузки не удваивают события. Время остаётся локальным временем терминала, момент потери питания неизвестен. Сырые строки логов не сохраняются в аналитике; TE20 использует отдельное правило web reboots → System boot и различает штатное выключение через web и с пульта ДУ; Extron сохраняет своё прежнее правило.

Для одного exact Huawei TE20 из текущей SR управление питанием позволяет оставить без изменений либо выбрать Shut Down/Restart, сон «Никогда» или 1/5/10/15/30/60 минут и плановый перезапуск. Включение расписания требует явного времени ЧЧ:ММ. После отдельного подтверждения исполнитель читает пять полей, отправляет максимум одну запись только изменённых значений и проверяет точный результат. Администратор подтвердил корректную работу новых параметров на рабочем TE20; обычный опрос остаётся read-only.

Для одного exact Huawei TE20 из текущей SR три поля NTP позволяют отдельно выбрать включение синхронизации, режим «Авто/Вручную» и новое имя сервера либо оставить каждое без изменений. При наличии хотя бы одного изменения требуется отдельное подтверждение; исполнитель проверяет модель, читает текущие значения, делает не более одной ограниченной записи и повторно читает все три поля. Сервер вводится только для ручного режима и ограничен 41 символом. Администратор подтвердил корректное изменение всех трёх показателей на рабочем TE20; обычный опрос остаётся read-only.

Для одного точного Huawei TE20 из актуальной SR поле SSH предлагает «Не менять», «Включить» или «Отключить». Изменение выполняется отдельной задачей после подтверждения, с чтением до и после максимум одной записи. Отключение может прекратить удалённый доступ. Администратор подтвердил работу включения и отключения SSH на рабочем ПК; другие модели не затронуты.

Для одного точного Huawei TE20, выбранного по IP из актуальной SR, поле «Автообновление» предлагает «Не менять» (по умолчанию) или «Отключить». При выборе отключения требуется отдельное подтверждение: локальный исполнитель читает настройку до записи, при необходимости записывает только её и повторно проверяет значение. Обычный опрос не меняет настройку. Администратор подтвердил работу отключения на рабочем ПК. С другими задачами изменения оно не совмещается.

В модуле «Загрузка данных и опрос устройств»:

1. при первом запуске настройте доступ к плану, затем входите с выбранными логином и паролем;
2. загрузите актуальную SR;
3. выберите общую папку для результатов;
4. введите пары логина и пароля устройств в нужном порядке; при необходимости добавьте или удалите строки и передайте пары локальному исполнителю;
5. сформируйте план Домен → Класс оборудования → Производитель → Модель, задайте время и границы случайного интервала в секундах (например, от 5 до 10 включительно); для трёх и более поддерживаемых устройств границы должны различаться, кроме режима 0–0 без пауз;
6. при диапазоне 0–0 прочитайте предупреждение и подтвердите запуск без пауз; затем нажмите «Сформировать и запустить опрос».

Python-runtime сверяет SHA-256 переданных пар, держит их только в памяти одного задания и очищает после завершения, отмены или ошибки. Поля ввода очищаются сразу после передачи; итоговые JSON, журнал восстановления и аналитика секретов не содержат. Каждый redacted JSON сохраняется браузером в выбранную папку `YYYY-MM-DD_HH-mm-ss`. Если один JSON записать не удалось, ошибка фиксируется и остальные устройства продолжают опрашиваться. Если браузер закрылся или компьютер перезагрузился, заново запустите инструмент, выберите прежнюю общую папку, повторно загрузите исходную SR (для задачи закрытия портов — тот же отдельный список целей), снова введите пары и нажмите «Продолжить опрос». Сохранённые файлы проверяются по точному IP и не опрашиваются повторно. Неясный исход задачи изменения настроек автоматически не повторяется и требует отдельной проверки. Видимый `polling-recovery.json` создаётся в папке запуска и не импортируется как опрос устройства.

В разделе «План автоматического опроса» отдельный XLSX-список и папка готовых JSON позволяют скачать локальную таблицу фактических настроек. Значения выводятся только при точном совпадении IP, модели и подтверждённого адаптера последнего успешного опроса. Обычный опрос читает HTTP/Telnet у Huawei TE20–TE60; у exact CloudLink Bar 310/Box 310/Box 610 — Site name, автоответ, NTP, Wi‑Fi, SSH и подтверждённые поля питания. Администратор отдельно сверил имена и значения обеих Box, поэтому новые JSON входят в XLSX и таблицу Site name как подтверждённые; старые provisional-файлы сохраняют «Требует проверки». У exact TE20 дополнительно читаются SSH, автообновление, автоответ, NTP и питание. Неподтверждённая настройка не заменяется значением по умолчанию. Отчёт не меняет устройство; отдельные write-задачи по-прежнему требуют явного согласия и собственных модельных контрактов.

Подтверждены локальные автоматические опросы контроллеров/панелей Extron и терминалов Huawei TE20/TE30/TE40/TE50/TE60/Bar 310/Box 310/Box 610. TE20 использует отдельный HTTPS/443 transport с legacy TLS 1.1 и проверкой модели. TE30/TE40/TE50/TE60 используют общий guarded web-CGI transport. Bar 310, Box 310 и Box 610 теперь используют один `huawei_310_rest_v1` / `huawei-310-rest-v1` на основе Bar 310 при сохранении точной проверки каждой модели до credentials и после входа. Модельные ключи и старые JSON сохранены; объединение не подтверждает предварительные настройки Box. Самоподписанный сертификат разрешается только явно для текущего задания; HTTP fallback отсутствует. Неподдерживаемые модели остаются `protocol_required`. Выключенная по умолчанию задача закрытия HTTP/Telnet доступна точным TE20–TE60 и по модельным правилам серии 310 через отдельный список целей; серия 300 остаётся read-only.

Для терминалов Huawei дополнительное Site Name считывается только после точной проверки модели и идентичности. TE20, серия 300 и Bar 310 используют проверенные модельные способы; значение Bar 310 посимвольно сверено с web-меню. Имена сайта Box 310 и Box 610 подтверждены администратором отдельно, поэтому новые успешные результаты доступны в таблице Site name; исторические provisional-файлы автоматически не повышаются. При несовпадении схемы сохраняется `protocol_required` или `unavailable`; имя локации SR никогда не подставляется вместо значения устройства.

Huawei CloudLink Bar 300 использует отдельный подтверждённый read-only HTTPS web-CGI опрос: модель проверяется до и после входа, затем читаются сведения об устройстве, прошивке, сети, времени, возможностях и Site name. Box 300 и Box 600 подключены к общему core через собственные exact-model проверки; администратор подтвердил успешные отчёты обеих моделей и совпадение Site name с меню устройств. Для этих трёх моделей нет задачи изменения HTTP/Telnet или переноса REST-контракта серии 310.

## Хранение и защита

- state интерфейса, разрешение папки, задания и учётные данные существуют только в памяти текущих процессов/вкладки; в выбранной папке хранится лишь видимый несекретный журнал восстановления;
- `localStorage`, `IndexedDB` и скрытое runtime-хранилище не используются;
- исходные SR/JSON не изменяются;
- готовые JSON пишутся только в явно выбранную пользователем папку;
- loopback принимает только текущий `127.0.0.1|localhost` порт, одноразовую HttpOnly-сессию и CSRF для изменений;
- сетевые обращения к оборудованию ограничены точными IP из неизменяемого плана;
- искусственной квоты данных приложения нет; фактический предел — память браузера и свободное место выбранного диска.

Сеансовая модель не защищает от компрометации текущей учётной записи Windows, вредоносного ПО или чтения памяти запущенного процесса.

## Справочник и развитие

Названия модулей, пользовательские статусы и справочные описания находятся в `product-catalog.js`. Общие производители, модели и статусы протоколов — в `runtime/device-catalog.json`. Новый vendor adapter допускается только после документального или проверенного на устройстве подтверждения endpoint, transport, аутентификации и схем ответов; граница регистрации находится в `mvp_runtime/polling.py`.

Node.js не является частью пользовательского запуска. Он используется разработчиком/CI только для тестов Vanilla JavaScript и проверки Справочника.

## Ключевые файлы

- `START_MVP_SPHERE_SR.py`, `mvp_runtime/` — Python 3.11+ launcher, loopback API, XLSX, polling job и Extron adapter;
- `runtime/device-catalog.json` — общий каталог устройств/протоколов;
- `index.html`, `app.js`, `styles.css`, `runtime-config.js` — интерфейс и прямой ручной режим;
- `runtime/credential-pool.js`, `vendor/xlsx.full.min.js` — проверка XLSX в браузере без CDN;
- `product-catalog.js`, `scripts/validate-reference.js` — единый Справочник и контроль согласованности;
- `python_tests/`, `tests.js` — Python API/security и интерфейсная регрессия;
- `specs/014-python-runtime-migration/`, `docs/decisions/ADR-0014-python-runtime-migration.md` — актуальное архитектурное решение.
